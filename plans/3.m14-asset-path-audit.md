# M14 independent asset-path audit

**Status (2026-10-19): independent asset preparation audited; runtime work not started.** This is the M14 asset-work exception allowed by section 17 after M09. It does not close M13 or satisfy M14 acceptance. HUD/effects/audio work that depends on live combat remains gated on M13.

## Findings

- **Models and skinning:** `submodules/halo-ps2/tools/halo2ps2/modelconv.py` converts selected Halo model tags to the bounded `MODL` tables consumed by `engine/src/world/model.c`; model batches are VU1 packets, capped at 24 triangles and 24 palette nodes. `docs/11-model-section.md` records the bind-pose/skinning conventions, validator coverage, and texture constraints. This is the existing reusable model path; no parallel format or heap-backed runtime path is warranted.
- **Animation:** `animconv.py` emits the bounded `ANIM` section read by `engine/src/world/anim.c`. `docs/12-anim-section.md` documents rest poses, loop/clamp sampling, compressed tracks, and source-frame error bounds. `engine/src/sim/fpview.c` already provides camera-attached first-person arms/weapon placement; however, the play build's weapon presentation is still experimental and must be qualified independently before being treated as M14 acceptance.
- **Source comparison:** the pinned CE sources sample object poses in `source/objects/objects.c` and draw weapon HUD overlays in `source/interface/hud_draw.c`; sound event creation is in `source/sound/game_sound.c`. The corresponding `halo-64` implementations have the same key entry points (`animation_get_node_orientations`, `hud_draw_weapon_overlays`, and `game_looping_sound_new` / impulse sound creation). These are the behavioral references for later work, not a claim that this PS2 subset already matches their complete behavior.
- **HUD:** `engine/src/render/text.c` is a bounded 5x7 debug text path (512 characters), not the Halo HUD implementation. No HUD tag conversion/state renderer was found in the PS2 engine. M14 HUD work should begin with a gameplay-snapshot contract and fixed-size glyph/bitmap batching, keeping simulation independent of presentation allocation.
- **Effects and audio:** no particle/decal runtime or SPU2/audio upload implementation was found under `submodules/halo-ps2/engine/src`. M14 steps 7–11 therefore remain unimplemented. They need bounded pools and explicit IOP/SPU2 transfer/voice limits before effect or sound assets are connected; do not infer capacity from host behavior.

## Boundary and next safe work

Asset conversion/validation may proceed after M09, as the M14 plan permits. HUD state integration, presentation against live player combat snapshots, and combat-linked effects/audio remain behind M13 acceptance. Keep resident assets and pools within the documented 9 MiB resident-object budget and existing PS2 texture/upload budgets; measure EE/IOP usage rather than extrapolating desktop costs. Do not edit `submodules/halo-ps2`, `submodules/halo-64`, or `submodules/halo-ce-universal` as part of this audit.

## Existing player/weapon asset output (read-only inspection)

The ignored `build/play-objects/` outputs already contain an asset conversion for Blood Gulch; they were inspected, not regenerated, because the shared generator and packed trigger data are being changed during M13. `manifest.json` reports 23 weapon records, 14 weapon models, and 5,886,672 resident object bytes (927,072 bytes below the generator's 6,815,744-byte cap). `hp2.py info` validated all five HP2 section CRCs and reported `MODL` (3,165,712 raw bytes), `OTEX` (2,064,960), and `ANIM` (650,048).

Read-only `modelconv.parse_section`, `animconv.parse_section`, and `scenconv.parse_section` validation found 39 models / 48,927 triangles and 16 animation graphs / 342 clips in the object pack. The Blood Gulch SCEN biped definition (`cyborg`) resolves to a model and animation graph; the first-person arms model tag resolves. A read-only inspection of `weapons.fp` found 23 WFP1 records, 14 nonzero weapon model references, and 23 RMP1 remap records; every nonzero model and animation-graph reference resolves in MODL/ANIM. This establishes that the existing converted records are structurally present and cross-referenced. It does **not** establish that the generator output is current against source tags, visually correct, animation-equivalent to Halo CE, or runtime-qualified on the EE. The SCEN first-person arms animation tag is zero; first-person animation uses the merged weapon/remap path and still needs its own presentation qualification.

### M14 step 3 — existing pack structural validation

Without invoking a converter or changing any pack, a read-only validation also exercised the existing geometry and animation payloads:

- Walked every model node's parent chain; no cycles were found. Decoded all 2,160 VIF batches (146,781 expanded vertices): finite positions/UVs/normals, valid model-node influences, weight fractions in range, and quantized normals within 2% of unit length. The 89 skinned parts use palettes of at most 12 entries, under the PS2 format's 24-entry cap.
- Sampled all 11,147 stored animation frames across the 342 clips. Every sample had the graph's node count, finite transforms and unit quaternions. All 5 nonzero graph model references resolve to a packed model with matching node count. Root-motion endpoints decoded as finite values.
- Parsed OTEX: 82 textures and 120 shader bindings; every model-part shader reference resolves.

This is a useful artifact integrity/skeleton-index check for section 3, not a source-frame comparison: it does not compare the converted values against Xbox tag bytes, inspect the rendered bind pose/skin on GS, verify first-person animation visually, or qualify EE time/memory. Source-equation/visual parity remains open.

### M14 step 3 — direct Blood Gulch source comparison

`data/retail/maps/bloodgulch.map` is the compressed Xbox cache (22,571,008 bytes); its already-present `data/retail/weapon-audit-maps/bloodgulch.map` counterpart is the decompressed 44,328,960-byte cache (the header reports the same decompressed size). I used the latter read-only with `MapData.open` and `scenconv.collect_objects(..., [])` to obtain the 24 scenario/player-required model tags and 5 animation graph tags; no converter output was written.

- For all 24 source-required model tags, `modelconv.read_model` and the existing `MODL` record have the same tag ID, ordered node names and links, bind translations, Hamilton rotations, and scales. No required model tag was missing. This is a direct bind-skeleton/index comparison, not a mesh-vertex equivalence check.
- `animconv.load_graphs` loaded all 5 source-referenced graphs (225 animations); all five tag IDs exist in the existing `ANIM`. `animconv.measure_errors` compared every source frame against the packed samples: maximum rotation error 0.179917 degrees (RMS 0.039887) and maximum translation error 0.349604 mm (RMS 0.017488); maximum scale error 0. The maxima are within the converter's documented 0.18-degree / 0.35-mm source-frame tolerances.

This is concrete source-level parity evidence for Blood Gulch player/scenario skeletons and animation samples. It still does not compare converted mesh vertices/material appearance, inspect the bind pose on GS, qualify first-person presentation/input, test console performance, or establish parity for models/animations outside the Blood Gulch-required set. The generic `test_modelconv.py` and `test_animconv.py` real-map checks still skip because their expected `assets/decompressed/a10.map` is absent; this direct check used the locally supplied decompressed Blood Gulch cache instead.

### M14 step 3 — source geometry comparison

I also compared the existing `MODL` mesh payload read-only against those 24 source-required tags. Reproduction path: open the decompressed Blood Gulch map with `texconv.MapData.open`; obtain required tag IDs with `scenconv.collect_objects(map, [])`; read each tag with `modelconv.read_model`; parse existing HP2 `MODL` with `modelconv.parse_section`; map source geometry/part order through the model's five permutation LOD ranges; then concatenate `modelconv.decode_batch` vertices in batch order and compare against each source triangle's expanded vertex sequence. No conversion or pack write was performed.

Across 158 source/output parts and 27,730 triangles (83,190 expanded vertices), all source/output permutation-LOD ranges, part triangle counts and triangle-list order, material shader IDs, and two-influence node indices/weights matched (zero mismatches). Quantized positions had max axis error 0.0000252218 world units, below the maximum observed per-batch half-step bound of 0.0000252282. UV max error was 0.0009764731, below the largest half-step bound of 0.0009765625. The measured maximum normal angular error was 0.374196 degrees; the format documentation gives a quantization method but no separate angular acceptance tolerance, so this number is evidence, not a pass against an invented bound.

This comparison uses the converter's own source tag reader and output packet decoder; it verifies the exported data and its retained triangle/material/skin ordering, not final GS shading, sampled textures, blend behavior, or rendered image parity. The direct check covers only Blood Gulch-required model tags; other maps and presentation remain open.
