M10 is in progress and is not complete. `python3 tools/build_world.py` compiles the pinned halo-ps2 engine sources into parent-owned `build/world-elf/`. The ELF SHA-256 is `23ccc739d2db6acd96622aca7dc67978a9fa20ca4e547a6043119c0cb7df8a41`. `BUILD_ENV=container` uses the existing locked offline image and separate output. Both builds passed and allocated ELF sections match in `build/emulator/world-elf-parity.json`.

The initial baseline used an unchanged upstream source tree; the later M10 correction checkpoint below records two local-fork fixes. The linker combines the existing BSP/model VU1 programs and PS2-native platform, renderer, visibility, texture cache, pack reader and object presentation sources. This executable does not contain original Halo gameplay code. Retail packs remain external private inputs from M09.

The runtime configuration sets `pack`, `tex`, the object pack, lightmaps, sky, sky fog, conservative culling, 30 fps, and `hold 1`. The viewer is launched with its working directory on the staged `host:` files. A 180-frame recompiler diagnostic at `(65,-95,9)`, yaw `-70`, pitch `-5`, drew the sky model and reported 79 textured materials, 15 lightmap pages, and 0 flat materials. Profiler output identifies EE preparation, batches, texture hits, and chain size. Portal counters stay at 0 under the forced conservative path. Emulator wall time is not a console performance result.

The independently implemented CPU projection/clipping/depth rasterizer is `tools/render_reference.py`. It reuses the pack decoder, but calls no PS2 rendering code. Its geometry/depth view at camera `(65,-95,9)`, yaw `-70`, pitch `-5` shows the valley floor, a base ahead, surrounding cliffs and open sky. The camera contract is `config/reference-scenarios/bloodgulch-static.json`; private PNG/JSON output lives under `build/reference/`. This is a geometry reference from converted data, not an oracle for retail materials or gameplay. Synthetic tests exercise near-plane clipping, camera axes and depth-order independence.

`python3 tools/run_world_viewer.py --route` runs 12 camera keys over 300 seconds, 9001 frames, in the requested CPU mode. The recompiler route `world-recompiler-5fb93b007f7d40f9b5b69934cceb149e` and the interpreter route `world-interpreter-188533b309954851867bd73310fd1d24` both finished with 0 dropped frames, a drawn sky, and no DMA overflow. `--freecam` drives the pad from the logged camera position. Those failed flights are historical attempts; the correction checkpoint below records the later successful pad flight. The 180-frame diagnostic is not acceptance.

The parent-owned `src/world/visibility.c` adapter selects the existing renderer's conservative `force_all` path. Native/container allocated ELF parity passes with the adapter. Initial diagnostics raise the clipping work allowance to prioritize completeness; they do not claim a 30 fps performance pass. ## M10 correction checkpoint

The resume review found that the old route's visual output did not match the independent geometry reference. The sky pass called `emit_part_state`, writing VU slots 2/3 over the BSP matrix; the BSP then reused those rows. Local fork commit `46787de` restores the BSP frame header after the sky pass. The corrected ELF is `e16df34e5d80a87d5e023b6d7f84dacfe5b329a49fc17f82dc141c0c75009726`. Native/container allocated-section parity passed. Historical route completion remains recorded, but it does not qualify the corrected renderer.

The corrected recompiler pad-camera run `world-recompiler-2ce3b40f236a4d29bb5669fe264e5daa` completed 3,001 frames with zero logged drops and reached five waypoints, covering both map axes and a height change. The runner now projects each target onto the logged camera basis and uses slow pad input. A preceding run exited before completion and remains failed. The pad run used the original object pack; the sky-only object-pack change below still needs fresh route coverage.

The remaining sky defect was a converter assumption: the first Chicago map is not the complete shader. `sky clear blue` combines star-detail and star layers with the later sky-color map; `clouds puffy light` multiplies cloud colour by the earlier alpha mask. Local fork `e1d8e11` bakes supported static sky stages using keep/replace/multiply/add operations. UV animation is omitted, alpha-replicate flags and unsupported functions fall back to the existing resolver, and this is not full Xbox shader equivalence. The source combiner table is in `submodules/halo-ce-universal/source/rasterizer/xbox/shader_transparent_chicago_preprocessor.c`.

`CONVERT_VARIANT=m10-static-sky python3 tools/convert_map.py` produced identical repeated packs in a separate private directory, preserving the old packs and route evidence. BSP and BSP-texture hashes and geometry bounds are unchanged. Object pack SHA-256 is `7bd9a5474724c30700bf3844fab1aae47edcbcf838e54767874c784bb1ad2127`, size 2,441,216 bytes. `build/convert/bloodgulch.json` records the new directory and converter pin. Synthetic tests cover cloud alpha, multiply/add colour, UV repetition, and unsupported operations. All 29 project tests and 12 upstream synthetic suites pass natively.

Fixed-camera run `world-recompiler-24b291464c9445dc99fd327804f60cd4` uses the corrected ELF and sky pack. Its view contains the valley floor, central base, enclosing cliffs and open sky in the same placement as `build/reference/bloodgulch-valley.png`. The reference omits objects, textures, and the sky model; these are expected appearance differences. Static sky baking and reduced texture/lightmap fidelity remain declared approximations. The prior missing-floor and grayscale-mask defects are resolved in this view.
