# Blood Gulch static-world viewer

M10 is in progress and is not complete. `python3 tools/build_world.py` compiles the pinned halo-ps2 engine sources into parent-owned `build/world-elf/`. The ELF SHA-256 is `23ccc739d2db6acd96622aca7dc67978a9fa20ca4e547a6043119c0cb7df8a41`. `BUILD_ENV=container` uses the existing locked offline image and separate output. Both builds passed and allocated ELF sections match in `build/emulator/world-elf-parity.json`.

The upstream source tree remains unchanged. The linker combines the existing BSP/model VU1 programs and PS2-native platform, renderer, visibility, texture cache, pack reader and object presentation sources. This executable does not contain original Halo gameplay code. Retail packs remain external private inputs from M09.

The runtime configuration sets `pack`, `tex`, the object pack, lightmaps, sky, sky fog, conservative culling, 30 fps, and `hold 1`. The viewer is launched with its working directory on the staged `host:` files. A 180-frame recompiler diagnostic at `(65,-95,9)`, yaw `-70`, pitch `-5`, drew the sky model and reported 79 textured materials, 15 lightmap pages, and 0 flat materials. Profiler output identifies EE preparation, batches, texture hits, and chain size. Portal counters stay at 0 under the forced conservative path. Emulator wall time is not a console performance result.

The independently implemented CPU projection/clipping/depth rasterizer is `tools/render_reference.py`. It reuses the pack decoder, but calls no PS2 rendering code. Its geometry/depth view at camera `(65,-95,9)`, yaw `-70`, pitch `-5` shows the valley floor, a base ahead, surrounding cliffs and open sky. The camera contract is `config/reference-scenarios/bloodgulch-static.json`; private PNG/JSON output lives under `build/reference/`. This is a geometry reference from converted data, not an oracle for retail materials or gameplay. Synthetic tests exercise near-plane clipping, camera axes and depth-order independence.
