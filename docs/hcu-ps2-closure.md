The real CE validator retains its 262,144-byte bootstrap claims bitmap and exposes `tag_validate_bind_claims_buffer` for separately-owned, aligned scratch sized to the bound cache and separate-BSP extent. Parent code must use `physical_memory_bind_tag_validation_scratch()` so the scratch span is aligned, bounded, and disjoint from every other configured HCU store; `physical_memory_free()` releases the validator binding with the provider's other spans. `physical_memory_ready()` requires `tag_validate_claims_buffer_ready()` to confirm that the actual bound scratch meets the computed cache+BSP requirement; this guards readiness but does not provision scratch. On map unload the owner must first unpublish tags/BSPs, then release that scratch and other stores in the proven order. No production parent arena currently calls these binding APIs, so the live tag-cache capacity remains 2 MiB and larger validation scratch is not provisioned. `ps2_cache.c` uses the same runtime capacity when validating/materializing CTAG and still has no production HP2/DVD caller.
