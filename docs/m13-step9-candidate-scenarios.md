# M13 Step 9 — candidate reference scenarios

**Status: candidate design only (2026-10-19). These are not finalized parity tests.**

This document fulfills Step 9 of [M13](../plans/0.native-ps2-halo-hybrid-port.md#16-milestone-m13--implement-weapons-projectiles-and-damage) by laying out reproducible, bounded test cases for later comparison with the pinned Halo CE source and retail behavior. Do not treat the candidate expected outcomes below as validated port results. Finalize each scenario only after the source transition order, random consumption, exact tag records, collision/material mapping, and runtime state interface are audited and recorded. Keep canonical per-tick state and RNG snapshots; compare discrete transitions exactly and floats with an explicitly declared tolerance.

These are N64-specific adaptations, not CE behavior. Use common/non-N64 source paths for semantics; preserve CE parity where the N64 port intentionally changes behavior.
- Retail input: `/home/ai/Documents/Halo/Halo - Combat Evolved.xiso.iso`, SHA-256 `43ec0813edadd592b7b489a930f108d289db9313ac337611110ffca8be0a7258`. The supplied Xbox `01.10.12.2276` Blood Gulch map is used for explicit tag paths and values below; the current decompressed `data/retail/weapon-audit-maps/bloodgulch.map` SHA-256 is `9eb0374cbe4571af640ae0d2e0ebf6119543cdbbece44d49543b4748c4cf0dc1`. Extracted/decompressed copies live in ignored `data/retail/`. The scenarios must read the source map by tag path/ID through the existing Halo-PS2 tag index, never bake host-generated guessed constants into the fixture.

- Current gaps: [Needler audit](combat-needler-audit.md) records the original family gaps; the current worktree has since added a bounded single-shot attach/fuse/attached-damage path (see the audit below), but still lacks target guidance and actor/parent sibling-combine behavior. The EE diagnostic target is a sphere rather than a complete actor/object hierarchy; camera-origin firing excludes mounted-source triggers. Existing host fixtures are useful starting points but are not automatically promoted to reference tests.

## Fixture and output contract

For every row, use a 30 Hz fixed simulation, explicit initial state, explicit seed, and command held/released on the listed tick boundaries. Assign stable object/projectile IDs independent of memory addresses. Snapshot after each simulation transition: tick, trigger/weapon states, magazine/reserve/heat/age/charge, random seed and draw count, spawned/deleted projectile IDs, position/velocity/collision material/response, target/parent attachment, vitality, and ordered effect/damage events. Presentation output is recorded separately and excluded from the canonical gameplay hash. No wall-clock time, renderer cadence, allocator address, or host pointer may influence the expected trace.

The initial campaign-level target profile is the retail Blood Gulch cyborg collision target (body 75, shield 75, indirect damage material 21, shield material 22). This is a *candidate fixture profile*, not a generic biped promise. Keep damage inputs and resulting shield/body normalized and absolute values both in the snapshot. For projectile scenarios, specify the exact muzzle/origin and a simple deterministic target/surface scene, then later repeat with the source collision/object implementation. A diagnostic sphere alone is insufficient for actor, region, parent/child, or mounted-weapon acceptance.

PS2 constraint for the reference harness: make scenarios table-driven and bounded; one active player, at most 16 live projectiles for the first comparison, and fixed arrays only. Add multi-projectile stress separately, at the actual configured pool limit. Record worst-case per-tick operation counts, static/runtime bytes, and R5900 frame-time separately from semantic assertions. Do not reduce the simulation rate, skip random calls, or alter damage outcomes to meet the EE budget.

## Candidate cases

### S9-01 — Pistol/rifle cadence and ready transition

**Readiness: high for host trace; still requires source-trace qualification and runtime parity.**

- Setup: one player, empty projectile world, fresh slot/inventory; select retail `weapons\\pistol\\pistol` with 12 loaded/60 reserve, or `weapons\\assault rifle\\assault rifle` with 60/240. Record source tag identity, first-person ready clip frame count, and initial `weapon`/trigger/magazine state.
- Input: issue pickup/equip at tick 0, hold primary continuously. Separate subcases start already ready and start through `units_update`/weapon ready transitions. Run pistol through tick 40 and rifle through tick 31.
- Candidate expected state/output: for a newly constructed weapon, CE initializes `idle_ticks=127` (`weapons.c:850-878`), so the first primary trigger update is cadence-eligible immediately; successful fire/recover resets idle ticks to 0 (`:1672-1688`). Thereafter `idle_ticks+1 >= 30/rate` (`:1935-1970`) yields intervals of 9 ticks at pistol 3.5/s, 2 at rifle 15/s, and 30 at shotgun 1/s. This settles the held-fire cadence equation for these constant-rate tags: source-aligned tick sequence begins 0,9,18,27 for pistol and 0,2,4,... for rifle if the weapon is already ready. Equip-ready first-fire tick remains a separate lifecycle case; current candidate 28/34 depends on update/animation schedule. Log every discharge bit, cadence timer, rate fraction, rounds loaded, projectile spawn, and random draw.
- Source/tag dependency: CE `weapon_update` (3016 onward), `weapon_trigger_can_fire_again` (1935 onward), `weapon_trigger_fire` (2591 onward), pickup/ready lifecycle (`weapon_new`/state setup near 630-680) in `weapons.c`; retail trigger rates 3.5 and 15 shots/s and magazine counts above; Halo-64 corresponding code at `weapons.c:1739` onward for cadence and `:3060` onward for trigger dispatch.
- Open gap: first-person animation timing and object/weapon update ordering are required to establish equip-ready boundary. The camera-origin EE test is not a retail player/object lifecycle. The cited cadence samples (pistol 0/9/18/27; rifle every even tick) are current host/source-equation fixture observations, not a complete independent trace from the retail executable.

### S9-02 — Pistol and rifle reload, chamber, reserve conservation

**Readiness: medium; reload source and tag-backed host path exist, but broader source parity remains open.**

- Setup: same tags as S9-01. Use two deterministic branches per weapon: (a) empty clip with exactly one magazine's worth in reserve; (b) partial clip with reserve insufficient to fill. Rifle reload-empty animation candidate 87 frames, pistol 67; tag `reload_seconds` is not a substitute for the first-person animation duration.
- Input: fire until empty, release, request reload on the next eligible tick; run until reload completion. Add interruption branch: press primary on the first legal reload-interrupt tick, then snapshot. For a player-owned weapon, test transfer from carried reserve.
- Candidate expected state/output: no reserve is removed before the source reload transfer point; clip increases only by the actual transferred rounds; unused reserve is conserved; the next shot respects chamber timing. In ordinary `weapon_update`, the magazine timer decrements and `weapon_magazine_finish_reload` runs at timer expiration (`weapons.c:3150-3210`); that helper transfers `rounds_reloaded`, marks the magazine unchambered, and may chain reload (`:1524-1560`). A separate reset/interruption path (`weapon_reset`, `:2180-2220`) preserves the loaded rounds only if the timer is already beyond the halfway test; this is not the ordinary reload transfer point. Track exact `weapon.state`, animation/frame, active magazine, rounds in clip/reserve, and all transition ticks. Current host/tag fixture observations are pistol 67-tick reload, rifle 87; empty-mag reload arms on the tick after the last shot in its tested sequence, and an unchambered magazine can add a chamber tick.
- Source/tag dependency: `weapon_magazine_start_reload` (`weapons.c:1713+`), `weapon_magazine_finish_reload` (`:1524+`), first-person frame-count lookup (`:1351+`), `weapon_reset` interruption behavior (`:2180-2220`), and magazine update (`:3150-3210`) in CE; matching Halo-64 source; first-person animation graph/clip records from retail map. Relevant tag sources are each weapon, first-person animation graph and indexed clip.
- Open gap: exact ordinary countdown/start-tick convention and interrupt-input/reset branch must be traced together; tag-selected shotgun/other animation variants also require the relevant weapon/update schedule. Current prototype supports a narrow weapon set only; reload behavior cannot be generalized to all weapon types. The weapon tag's `reload_seconds_tag` is not the runtime timer oracle.

### S9-03 — Shotgun shell-by-shell reload and 15-pellet spread

**Readiness: medium; spread equations have an independent source-equation fixture, but integrated weapon/reload trace is not yet parity-qualified.**

- Setup: retail `weapons\\shotgun\\shotgun`, clip max 12, initial reserve 24, one shell per reload increment, 15 projectiles per shot, initial trigger error 0. Pin one 32-bit seed, the source 1,026-vector `geosphere_new(16)` table identity/hash, player aim axis, and muzzle origin.
- Input: case A: ready weapon, fire at tick 0; case B: begin reload from zero loaded, no fire until reload ends; case C: begin reload and hold primary so the first shell fires as soon as legal. Record one complete 15-projectile volley and a 12-shell reload.
- Candidate expected state/output: a single shot emits exactly 15 ordered cone samples before allocation attempts; every direction is within tag bounds (shotgun 0° inner, 10° equal bounds), final RNG state must match exactly, and `projectile_distribute` changes direction but must not consume RNG. In `tests/shot_cone_pack_main.c`, the source-equation transcription consumes one LCG for the table index and, if the chosen vector is nonparallel to the +X axis, one for cone angle; seed 1 produces 15 nonparallel choices, exactly 30 LCG advances and final seed `0xc03b4ad7` (`tests/test_shot.py:90-112`). The port sampler and transcription agree for each vector within `2e-7`. This settles the fixed-bound sampler equation subcase, not combined dynamic error, actual trigger dispatch, allocation failure, or renderer/runtime parity. One-shell reload uses the 15-frame enter clip and 12-frame subsequent reload-empty clip; shotgun cadence is 1 shot/s. Candidate currently observed host tick values (shot ticks 0/30; hold-through-reload shot at 16; chained shells through tick 134) still need source-compatible weapon/update/animation replay before promotion.
- Source/tag dependency: CE `trigger_create_projectiles` (`weapons.c:2373-2590`), `projectile_distribute` (`:2321+`), `random_math.c` cone sampler, shotgun tag `projectiles_per_shot`, cone fields, magazine and animation graph; Halo-64 equivalents `weapons.c:2157+` and `source/math/random_math.c`.
- Open gap: the fixed-bound vector/seed oracle exists, but dynamic-error golden traces and a single integrated 15-pellet trace with allocation behavior do not. CE samples error/distribution before `object_new` (`weapons.c:2520-2575`) and loops after an allocation failure; port must compare this order, requested/allocated/dropped counts and actual R5900 costs.

### S9-07 — Needler cadence, target guidance, attachment/fuse, damage, supercombine

**Readiness: low; this is a diagnostic family scenario, not currently an executable reference test.**

- Setup: retail `weapons\\needler\\needler`, `weapons\\needler\\needle` (not `projectile`), and its impact/attached damage tags. Needler magazine is 20 loaded/80 reserve; trigger rate ramps from 3 to 10 shots/s. Set seed, target datum, team/owner, material, and projectile IDs. For isolated steering, inject a valid target datum directly; separately test player target acquisition through aim assist. Use one target biped. Guidance subcases: target >10 units, in the `(2,10]` attenuation interval, and at/inside 2 units. Attach to cyborg body/shield material 21/22. For combine, use one parent biped and five existing same-definition attached children before the candidate (six total), plus six existing children before candidate (seven total), and negative controls (different parent/definition, non-biped, or player biped outside running game).
- Input: fire a bounded 20-round clip in a cadence case; in flight cases fire one needle; in fuse case allow one needle to attach and step through 0.75-second rest fuse; combine case attach needles in explicit stable order around the threshold. Keep target transforms fixed except the designated crossing case.
- Candidate expected state/output: retail tag says projectile initial/final velocity 0.13333334, guided angular speed 1.57079637 rad/s (nominal `pi/60` radians/tick), max range 20, rest timer with equal 0.75 s bounds, attach on material 21/22, impact damage 0 and attached damage 10 with type-21/type-22 modifiers 1. Source stores timer delta as `1/(0.75*30)`; after 22 additions the normalized timer is below 1, after 23 it reaches/exceeds 1. Since timer is advanced at the beginning of `projectile_update` and collision/attachment occurs later in that update (`projectiles.c:695-732`, `:1800-1845`), the first detonation is on attached update 23; that update calls `projectile_detonate` before deletion (`:1068-1088`). Existing host regression also observes 23 updates (`tests/test_shot.py:68-88`), but it is not an independently built CE-source trace. On each attach to an object, CE resets matching existing children’s arming and detonation timers; the current attach is flagged for super-explode when it finds six qualifying existing children (`projectiles.c:1800-1840`), then the detonation pass checks a count greater than six, biped parent and either NPC parent or running engine (`:1357-1417`). Record target acquisition, steering, wander vector, parent/node link, fuse timer, regular/super effect, child timer changes, damage target/value, and event order.
- Source/tag dependency: CE projectile assignment (`weapons.c:2476-2578`), `player_aim_projectile` and sorted/LOS target selection (`game/aim_assist.c:500-~640`), guidance/timer (`projectiles.c:665-814`), attachment (`:1800-1845`), and supercombine/effect/damage (`:1357-1465`); Needler/material/damage/effect records; Halo-64 equivalents in `weapons.c:2266+`, `projectiles.c:702+`, `:1443+`, `:1860+`, and `game/aim_assist.c:635+`. Tag record values are detailed in `combat-needler-audit.md`.
- Open gap: aim-assist candidate eligibility and sort order are source-settled: visible, uncloaked enemy bipeds in the cone (alive, not ignored) are scored; ranking is autoaim level, magnetism level, distance, angle, then absolute datum index (`game/aim_assist.c:205-225`, `402-~525`). Player projectile aim then blends with camera-ray collision and pins to the weapon deviation cone (`:542-~630`). Exact target output still needs retail actor geometry, difficulty/weapon aim parameters and deterministic camera/collision input. Parent-child behavior is visible in source but not represented by the current generic diagnostic target; damage ownership/material-region integration, game engine state, effect dispatch, and object/pool schedule remain missing. The single-target host regression agrees with the source-derived 23-attached-update arithmetic (`tests/test_shot.py:68-88`), but it is not an independently compiled CE-source trace and does not validate CE's object attachment graph. Existing 16-slot port pool cannot imply CE pool-exhaustion parity. No host/EE diagnostic sphere may stand in for actor/parent semantics.
