# M0 pinned Newlib ASCII ctype review

The rooted `isalpha`, `isspace`, and `_ctype_` symbols resolve to the pinned Newlib 4.6.0 EE archive members `libc_a-isalpha.o`, `libc_a-isspace.o`, and `libc_a-ctype_.o` in the exact current link map. Source pin: `8881dc4b138f0561596980ac9a481c7e638aebd0` ([`toolchain-sources.json`](../config/toolchain-sources.json#L19)). The table is Newlib's built-in C-locale byte-classification table, not a generated zero object. Newlib's source explicitly defines `isalpha` as the ASCII alphabetic predicate; `isspace` is used by CE's script token scanner with an explicit unsigned-char cast; `isalpha` is used while parsing a drive-style file path, where the accepted input is the ASCII drive prefix. These calls therefore require only the standard C-locale ASCII classifications.

`_ctype_` is read by CE's case-conversion helpers, but this disposition is only for supplying the actual pinned table bytes. The `tolower` call in console completion is separately approved for its narrow ASCII-only HaloScript token domain (see [`hcu-ps2-ascii-tolower-review.md`](hcu-ps2-ascii-tolower-review.md)); that does not approve arbitrary signed-byte inputs. `towlower` remains pending because CE Unicode case-fold parity needs locale/UTF-16 vectors. Other ctype family symbols are not implicitly approved.

`test_pinned_newlib_ascii_ctype_resolves_to_exact_archive_members` verifies the three providers and caller-specific scope. Later EE toolchain qualification should include values `EOF`, ASCII letter/digit/whitespace/punctuation and the 0x80–0xFF edge range; this M0 disposition establishes ownership and the documented ASCII call contract, not full locale or high-byte equivalence.
