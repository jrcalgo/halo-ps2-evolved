# HCU PS2 platform-placeholder audit — M1 input

**Status:** inventory and risk triage only; no generated definition is accepted as a working service. The audit reads `build/hcu-ps2-closure/all/ps2_platform_audit.json`, which `tools/hcu_ps2_link.py` emits from the live R5900 link closure. Rebuild that ignored artifact before relying on these counts.

## Inventory

The refreshed closure has 562 generated definitions: 485 functions and 77 data symbols. The generated bodies comprise 223 zero/null returns, 261 no-ops, 77 zero-initialized storage placeholders, and one dropped log. The classifier divides them into 93 `ps2-service`, 187 `render`, and 282 `excluded-feature` entries. `GetTickCount`, QPC/frequency, and `GetSystemTime` are implemented in `port/ps2/src/ps2_time.c`. Four CE-facing input calls are implemented in `port/ps2/src/ps2_input.c`; neither pad hardware sampling nor guest behavior is verified. Class labels describe the closure classifier, not proof that a no-op is behaviorally safe.

The `excluded-feature` label is not blanket approval: the source-reference list still needs call-site review for every live symbol. In particular local campaign co-op helpers are simulation-owned in `ps2_local.c`, while online event-replication may be omitted only after confirming no state mutation is required. The classifier itself documents the name-based category rules ([classifier](../tools/hcu_ps2_closure.py#L55)); names are a triage mechanism, not a semantic proof.

## M1 work sequence and gate

1. Regenerate the closure and platform audit; retain the exact manifest, ELF hash, toolchain identity and JSON artifact with the report.
2. Choose and implement the cache/map service owner; the manifest marks this source replacement as planned, not implemented. The physical-memory replacement points to existing `port/ps2/src/ps2_memory.c`, but that provider still uses private arrays rather than parent arenas.
3. Mark each of the 562 remaining generated entries as implemented, state-only adapter, unreachable with a call-graph proof, or still open. Track the four implemented XInput calls separately as semantic-only until pad sampling is wired. For every open call, retain source references and whether it can affect lifecycle, simulation, presentation scheduling, or only diagnostics.
4. Implement local startup/time/pad/map-service paths in narrow slices; use positive and negative tests for missing map, malformed header, partial read, exhaustion and repeated load/unload. No success-shaped no-op may stand in for a required service.
5. Rebuild, then boot the exact hashed ELF in PCSX2 interpreter and recompiler through local-game initialization and one known map-load/tick path. Compare logs/state and retain captures. Emulator success does not establish EE timing or memory fit.

**Gate:** M1 remains open until the current image boots the CE-owned local lifecycle, all live required services have tested owners, render callbacks cannot mutate state outside the tick/snapshot contract, no runtime heap fallback remains, and allocated/static plus arena bytes reconcile without overlap. The previous display-server failure is environmental and is not a pass or a source-level blocker; retry guest verification when a usable PCSX2 display is available.
