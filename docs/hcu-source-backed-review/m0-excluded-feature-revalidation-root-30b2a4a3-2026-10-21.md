## Network-co-op hook boundary: explicit hazard conclusion

The prior report's statement that `network_coop_active()==FALSE` is not the proof for the five current note hooks. The functions are called on local object/script/unit operations without a preceding active-co-op condition. Their source semantics make a local no-op a reasonable adapter: they return `void`; the caller does not branch on a value; and the authoritative local mutation is still executed. But because attach/detach/open notes occur *before* their local mutation, source ordering must be covered by tests at those exact functions. The Linux co-op implementation (`network_coop.c` hash above) confirms that the omitted side effect is event recording/replication, but cannot prove that PS2's distinct local adapters have no hidden dependency. Therefore, **leave all five pending until local operation fixtures demonstrate postconditions**, and never use the general `network_coop_active()` false assertion as their sole evidence.

This distinction does not apply to `network_game_get_game` or `network_game_server_port_cooperative_won`: those callers are explicitly gated by the false local-session predicate. Nor does it apply to the unconditional `initialize_network_game_packets`: that function is called, so its no-op needs an unused-metadata proof rather than reachability proof.
