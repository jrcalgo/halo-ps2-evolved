# M0 PS2 timer API review

`GetTimerSystemTime` is provided by the pinned PS2SDK EE kernel, not an HCU generated placeholder. The source pin is `submodules/ps2sdk` commit `4960c2e2bf65c5ea4b604d1a41766a82f97b104e` in [`dependencies.json`](../config/dependencies.json#L57). Its implementation reads timer 2's count/mode and accumulated rollover count, combines them into EE BUSCLK units, and disables interrupts around the non-interrupt-safe read before restoring the prior interrupt state. PS2SDK documents the thread-safe function as callable from either a thread or interrupt handler and returning zero if the timer was not initialized ([`timer.c`](../submodules/ps2sdk/ee/kernel/src/timer.c#L515), [`timer.h`](../submodules/ps2sdk/ee/kernel/include/timer.h#L80)).

The rooted HCU caller is the PS2 time adapter (`port/ps2/src/ps2_time.c`), which derives wrapping milliseconds by dividing BUSCLK ticks by `MSec2TimerBusClock(1)`; the same monotonic source backs performance-counter APIs. The exact current target link map resolves `GetTimerSystemTime` from `libkernel.a(GetTimerSystemTime.o)` and its interrupt-safe helper from `libkernel.a(iGetTimerSystemTime.o)` ([`halo-local.map`](../build/hcu-ps2-closure/all/halo-local.map#L567)). The M1 guest boot executes the adapter and advances through its timed boot phases; this verifies integration, not timer accuracy calibration. The rooted external is therefore implemented by the pinned kernel service; cycle-accurate performance and game-tick parity remain their own qualification concerns.
