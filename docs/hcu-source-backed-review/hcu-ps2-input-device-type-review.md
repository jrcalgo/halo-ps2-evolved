# M0 XInput device-type table review

The three rooted table symbols are address-identity tokens: CE passes the address of each table to `XGetDeviceChanges` and `XInputOpen`; the reconstructed XDK header documents the same public-symbol identity and the native port defines zero-initialized table objects ([`xdk_xbox.h`](../submodules/halo-ce-universal/port/include/xdk/xdk_xbox.h#L71), [`xdk_xkbd.h`](../submodules/halo-ce-universal/port/include/xdk/xdk_xkbd.h#L17), [`xinput_sdl.c`](../submodules/halo-ce-universal/port/linux/src/xinput_sdl.c#L63)). The PS2 image needs distinct stable addresses, not Xbox table contents, because `ps2_input.c` recognizes the gamepad token by pointer identity and enumerates the machine's four parent-published pad samples.

`XDEVICE_TYPE_GAMEPAD_TABLE` is owned by the PS2 input ABI as a stable gamepad token. `XDEVICE_TYPE_MEMORY_UNIT_TABLE` and `XDEVICE_TYPE_DEBUG_KEYBOARD_TABLE` remain distinct stable tokens but intentionally have no device provider: `valid_device_type` accepts only the gamepad token, and `XGetDeviceChanges`/`XInputOpen` fail closed for the other kinds. This leaves CE's memory-unit event mask zero and avoids manufacturing Xbox memory-unit/debug-keyboard events. The debug-keyboard initialization and worker are compiled out under `HALO_PS2`; the remaining keyboard poll safely observes no keyboard event.

The tests in [`hcu_ps2_input_main.c`](../tests/hcu_ps2_input_main.c) now define all three tokens and verify unsupported memory-unit/debug-keyboard enumeration and opens fail, while existing gamepad conversion, insertion/removal, packet progression, and disconnected reads continue to pass. `test_dualshock_conversion_connection_and_packet_semantics` compiles and runs the real PS2 input provider. This approves only type-token and current local-input semantics; multitap physical qualification and persistent memory-card save support remain separate acceptance items.
