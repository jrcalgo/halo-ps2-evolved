## Stateful vs drawing-only boundary

1. **Required current state/presentation ownership:** `main_screen_shell_begin_fade` updates widget/audio state; `render_frame_present` is an ordinary display/screenshot boundary and needs an explicit parent-present contract. Neither may be waived as “just drawing.”
2. **Fatal-frame state setup:** the ten `rasterizer_*` calls above are rooted only inside the infinite fatal loop. They configure and close a diagnostic frame/window; the source also logs the error and stops rumble before entering that loop (`main.c:3169-3184`). Their narrowly fatal-only caller identity supports a possible explicit log-only omission policy, but does not establish that rasterizer state is generally unnecessary. In particular, `rasterizer_window_begin` consumes camera/window/fog state.
3. **Observational debug output:** the seven pending `render_debug_*` helpers only draw or queue optional diagnostic output. The pre-existing source review `hcu-ps2-render-debug-primitives-review.md` covers the common no-simulation-mutation principle, but this report maps the exact refreshed callers and notes `render_debug_string` has a deferred cache side effect. Debug rendering must stay separate from authoritative collision, sound, effects, object, and camera computations.
4. **Port-only additions with concrete fallback risks:** `first_person_legs_reset` and the two HUD hooks originate in Linux-specific extensions. The HUD hook pair is not sufficient to omit blindly: Linux `hud_hires_sprite_bitmap` returns the original sheet when no override is active (`port/linux/game/hud_hires_tags.c:226-290`), while the generated PS2 pointer placeholder currently returns `NULL` (`build/hcu-ps2-closure/all-no-bootstrap-memory/ps2_platform.c:178`). The active CE call then passes the result to `hud_draw_bitmap_direct` (`source/interface/hud_messaging.c:548-565`; `ui_widget.c:4065+`). Implement an identity fallback (`return bitmap`) or equivalent bounded PS2 stock-HUD behavior before declaring those related callsites safe; no-op load/unload is only safe once no stale custom asset pointer can be retained.
5. Halo-64 is a useful adapter-pattern comparison, not evidence to cut simulation or campaign UI. Its separate render/game glue (`submodules/halo-64/port/n64/n64_render_game.c`, `n64_hud_game.c`) keeps platform presentation distinct from CE state; the PS2 must similarly preserve the live camera, frame, HUD, first-person and lifecycle values required by this pinned PS2 root.

## Recommended decision sequence

1. Keep `main_screen_shell_begin_fade` and `render_frame_present` pending until UI/audio and the parent GS present boundary are implemented and acceptance-tested.
2. Keep the fatal rasterizer rows individually pending until the product explicitly chooses fatal log-only output or provides a GS fatal overlay; then disposition these ten rows together by exact caller-set proof while retaining separate ledger evidence/tests per symbol.
3. Treat the seven `render_debug_*` rows as candidates for diagnostics-only exclusion, with `render_debug_string` requiring the cache-isolation test.
4. For `first_person_legs_reset`, record the feature as Linux-only and prove the corresponding mesh/legs consumers absent from the PS2 closure before exclusion.
5. Do not approve HUD hooks just because their implementation comes from Linux-only source: first establish the required stock-bitmap identity fallback for `hud_hires_sprite_bitmap`, then decide whether high-resolution replacement tables are a supported PS2 feature.
6. `ui_widgets_safe_to_load` can be source-proven empty independently because its current CE function body is empty; keep the rationale narrowly attached to this symbol.
