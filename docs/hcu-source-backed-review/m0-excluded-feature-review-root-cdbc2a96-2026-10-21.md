## Network notification distinction

The five pending `network_coop_note_*` functions are not protected by `network_coop_active()==FALSE` at every callsite. They are invoked during normal local script/object/unit operations. Local safety instead rests on the fact that each is a void replication side effect and the CE caller continues to perform the authoritative local operation: attach note then `object_attach_to_marker`, detach note then `object_detach`, animation note after animation-state update, frame note after frame assignment, and open note before local animation-state change. Linux's implementation demonstrates the omitted side effect is queueing/distributing co-op events, not returning a decision to the local simulation. This is a credible local no-op contract, but it is not proven by a test that merely asserts `network_coop_active()` false. Give each operation a fixture that asserts local state changed and no local gameplay branch is conditional on the notification. Reopen all five as soon as network co-op/replication enters the PS2 profile.

The other network rows differ: `network_game_get_game` and the cooperative-won hook are behind an explicit active-co-op/server predicate; `network_test_update` and `network_voice_update` are independent void platform services; `initialize_network_game_packets` is invoked unconditionally but initializes metadata used by omitted packet transport. A single "network is disabled" category is not an adequate source disposition for all of them.
