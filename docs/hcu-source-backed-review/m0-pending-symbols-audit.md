Date: 2026-10-21. Report-only review; no ledger row, tool, or plan was changed during the audit itself. A later integration follow-up fixed the signed-character callsite described below; this addendum records the resulting rebuild and keeps the row pending until its source-backed ledger disposition is completed.

## Executive finding

The ledger is now bound to the selected production HCU closure, `all-no-bootstrap-memory`, with rooted-object SHA-256 `fb12b1603674f15af4aff5336accd04603e0193175fa06f8bcf77409aeb8f2aa`. The combined link probe records that exact profile and rooted hash in `build/hcu-parent-link-probe/result.json`; the previous ledger hash was `39f20bc6…`, from the bootstrap `all` profile. The source-backed ledger therefore has the right production-profile identity now, but its 26 pending rows are not 26 newly discovered missing implementations.

Comparison against the immediately previous ledger (`git show HEAD:docs/hcu-source-backed-review/hcu-ps2-external-review.json`) finds that all 26 rows had previously been labeled `implemented` or `excluded-proven`. Twenty-five retain exactly the same `caller_sections`; `printf` is the sole row whose live caller-section set changed. The source-hash changes came from the current HCU edits in `port/ps2/src/ps2_cache.c`, `port/ps2/src/ps2_cbsp.c`, `source/hs/hs.c`, and `source/hs/hs_runtime.c`. The bulk refresh correctly invalidated those source-bound decisions instead of silently carrying them forward, but it also exposed pre-existing conflicts between the ledger and several review documents. Consequently, these rows must not simply be restored wholesale.

The report's artifact finding is precise: the *rooted hash* difference is a profile switch; the *per-source hash* differences are actual source edits, not a profile artifact. For 25 rows, section names are unchanged, but source-file hashes are too coarse to prove that every caller body is unchanged. `printf` gained `.text.hs_syntax_get_checked`, the malformed-HaloScript-datum diagnostic added in `source/hs/hs_runtime.c:561-588`. The exact section/source/hash sets for every current row are retained in `docs/hcu-source-backed-review/hcu-ps2-external-review.json`.

## Source-backed disposition by class

### Rows whose provider/owner evidence is strong, subject to rebinding the current profile

- `__extendsfdf2`, `__fixdfsi`, `__truncdfsf2`, `rint`, and `sqrt` have real archive providers in the current combined optical link map: the three GCC helpers resolve from `libgcc.a` members and `rint`/`sqrt` from Newlib `libm.a` members. The exact root-function families and software-double caveat are described in `hcu-ps2-toolchain-eight-review.md:11-25,47-57`; the runtime-owner regression checks provider names and rejects generated bodies in `tests/test_hcu_ps2_toolchain_runtime_owners.py:11-43`. This is credible owner evidence, not an EE numerical-parity or performance test; software-double cost and edge vectors remain open for later target qualification.
- `_stricmp` and `_strnicmp` are provided by the PS2 CRT's ASCII-only comparators. The source-backed contract and mixed-case/prefix/high-byte host fixture are in `hcu-ps2-ascii-compare-review.md:1-17` and `tests/test_hcu_external_review.py:1079-1090`. The old source hash changed because the HaloScript translation unit changed; the `ps2_crt.c` body did not. This supports re-reviewing the owner, but current production-profile tests should consume `all-no-bootstrap-memory`, not the old `all` profile.
- `isspace` is a real pinned Newlib ctype implementation, not a generated placeholder. The lexical scanner's calls at `source/hs/hs.c:15338,15352` cast through `unsigned char`. However, the third live call at `source/hs/hs.c:15503` passes `*character` directly to `isspace`. The source report's blanket statement that the call is explicitly unsigned is therefore too broad. Confirm that the input is constrained to ASCII/nonnegative bytes or fix/corroborate the call contract before reapproving this row. `tests/test_hcu_external_review.py:238-250` checks provider/member and ledger state only; it does not exercise high-bit input.
- `printf` remains owned by pinned Newlib stdout routed through PS2SDK `tty0:`. The provider and standard output route are traced in `hcu-ps2-libc-stdout-review.md:3-17`; its existing test verifies the selected archive members and ordinary boot markers at `tests/test_hcu_external_review.py:947-965`. That evidence does not yet cover the new diagnostic call. The new caller is guarded by `if (!node)` and logs the invalid index/array metadata before deliberately re-entering CE's `datum_get` failure boundary (`source/hs/hs_runtime.c:564-588`). Update the row's source-backed reason to identify this diagnostic-only caller and add a malformed-node fixture/guest log check before treating the refreshed row as fully re-reviewed. The printf provider itself is not the risk; the new caller behavior and evidence coverage are.
- The four physical-memory getter bodies are still supplied by HCU's PS2 fixed-memory provider. `ps2_memory.c:113-139` commits only pre-bound spans, while `tests/test_hcu_ps2_closure.py:57` covers binding, capacity reads, idempotence, bootstrap/external-only paths, and release. `hcu-ps2-physical-memory-api-review.md:3-11` explicitly limits that approval: it does not prove retail map fit or allocation/unload lifecycle. `ps2_cache.c:358-425` shows the current use, including the new tag-image pointer consumed by the CBSP materializer at lines 404-409. These API rows can have a valid M0 owner while M2 capacity/materialization gates remain open; do not use the getter approval as evidence that maps fit or render.
- `strchr`, `strcpy`, and `strrchr` resolve to pinned Newlib members and have exact-name/member regression checks in `hcu-ps2-libc-string-review.md:3-15` and `tests/test_hcu_external_review.py:219-235`. The report correctly limits this to provider/API roles and notes missing target edge vectors and caller buffer obligations. The modified HaloScript source hash is not by itself evidence that those standard-library owners changed, but current section/source identities still need to be relocked in the production ledger.
- `snprintf` and `sprintf` have real pinned Newlib formatters. `hcu-ps2-libc-numeric-format-review.md:3-34` documents their owners and explicitly does **not** certify all formats or unbounded `sprintf` capacities. Its test at `tests/test_hcu_external_review.py:1054-1076` checks map-member identity and evidence, not every destination span. Treat provider ownership and caller safety as separate questions.
- `ui_widget_debug_show_path` remains supported as an exclusion: the only rooted call is a script evaluator in `source/hs/hs.c:15102`, while the only state-writing implementation/reader is in excluded `source/interface/ui_widget.c:1860-1865,7365`; the PS2 manifest excludes that file. `hcu-ps2-fatal-debug-surface-review.md:19-22` and the excluded-feature tests document this. The status reset is a source-hash invalidation, not evidence that a PS2 reader became live.

### Rows that should remain pending until the contradictory evidence is resolved

- `fopen`, `fclose`, and `fprintf`: their previous `implemented` labels conflict with `hcu-ps2-libc-file-stdio-review.md:1-28`, which explicitly calls the file-backed group pending because Xbox `d:`/`z:` roots, write modes, and the read-only asset bridge do not establish CE stdio behavior. HaloScript's `fopen("hs_doc.txt", "w")`/`fprintf`/`fclose` path is concrete at `source/hs/hs.c:13858-13867`. Newlib is the implementation owner, but the accepted PS2 storage contract is not. Keep these pending rather than restore the old labels; test failed/unmapped paths and write rejection through the current production runtime before deciding whether a local nonfatal exclusion is source-proven.
- `memcpy`: the previous `implemented` label conflicts with `hcu-ps2-libc-memory-review.md:1-20`, which intentionally leaves the 100-plus-caller function pending pending a bounds/non-overlap review. `hcu-ps2-toolchain-eight-review.md:59-67` establishes Newlib's standard contract and the `csmemcpy` wrapper's checks, but only states that the other live copies are non-overlapping; it does not enumerate/verify every row. `tests/test_hcu_external_review.py:71-83` still allows either state, so it cannot close this discrepancy. The existing callers include newly changed CBSP/cache code; review the production caller list, size ranges, and overlap preconditions before approval.
- `qsort`: the previous `implemented` label conflicts with `hcu-ps2-ascii-compare-review.md:19-23`, which deliberately withholds approval because live CE callers order aim-assist targets, actor candidates, vehicles, and other inputs where equal-key ordering may affect gameplay. Although `hcu-ps2-batch-4-review.md:26` and its batch JSON call the symbol implemented, the report itself names the risk and no CE-vs-Newlib equal-key fixture was identified. Resolve the conflicting reports and compare tie cases at the important live call sites before closing this source-backed row.
- `isspace`: because of the uncast caller at line 15503 described above, keep pending until the signed-char/UTF-8 range is proven or the call is made well-defined. This is a narrower risk than provider identity.

## Current tests and what they prove

I ran the six focused ledger/provider tests (`test_hcu_ee_runtime_symbols_are_provided_by_pinned_libraries`, Newlib memory, ASCII ctype, stdout, numeric formatting, and strings). Result: **6 failed**; each reached the existing assertion that the ledger row must be `implemented` and found `pending`. Tests must be retargeted to the selected production closure as part of the parent integration work, not made green by blanket-promoting all pending rows.

The production optical machine map at `build/hcu-parent-link-probe/hcu-gameplay-machine-optical.map` resolves the reviewed libgcc/Newlib members; for example, the map includes the double helpers around lines 221-247, ctype/stdio/format/memory/string members around lines 299-391, and libm members around lines 135-163. This is useful provider evidence, but a map-member hit alone is not source-backed approval for file I/O, every `memcpy` caller, qsort tie behavior, or the new malformed-HS diagnostic path.

## Integration follow-up (2026-10-21)

The `isspace` caller in `source/hs/hs.c` was changed from `isspace(*character)` to `isspace((unsigned char)*character)`. This preserves the intended byte-oriented command parsing while avoiding undefined behavior for negative signed-char values. [`tests/test_hcu_isspace_call_contract.py`](../../tests/test_hcu_isspace_call_contract.py) confirms all three direct HaloScript `isspace` calls cast their input; it passes. The `isspace` row was then re-reviewed against the production profile: its exact source hash/caller section match, the linked provider is pinned Newlib `libc_a-isspace.o` at combined optical map lines 299–300, and the test checks all direct callsites. The row is `implemented` for the bounded byte-classification contract, not arbitrary locale behavior. After rebuilding with `python3 tools/hcu_ps2_closure.py --layer all --no-bootstrap-memory`, the exact production-profile rooted object is SHA-256 `0645f18c1bc7332b8f4ec161b85b947653e4673fdab1a7fa57fac4e7de64a3e1` (the report-time hash above is historical). `python3 tools/hcu_parent_link_probe.py` rebuilt combined machine ELF SHA-256 `ab9bcc19532e562e16b851da108919e5f8a204211a3cf40ed57eebaf559b5fff`, with zero undefined symbols and 2,084,356 PT_LOAD file bytes. The ledger now has 25 pending rows; M0 remains open and no other semantic row was blanket-approved by this fix.
