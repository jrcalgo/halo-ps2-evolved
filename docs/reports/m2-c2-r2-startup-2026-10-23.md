# M2 C2 r2 startup lane: production partition selection and owner telemetry

Date: 2026-10-23. Lane: startup (C2.2 and C2.6 production wiring).
Ownership: `src/stream/hcu_main.c`, new `tests/test_hcu_main_wiring.py`.
`src/stream/hcu_owner_telemetry.{c,h}` and `tests/hcu_owner_telemetry_main.c` were
not changed: the registry already covers every named owner, so no registry change was needed.

## What changed in hcu_main.c

- **Partition selection (C2.2).** `hcu_select_and_bind_partition()` runs after
  `mem_layout_v2_init_charged_guarded()` and before `physical_memory_allocate()`.
  `HALO_HCU_PARTITION_PROFILE` names the row. Any name other than `bootstrap` must be
  a row of `hcu_memory_partition_select_v2()` or boot fails closed. A selected row is
  bound through `hcu_memory_bind_profile_v1()`, and its guards are checked after
  `physical_memory_allocate()` with `hcu_memory_partition_guards_intact()`. The
  selected row name and version are logged as `HALO_PS2_LOCAL partition-selected`.
- **Default is not a qualified row.** The default `bootstrap` keeps the unqualified
  2 MiB tag span through `hcu_memory_bind_parent_v2()` and logs `qualified=0`. No
  table row is admitted by default.
- **Owner telemetry (C2.6).** `hcu_bind_owner_telemetry()` runs after CE binding and
  before the first `hcu_map_service_init_with_arenas()` and `halo_shell_main()`. Every
  named owner is registered: game_state (capacity `HALO_PORT_GAME_STATE_SIZE`),
  object_pool (nested in game_state, capacity `HALO_PORT_OBJECT_MEMORY_POOL_SIZE`),
  dynamic_simulation, tags, bsp, render_chunks, streaming, scratch, dma and
  audio_requests as arena- or cache-backed samplers. actor_pool and render_texture are
  not bound (see limits). Nested owners are never summed into the backing totals.
- **Renderer fence.** `hcu_renderer_drained()` returns
  `bsp_render_fence_observed(bsp_render_kick_seq()) != 0`, or 1 when no kick has been
  issued. It is printed in each snapshot. No `renderer_drained` field exists on
  `hcu_map_profile_runtime`, so it is not registered there.
- **Snapshots.** `HALO_PS2_LOCAL owner-telemetry phase=... name=...` lines are printed
  at `bound`, `before-shell`, `after-shell` and `shutdown`.
- **Render samplers.** Calls to `hcu_render_telemetry_sample_{dma,render_chunks,texture}`
  sit behind `HCU_RENDER_TELEMETRY_AVAILABLE`. `src/stream/hcu_render_telemetry.h` does
  not exist yet, so the calls are not compiled into the current build.

## Not established

- No full ELF link was produced, so the link-map, undefined-symbol and placement checks
  have not been re-run for this change.
- No PCSX2 interpreter or recompiler run was made. No guest marker or telemetry line
  has been observed from this build.
- No production partition row is admitted. The default path is the unqualified bootstrap.
- Per-map snapshot boundaries are printed only at `bound`, `before-shell`,
  `after-shell` and `shutdown`. A print at each map load and unload needs a hook in
  `hcu_map_service.c`, which is outside this lane.
- Owner sources are approximate:
  - `game_state` and `object_pool` have capacities only. used/high/failures are not fed,
    because the Step 8 game-state and object-pool diagnostics are opt-in in CE.
  - `actor_pool` is unbound because no arena backs it.
  - `render_texture` is unbound until the render-telemetry header exists.
  - `audio_requests` reports the audio region itself. No request queue exists yet, so
    this is not a request count.
  - `streaming` reports its parent arena only; the map-owner and scratch children are
    counted under their own rows.
