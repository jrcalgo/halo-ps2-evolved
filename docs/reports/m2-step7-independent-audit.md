# M2 Step 7 independent audit: CBSP pointer relocation and BSP-field preservation

**Scope:** report-only review of M2 Step 7 in `plans/7.hcu-remake-m2-m4.md`. This audit did not edit code, run or mutate PCSX2, or change the plan. It distinguishes source/schema conversion evidence from actual CE runtime acceptance.

## Conclusion

The CBSP design has the right core safety property: pointer slots are emitted by a linked-CE-schema walk, encoded with explicit BSP-local versus CTAG-name domains, and materialized against caller-provided bases. It is not yet Step 7 acceptance. Present end-to-end relocation checks are mostly synthetic; the real Blood Gulch artifact proves the Python converter/packer can walk one non-UI BSP and retain its bytes, but the paired C materializer test is a 64-byte fixture and the production BSP verifier/runtime consumer has not been exercised with that actual payload. Further, the C materializer bounds tag-name targets but does not itself prove the target is a NUL-terminated string; the C/Python validators also disagree on pointer-field alignment and virtual-region overlap behavior.

No BSP fields should be stripped for Step 7. The schema-walk audit explicitly inventories collision, pathfinding, clusters/PVS, sound, and visual data as CE-owned extents, and labels compressed-vertex subtraction as arithmetic only, not a proven replacement (`tools/audit_retail_bsp_schema.py:120-138,181-189`). Preserve the complete schema-walked retail image and use `structure_bsp_port_verify` as an additional CE acceptance check, not a field-removal license.

## What the current implementation does

1. `walk_structure_bsp` invokes the same schema walker on a retail BSP extent and accepts an external reference mapper for tag-reference names outside that extent; its docstring explicitly says the result is relocation metadata, not a runtime load proof (`tools/ctag_schema_walk.py:378-393`). Nested `tag_block` and in-image `tag_data` addresses are normalized through `pointer_target`, checked against the source image, and recorded as schema-declared slots (`tools/ctag_schema_walk.py:129-141,188-243`). For non-empty blocks, the walker also checks CE maximum counts and requires the entire nested-record extent to fit (`tools/ctag_schema_walk.py:192-210`).
2. `tag_reference.name` is treated specially: an address outside the BSP extent is passed to the mapper, normalized to a CTAG-relative offset, and recorded in the external relocation table (`tools/ctag_schema_walk.py:244-269`). For names directly inside the walked image, the walker checks for a NUL within at most 256 bytes (`tools/ctag_schema_walk.py:269-272`). The external mapper must independently preserve the same termination and membership invariant; the retail Blood Gulch report says all external names resolved to bounded, NUL-terminated CTAG strings (`docs/reports/retail-bsp-cbsp-bloodgulch.json`, `round_trip`).
3. CBSP v1 stores the unchanged normalized image plus a sorted explicit relocation table. Python encode/decode validates checksum, table extent, target/value agreement, pointer-domain uniqueness, and 32-bit base arithmetic (`tools/cbsp.py:107-156,159-192,195-243`). Domain 0 is a BSP-relative offset; domain 1 is a CTAG-relative tag-name offset. The C decoder checks header/version, image and relocation bounds, checksum, reserved bytes, sorted/aligned relocation fields, and internal BSP targets (`submodules/halo-ce-universal/port/ps2/src/ps2_cbsp.c:62-128`). Its materializer copies the image and patches the explicit fields, checks 16-byte base alignment, 32-bit range, virtual BSP/CTAG non-overlap, and source/destination host-pointer non-overlap (`submodules/halo-ce-universal/port/ps2/src/ps2_cbsp.c:131-169`).
4. The real Blood Gulch audit is useful direct input evidence. The local `build/retail-maps/decompressed/bloodgulch.map` has SHA-256 `9eb0374cbe4571af640ae0d2e0ebf6119543cdbbece44d49543b4748c4cf0dc1`, matching the report; the report records BSP extent file offset 2048, size 1,296,384, 463 internal pointers, 93 typed CTAG-name relocations, and a CBSP hash `0fc221a36e097285e472e6fc4227a6bf07f20b063d285d4b464303c7d7a0715d` (`docs/reports/retail-bsp-cbsp-bloodgulch.json`, `source`/`structure_bsp`). This is an excellent first retail C-decoder fixture: unlike the UI diagnostic BSP, it includes meaningful collision and cluster data and fits the current 6 MiB BSP arena.
5. The all-map offline audit reports 24 maps / 82 BSP blocks and zero Python CBSP round-trip failures (`docs/reports/retail-bsp-cbsp-audit-current.json:17368-17376`; `tools/audit_retail_bsp_schema.py:96-106`). A separate package audit confirms complete catalog-to-section correspondence but explicitly makes no memory-fit/runtime-load claim (`docs/reports/retail-cbsp-catalog-package-audit-current.json:1-5`). This evidence supports broad conversion coverage, not target materialization or CE behavior parity.

## Material gaps and likely failure points

### A. Real retail artifact never reaches the C materializer test

The current C/Python parity test encodes the synthetic `fixture()` and computes expected bytes from that same toy input (`tests/test_cbsp.py:112-140`). Its C driver hard-codes `maximum_image_size=4096`, `source_file_offset=2048`, and `tag_size=256` (`tests/ps2_cbsp_main.c:28-44`), which cannot accept the 1,296,384-byte retail Blood Gulch BSP or its real 4,477,116-byte CTAG image. The Blood Gulch report's `ps2_c_decoder_materializer_matches_python_fixture: true` confirms only that fixture parity, not real retail C parity (`docs/reports/retail-bsp-cbsp-bloodgulch.json`, `round_trip`).

### B. Runtime C materialization does not validate NUL termination for domain-1 strings

The schema conversion/tool path validates name strings before producing CBSP, and the retail audit records bounded NUL-terminated names. The C materializer, however, only checks `target < tag_size`, then writes `tag_base + target` (`ps2_cbsp.c:159-167`). It neither receives CTAG bytes nor scans for NUL. If the platform's trust model permits corrupted/replaced asset packages, an in-bounds target into arbitrary data can become a CE `tag_reference.name` pointer. Either enforce name-pool membership/termination before materialization in the bounded adapter, or make an explicit, tested statement that immutable, hash-authenticated HP2 data is the runtime trust boundary. Existing section CRCs alone are not an authenticity guarantee.

### C. Cross-implementation validation is not identical

Python `_validate` accepts any 4-byte slot offset in bounds (`tools/cbsp.py:135-156`); Python `decode` also does not require a relocation field to be 4-byte aligned (`tools/cbsp.py:224-240`). The C decoder rejects an unaligned field (`ps2_cbsp.c:112-114`). Thus malformed encodings may decode in Python but fail in C. Python `materialize` validates base alignment and 32-bit wrap but does not reject overlapping BSP and tag virtual ranges (`tools/cbsp.py:107-131`); C explicitly rejects those ranges (`ps2_cbsp.c:140-149`). Make the accepted CBSP format's rules identical and add a cross-language negative-test matrix so host packaging cannot emit content the target rejects.

### D. Schema-range validity is not equivalent to CE BSP validity

The offline audit walks declared structures and spans but does not test all semantic relationships between indices/counts or run the resulting object through CE's BSP verifier/consumers. CE requires a non-empty collision BSP, valid positive cluster count within the fixed maximum, bounded surface count, and sufficient cluster PVS and sound-cluster data (`submodules/halo-ce-universal/source/structures/structure_bsp_definitions.c:31-43`). Scenario switching calls this verifier before publishing new global BSP pointers, then has explicit unload/rollback behavior (`submodules/halo-ce-universal/source/scenario/scenario.c:1104-1158`). That verifier checks only those conditions; it does not establish that every collision graph index, material/surface link, or visual query is valid.

Relevant fields are mixed throughout the same structure: collision material/BSP blocks, nodes/leaves/surface references/surfaces, lightmaps, clusters/cluster PVS, cluster portals, pathfinding surfaces/edges, background/sound palettes and sound-cluster data, detail objects, and runtime decals (`submodules/halo-ce-universal/source/structures/structure_bsp_definitions.h:186-217`). Do not delete or relocate any of these without a separate proven PS2 owner and CE parity tests. The existing report correctly states compressed vertices support CE visual surface/material/light queries and have no demonstrated equivalent in the PS2 BSPS pack (`tools/audit_retail_bsp_schema.py:181-189`).

### E. Existing switch test asserts source ordering, not runtime state invariants

The host test uses a synthesized BSP and tests the PS2 cache adapter plus caller-contract driver; the CE scenario check parses source text and asserts operation ordering (`tests/test_cbsp.py:142-...`). This is valuable regression evidence, but it does not demonstrate that real CE globals, datum/reference indices, object/actor references, and arena marks remain coherent across a live BSP switch or rollback. Step 7 should gate its own relocation correctness separately from the later scenario transaction acceptance, while sharing an actual retail payload.

## Safest test boundary, in order

1. **Immutable source fixture:** pin the retail decompressed map SHA and schema ELF SHA in a generated fixture manifest. Use Blood Gulch first (1.30 MB BSP, 4.48 MB CTAG) because both fit existing capacities; do not use the 2 KB UI BSP as the only retail example. Keep input and expected outputs under build/ or a test fixture policy that avoids staging copyrighted retail data.
2. **Independent conversion oracle:** regenerate CBSP from that map with the production schema walker and packer. Require exact extent `(2048, 1296384)`, the report's 463/93 pointer-slot counts, exact normalized image equality before patching, and unchanged BSP header/signature and all non-pointer bytes. Require every domain-1 target to be a CTAG name-pool address with a terminating NUL in the permitted name span.
3. **Python bounds/materialization:** materialize the actual CBSP at synthetic, aligned, disjoint 32-bit bases; compare every relocation slot against expected `base + target`, compare every other byte to the normalized image, verify all results stay in the assigned intervals, then exercise overflow, overlap, bad slot alignment, out-of-range target, duplicate slot, and unterminated-name cases. Do not label these addresses physical RAM evidence.
4. **C parity over actual retail bytes:** compile/run `ps2_cbsp.c` against this actual CBSP, not a re-encoded fixture; provide the actual CTAG size and fit its actual BSP length. Compare C materialized output byte-for-byte with the Python result. Repeat with C under R5900 compilation for ABI/undefined-behavior coverage, while keeping host execution as the functional comparison. Check failure paths do not mutate/publish a partially valid destination or caller-owned global pointers.
5. **Bounded semantic acceptance:** run CE schema/tag validation plus `structure_bsp_port_verify` on the materialized Blood Gulch BSP; then exercise actual consumers on a controlled scenario: player ground collision, one line/sphere collision query, valid cluster PVS, sound-cluster lookup, and at least one material/surface lookup. Compare results with CE reference/oracle and assert no access outside BSP/CTAG spans. Keep render-only claims separate because the parent GS renderer is not CE's renderer.
6. **Non-UI range coverage:** after Blood Gulch passes, pick at least one smaller non-UI BSP from another map and one structurally complex case (large clusters/portals, nested pathfinding/lightmap records). For blocks above 6 MiB, exercise converter/schema/materializer and rejection/capacity behavior offline; do not allocate them into the PS2 6 MiB current-BSP span. Whole-map gates remain blocked until the memory plan has a measured, bounded owner for any externalized data.
7. **Required preservation contract:** assert `collision_bsp`, `clusters`, `surfaces`, `cluster_data` (PVS), `sound_cluster_data`, `pathfinding_surfaces`, `pathfinding_edges`, and any referenced materials/lightmap/surface structures remain present and addressable. No field omission based on labels or projected savings. To qualify removal, first instrument all CE callsites, name the replacement PS2-owned representation, then run same-query parity and performance tests with the omitted bytes absent.

## Step 7 disposition recommendation

Keep Step 7 **open**. The implemented mechanism is a promising schema-directed normalization/materialization layer, and the 24-map offline converter audit reduces uncertainty about pointer inventory. To finish Step 7, the first high-value narrow slice is actual Blood Gulch CBSP through both Python and C materializers, plus CE verifier/consumer checks and terminated-name enforcement. This would establish a real retail relocation foundation without prematurely claiming all-map capacity, renderer parity, scenario switching, or M2 completion.
