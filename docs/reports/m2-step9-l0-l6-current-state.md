# Remake M2 Step 9 — L0–L6 current-state audit

**Scope:** report-only mapping of Step 9 in [`plans/7.hcu-remake-m2-m4.md`](../../plans/7.hcu-remake-m2-m4.md) to the current parent, HCU, halo-ps2, test, and runtime boundaries. No implementation or plan files were changed. The audit is based on current worktree source, including dirty changes; it does not imply those changes are committed or target-qualified.

**Conclusion:** Step 9 remains **partial**. There is now meaningful host evidence for bounded HP2 section decoding, package/service rollback, real HCU cache-adapter refusal before publication, real CE tag/BSP validation in a retail-package-backed CE BSP-switch fixture, and CE BSP switch rollback. Those are not yet one production end-to-end L0–L6 transaction. In particular, CTAG and CBSP are still decoded as complete raw sections into temporary owners before materialization; production admission is UI-only; actual optical/OPL reads and target capacity are unproven; map-service preflight runs before CE unload while final materialization happens after unload; late failures consequently require a specified safe-empty state, not restoration of the overwritten old map; and L6 has no explicit presentation payload/atomic commit contract.

## Cross-stage sequencing and unload semantics

1. **Pre-unload failure must preserve the old committed map.** CE requests the target through `ps2_cache_preflight_map()` before `game_unload()`; the parent callback only stages a private catalog entry/source and temporary metadata buffers. The current implementation intentionally refuses to open a second map while `mount.active` / `source.active`, except same-map deferred reload. Tests should capture old map's CE globals, cache adapter fields, arena owner, source descriptor, active BSP bytes/globals, and render generation before every L0–L3 preflight error and show they remain valid.
2. **Post-unload failure cannot restore overwritten single-cache bytes.** The subsequent map loader runs after CE unload. The service repeats deferred same-map validation only after its old owner is released, then materializes into boot-fixed cache spans. Any late L2–L6 failure must close readers, clear CE/HCU globals and callback publication, rewind temporary arenas, invalidate snapshots referencing old map memory, show deterministic menu/no-map state, and permit valid same-process retry. Do not claim old-map rollback after writing the shared tag/BSP destinations.
3. **File source ownership is staged, borrowed, then transferred/closed.** Parent `ctag_mount_hp2_internal()` borrows the source during mount; service clears failed staged state and only closes inactive-reader ownership; `ctag_mount_unload()` releases BSP/backend callbacks and arena data before closing the retained resource reader. Need fault tests for source loss/short reads at resource access after successful CTAG publication, and exact descriptor/ownership invariants across CE unload.
4. **CTAG and CBSP need separate streaming plans.** `hp2_load_stream()` bounds encoded-I/O and decoder scratch, but `world_load_section_with_scratch()` still materializes complete decoded raw section into its owner. Step 8's CTAG direct-destination concept does not by itself solve CBSP; each visitor needs exact output CRC, relocation ordering/domain checks, no-partial-publication behavior, and target byte-parity against current materializer. Do not increase `streaming` or `frame_scratch` to hide this issue.
5. **Device and target evidence is a separate gate.** All cited failure tests use host files/fake FileXio or prebuilt package inputs. Need OPL USB/SMB/HDD and optical real read/seek/stat/EOF/close evidence, plus the exact current production ELF in PCSX2 (and eventually hardware) with actual destination bases/high-water. A previous UI load marker is not proof of gameplay L0–L6.

## Recommended closure sequence

1. Freeze an exact source/package/toolchain/ELF set and build a single L0–L6 snapshot helper that distinguishes pre-unload and post-unload contracts. Include parent arenas and file state, HCU cache adapter publication, CE tag/scenario/BSP globals and loaded flags, and render generation.
2. Finish L0/L1 composed fault coverage (path/root, stat/seek, each HP2 header/table/codec/extent/CRC/read branch) and require a valid same-process retry for every case.
3. Implement bounded-output CTAG visitor into the fixed tag destination only after old-map unpublication; compare bytes/CRC/relocation result against existing materializer, then add CE `scenario_tags_load()` failure injection before and during schema validation.
4. Implement independent CBSP bounded-output validation/materialization into fixed BSP cache; prove no destination bytes/globals are published for failed CRC/domain/schema/extent/capacity cases; exercise CE switch fallback and repeated package-backed BSP loads.
5. Define L6 presentation profile and commit boundary; connect all required tag/BSP/presentation readiness predicates to one success point and generation update, or explicitly document and test that the M2 residency profile requires no additional presentation sections.
6. Only then test candidate gameplay map capacities and OPL/optical reads on the exact production image; collect PCSX2 interpreter/recompiler stage logs and arena high-water. Current UI-only admission must remain until the chosen map fits without consuming the reserve.

**Disposition:** no Step 9 stage is wholly closed at production scope. L1's bounded generic decoder and parts of L0/L2/L3/L4/L5 are substantially implemented and host-tested; L4/L5 have useful real-CE host execution. Remaining critical dependencies are streamed final-destination materialization, exhaustive failure/retry snapshots across CE publication, physical capacity, actual device I/O, and an explicit L6 commit contract. Keep Step 9 and M2 open.
