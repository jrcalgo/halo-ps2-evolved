# M2 Step 7 — bounded CE sound-obstruction host slice

**Disposition:** a narrow host ILP32 probe of `compute_sound_obstruction()` is feasible for its missing-cluster, unreachable-distance, and reachable-hidden-PVS branches over the existing `a30`/`a50` materialized-BSP transaction. A test-only bridge is needed because CE keeps `struct sound_source` private to `game_sound.c`. The visible-PVS branch is **not** bounded by the current fixture when using the real collision wrapper: CE passes object/scenery/machine flags, while the fixture deliberately aborts if dynamic-object collision adapters are entered. Either defer that branch or use an explicitly labeled test-only collision spy; neither route establishes audible output, sound-tag selection, or SPU2/device parity.

## Exact CE contract and transaction boundary

The public declaration is `void compute_sound_obstruction(short local_player_index, struct sound_source *source, real distance)` in [`game_sound.h:96-99`](../../submodules/halo-ce-universal/source/sound/game_sound.h#L96). The real body is [`game_sound.c:950-1049`](../../submodules/halo-ce-universal/source/sound/game_sound.c#L950). It obtains the camera from `observer_get_camera()`, caches by game tick + player + source position, pushes `_collision_user_sounds`, initializes obstruction/occlusion to `0.6/1.0`, then uses the published BSP’s sound-distance and PVS accessors. A reachable non-PVS pair leaves obstruction at `0.6` and computes attenuation; a PVS-visible pair sets obstruction to `0.45` and invokes CE `collision_test_vector()` with front-facing structure, media, object, scenery, and machine flags. A miss changes both outputs to zero. The encoded distance masks bit 7 and scales the low seven bits by `256/127`; byte `0xFF` therefore becomes exactly 256 and fails the strict `< 256` reachability check ([`game_sound.c:985-1034`](../../submodules/halo-ce-universal/source/sound/game_sound.c#L985)).

The fixture already runs after CE `scenario_switch_structure_bsp()` has published the real `global_structure_bsp`, collision BSP, and relocated PVS/sound payloads. It currently proves accessor address/value bounds, ordered/reversed sound-distance equality, and payload immutability but explicitly does not execute `game_sound.c` ([`hcu_scenario_bsp_switch_main.c:753-850`](../../tests/hcu_scenario_bsp_switch_main.c#L753); [`m2-step7-retail-consumer-query-qualification-2026-10-21.md:62-71`](m2-step7-retail-consumer-query-qualification-2026-10-21.md#L62)). Keep the new probe at that same post-publication seam so it tests the package owner + PS2 materializer + CE transaction, not a separately constructed BSP.

## Private layout and bounded test bridge

`struct sound_source` is defined only in [`game_sound.c:159-168`](../../submodules/halo-ce-universal/source/sound/game_sound.c#L159), with a compile-time 0x40-byte size assertion at lines 199-204. Its `sound_location` contains position, forward, velocity, and a `struct location`; CE declares the location layout as leaf index, cluster index, and bonus in [`objects.h:228-233`](../../submodules/halo-ce-universal/source/objects/objects.h#L228). Do not duplicate the private struct in the test main. The narrowest safe bridge is a new test-only translation unit that includes the unmodified CE `game_sound.c` and exports a small fixture function which constructs/initializes a real CE `sound_source`, calls the real `compute_sound_obstruction()`, and returns only the output floats and any input fields needed for assertions. Compile that bridge instead of separately compiling `game_sound.c`; use function/data sections and `--gc-sections` so unrelated looping/music/effect code is discarded. Do not copy the obstruction formula or add production gameplay semantics.

Minimal deterministic machine adapters:

- `observer_get_camera(local_player_index)`: return a static real CE `observer_result`, whose source layout is [`camera/observer.h:48-56`](../../submodules/halo-ce-universal/source/camera/observer.h#L48). Set its camera position and `location.cluster_index` from the fixture case; reject unexpected player indices.
- `game_time_get()`: return a controllable monotonically advancing host tick. Advance for every distinct case because the CE static 128-slot cache is keyed by tick/player/source position, **not** cluster pair or distance ([`game_sound.c:923-969`](../../submodules/halo-ce-universal/source/sound/game_sound.c#L923)). Reuse a tick only for an explicit cache test.
- Keep the existing real `collision_test_vector()` from [`collisions.c:478`](../../submodules/halo-ce-universal/source/physics/collisions.c#L478), actual `global_structure_bsp_get()`, collision-user stack, and materialized BSP. `vector_from_points3d()` can use the existing host math implementation; if an adapter is necessary, test its exact point-difference behavior independently.
- Existing fixture stack starts at depth 1 and supplies `global_current_collision_users` at [`hcu_scenario_bsp_switch_main.c:169-170`](../../tests/hcu_scenario_bsp_switch_main.c#L169). Assert depth and base entry are restored after each probe. The current collision fixture already provides collision profiling stubs and fail-closed object-path adapters ([same C fixture:179-207, 1037-1054](../../tests/hcu_scenario_bsp_switch_main.c#L179)). Keep the game-sound visible query’s object flags unchanged; if it reaches the real dynamic-object branch, the existing forbidden adapters should fail rather than quietly emulate gameplay.

Compile-list delta should be only the test bridge plus any required include path for `source/camera`. `tests/test_hcu_scenario_bsp_switch.py:231-274` already uses ILP32 flags, CE scenario/collision/BSP units, the HCU PS2 CTAG/CBSP/cache path, parent visitor/CTAG mount, halo-ps2 HP2 reader, and dead-section collection. After adding the bridge, inspect the new link map/rooted symbols and report retained `game_sound.c` code/data and unresolved adapters. A clean compile is not proof of a bounded runtime closure.

## Smallest high-value cases

Generate cases per exact source map and BSP identity, not by assuming `a30` and `a50` have the same cluster numbering:

1. **Missing-cluster default:** set one cluster index to CE `NONE`, use a fresh tick/position, and assert outputs remain `0.6/1.0`, collision is not called, cache publishes the result, and the collision stack is balanced. This checks the default path only.
2. **Unreachable pair:** select two valid distinct clusters whose raw encoded sound byte has bit 7 set (normally `0xFF`). Assert the CE query returns the same source-backed byte, CE leaves `0.6/1.0`, and does not enter collision. The calculation depends on the exact `0xFF → 256` boundary and `< MAXIMUM_CLUSTER_SOUND_DISTANCE` condition.
3. **Reachable hidden pair (essential package-backed case):** select a raw-map pair with PVS clear and encoded-distance byte `< 0xFF`. Use a fixed positive `distance`, fresh time tick, and source position. Assert obstruction remains `0.6` and occlusion equals `PIN((1 - distance/(cluster_distance + distance))*1.4, 0, 1)` within a documented float tolerance; assert no collision call. A same-tick repeat with identical player/position but changed cluster/distance can verify the existing cache contract, but must be separate and explicitly assert that CE intentionally returns the cached prior values.
4. **Visible PVS branch (optional, explicitly staged):** `compute_sound_obstruction()` calls `collision_test_vector()` with `_collision_test_objects_bit`, `_collision_test_objects_scenery_bit`, and `_collision_test_objects_machines_bit` in addition to structure/media ([`game_sound.c:1007-1022`](../../submodules/halo-ce-universal/source/sound/game_sound.c#L1007)). The current fixture’s adapters intentionally abort on this path ([`hcu_scenario_bsp_switch_main.c:173-207`](../../tests/hcu_scenario_bsp_switch_main.c#L173)), and the actual wrapper traverses collideable objects if its BSP result has leaves ([`collisions.c:642-690`](../../submodules/halo-ce-universal/source/physics/collisions.c#L642)). Consequently, do not claim this branch runs end-to-end with current adapters. To verify only CE's PVS/obstruction policy, an interposed test-only collision spy can record the exact flags/endpoints and return a controlled miss; label this as policy-branch evidence and assert it is not a geometry test. To run actual real collision, first define a bounded, source-backed dynamic-object scene/adapter closure with independently verified empty or populated object state; that is a separate wider slice and must not weaken CE's flags or the current fail-closed behavior.

## Independent source oracle and non-circular assertions

The current Python `retail_source_pvs_pair_oracle()` already reads the original raw BSP extent, independently derives visible/hidden PVS pairs, and compares those with CE’s relocated observations ([`test_hcu_scenario_bsp_switch.py:25-91`](../../tests/test_hcu_scenario_bsp_switch.py#L25)). Extend that raw-source oracle to extract `sound_cluster_data` extent and the exact triangular pair byte for each selected pair. The index formula is visible in CE’s accessor implementation ([`structure_bsp_definitions.c:207-267`](../../submodules/halo-ce-universal/source/structures/structure_bsp_definitions.c#L207)); Python should implement the on-disk address/extent decode independently, then bind each oracle row to source-map SHA, HP2 package SHA, CBIX BSP index/path, and CBSP payload/image SHA. Do not derive expected distance from the relocated CE accessor and then use it as the expected value.

For each test query, assert the C side reports the selected camera/source cluster indices, PVS bit, raw sound byte, source position, and output floats; Python compares those values to raw-map expected records. The expected attenuation should be independently computed from the raw byte and the documented CE constants (256 and 127), not obtained by a second call to CE’s helper. Retain before/after byte snapshots of both relocated payloads and the existing rollback/retry transaction checks. If a later test runs the real collision-visible branch, the independent collision geometry oracle remains a distinct concern: current wrapper tests compare against CE’s lower-level CE traversal and explicitly do not yet provide an independent retail hit tuple ([`m2-step7-full-ce-collision-wrapper-implementation-review-2026-10-21.md:46-57`](m2-step7-full-ce-collision-wrapper-implementation-review-2026-10-21.md#L46)). Such a test could claim CE sound-policy + real collision composition, not complete collision parity.

## Acceptance boundary

For the *minimal* no-visible-branch slice, acceptance should be phrased narrowly: “CE `compute_sound_obstruction()` consumes relocated encoded sound distance and clear-PVS data, preserves CE defaults for missing/unreachable clusters, and balances its collision-user stack.” It does not prove the visible-PVS geometric branch. If the collision-spy variant is added, say only that CE selects the visible-PVS collision call with the prescribed flags; do not call that real occlusion.

This slice would not qualify all sound sources, sound tags, sound selection, actual playback, codecs, SPU2 voice allocation/mixing, sound hardware, production EE memory/capacity, or target/PCSX2 campaign behavior. Step 8 remains a dependency for target-sized topology; the present transaction host arrays intentionally overprovision BSP storage. No sound output or device parity is implied. REA is not applicable: this is direct current CE source over exact retail package/source data, not unexplained shipped-binary behavior. Halo-64 is at most ownership-boundary context: keep CE's CPU-side query/selection state even when rendering/audio backends are replaced; its N64 budget/cuts provide no PS2 sound or memory authority.
