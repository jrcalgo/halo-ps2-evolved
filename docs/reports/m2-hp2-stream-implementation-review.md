# M2 review: unintegrated HP2 bounded stream decoder

**Scope and disposition:** independent report-only review of the current `hp2_load_stream()` implementation in the dirty `halo-ps2` submodule, its host coverage, its R5900 suitability, and the remaining adapter seam to replace whole-section staging for CTAG. No implementation or plan was changed in this follow-up. The decoder is a useful bounded primitive and its real Blood Gulch CTAG parity test passes, but it is not yet connected to `world/section.c`, the HCU map service, or `ctag_mount`; therefore current M2 admission/capacity behavior is unchanged.

## Executive findings

1. **Core streaming decode appears structurally sound for its documented contract.** `hp2_load_stream()` receives an already parsed `hp2_section`, refills caller-owned input storage through `read_at`, expands stored or LZ4 data through a fixed 64 KiB history ring, emits bounded output chunks through `write_at`, counts exact output, and checks the HP2 raw-section CRC (`submodules/halo-ps2/engine/src/stream/hp2.c:159-369`; API contract in `submodules/halo-ps2/engine/src/stream/hp2.h:41-90`). The 64 KiB ring is sufficient for the current LZ4 block decoder because the encoded match distance is 16-bit and the implementation rejects zero or not-yet-produced distances (`hp2.c:319-343`).
2. **The dominant safety contract is caller-owned transactionality.** The decoder explicitly warns a failed run may have emitted a prefix (`hp2.h:82-90`), and output callbacks can already have accepted chunks before a later malformed token, read error, output failure, or final CRC mismatch. This is safe only when the destination remains unpublished and the caller invalidates/rolls back on every non-`HP2_OK` result. An arena-backed section loader can release its mark; a fixed CE cache cannot rewind, so its cache-open/completion/publication state must remain failed until a whole fresh retry succeeds.
3. **Host evidence is stronger than synthetic-only but not target evidence.** The new host test streams the actual Blood Gulch CTAG HP2 section (raw 4,556,496 bytes, stored 1,901,809 bytes) and compares all raw bytes to Python's decoded section. It reports a combined 86,010 bytes of history/input/output scratch (`tests/test_hp2_stream_retail.py:15-49`; `submodules/halo-ps2/engine/tests/test_hp2_stream_retail.c:25-91`). The host unit test also covers tiny-buffer token/refill/flush splits, stored data, CRC mismatch, and source/sink errors (`engine/tests/test_hp2.c:87-121,138-151`). Neither harness proves PS2 FileXio behavior, target alignment, target stack, R5900 throughput, or the CE destination transaction.
4. **The current product code still allocates full `raw_size` and full `stored_size`.** `world_load_section_with_scratch()` has no call to `hp2_load_stream()` and continues to allocate both extents (`submodules/halo-ps2/engine/src/world/section.c:23-90`). The HCU map service calls that whole-buffer loader for HMAP/CTAG/CRNG/CBIX (`src/stream/hcu_map_service.c:55-79,255-285`), while mount retains full CTAG/CRNG and the selected CBSP loader retains the whole CBSP envelope (`src/stream/ctag_mount.c:67-104,112-173`). Consequently the host test passing does not yet change the 1.5 MiB streaming or 384 KiB CBSP scratch blockers.
5. **The exact production seam needs two layers, not just a replacement function call.** First, add a bounded HP2 section-open/read adapter that reads the fixed header/table, resolves a section descriptor, and feeds `hp2_load_stream()`. Second, add an HCU CTAG visitor/materializer that consumes the CTAG envelope and relocation table without retaining the whole raw section, while writing the image to CE's stable, final tag-cache address only after the old scenario has been unpublished. The latter still needs a boot-time tag-cache capacity above the target map's compact image size; current CE binding is 2 MiB and current runtime preflight/mount retain wire sections (`src/stream/hcu_memory_bind.c:41-56`; `src/stream/hcu_map_service.c:202-295`; `ps2_cache.c:358-397`).

## Decoder behavior review

### Bounds and LZ4 history

`hp2_load_stream()` checks non-null callbacks and scratch members, the minimum 65,536-byte history size, nonzero input/output buffers, `section->offset + stored_size` overflow, supported codec, and the stored-codec size equality (`hp2.h:47-55,82-90`; `hp2.c:251-278`). Every emitted byte is rejected once `produced == raw_size`. LZ4 length extensions are bounded against remaining expected output (`hp2.c:232-249,303-350`); literal bytes are read only through the bounded refill callback; the match distance is checked against zero and available prior output before ring lookup. Overlapping match copies are naturally supported because each byte is read from history then immediately emitted back to history (`hp2.c:319-343`).

The history index uses `produced & (65,536 - 1)` and the public minimum is exactly 65,536 bytes (`hp2.c:218-225,337-341`). Since an LZ4 block stores a maximum match distance of `0xffff`, the current ring covers every legal distance. Do not reduce it below 65,536 without changing/strictly narrowing the codec contract and proving every real package; a smaller history would silently corrupt valid cross-window matches. A history buffer larger than 65,536 is accepted but only its first 64 KiB is used.

There is no direct check that `history`, `input`, and `output` scratch ranges are pairwise disjoint or disjoint from the sink's backing source/destination. The API docs say caller-owned buffers but do not state non-aliasing. Aliasing is hazardous: e.g. overlapping input/output can overwrite compressed bytes before the token loop consumes them; history/output overlap can destroy prior back-reference bytes when output is buffered; scratch aliasing with a fixed destination may mutate the destination before the intended callback commit. Add explicit no-alias preconditions and a range-overlap check where feasible, or state and test the required layout in the API. Also define whether callback reentrancy is forbidden; the function has stack-local decoder state, but nested calls with reused caller scratch are not safe.

The decoder accepts a caller-supplied section descriptor and validates codec/size arithmetic, but it cannot prove that the section belongs to an actual HP2 pack or that the extent lies within the opened file. This is by design at this layer; its caller must obtain the descriptor from `hp2_open_header()`/`hp2_find()` and ensure callback reads are constrained to the known file size. The proposed section adapter must not construct descriptors from untrusted values without carrying and checking `file_size`.

### Callback contract and failure behavior

The callback typedefs use `int` and the implementation interprets exactly zero as complete success and any nonzero as failure (`hp2.h:41-45`; `hp2.c:189-204,207-215`). The public header should explicitly require that `read_at` fills the entire requested range before returning zero; a short read reported as zero is indistinguishable from success and can feed stale bytes to the decoder. The existing `file_reader_read_at()` is appropriate because it bounds the request and loops until all requested bytes are read or returns an error (`submodules/halo-ps2/engine/src/stream/file.c:143-169`).

The stream function can return `HP2_ERR_LAYOUT`, `HP2_ERR_CODEC`, `HP2_ERR_IO`, `HP2_ERR_DECODE`, or `HP2_ERR_CRC`. It flushes output as soon as its buffer fills and once more at the end; thus `write_at` may have seen multiple prefix writes before any final CRC result (`hp2.c:207-230,352-369`). Sink failure returns `HP2_ERR_IO` immediately; source failure from either stored or LZ4 paths does the same. This is a deliberately non-atomic producer. Callers must:

- begin a transaction before the first sink call;
- keep the target range unreachable from CE/world/render consumers until success;
- set publication/completion only after `HP2_OK` and any higher-level validation/materialization;
- rollback the arena mark or mark fixed destination invalid on every error;
- on retry, re-decode the whole section rather than continuing from the last prefix.

For `cache_file_read()`, failure must leave the initialized `_cache_file_read_failed` completion value intact and avoid setting the CE cache as loaded; the CE caller treats non-`TRUE` completion as a rejected read after the synchronous wait (`submodules/halo-ce-universal/port/ps2/src/ps2_cache.c:358-427`; `source/cache/cache_files.c:1260-1297`). Add a regression test that verifies this *integration* behavior; the current HP2 sink test checks only `HP2_ERR_IO`, not CE publication or fixed-span invalidation.

### CRC and R5900 cost

The final CRC is standard reflected CRC-32 with polynomial `0xedb88320`, initialized/finalized like `hp2_crc32()` (`hp2.c:7-16,175-185,365-369`). The stream implementation updates it once for every emitted byte by calling `crc32_update(..., &value, 1)`; that helper executes eight bit iterations per byte (`hp2.c:175-185,218-229`). For the 4,556,496-byte Blood Gulch CTAG raw section, this is 36,451,968 bit-update iterations per pass, before LZ4 token/history/output work. A multipass CTAG verifier/materializer would repeat that cost. It may be acceptable, but there is no EE cycle measurement and the bitwise update/per-byte function call is a likely R5900 CPU hotspot. Prefer a chunk update over buffered output bytes or a small table-driven CRC only after byte parity tests, code-size review, and target timing; do not make CRC weaker or skip the final pass's integrity check.

The host retail harness uses 4,093-byte input and 16,381-byte output buffers, intentionally awkward sizes, plus 65,536-byte history, for exactly 86,010 bytes (`test_hp2_stream_retail.c:30-33,67-76`). These are host fixture parameters, not an accepted PS2 scratch profile. On R5900, validate actual placement/alignment of the arrays in `frame_scratch`, `SyncDCache` expectations for the destination, FileXio's exact behavior with non-sector, non-16-byte chunk lengths, and whether each `read_at` call incurs a seek. `file_reader_read_at()` performs `lseek`/`fileXioLseek` per invocation and then exact reads (`file.c:143-169`); the streaming decoder refills by input-buffer-sized callbacks (`hp2.c:189-204`). For a 1,901,809-byte stored CTAG section and 4,093-byte input, that is on the order of 465 callback/seek refills per pass; larger, aligned buffers may reduce calls but consume more scratch. Compare chunk sizes on target and consider a sequential source callback that avoids redundant seeks, provided offset/short-read checks remain strict.

The missing local `a10.map` caused the documented real-map checks in submodule converter tests to skip. This only disables LeakSanitizer; address/undefined-behavior sanitizers stayed enabled.
- No R5900/EE build or PCSX2 performance run was performed for this report. `ee-gcc` was not found through the shell's `PATH`; current host results should not be described as EE qualification.

### What the HP2 tests do not yet prove

- Retail parity test compiles `hp2.c` on the host and allocates full `raw` and `expected` outputs to compare; the bounded claim applies to decoder scratch, not total process memory (`test_hp2_stream_retail.c:25-31,61-91`).
- The stream test's tiny LZ4 fixture verifies split tokens/refills/flushes, but no explicit >64 KiB source sequence verifies ring wrap plus the maximum legal 65,535-byte match. Current fixture comments promise splits but not maximum history distance (`engine/tests/test_hp2.c:87-121`).
- The stream test doesn't assert alias rejection or define a safe alias contract. It doesn't inject short reads that return “success” without filling, nor ensure the reader/sink offsets exactly cover `[section.offset, section.offset+stored_size)` and `[0, raw_size)` for every adversarial case.
- The flipped-payload corruption loop near `test_hp2.c:153+` exercises the legacy whole-buffer `hp2_load()` path, not the stream decoder's malformed LZ4 parser. The stream tests do mutate expected CRC, test a total read failure, and test sink rejection, but they do not exercise late failure after a sink has already committed several chunks and then assert that the caller invalidates that prefix.
- There is no `hp2_load_stream()` caller in production section or HCU map service code; no `world_load_section_stream()` transaction test; no CTAG envelope visitor/materializer; and no CE cache callback lifecycle test. `tests/test_hp2_stream_retail.py` specifically proves the standalone stream API output, not a destination cache owner.
- There is no target measurement for 64 KiB ring cost, bytewise CRC, repeated FileXio seeks, DMA/cache coherency, maximum blocking load duration, or coexistence with the frame/render scratch lease.

## Required API seam to remove whole-section staging

### Layer 1: section descriptor plus stream bridge (halo-ps2)

Retain `world_load_section_with_scratch()` as the simple whole-section API for small existing users and its rollback contract (`submodules/halo-ps2/engine/src/world/section.c:23-96`). Add a sibling adapter such as `world_stream_section(path/reader, tag, scratch, output_fn, context, raw_size, optional)`:

1. Read only the bounded HP2 header/table into aligned metadata, call `hp2_open_header()`, and resolve `hp2_section` with `hp2_find()`; do not use the current static `hdr` concurrently from another loader (`section.c:26-55`; HP2 header validation at `hp2.c:18-88`).
2. Retain the bounded source file handle/reader for the call, provide `hp2_read_at_fn` that checks every request against the opened file length and section extent, and preserve exact-read semantics. For resident map callbacks, the package reader must remain alive as long as later CTAG/CBSP requests may decode from it; do not close it at the end of preflight and leave only a stale handle.
3. Pass caller-owned `hp2_stream_scratch` to `hp2_load_stream()`. For the general arena materializer, preallocate the final raw destination in the chosen owner, use an offset sink that bounds each write against `raw_size`, release the owner mark and zero the returned pointer/size on any error, and `SyncDCache` before exposing a successful EE buffer. This still reserves full raw output, as appropriate for a section whose true final owner is that whole buffer; it does not make CTAG safe by itself.
4. Keep the exact source hash/HP2 CRC/section tag metadata paired with the opened package and report produced length, scratch high-water, bytes read, and failure stage. A callback that writes direct to an irreversible target must be explicitly marked non-transactional/prefix-producing.

The API already has the right low-level machinery (`hp2_load_stream`), but `world/section.c` must own pack-table validation and arena rollback, because these are the current callers' contract. A caller should not duplicate HP2's header layout or silently bypass section-table overlap checks.

### Layer 2: CTAG streamed mount and CE final destination (HCU/CE PS2 port)

Generic `world_stream_section()` cannot return the current `const uint8_t *payload` expected by `ctag_mount_hp2_internal()` while avoiding a full raw payload. That mount currently loads and retains CTAG/CRNG section buffers and binds `mounted_payload` to the complete CTAG bytes (`src/stream/ctag_mount.c:112-173`; `submodules/halo-ce-universal/port/ps2/src/ps2_cache.c:48-57,79-110`). Replace that data model with explicit compact descriptors and callbacks:

1. In preflight, parse/validate HP2 header/table and stream-validate HMAP, CTAG, CRNG, and CBIX without writing to or overwriting the active CE tag cache. Convert CRNG and CBIX to bounded, retained index records (their present parsers/views point into raw section bytes, so lifetime cannot be dropped without new owned representations: `src/stream/ctag_resource_index.c:1-130`; `src/stream/cbsp_catalog.c`). Keep map source identity/hash and package identity explicit.
2. Extend the HCU PS2 cache mount API with CTAG metadata (final image size, scenario index, and a source/reference for the HP2 CTAG section) rather than raw CTAG payload. Keep the original map resource-source callback separate from the HP2 section reader used to populate tags.
3. On the CE exact tag-data read where the supplied buffer is `physical_memory_get_tag_cache_base_address()`, stream-validate and materialize CTAG directly at that final address. Preserve all `ps2_ctag_open()` rules: 52-byte header, exact image/relocation extent, image CRC, CE tag-header/signature/count checks, sorted/aligned/in-range relocation slots, required table relocations, and in-image relative targets (`submodules/halo-ce-universal/port/ps2/src/ps2_ctag.c:64-145`). Add a CTAG visitor API; do not delete validations just because the raw envelope is no longer contiguous.
4. Keep cache/tag globals unpublished and `completion_flag_reference` failed until the full HP2 decode CRC, CTAG CRC, relocation application, CE tag-header check, and capacity bounds pass. A direct sink may have written bytes already, so this can only run after scenario unpublish for a single in-place cache. If the current map must survive any post-unload I/O failure, provide a second full destination or explicit rollback storage; otherwise document destructive switch-after-unload and fail to the no-map/menu state on any late fault.
5. Ensure the tag-cache physical span can hold the full final compact image and the separate BSP span remains nonempty/large enough. Current binding configures a 2 MiB tag span at `hcu_memory_bind_parent_v2()` boot and binds the remaining `current_bsp` tail as BSP; `physical_memory_bind_*` refuses changes after `physical_memory_allocate()` (`src/stream/hcu_memory_bind.c:41-56`; `submodules/halo-ce-universal/port/ps2/src/ps2_memory.c:91-110,147-155`). Direct streaming removes the raw staging requirement but does not resolve this destination-capacity blocker.

The BSP path has the same need for a direct destination, but it is a separate parser/transaction: `ctag_mount.c:67-104` loads an entire CBSP section before `ps2_cache_mount_cbsp_for_extent()` validates it and CE reads/materializes the requested BSP (`submodules/halo-ce-universal/port/ps2/src/ps2_cache.c:219-250,358-419`). Do not assume streamed CTAG integration fixes the Blood Gulch B000 scratch failure.

## Prioritized follow-up tests

**P0 — API contract and adversarial correctness**

- Add maximum-distance LZ4 fixture: make at least 65,535 bytes of history, emit a match using distance 65,535 after ring wrap, and compare output to existing `lz4_decode()`/`hp2_load_stored()`; also test distance 65,536 rejection if input format can represent it (it cannot in ordinary LZ4 block syntax), zero distance, distance beyond produced prefix, overlapping repeat, and exact raw-size edge.
- Add one-byte and odd-size I/O/output buffers; truncated read after N successful refills; sink error after N successful flushes; bad final CRC after multiple output writes; stored zero-byte section; exact-fit and one-byte-short destination windows. Check callback offsets are monotonic, non-overlapping, and cover expected intervals.
- Document/test exact-read success semantics, callback non-reentrancy, and scratch/source/destination non-aliasing. If the API elects to reject overlapping ranges, add pointer overflow and equal-base/partial-overlap tests.
- Add a reusable transactional sink test: after every non-OK status, owner `used` returns to its starting mark, output size is zero, callback state is unpublished, and a fresh retry produces exact output.

**P1 — section adapter and real retail consumption**

- Build a production-path host fixture around new `world_stream_section()` using real `.hp2` header parsing and file-reader callbacks; stream UI and Blood Gulch CTAG into bounded sinks, compare with whole-buffer decoder and `tools/ctag.py` expected bytes. Validate no raw/stored-sized allocation appears in the adapter.
- Add package truncation/changed identity/short I/O cases to prove source-file-size and section extents are checked at the adapter, not presumed from `hp2_section` alone.
- Implement and test the CTAG stream visitor/materializer against real UI and Blood Gulch. Verify no destination changes on first-pass rejection; for late second-pass failure, prove CE cache/tag globals remain unpublished and `cache_file_read()` completes with the explicit failure sentinel, then full retry succeeds.
- Exercise the actual same-process CE unload → parent release → post-unload decode → scenario tags load path. Host callback order tests are useful but insufficient for global pointer lifetime.

**P2 — R5900 and integrated memory qualification**

- Compile under the R5900 manifest with the PS2 header/profile, then test interpreter/recompiler with the exact package and ELF hashes. Record code size, EE cycles per pass, FileXio read/seek count and timing, frame_scratch peak, streaming peak, cache/BSP physical spans/canaries, and the PCSX2 logs.
- Benchmark several input/output windows, e.g. 4 KiB, 16 KiB, 32 KiB, aligned to the actual FileXio/cache requirements. Compare sequential-reader callbacks (no repeated lseek where safe) against offset-reader callbacks. Include exact full source hashing and CTAG multi-pass decode in the total map-transition time.
- Verify all pointers stay within one permanent final CE tag-cache base and are never copied after publication. Gate each map on full compact CTAG image, active BSP, claims bitmap, retained CRNG/CBIX metadata, and simultaneous render/texture/audio/animation/transition working-set data; no reserved EE bytes or other arenas may be double counted.

## Evidence distinction and bottom line

The new primitive has useful test evidence: host sanitizers pass for the small codec tests, the actual 4.56 MB Blood Gulch CTAG raw section matches the Python decoder exactly, and observed decoder scratch for that host fixture is 86,010 bytes. The whole-engine host test suite also passed after setting `ASAN_OPTIONS=detect_leaks=0` because this execution environment reports LeakSanitizer incompatibility under ptrace. These facts show exact host decoding and bounded decoder work arrays.

They do **not** show: R5900 compile/runtime, PS2 FileXio correctness or performance, durable tag-cache capacity, no-allocation behavior across the entire loader, HCU CTAG validation from a stream, CE tag publication safety, a valid map transition, CBSP streaming, gameplay-map fit, or visible rendering. Keep all non-UI entries blocked. Integrate HP2 at the section-reader boundary and CTAG at the CE tag-cache boundary, with failures treated as prefix writes into an unpublished destination until a complete target-qualified transaction is proven.

## Addendum — section-reader integration observed in current worktree (2026-10-21)

This addendum supersedes the earlier statements above that there is no production caller of `hp2_load_stream()` and that the section reader still allocates a full stored-payload scratch buffer. The shared worktree changed while this review was in progress. The current `submodules/halo-ps2/engine/src/world/section.c` now opens one `file_reader_t`, parses the bounded HP2 header/table, reserves the full decoded `raw_size` in the requested owner, takes exactly 98,304 bytes from the scratch arena (65,536-byte LZ4 history + 16,384-byte input + 16,384-byte output), and calls `hp2_load_stream()` (`section.c:23-54,57-149`). It keeps one file descriptor open for all decode reads, applies output bounds in its sink, rolls back the raw allocation on failure, releases decode scratch, closes the descriptor, and runs `SyncDCache` before returning the completed raw section (`section.c:32-54,103-149`). This is a meaningful integration slice: the generic world section reader now removes the second full `stored_size` allocation and has real transactional arena cleanup.

### Current exact effects and remaining blockers

1. **The API is integrated at the generic HP2 section boundary, but not at the CE residency boundary.** `hp2_load_stream()` is now called by `world_load_section_with_scratch()` (`section.c:138`), but that API still reserves `s->raw_size` contiguously in its owner (`section.c:103-111`). Consequently Blood Gulch CTAG (`raw_size=4,556,496`) still cannot fit in the current 1,572,864-byte `streaming` arena. This is the correct bounded failure; it is not yet direct CTAG-to-tag-cache loading. M2 still requires the separate HCU CTAG visitor/materializer and boot-fixed destination described above. Current UI preflight/mount also retains the decoded CTAG/CRNG sections for the mount lifetime (`src/stream/hcu_map_service.c:255-285`; `src/stream/ctag_mount.c:112-173`).
2. **CBSP remains blocked independently.** `ctag_mount` asks its section callback to allocate the entire decoded CBSP section in `bsp_scratch` (`src/stream/ctag_mount.c:87-104`). Production currently passes `service->section_scratch` as that owner and also supplies it as the decode scratch arena (`src/stream/hcu_map_service.c:130-134`); with the section reader's 98,304-byte scratch plus the raw CBSP payload, a 1.3 MiB Blood Gulch B000 cannot fit the 393,216-byte frame-scratch region. The new reader fixes the old requirement to fit the *encoded* 914,977-byte extent in scratch, but it does not yet route a bounded decoder sink to the stable BSP destination or preserve `ps2_cbsp_open()`'s requirement for a complete contiguous CBSP envelope (`submodules/halo-ce-universal/port/ps2/src/ps2_cbsp.c:62-128`). A separate CBSP visitor/materializer remains necessary; do not simply enlarge frame scratch or expose partially materialized BSP state.
3. **The current static-arena alias behavior is intentional but deserves explicit fixture coverage.** `world_load_section_with_scratch()` rejects overlapping distinct arenas while allowing `a == scratch_arena` (`section.c:8-20,77-78`), and `world_load_section()` uses the same arena for both (`section.c:152-155`). In that case raw output is allocated first and temporary decode work follows it, then only the latter mark is released. Keep regression coverage for same-arena and distinct-arena layouts, including failure rollback, since changing the overlap guard could accidentally reject the public no-scratch wrapper or permit partial overlap.
4. **Do not claim target suitability from these fixed values yet.** The 98,304-byte workspace fits numerically inside the assigned 393,216-byte `frame_scratch`, but that arena is also used as the current CBSP owner and frame/render scratch by other paths (`config/memory-budget.json:19`; `hcu_map_service.c:130-134`). Decode currently performs synchronous read/seek through `file_reader_read_at()` on each input refill (`section.c:32-42`; `submodules/halo-ps2/engine/src/stream/file.c:143-169`). The descriptor is retained, avoiding repeated open/close, but each refill still seeks; output is produced byte-wise and the CRC update performs eight bit iterations for every output byte (`hp2.c:175-185,218-229`). Measure blocking time/cycles and actual arena overlap at EE/PCSX2 before accepting 16 KiB windows or using frame scratch during map load. Do not change simulation cadence or discard integrity checks as a performance shortcut.
