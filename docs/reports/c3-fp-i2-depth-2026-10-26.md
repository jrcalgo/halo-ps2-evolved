# C3 first-person depth probe (I2) — 2026-10-26

## Scope

This isolated probe exercises the engine's actual `fp_depth_clear_emit()` and `fp_depth_state_restore_emit()` helpers on PCSX2 GS with synthetic geometry. It validates packet behavior and viewport isolation; it does not evaluate Halo weapon pose, model scale, FOV, wall clipping, or game performance. Probe sources and run artifacts are under ignored `build/c3/first-person-fix/depth-probe/`.

## Harness correction and retraction

The first probe harness allocated `uint64_t chain_mem[256]` and `gif_mem[256]` while passing a 256-QW capacity to `chain_init()`. Since each QW is 16 bytes, each array backed only 128 QW. Those earlier captures, including the apparent adjacent-view bleed and black 3/4-view captures, were invalid and are retracted; they are not evidence of a production helper defect.

The corrected harness uses shared `probe_dma_buffer_t` storage with `CAP_QW * 2` 64-bit payload words and two-word sentinels before and after the payload. It checks the chain sentinels after chain finalization and before packet parsing, and checks the GIF sentinels after finalization and before DMA submission. A host ASan fixture uses the same buffer type with the actual engine chain and FP depth helpers, verifies a 256-QW payload allocation, writes both helpers, fills to the final legal QW, and confirms the guard remains intact. Command and result: `gcc -std=c11 -Wall -Wextra -Werror -fsanitize=address -fno-omit-frame-pointer -Isubmodules/halo-ps2/engine/src -Ibuild/c3/first-person-fix/depth-probe build/c3/first-person-fix/depth-probe/test_probe_buffer.c submodules/halo-ps2/engine/src/render/chain.c submodules/halo-ps2/engine/src/render/fp_depth.c -o /tmp/test_probe_buffer && ASAN_OPTIONS=detect_leaks=0 /tmp/test_probe_buffer` → `probe-buffer-guard: actual fp-depth helper and 256-QW boundary pass`.

The viewport geometry now matches the game layout from `hcu_render_layout_compute`: one full view; two stacked half-height views; three views with a full-width top and two bottom quarters; or four quadrants. Each capture log reached chain submit, GIF completion, GS FINISH, and presentation, with no harness failure.

## Packet behavior under test

`fp_depth_clear_emit()` writes 12 QW: a 5-QW A+D state packet (including DMA/VIF/GIF tags) enabling alpha-fail Z-only and Z-always, then a 7-QW sprite packet. It clears only the requested rectangle to reverse-Z zero while preserving framebuffer color. The caller establishes that view's XYOFFSET/SCISSOR first.

`fp_depth_state_restore_emit()` writes 7 QW: a 6-QW A+D packet restoring TEST, ZBUF, ALPHA, and CLAMP, plus the DMA CNT tag. The probe then checks standard GEQUAL/Z-write behavior using colored overlap controls.

For FP mode the fixture draws a blue world-depth panel in each view, clears view zero using the engine helper, draws red behind the world, and overlays nearer green and farther yellow. After helper state restore, cyan/magenta overlap controls check restored depth testing. Adjacent views receive lower-Z red and cyan/magenta controls without a clear. The no-clear control mode omits the clear. A separate scissor mode overdraws a magenta color-only sprite beyond view zero.

## Outcome and limits

The corrected isolated GS probe passes the intended depth-clear, FP self-depth, state-restore, and viewport-isolation checks across all four game layouts. This is synthetic GS evidence only. It does not qualify actual Halo weapon/hands clipping or placement and makes no FPS claim. No production source changes were made during this probe.
