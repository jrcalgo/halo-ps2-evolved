# M2 animation-observer coverage review

## Result

The current CE observer already hooks the two direct-access cases called out in the latest independent Step 8 review: `animation_get_x_offsets()` records its bulk `animation->frame_info.address` scan, and `animation_get_node_orientations()` records consumed uncompressed `animation_get_default_data()` bytes. The review's finding that those reader boundaries were uninstrumented is therefore corrected by the checked-out source. The existing source inventory also counts direct `animation.data` pointer acquisitions, direct frame-info addresses, frame-info accessors, and the default-data macro; it fails if those counts or file locations change.

The source inventory in [`test_animation_data_ranges.py`](../../tests/test_animation_data_ranges.py) enumerates direct reader families and pointer-access locations. The per-reader assertion that each enumerated family contains its matching trace call inside the `HALO_PS2_M2_ANIMATION_TRACE` guard is in [`test_ps2_animation_trace.py`](../../tests/test_ps2_animation_trace.py) (`frame_data`, indexed/bulk `frame_info`, `default_data`, compressed rotation/translation/scale, and schema data). Its trace-on/off harness executes the exact CE `animation_get_frame_info()` body, checking valid, oversized-rejected, and logical-index-invalid inputs while preserving CE return behavior. The focused trace/range tests pass: `python3 -m pytest -q -rs tests/test_animation_data_ranges.py tests/test_ps2_animation_trace.py` — **7 passed**. `git diff --check` and `git -C submodules/halo-ce-universal diff --check` passed. These tests establish source inventory, guarded call-site pairing, and accessor trace-on/off examples; they do not establish runtime lifetime, residency, or complete semantic behavior.

Historical opt-in R5900 closure (superseded by the follow-up below): `f976281db97f19ed0baf2aa33422594c45b0670d58d45cb6d47b6c5e837f6852`; it compiled **341 selected sources / 370 units, zero failures**, with the pre-refactor recorder source. Do not use this hash as the current observer artifact.

## Remaining observer gaps

- Events identify animation and data bases by transient addresses only; they do not carry a stable map/package identity, tag id/index, animation ordinal, or descriptor family.
- There is no caller-phase scope that distinguishes schema validation, world actor, player, first-person, vehicle/device, scripted camera, or overlapping four-frame aiming work.
- The event ring is global and unsynchronized. The recorder exposes `ps2_animation_trace_valid()` and marks any overflow invalid; the dropped count saturates at `LONG_MAX`. Focused tests cover the invalidation contract, but do not force the counter itself to `LONG_MAX`. The storage is now caller-bound; production diagnostic arena binding has not yet been implemented.
- There is no bounded guest extraction path and no representative campaign run. A UI map marker cannot provide the d20 authored-encounter/camera/first-person lifetime workload needed for a capacity decision.
- Existing compression-helper records describe conservative container spans rather than exact byte dereferences. They are not pin/lifetime events and must not be summed as a simultaneous-live set.

## Caller-owned trace storage follow-up (2026-10-21)

The recorder no longer embeds its 4,096-event array in static `.bss`. `ps2_animation_trace_bind()` accepts one caller-owned, fixed-capacity buffer before recording begins; a second bind is rejected, and an unbound recorder is invalid. The focused CE accessor harnesses supply their own static test buffers and still prove identical trace-on/off return behavior. This removes the diagnostic array from `.bss`; it does **not** remove its 98,304-byte R5900 storage requirement. Production diagnostic startup must allocate and charge the buffer to a measured named owner after CE game-state and claims reservations; no existing arena may be presumed free. In particular, `frame_scratch` backs snapshots and section decode, and Halo-64's N64 animation cache is only a seam comparison—not a PS2 allocation precedent.

The binding API now rejects null, undersized/overflowing, misaligned, pointer-wrapping, and second bindings in the host fixture. The opt-in parent profile allocates its buffer from `resident_gameplay` after the CE game-state and claims reservations, then binds before `physical_memory_allocate()` and CE startup ([`hcu_main.c`](../../src/stream/hcu_main.c#L288-L320)). `python3 tools/hcu_parent_link_probe.py --asset-profile host --m2-animation-trace` rebuilt the exact profile: ELF SHA-256 `739076e159c56a5b7715a499a46eb1922ccc3cddf6540643855c1c4345fe9b03`, map SHA-256 `8144bfc3ba03fb036a74007f3fe6ab2df339c154a77ec470c3f2ce1be245d302`, probe result SHA-256 `ff4e0dc77f62c19f1cf7706b80f116cb05d8bb19b4a6c99453612269f471c23f`, and opt-in closure result SHA-256 `dc547c4f041bf9c3fb128ef0419de95224aa110a0cc4dcc02f729e2bfac44d1a`. It has **zero unresolved imports** and the link/placement preconditions pass, but the probe's acceptance remains false and its estimated minimum headroom before the untouched reserve is only **2,250 B**. PCSX2 `m2-ui` runs with `--require-physical-placement` passed in interpreter and recompiler for this ELF: result hashes `8992edc050bce462e9583c6e7254a73331568d6fc1e7778328c2da4458303c3e` and `536f2f9a2ce14c7b3210d5dce94ccf1d7bee7366741ef152474b7ce330fd1f24`; settings hashes `cc109ead1f407488b8689e3f2e9465e8927731782732776fc5b422a90e7e04f6` and `b3ceab52557550d91c77b0191b2c5dfc296bb8d2618f26872cee8e789f8e061d`.
