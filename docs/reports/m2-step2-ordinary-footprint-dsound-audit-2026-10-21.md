# M2 Step 2 — ordinary-image footprint and DirectSound image audit

**Scope:** report-only source/map review. No implementation or plan files were changed. The ordinary ELF/map are the previously identified exact pair: ELF SHA-256 `147f386d9f34eb6b87254f83c124b4a73ad790855dc0219fe9ae868a1348e66d`, map SHA-256 `b8fd1647545ce056bccf933842b769f17bde995aecc61cd7eb2e3a187c7ba85f`, HCU rooted-object SHA-256 `9640620fcf5eb19b625ffb835ee5e8af73bfc41300543d75f0b268425894f0b3`. The ordinary size result recorded in the preceding audit was 2,097,540 PT_LOAD bytes versus the fixed 2,097,152-byte `elf_static` ceiling (+388 B; zero undefined symbols, but acceptance false); see [`m2-step2-ordinary-image-size-crossreview-2026-10-21.md`](m2-step2-ordinary-image-size-crossreview-2026-10-21.md).

## Finding: the Xbox DirectSound effects image is a safe, concrete PS2-only exclusion candidate

The linked map retains `.rodata.dsound_effects_image` at `0x002ec160`, size `0x3a5c` = **14,940 bytes** ([ordinary map, lines 27314–27318](../../build/hcu-parent-link-probe/hcu-gameplay-machine.map#L27314)); the ELF symbol table independently reports the same size. In CE source it is a static byte array ([`sound_dsound_xbox.c:318-324`](../../submodules/halo-ce-universal/source/sound/sound_dsound_xbox.c#L318)). Its only source reference is the `IDirectSound_DownloadEffectsImage` argument in `dsound_initialize` ([`sound_dsound_xbox.c:1814-1832`](../../submodules/halo-ce-universal/source/sound/sound_dsound_xbox.c#L1814)). The exact PS2 object has one corresponding linked DirectSound call symbol, so this is not a shared sound-tag payload.

That consumer is unreachable on the current PS2 profile by two independent gates:

1. `read_sound_preferences` returns the PS2 preference with `platform == -1` ([`sound_preferences.c:28-50`](../../submodules/halo-ce-universal/source/sound/sound_preferences.c#L28)). `sound_initialize` resets `initialized` to false, sets up common cache/environment state, then returns at the platform-range check before selecting a platform, creating sound datums, or invoking its backend ([`sound_manager.c:908-951`](../../submodules/halo-ce-universal/source/sound/sound_manager.c#L908)).
2. Even if a PS2 caller were to reach the Xbox backend directly, PS2 `DirectSoundCreate` clears the output device pointer and returns `E_FAIL` (`0x80004005`) ([`ps2_edge.c:110-119`](../../submodules/halo-ce-universal/port/ps2/src/ps2_edge.c#L110)). `dsound_initialize` only enters the branch containing the effects download when `DirectSoundCreate` succeeds; failure logs and disposes, then returns false ([`sound_dsound_xbox.c:1761-1779,1885-1905`](../../submodules/halo-ce-universal/source/sound/sound_dsound_xbox.c#L1761)).

Therefore, a narrowly scoped `HALO_PS2` compile guard around both the 0x3A5C array and its download block is semantics-preserving for the current PS2 sound-manager state: the PS2 path already declines backend initialization and never downloads the Xbox effects image. Non-PS2 builds should keep both array and download unchanged. This removes at least 14,940 load bytes if section GC drops the now-unreferenced array, far more than the ordinary image’s recorded 388-byte overage. The predicted saving is not an accepted result until the candidate is rebuilt and the PT_LOAD size/map are measured; alignment or link changes may affect the exact total.

Do **not** remove `sound_dsound_xbox.c`, the `platform_sound_dsound` table entry, `sound_manager`, `sound_cache`, `game_sound`, or sound tag/data logic as part of this narrow cut. The common manager owns platform selection and shared voice/tag policy; `game_sound_initialize` allocates CE looping-sound state ([`game_sound.c:234-247`](../../submodules/halo-ce-universal/source/sound/game_sound.c#L234)), and `game_sound_update` is called every game frame and processes the scenario sound environment and looping sound objects ([`game.c:1004-1011`](../../submodules/halo-ce-universal/source/game/game.c#L1004), [`game_sound.c:820-905`](../../submodules/halo-ce-universal/source/sound/game_sound.c#L820)). In M14, those CE selection/tag semantics need to feed a PS2/SPU2 request/playback adapter; the Xbox DSP effects image is not that adapter. Today `platform_definitions[0]` still names the Xbox backend and slot 1 is empty ([`sound_manager.c:729-734`](../../submodules/halo-ce-universal/source/sound/sound_manager.c#L729)); PS2 preference `-1` deliberately prevents selection until the PS2 backend exists.

## Larger retained sections are not automatic cuts

The exact ELF’s largest retained code includes `_vfprintf_r` (14,360 B), `_svfprintf_r` (14,264 B), `vehicle_update` (11,968 B), `ai_communication_event` (10,520 B), `__svfscanf_r` (10,348 B), `actor_perception_update` (8,720 B), `unit_update` (8,460 B), `projectile_update` (8,440 B), `object_compute_node_matrices` (7,220 B), `actor_move_update` (7,056 B), and `actor_select_firing_position` (6,632 B), as measured with the R5900 `nm` against this ELF. These resolve to real CE gameplay/AI/physics/scripting callers, not isolated padding. The current plan keeps campaign AI, scripting, effects, object/collision behavior and CE game state in scope; do not cut these to save the small static overage. The map’s `ai_debug` (547,628 B) and `render` (201,364 B) are BSS, not PT_LOAD file bytes; shrinking them would not satisfy the 388-byte `p_filesz` gate and would require separate parity/ownership evidence.

The Halo-64 notes are useful as a warning, not a cut list: they call out frame/camera/first-person/HUD state that must still advance even when drawing is omitted ([`NOTES.md:33-55`](../../submodules/halo-64/port/n64/NOTES.md#L33)) and describe N64-specific far-AI skipping and particle/widget omissions under its constrained runtime ([`NOTES.md:205-208`](../../submodules/halo-64/port/n64/NOTES.md#L205)). Those N64 optimizations do not justify removing campaign AI, effects, render-state, or sound-selection behavior from the 32 MiB PS2 port.

## Verification required before accepting this optimization

- Compile a PS2 object/image and assert that `dsound_effects_image` and the `IDirectSound_DownloadEffectsImage` relocation are absent; compile a non-PS2 build and confirm both remain. Check the map, ELF symbol table and source manifest, then record fresh hashes and refresh rooted-external/M0 ownership rows affected by the changed closure.
- With PS2 `platform == -1`, run a focused test that calls `sound_initialize` and proves `initialized` remains false, no platform initializer or effects-download shim is called, and common CE sound environment/looping-sound state can still initialize/update. Add a negative test that direct invocation of the Xbox initializer fails through the PS2 `DirectSoundCreate` stub before any null device use.
- Run the **new exact ordinary ELF** through the current M2 UI test in PCSX2 interpreter and recompiler, with stable post-marker windows. Retest the lifecycle diagnostic profile separately; do not substitute that profile for the ordinary executable. This only qualifies the UI lifecycle step, not SPU2 playback or M14 sound parity.
- For M14, add tests around the PS2 backend interface: preference/platform selection, channel allocation/priority, sound-tag/permutation requests, start/queue/stop/finish notifications, map unload/reload, and silent/failure behavior. Compare requests/state to CE fixtures before calling the sound port complete.

## Artifact hygiene caveat

During this review the on-disk `hcu-gameplay-machine.elf` and map still hash to the ordinary pair above, but `build/hcu-parent-link-probe/result.json` was overwritten by a different parent-link diagnostic: its current SHA-256 is `f72a9fb88aea3df212ddf9e90dac0f67973046f838e14a74dd05119826331913` and it identifies ELF `01c56a24550dd588ac6c4645c217b54236ee1a235b64c1c8044e7ccbb9881275`, not `147f…`. Do not pair that newer result JSON with the ordinary ELF/map. Re-run the ordinary probe or restore its exact result artifact before claiming a fresh current-image budget result.

**Disposition:** recommend implementing and measuring only the PS2 guard around the Xbox effects blob and its sole download block. It is a source-backed, platform-specific, semantics-preserving candidate for current PS2 sound state and should save enough bytes to resolve the recorded 388-byte static-image overage. Keep Step 2 partial until the ordinary image is rebuilt under the unchanged limit and requalified in both PCSX2 modes. No binary reverse-engineering step was needed: the exact map/symbol table plus source call graph answer the reachability question; this audit does not claim SPU2 behavior.
