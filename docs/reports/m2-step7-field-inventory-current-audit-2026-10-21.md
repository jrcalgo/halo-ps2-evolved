# M2 Step 7.1 — current BSP field and consumer inventory audit

Date: 2026-10-21  
Disposition: source-backed inventory is substantial but not complete as a field-by-field proof; Step 7.1 remains open. This is a report-only audit. It does not change code, plans, or map admission.

## Executive finding

The existing BSP consumer disposition identifies the major schema families and their CE call sites, and subsequent package-backed tests exercise several selected collision, PVS, sound, and location queries. Those are distinct evidence levels:

1. **Source-traced** means the pinned CE structure declaration and one or more consumer call sites have been identified. It does not prove a caller runs in the PS2 runtime or that all fields in a family are behaviorally covered.
2. **Behavior-tested** means a specific CE routine was executed against a materialized, package-backed retail BSP and compared with an expectation. Most current behavior tests are native host ILP32 tests using overprovisioned memory, not PS2/PCSX2 target evidence.
3. **Safe-to-strip proven** means every relevant consumer is excluded or replaced, the transformation preserves required behavior, and the result has appropriate parity and lifetime evidence. No substantive BSP data family meets this bar.

The current source-trace inventory contains roughly fourteen grouped rows in [`m2-step7-bsp-consumer-disposition.md`](m2-step7-bsp-consumer-disposition.md#L20-L37), not an authoritative count of individual fields. The CE schema has nested records and many per-member semantics; grouped rows combine arrays, indices, data blocks, and cross-references. A machine-readable member-by-member ledger with a disposition and test pointer for every declared member is still needed before claiming the inventory is exhaustive.

Only one narrowly scoped header normalization is supported: the PS2 cache adapter clears Xbox renderer vertex/index-buffer counts and pointers after successful CBSP materialization. This is not a whole BSP-field-family removal. Preserve all other declared BSP fields and payloads unless a separately reviewed, tested replacement is demonstrated.

## Evidence basis and ownership

The CE BSP members are declared in [`structure_bsp_definitions.h`](../../submodules/halo-ce-universal/source/structures/structure_bsp_definitions.h#L178) and nested collision records in [`collision_bsp_definitions.h`](../../submodules/halo-ce-universal/source/physics/collision_bsp_definitions.h#L35). CE's PS2 manifest includes collision, structure-BSP definitions/visibility, scenario/wind, and game-sound source, while excluding CE drawing/rasterizer backends ([`port/ps2/port.json`](../../submodules/halo-ce-universal/port/ps2/port.json#L31)). A compiled or rooted CE routine is not by itself proof it executed during a guest map query.

Parent/PS2 owns map packaging, HP2/CTAG/CBIX ingress, memory binding, and GS/VU rendering. The HCU cache adapter materializes and publishes the CE BSP and performs the single header normalization at [`ps2_cache.c:405-457`](../../submodules/halo-ce-universal/port/ps2/src/ps2_cache.c#L405). The relevant parent allocation/binding path is [`hcu_memory_bind.c:43-57`](../../src/stream/hcu_memory_bind.c#L43). The current package transaction fixture composes real CE cache/switch code with PS2 adapters on host, but that is not proof of target-sized residency or guest gameplay.

## Classification summary

### Source-traced

Major consumer families are source-traced: collision traversal/material/leaf results; cluster/PVS and player aggregation; sound pair distances/PAS/obstruction; fog/weather/location and wind selection; sound-environment selection; visibility surface/portal construction; material/lightmap lookup; breakables; predicted-resource precache; and the cache-header Xbox buffer handles. The grouped report remains a useful call-site index, but it is not an exhaustive field-by-field trace. In particular, every member nested under the less-exercised decal/detail/pathfinding/marker/sound-scenery blocks still needs explicit member-level disposition.

### Behavior-tested (bounded subchecks)

- CE public collision vector hit tuples against independent raw-map geometry/tree expectations on six BSPs, plus selected miss/reverse-face, edge/tie, invisible/two-sided, and breakable-bit cases.
- CE PVS row/aggregation/local filtering and root-cluster refresh/NONE fallback on synthetic player/object records over the package-published BSPs.
- CE combined PAS, selected sound obstruction cases, and sound-environment selector using raw-source-derived expectations.
- CE location/weather fallback for a cluster with no fog-region reference.
- PS2 CBSP materialization/validation transaction and the four Xbox-only header-field normalization postcondition.

All above qualifications are host ILP32/package-backed unless the report explicitly says otherwise. They do not constitute target-address/EE placement, PCSX2 gameplay-map, or renderer/audio playback acceptance. Step 8 capacity remains a prerequisite for production-sized BSP query claims.

### Safe-to-strip or normalize proven

Only Xbox renderer buffer header handles are cleared: both vertex/index buffer counts and pointers are set empty after a successfully materialized valid `psbs` header. CE's cache containment checks remain active and PS2 geometry has a separate HP2/VU-pack owner. **No collision, PVS, fog/weather, sound, surface/material/lightmap, breakable, prediction, portal, pathfinding, decal, detail-object, marker, or other BSP payload family is proven safe to strip.**

## Recommended next verification slice: valid fog-region semantics

Extend the existing package-backed retail fixture and raw-source oracle with a BSP/cluster whose original Xbox `fog_reference` is a valid in-range index—not `NONE`. Derive, from bounded raw BSP records, the selected cluster, fog plane/reference, fog-region index and region weather-palette index; tie the C assumptions to CE `sizeof`/`offsetof` assertions. Execute CE's real `scenario_get_fog_region_index()` and `scenario_location_underwater()` against the published BSP and compare every returned value with the oracle. Include the related collision-vector fog-plane read only if the fixture can provide an independently expected collision point/plane, not as an inferred side effect.

Add separate malformed-reference and out-of-range palette cases through a controlled fixture copy or direct validation seam. For each case assert no out-of-owner read, no mutation of source BSP bytes, and stable CE BSP/scenario publication and owner cursor. Ensure the selected retail case actually has a non-`NONE` valid fog reference; do not allow fallback to an unfogged cluster to report success. Keep wind/weather progression as a later, separate slice: a fog-region lookup does not prove `scenario/wind.c` behavior. Run the native ILP32 package test through the approved execution path when the sandbox reports SIGSYS, retain ELF/map/source/package identities, and label it host semantic evidence only.

After fog, the next highest-value inventory gap is CE visibility/material preprocessing against the same materialized BSP, compared surface-by-surface with the matching HP2 pack/converter mapping. This comparison must preserve source surface identity and account for data the converter quantizes, reorders, or omits. It is not enough to compare rendered positions alone, and no candidate bytes should be credited as capacity savings until CE query parity and simultaneous ownership are measured.
