# M2 Step 9 follow-on: direct CBSP visitor through CE scenario publication and rollback

**Purpose:** report-only design for the smallest next integration fixture. It must send retail-derived CBSP bytes through the bounded HP2 section visitor and PS2 cache adapter, then let the real CE `scenario_structure_bsp_load()` / `scenario_switch_structure_bsp()` validate and publish them, including a candidate-failure/old-BSP-restore case. Normal gameplay-map admission must remain disabled. This report does not change code, does not qualify a gameplay map, and is not M2 acceptance.

## Finding

Extend the current ILP32 retail scenario transaction fixture around **a50**, not the standalone Longest test. The existing fixture already mounts retail-derived CTAG/catalog data, uses CE’s real scenario switch body, and includes retail structural validation; it currently materializes CBSP via the whole-section loader callback. Add the visitor registration to that fixture and arrange for a **late outer-HP2-CRC error in a non-current candidate section** (e.g. B001) so the first B000 remains published, B001 fails after sink writes, CE restores B000 through a second successful visitor traversal, and repairing the one-byte package corruption permits an immediate same-process B001 retry.

Longest remains useful for the exact **single-BSP** direct visitor and cache boundary, which is already covered by `tests/ps2_cache_cbsp_longest_main.c` and `tests/test_cbsp.py`. It has only one scenario reference (`src/stream/hcu_map_catalog.c`, catalog rows at [line 89](../../src/stream/hcu_map_catalog.c#L89) and [line 219](../../src/stream/hcu_map_catalog.c#L219)), so it cannot naturally exercise CE’s candidate-BSP rollback to a different prior BSP. Do not fabricate a second retail reference for Longest merely to force that branch.

## Existing behavior and seam

The current retail scenario test is the best host harness to extend:

- [`tests/test_hcu_scenario_bsp_switch.py`](../../tests/test_hcu_scenario_bsp_switch.py#L89) checks package/source hashes, decodes CTAG/CBIX/CBSP metadata, then builds an ILP32 executable with CE scenario code, PS2 cache/CTAG/CBSP adapters, parent mount/catalog/source code, and halo-ps2 section/HP2/file/memory code. Its `a50` case supplies four BSP references; the current package audit records 4 references, 25,207,124 aggregate CBSP payload bytes, package hash `9359e0eb09427b098d9773708352c77dbf426ebcec9d7b27400268d84221941a`, and source-map hash `d7a3e80a86f2b0f23d855ce353aed3c0eb252145697797d87f25623dc470f38d` in [`retail-cbsp-catalog-package-audit-e4a97218.json`](retail-cbsp-catalog-package-audit-e4a97218.json#L23).
- [`tests/hcu_scenario_bsp_switch_main.c`](../../tests/hcu_scenario_bsp_switch_main.c#L610) loads a real retail CTAG and scenario, checks the scenario’s references against CBIX, and calls CE’s real `scenario_switch_structure_bsp()`. Its existing callback `load_package_section()` at [line 322](../../tests/hcu_scenario_bsp_switch_main.c#L322) calls the whole-buffer `world_load_section_with_scratch()` for every section; this is why CBSP currently uses the legacy registered BSP loader rather than the direct section visitor.
- The parent direct path exists: [`ctag_mount_set_bsp_section_visitor()`](../../src/stream/ctag_mount.c#L332) registers `visit_bsp_extent()`, which validates the exact catalog extent and rejects tag/resource overlap before dispatching transient section chunks to the visitor ([`ctag_mount.c`](../../src/stream/ctag_mount.c#L108)). The cache adapter’s [`stream_cbsp_for_read()`](../../submodules/halo-ce-universal/port/ps2/src/ps2_cache.c#L474) parses the streamed envelope in the fixed BSP destination, validates/rebases it, normalizes absent Xbox vertex/index handles, and only then reports completion to CE. `cache_file_read()` selects this route when a visitor is installed ([`ps2_cache.c`](../../submodules/halo-ce-universal/port/ps2/src/ps2_cache.c#L566)).
- The exact service adapter is currently private: [`visit_section()`](../../src/stream/hcu_map_service.c#L75) bridges HP2’s zero-success convention to the parent sink’s nonzero-success convention and calls `world_visit_section_with_scratch()`. The production map loader registers it only after the mount succeeds ([`hcu_map_service.c`](../../src/stream/hcu_map_service.c#L135)). The public preflight deliberately rejects every non-UI map before opening it ([`hcu_map_service.c`](../../src/stream/hcu_map_service.c#L276)); that gate must remain unchanged.
- CE’s actual validation and publication path is in [`scenario_structure_bsp_load()`](../../submodules/halo-ce-universal/source/cache/cache_files.c#L1380): it validates retail extent bounds, calls `cache_file_read()`, checks the completion sentinel and structure-BSP header pointers, invokes `tag_validate_structure_bsp()`, then registers vertex-buffer state and sets the tag instance base. The caller validates port capacity before publishing global BSP pointers. [`scenario_switch_structure_bsp()`](../../submodules/halo-ce-universal/source/scenario/scenario.c#L1088) unloads the old BSP first; on failed candidate load it attempts the old reference again, and publishes the restored globals only after that load succeeds ([`scenario.c`](../../submodules/halo-ce-universal/source/scenario/scenario.c#L1124)).

## Smallest safe fixture design

Use a dedicated test mode or a separate test main that reuses the existing C fixture/shims. Keep it report-only until an implementation task explicitly authorizes the edits.

1. Reuse the current `a50` source map and matching HP2 package already required by the retail transaction fixture. Before executing C, assert manifest package/source hashes and decode the package’s B000/B001 CBSP directory entries. Preserve a clean immutable package copy for the final retry.
2. Construct a test-only copy of the HP2 package with **only the B001 directory entry’s stored section CRC changed**. Do not alter HMAP, CTAG, CRNG, CBIX, the decompressed retail map, or B000 bytes. The mount path reads/validates HMAP/CTAG/CRNG/CBIX; B001 data remains lazy, so the map should mount and its initial B000 should load. Independently verify that Python parses the corrupt package directory and rejects B001’s data CRC when the section is read.
3. Initialize the same bounded host arenas and CE fixture globals used by `package_transaction()`. Use an `hcu_map_service` object only as callback context, with its `section_scratch`, `source`, and `staged_entry` initialized for the fixture. Mount through the existing verified source/CTAG/catalog APIs; pass this service context to the section loader and register the **exact production `hcu_map_service.c` visitor callback**.
   - Because `visit_section()` and `load_section()` are `static`, do not copy their logic into a second “production-like” test callback. A test-only bridge translation unit can include `src/stream/hcu_map_service.c` once and expose narrow wrappers that call those static functions. Compile it with function/data sections and linker GC, retaining only the wrappers and their real dependencies. Alternatively, make a narrowly scoped public visitor seam in a separately reviewed implementation change; do not silently broaden the test to a duplicate adapter.
   - Exercise `hcu_map_service_preflight("a50")` once and assert that it rejects with `capacity-not-qualified`, leaves the owner empty, and does not open or mount the source. Then use the fixture’s explicit low-level verified-mount setup (not the game-facing preflight/cache-loader path) to test callback and CE semantics. Label this deliberate admission bypass in test output. Do not change catalog eligibility or the guard in `hcu_map_service_preflight()`.
4. For CE structures, reuse the existing `HCU_BSP_RETAIL_INTEGRATION` build path: real HCU `scenario.c`; `cache_files.c` compiled through the fixture include; the real bounded `tag_validate_structure_bsp()` path and schema group files; real HCU `ps2_cache.c`, `ps2_ctag.c`, `ps2_cbsp.c`; parent `ctag_mount.c`, `ctag_ps2_backend.c`, `cbsp_catalog.c`, `ctag_resource_index.c`, `ctag_map_source.c`, `hmap.c`, `sha256.c`; and halo-ps2 `world/section.c`, `stream/hp2.c`, `stream/file.c`, `core/mem.c`. Keep the `--wrap=read` hook only for the pre-existing source-resource partial-read test; the new deterministic B001 CRC fault belongs in the package fixture, not a broad host read wrapper.
5. Load and validate the actual a50 CTAG, resolve its actual scenario datum and BSP references, and publish B000 using `scenario_switch_structure_bsp(0)`. Capture a complete baseline: CE global/scenario BSP indices and pointers, current tag-instance base addresses, cache-file BSP header pointer, BSP bytes/header, parent owner/scratch cursors, `mount.bsp_active`, source descriptor, and callback/visitor counters.
6. Call `scenario_switch_structure_bsp(1)` with the B001-CRC-damaged package. Assert the first visitor produces at least one sink write and then fails outer section integrity; the PS2 cache completion output must be `_cache_file_read_failed` (enum value 2 in [`cache_files.h`](../../submodules/halo-ce-universal/source/cache/cache_files.h#L30)), not TRUE. CE must reject B001 before tag/BSP publication, reread B000 through the visitor, restore the exact baseline publication and bytes, leave parent BSP scratch at zero and no encoded-BSP lease active, and avoid menu fallback because B000 restoration succeeds. Important: CE deliberately tests `read_complete != TRUE`; the sentinel is not zero, so this synchronous failure is terminal to its loader rather than an infinite “pending” loop.
7. Replace the corrupt test package at the same HP2 path with the original package bytes. Without restarting the process, retry B001; it should now publish successfully. Switch back to B000 and verify its bytes and tag-instance/global state again. Finish with unload/release ordering: all CE pointers unpublished before the parent owner/source is released, all arena cursors returned to the baseline, and no visitor/scratch lease remains.

## Failure, rollback, and retry matrix

| Operation / injected condition | Expected observation | Required invariant |
|---|---|---|
| Normal `hcu_map_service_preflight("a50")` | Capacity gate rejects before source open/mount | No policy/admission change; no owner bytes or CE pointers |
| Verified low-level fixture mount, then initial B000 read | HMAP identity, CTAG, CBIX and real map extents accepted; direct visitor runs | `completion == TRUE` only after full envelope CRC, CBSP structural/domain checks, rebase, and normalization |
| B001 outer HP2 CRC bad after partial sink output | Visitor ends non-OK; cache completion is `_cache_file_read_failed`; CE validator rejects | Candidate B001 not published; partial destination is treated as unpublished; owner/mount remain valid |
| Candidate B001 failure followed by old B000 restore | Second B000 visitor succeeds, CE globals return to B000 | Full snapshot equals baseline including tag-instance bases, BSP header/data, owner/scratch cursors, and `mount.bsp_active == 0` |
| Restore original package and retry B001 in same process | B001 direct visitor and CE validation now succeed | One-shot failure did not poison source descriptor, callback state, mount, or CE validation state |
| Switch B001 back to B000 and unload | B000 published, then globals cleared before parent unmount/release | No dangling CE pointer; owner and scratch return to marks; source closes once |
| Wrong extent / CBIX mismatch | Catalog rejection before HP2 visit | Destination untouched; no CE publication; no fallback read unless scenario code had already unloaded an old BSP |
| Corrupt CBSP internal CRC/relocation after valid HP2 CRC | Visitor fully reaches cache parser, which rejects before `completion=TRUE` | Do not assume destination unchanged (the streamed candidate may have been copied); CE must not validate/publish it |
| `tag_validate_structure_bsp()` rejection after successful visitor | CE unloads the rejected candidate, reloads old B000 | Candidate instance base cleared and old snapshot restored |
| `structure_bsp_port_verify()` rejection | CE releases candidate and restores B000 | Same publication/ownership invariants; distinguish this from schema failure |

The outer HP2 CRC case proves late visitor failure and CE rollback. Add one separate CBSP parser/domain failure only if the first fixture stays deterministic; do not combine multiple corruptions in one execution. In particular, do not assert the candidate BSP destination remains byte-identical after a post-sink CRC failure; only publication and ownership are atomic, while an unpublished destination prefix may have changed.

## Host and hardware limits

- Existing `tests/hcu_scenario_bsp_switch_main.c` has 16 MiB tag cache, 8 MiB BSP cache, 16 MiB owner, 16 MiB BSP scratch, and 128 KiB section scratch under `HCU_BSP_RETAIL_INTEGRATION` ([definitions at lines 30–42](../../tests/hcu_scenario_bsp_switch_main.c#L30)). The existing `a30`/`a50` transaction is explicitly host lifecycle evidence. It is not the fixed 32 MiB PS2 layout, and it does not show that full CTAG+BSP co-residency fits.
- Longest has a 4,477,120-byte CTAG image, only one B000, and the current 1,814,336-byte candidate BSP span. Its aggregate lower bound and other resident owners are still outside the available PS2 budget; its current direct harness intentionally uses an 8 MiB host owner. Do not use Longest test success to open its map catalog entry.
- A successful direct visitor + CE schema/publication/rollback fixture proves callback convention, outer HP2 CRC completion ordering, CBSP rebase at the **actual low host pointers**, CE’s actual scenario state transitions, and source/mount lifetime on that host build. It does not prove physical PS2 placement, persistent streaming high-water, PCSX2/EE execution, a rendered scene, full M2 map admission, gameplay, or M2 Step 10.
- If the compiled fixture cannot produce stable low 32-bit addresses for the complete tag and BSP allocations, stop rather than masking addresses. Use the existing `-m32 -no-pie` path or a purpose-built low-address mapping with strict range checks; do not use `MAP_32BIT` as an unvalidated portability assumption.
- The test-only admission bypass must be visible in the test name/output and keep `hcu_map_service_preflight()`’s non-UI capacity rejection unchanged. M2 requires the accepted capacity/ownership redesign and guest evidence before any retail gameplay map is admitted.

## Decision

Implement the a50 visitor-backed CE transaction as the next Step 9 host fixture, reusing the real service adapter via a test-only bridge and the current CE transaction harness. Preserve Longest as the single-BSP visitor control. Keep M2 Step 9 partial until visitor failure, CE schema/capacity rejection, rollback-to-old-BSP, same-process repaired-source retry, and owner release all pass against this composed path. Keep Step 10 and gameplay-map admission blocked on the independent capacity and exact-guest gates.
