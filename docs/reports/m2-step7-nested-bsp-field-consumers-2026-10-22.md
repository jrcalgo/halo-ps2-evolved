# M2 Step 7 — nested BSP field/consumer disposition

Date: 2026-10-22. This is a source-backed follow-up to the declared-member inventory in [`m2-step7-bsp-member-ledger-2026-10-21.md`](m2-step7-bsp-member-ledger-2026-10-21.md), scoped to decal, detail-object, pathfinding, marker, and scenario sound-scenery members. It does not change production behavior or claim those consumers are fully qualified.

## Classification key

- **Preserved + schema-relocated:** the production HCU schema recursively registers the pointer-bearing block/data; the all-13 retail fixture loads real scenario/BSP packages through CE and therefore exercises those schema walks. This establishes parser/relocator traversal, not semantic correctness of each field.
- **Schema-checked:** CE validates an index/range or nested relationship during load. This is stronger than source declaration alone but does not prove the later gameplay/render/audio result.
- **Behavior queried:** a fixture invokes the actual runtime consumer and compares its result to an independent source-derived oracle. None of the newly scoped families below has this level of coverage today.
- **Unresolved:** bytes remain retained, but a semantic consumer, usable relocation, or required adapter behavior is not demonstrated. Do not strip or normalize the member.

## Test disposition and next executable slice

The existing all-13 host matrix in [`hcu_mp_capacity_main.c:396-447`](../../tests/hcu_mp_capacity_main.c#L396) performs real CE map load, late BSP failure/retry, a BSP query suite, and unload for each retail multiplayer package. It proves broad package/schema traversal but current explicit post-load queries cover collision/location/PVS/fog/weather/sound, not the families in this report. The nested-detail validation itself checks cell ordering and `count_index`/object/z-vector bounds, and decal/lens ranges are normalized on load. Therefore the immediate cheap improvement is an isolated generated census in that existing host fixture: for each active BSP, assert every non-empty nested `tag_block.address` lies wholly inside the mounted tag/BSP owner and every count/stride extent stays in that owner's bounds; report zero/nonzero counts by map. This would verify post-relocation reachability, **not** semantic parity.

Do not add a source-text-only “test” as a substitute. A behavior regression requires independent raw-map expectations for decal create/delete, detail-object camera-cell selection, bot/pathfinding traversal, lens marker clustering, and sound-scenery object/audio events. Those are separate query cases and remain Step 7 work. No Step 7 or Step 8 exit is implied by this ledger.

## Comparative note

Halo-64 is useful only to distinguish CPU-side simulation/adapter state from its rendering backend. Its N64 omissions do not justify deleting these HCU records. The PS2 retains its own renderer and constrained GS/VU/data paths; CE field ownership remains in HCU until a field-specific oracle proves otherwise.
