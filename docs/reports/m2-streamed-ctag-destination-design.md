# M2 streamed CTAG destination design

**Disposition: design plus partial loader infrastructure.** This report identifies a bounded-memory path for moving a retail HP2 CTAG section into CE's final physical tag-cache span without staging the full section in `streaming`. The parent halo-ps2 tree now implements a generic bounded HP2 section visitor and verifies it against a frozen Longest package on the host (`submodules/halo-ps2/engine/src/world/section.h:8-19`, `section.c:63-130`, `tests/test_world_section_visitor.py:9-38`). No HCU CTAG consumer uses that API yet. It does not implement a transactional CTAG validator/materializer, change map admission, establish a whole-map fit, or claim target timing/high-water. The current code and reports remain authoritative for those remaining gates.

## Finding in brief

The current production map path still materializes a full HP2 section in two temporary buffers: `world_load_section_with_scratch()` reserves `raw_size` in its owner and `stored_size` in a second arena, reads the complete stored extent, then invokes `hp2_load_stored()` into the full raw output (`submodules/halo-ps2/engine/src/world/section.c:133-233`; `submodules/halo-ps2/engine/src/stream/hp2.c:129-146`). The new `world_visit_section_with_scratch()` has a bounded sink path, but no caller in `hcu_map_service_preflight()`/`ctag_mount` uses it; production preflight still loads HMAP, CTAG, CRNG, and CBIX in `streaming`, then rewinds its transaction (`src/stream/hcu_map_service.c:202-295`). The mount repeats the load and keeps the full raw CTAG and CRNG payloads owned until unload (`src/stream/ctag_mount.c:112-173`). This is why the real Blood Gulch CTAG raw payload of 4,556,496 bytes is refused against the 1,572,864-byte streaming arena, even though its compact image is a separate 4,477,116-byte destination requirement (`tests/world_section_capacity_main.c:44-56`; `docs/reports/retail-ctag-compaction-2fba411b-v2.json`, `bloodgulch` row; `plans/7.hcu-remake-m2-m4.md:212`).

The CE cache path already names the final destination: `cache_file_read()` handles the exact tag-data extent when `buffer == physical_memory_get_tag_cache_base_address()` and calls `ps2_ctag_materialize()` there (`submodules/halo-ce-universal/port/ps2/src/ps2_cache.c:358-397`). That materializer copies the complete compact image and applies relative-pointer fixups (`submodules/halo-ce-universal/port/ps2/src/ps2_ctag.c:148-170`). So the right structural change is to make HP2/CTAG decoding target this existing CE cache destination, not to enlarge `streaming` to hold an extra complete CTAG copy.

There is a second independent blocker: the current target tag-cache binding is only 2,097,152 bytes, smaller than Blood Gulch's 4,477,116-byte compact image. `hcu_memory_bind_parent_v2()` currently puts tag cache at the start of `current_bsp`, then binds the remaining tail as the separate BSP store (`src/stream/hcu_memory_bind.c:41-56`); `hcu_main.c` requests the 2 MiB bootstrap size (`src/stream/hcu_main.c:16-18,180`). Thus, streaming decode alone cannot admit a retail map. The destination-capacity/topology change must be measured and bound at boot before `physical_memory_allocate()`; the HCU PS2 provider refuses any late bind after physical allocation (`submodules/halo-ce-universal/port/ps2/src/ps2_memory.c:91-110,147-155`). The retained 2fba audit's 4,477,120-byte tag / 1,814,336-byte BSP split is arithmetic for Longest and Blood Gulch, not runtime evidence or a generally sufficient split (`docs/reports/m2-next-capacity-design-review.md`, “Provisional boot-fixed tag/BSP split”).

## Existing ownership and lifetime constraints

1. **The final tag image belongs to CE's fixed tag-cache span.** CE tag headers, instances, and tag fields point inside the materialized image. It must remain at one stable EE address throughout scenario/gameplay use. `physical_memory_bind_tag_cache()` installs the pointer before CE memory allocation, and `physical_memory_get_tag_cache_base_address()` is used both by cache reads and schema validation (`submodules/halo-ce-universal/port/ps2/src/ps2_memory.c:91-110,147-150`; `submodules/halo-ce-universal/source/cache/cache_files.c:1260-1329`). Do not decode into a temporary region and later move it after CE has published pointers.
2. **The target span is not available during preflight while an old map is live.** CE calls map preflight before its map teardown in the main map-load paths; the current integration records only private staged state and does not mutate the active owner's arena (`submodules/halo-ce-universal/source/main/main.c:1555-1580,2860-2890`; `src/stream/hcu_map_service.c:226-239`). CE then clears the scenario/tag/BSP state before `scenario_unload()` releases the parent cache owner (`submodules/halo-ce-universal/source/scenario/scenario.c:371-389`; `docs/reports/m2-ce-lifecycle-path-audit.md`, lifecycle sequence). Direct writing to the single fixed tag-cache span is safe only after this unpublish/release boundary.
3. **The resource source has a distinct map-lifetime lease.** `ctag_mount` retains the original-map read callback and `ctag_resource_index` for tag-associated resource extents. On unload it releases a loaded BSP, unmounts the CE cache, closes the source, then rewinds owner storage (`src/stream/ctag_mount.c:54-65,277-290`). The HP2 file/section reader also needs a valid lifetime if CE's tag-cache read callback will decode CTAG later; do not leave only a path string where the reader assumes an open handle or stable file. Resource reads outside CTAG must remain serviced from the original `.map` source, not be confused with the `.hp2` conversion package.
4. **The cache read is synchronous at the current seam.** `ps2_cache.c` starts each operation with `_cache_file_read_failed`, marks success only after the exact extent operation completes, and CE waits until its completion flag is nonzero before rejecting non-`TRUE` results (`submodules/halo-ce-universal/port/ps2/src/ps2_cache.c:358-427`; `submodules/halo-ce-universal/source/cache/cache_files.c:1260-1297`). A streamed decoder must preserve this contract: publish no `tags_loaded`/tag-header state and set success only after all reads, HP2 CRC, CTAG CRC, envelope, relocation, and destination checks pass. Every failure must leave the flag in the explicit failed state; never leave it at zero and make CE spin indefinitely.
5. **The CE validator bitmap shares a capacity dependency.** It sizes claims over `tag-cache + separate-BSP`, using one bit per addressable byte on PS2; boot code currently reserves this bitmap separately in `resident_gameplay` (`submodules/halo-ce-universal/port/linux/game/tag_validate.c:239-284`; `src/stream/hcu_memory_bind.c:65-71`). Repartitioning the combined span does not automatically require a larger bitmap, but any changed combined span does. Account the tag image, BSP span, claims bitmap, CE game-state/object store, and all other live allocations exactly once. Do not treat the provisional tag/BSP split as a capacity pass.

## Recommended API shape and decode flow

Keep this work at the existing parent HP2 and HCU cache seams. `halo-ps2` owns file/arena utilities and the current HP2 parser; HCU owns CTAG wire semantics and the CE cache callback. Do not add another full-copy buffer or turn the HALO-64 renderer/asset code into a substitute loader.

### A. Add a bounded section reader/stream decoder under `halo-ps2`

The first engine-level visitor is now implemented at `world_visit_section_with_scratch()` (`submodules/halo-ps2/engine/src/world/section.h:8-19`, `section.c:63-130`). It accepts an arena, path/tag, and sink, retains one file-reader descriptor, streams `hp2_load_stream()` output through a 98,304-byte bounded scratch lease, and releases the lease/reader on completion. Host parity compares decoded Longest CTAG/B000 and Blood Gulch CTAG/B000 output to the legacy full-output API; the Blood Gulch case uses the existing pinned package `build/retail-maps/bloodgulch-with-bsps.hp2` and its current on-disk SHA is fixed in `tests/test_world_section_visitor.py:12-16,34-48`. The synthetic engine fixture covers short scratch, sink rejection, I/O error, CRC failure, and rewind (`submodules/halo-ps2/engine/tests/test_world_loader.c:135-197`). This is not yet a generic asynchronous/random-access section-reader descriptor; it shares a static header buffer, is synchronous/non-reentrant, and its sink may receive a prefix before a late error. Continue extending this seam only after a consumer defines the unpublished destination and retry contract. Suggested next conceptual API shape:

```c
hp2_status hp2_section_open(hp2_section_reader *reader,
    hp2_read_at_fn read_at, void *source, uint32_t file_size,
    const char *section_tag, hp2_section *section);
hp2_status hp2_section_decode_visit(const hp2_section_reader *reader,
    const hp2_section *section, void *work, size_t work_bytes,
    hp2_output_fn output, void *output_context, hp2_decode_stats *stats);
```

The descriptor operation must preserve all current `hp2_open_header()` checks: magic/version, section count, fixed header/table extent, unique section tags, legal codecs/alignment, non-overlapping in-file extents, and overflow-safe file bounds (`hp2.c:18-70`). The visitor must reproduce `hp2_load_stored()` exactly for stored and LZ4 codecs and report precise produced length plus raw CRC before success. It should not allocate, assume one giant section is contiguous, or use hidden heap storage. Keep `world_load_section_with_scratch()` unchanged for small sections until all existing callers/tests continue to pass; add a specialized streamed interface for high-capacity CTAG/CBSP use rather than silently changing its allocation/lifetime semantics.

An LZ4 block stream cannot forget arbitrary prior output: matches can refer back up to 65,535 bytes (`hp2.c:90-127`, especially offset validation/use at 110-124). A bounded decoder therefore needs a 64 KiB history window (or an equally proven implementation), not just a tiny input buffer. A reasonable *initial test configuration*, not a measured target optimum, is 64 KiB LZ4 history + 16 KiB aligned input + a small parser/output chunk buffer. That is about 80–96 KiB plus a few hundred bytes of parser state, below today's 393,216-byte `frame_scratch`; actual EE high-water, FileXio alignment/throughput, stack use, and timing must be recorded before accepting the number. `file_reader_read_at()` is an offset-based bounded source suitable for the callback, but its normal helper chunk constant is 256 KiB; callers should pass smaller destinations instead of allocating the full `stored_size` (`submodules/halo-ps2/engine/src/stream/file.c:16,143-169`).

### B. Validate CTAG in a no-write first pass

Add an HCU streaming CTAG validator (or generalize `ps2_ctag_open()` into a visitor-based parser) that consumes decoded HP2 output without retaining the whole raw section. Current CTAG v1 wire data is a 52-byte envelope, followed by `image_size` bytes and then `relocation_count * 4` relocation offsets. The parser currently validates envelope fields, exact extents, inner image CRC, CE tag header/count bounds, sorted/aligned/in-range relocation offsets, and relocation target ranges (`submodules/halo-ce-universal/port/ps2/src/ps2_ctag.c:64-145`). Preserve every one of these checks and the HP2 raw CRC from `hp2_load_stored()`.

The pass can retain the 52-byte header, a handful of parsed image-header words, CRC/hash accumulators, and a 4-byte relocation-record accumulator. It need not retain the 4.3–4.6 MiB section or its ~19k–44k relocation records. Because CTAG relocation validation compares each listed pointer target with the image bytes at that offset (`ps2_ctag.c:127-139`), avoid assuming that a table-only parser has enough information: after the first pass verifies the image and structural envelope, a subsequent pass may validate each pointer target against the staged destination before applying fixups. Alternatively, perform additional bounded passes, but explicitly count I/O and pass costs. The existing direct memory lookup in `ps2_ctag_open()` is not available without a complete image, so its proof obligations must be reproduced, not dropped.

The preflight pass must not write the currently published tag cache. Before unload it may validate and remember immutable metadata and identity, but it cannot promise a later destination write will succeed. The post-unload loader must redo the exact pack and CTAG validation against the bytes it is about to materialize (or bind those bytes to an immutable, open, content-hash-verified package lease). This closes the race between CE's preflight and later read and follows the current service's reload rule that full validation reruns after old owner release (`src/stream/hcu_map_service.c:99-116`).

### C. Materialize at the existing CE read destination after teardown

Replace the production assumption that `mounted_payload` points to a retained complete CTAG wire section with a compact `ps2_ctag_stream_descriptor`: validated section metadata, image size, tag-data extent, scenario index, expected source/package identity, and a live HP2 package reader. Mounting then reserves only bounded descriptors/index records and retains both map-resource and HP2 source lifetimes as required. `cache_file_open()` can still synthesize the retail header with the validated image size (`ps2_cache.c:338-355`). For the exact CE tag-data read (`ps2_cache.c:387-397`), invoke the specialized stream materializer with the actual physical tag-cache base and capacity.

The simplest safe implementation is at least two decode passes after old-map unpublish:

1. **Verify pass:** reread and hash/check the HP2 section and complete CTAG wire envelope; validate HP2 raw CRC, CTAG image CRC, all envelope extents and table invariants. No writes to the final span.
2. **Image pass:** decode again, discard the CTAG header, and copy only the image interval directly to `tag_cache_base`; continue consuming/checking relocation records and the second HP2 raw CRC. The destination remains unpublished while writing. On any read/decode/checksum error, keep cache/tag state closed/failed, poison or mark invalid the unpublished span, and do not set completion success.
3. **Relocation phase:** once the full image exists at its final address, validate each field against the just-written image and apply `base + target` exactly as `ps2_ctag_materialize()` does. This phase can be part of the second pass if the table arrives after the image, provided a failed late validation is still treated as an unpublished failed destination and the success flag is not set. To avoid partially patched bytes being mistaken for valid state, prefer a complete relocation validation pass before applying fixups, or use a transaction marker that makes the CE read impossible until fixups are all done. No 4-byte relocation table allocation is necessary, but the extra read/decode pass and its EE cost must be measured.

The intermediate bytes of a failed write may remain physically in the cache span, but no CE pointer may refer to them. Ensure cache adapter state is closed/reset after failure so retry starts from a known base and the destination gets fully rewritten. Since an in-place cache cannot retain the prior map image during this operation, the map transition after teardown is destructive: failures after unload must go to a deterministic no-map/menu error state and support a fresh retry; do not claim preservation/rollback to the old map. Preflight can preserve the old map for errors it detects before unload, but not for disk/IO faults during post-unload materialization.

## Arena ownership and scratch budget

* `current_bsp` continues to contain the final tag-cache and the separate active BSP spans only if that allocation topology is retained; bind their exact aligned addresses/capacities once before `physical_memory_allocate()`. The map's final compact image must fit the configured tag span, and every BSP that is admitted must fit the separate BSP span after canaries/alignment. Capacity gating remains closed until those exact capacities are proven. The current whole-section `streaming` owner should retain only bounded HMAP/CRNG/CBIX parsed metadata and small descriptors; no full CTAG section buffer.
* Use `frame_scratch` for one bounded streaming decode work area with explicit mark/release. A testable provisional work layout is 64 KiB LZ4 history plus 16 KiB I/O input plus decoder/parser state and alignment. If the implementation must simultaneously decode a second sink window or SHA buffer, account the combined peak. Do not take a separate 256 KiB hash buffer and 80 KiB decoder if they coexist without charging that overlap. `verify_source_hash()` currently asks up to 262,144 bytes of `frame_scratch` (`src/stream/hcu_map_service.c:25-52`); make hash and section decode sequential leases or explicitly include their simultaneous peak.
* The 1.5 MiB `streaming` region is not automatically all available to metadata: the UI service currently reaches 1,550,572 bytes including CTAG/CRNG/CBIX (`plans/7.hcu-remake-m2-m4.md:235`). Dropping CTAG payload staging should free substantial room, but exact compact CRNG/CBIX record storage, HMAP data, catalog structures, arena alignment, HP2 reader state, and CBSP metadata must be measured per map. Prefer parsing CRNG intervals and CBIX entries into fixed/count-bounded records only after deriving maximum counts for all supported retail inputs. Do not simply point these structures into a temporary decode buffer.
* Current BSP loading is a separate instance of the same full-buffer problem: `ctag_mount.c:67-104` asks the common section loader for the entire selected B000/CBSP section in `frame_scratch`, then holds it until CE's read/materialization completes. The Blood Gulch B000 payload is 1,303,092 bytes vs. the 393,216-byte frame scratch (`docs/reports/m2-step7-retail-cbsp-validation.md`, reproducible fixture identity; `plans/7.hcu-remake-m2-m4.md:212`). A streamed CTAG fix does not fix CBSP capacity. Reuse the HP2 visitor, but design CBSP validation/materialization separately: full CE/source pointer-domain semantics, domain-1 target names within the final tag image, one active BSP, and publish only after validation.

## Tests and acceptance evidence required before enabling a retail map

### Host decoder and transaction tests

1. Keep `world_load_section_with_scratch()` behavior tests and expand byte-for-byte comparisons between old whole-buffer decode and the visitor for stored and LZ4 sections: UI CTAG, Blood Gulch CTAG, Blood Gulch `B000`, Longest CTAG, plus malformed synthetic packs. **Follow-up (2026-10-21):** the host visitor matrix now compares all five sections—CTAG, CRNG, HMAP, B000, CBIX—in UI, Longest, and Blood Gulch packages. It also rejects a sink after two successful 16-KiB output windows and checks the prefix remains unpublished (`raw_size=0`) and scratch returns to baseline. See [`m2-hp2-visitor-correctness-audit.md`](m2-hp2-visitor-correctness-audit.md#follow-up-2026-10-21). Additional malformed stream-boundary cases, HCU CTAG integration, and target validation remain open.
2. Exercise adversarial boundaries: truncated header/table/data; overflowed section offsets/sizes; bad/duplicate tags; unsupported codec; zero-length; stored-size/raw-size mismatch; bad LZ4 literal length/offset/output cap; exact 64 KiB back-reference and wraparound; one-byte-short work window; short-read/error after arbitrary chunk; bad raw CRC; output callback rejection; retry with same file descriptor. Confirm no heap allocation and no `streaming` usage proportional to raw/stored CTAG sizes.
3. CTAG parser tests must cover each current `ps2_ctag_open()` error condition and prove no destination writes on first-pass rejection. For materialization, compare final bytes and each pointer fixup against the current C implementation/Python reference for the real UI and Blood Gulch fixtures. Inject failures after partial image write, during relocation read, at the last relocation, and on CRC mismatch; assert CE cache not loaded, completion is failure, no published global points into the destination, and a complete subsequent retry succeeds.
4. Host-test old/new transition order with the same production callbacks, but do not treat a callback model as a CE lifecycle test. Exercise preflight with old map live (metadata-only/no mutation), `scenario_unload()` unpublish, owner release, post-unload validation, direct materialize, cache publication, and repeat reload. On post-unload failure require deterministic empty/no-map state, not old-map rollback.
5. Test parser/reader concurrency assumptions explicitly. Current map service/cache globals and static HP2 header buffer are single active-map/synchronous designs; either enforce the single-thread contract or protect independent reader descriptors. Do not allow a second map loader or resource read to overwrite static header/parser state while decode is in progress.

### Target and game-runtime acceptance

1. Instrument actual `frame_scratch` current/high-water, `streaming` current/high-water, tag-cache and BSP base/cap/used, and bytes read/decoded for each pass on the exact R5900 combined ELF. Canary each end and verify all stores are disjoint from ELF/BSS, boot backing, dynamic heap, render packs, kernel reservation, and the untouched EE reserve. Verify no hidden libc heap growth.
2. Measure EE cycles and FileXio throughput for all passes under PCSX2 interpreter and recompiler, then on the intended physical OPL/optical storage profiles. A 64 KiB history/16 KiB input arrangement is a starting implementation parameter only; runtime high-water and performance decide acceptance. Ensure a blocking map transition cannot watchdog/time out and the regular frame scratch lifetime is restored after load.
3. Run exact package/source hashes for UI first, then Longest and Blood Gulch as the first candidate gameplay scenarios only after destination/topology capacity is bound. Run both PCSX2 modes on the same exact ELF and package hashes; retain guest logs and screenshot. Marker success must occur only after CE's `scenario_tags_load`, tag header/schema validation, scenario/BSP publication, `structure_bsp_port_verify`, and successful collision/surface/PVS/sound consumers—not immediately after package mount.
4. Require all failure/retry, unload/reload and pointer-lifetime traces on guest. **Successful UI unload/reload now passes two cycles in interpreter and recompiler**, and `scenario_unload()` performs the owner-release call in ordinary `HALO_PS2` builds after CE globals are cleared; failure-injection and corrected-source retry remain open. Keep catalog admission for every non-UI map closed until its final tag image, active BSP, validator claims, retained resource metadata, renderer packs, texture/audio/animation working sets, and transition/decode peak have a measured allocation ledger. Continue intentional rejection for maps that exceed the fixed budgets. A streamed CTAG path removes one staging limitation; it is not itself a map fit or render pass.

## Reference comparison

* **halo-ps2** is the platform/utility source for bounded arenas, FileXio-compatible `file_reader_read_at()`, and HP2 format/codec parsing. Its current `world_load_section_with_scratch()` is intentionally whole-section and transactional; preserve it for small sections and extend the source at the HP2 layer for bounded consumers rather than teaching the renderer or CE cache to duplicate its parser (`submodules/halo-ps2/engine/src/world/section.c:23-96`; `submodules/halo-ps2/engine/src/stream/hp2.c:18-146`).
* **halo-ce-universal** remains the owner of cache/tag semantics and pointer validation. `ps2_cache.c` supplies the exact final tag-cache/BSP destination seam; `ps2_ctag.c` defines relocation rules; CE's `cache_files.c` verifies the resulting header and full schema before publishing `tags_loaded` (`submodules/halo-ce-universal/port/ps2/src/ps2_cache.c:338-427`; `source/cache/cache_files.c:1260-1329`; `port/linux/game/tag_validate.c:239-284`). The parent must not bypass those validators to win capacity.
* **Halo-64** is a comparison for the consequence of constrained memory, not an implementation source for this file format. `port/n64/NOTES.md` explicitly records render-state still required when drawing is omitted, and `port/n64/HISTORY.md` documents map/asset arena high-water and real capacity failures/adjustments. Its own N64 pack/cache and 8 MiB choices do not prove R5900 HP2 streaming, and no `n64_*` pool limits should be copied. Use its discipline—measure specific allocations, preserve needed state, fail safely—not its architecture or numerical limits.

## Decision and stop conditions

Retain the implemented bounded HP2 visitor as infrastructure, preserve the whole-buffer API for current UI and existing callers, and expand host parity across the required retail cases. Then add CTAG stream validation/materialization as a distinct HCU-owned adapter using the CE cache read's physical destination. Do not enlarge or move the cache dynamically: settle a boot-time, disjoint tag/BSP ownership layout first, sized from source-pinned retail data and CE validation claims. The recommended order is (1) complete host streaming parity, (2) stream CTAG validator, (3) boot-fixed destination binding, (4) post-unload direct materialization and negative/retry tests, (5) target scratch/high-water/timing, (6) CE/PCSX2 map-lifecycle and first gameplay-map verification. Keep the non-UI catalog guard until all applicable gates pass.

Known measured capacities remain only the configured arena sizes: `frame_scratch=393,216`, `streaming=1,572,864`, `current_bsp=6,291,456`, `resident_gameplay=6,815,744` (`config/memory-budget.json:7-19`). The proposed 64 KiB history and 16 KiB input buffer have not been measured in the EE guest. No successful streamed decode, runtime scratch high-water, or retail map fit is asserted by this report.
