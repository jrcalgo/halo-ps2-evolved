# C2.6 owner telemetry audit (2026-10-23)

## Scope and disposition

This is a source audit of requirement 6 at `plans/7.hcu-remake-m2-m4.md:393`. It inventories retained producer-side high-water, failure, reset, release, and diagnostic values for the named owners. It does not claim C2.6 complete, report a new workload measurement, or modify production owners. The generic `arena_t` counters currently visible in `submodules/halo-ps2/engine/src/core/mem.[ch]` are considered separately from owner-specific producers.

## Generic arena counters and attribution limits

`arena_t` now has `high`, saturating `failed_allocations`, `reset_count`, `release_count`, and `invalid_releases` in `engine/src/core/mem.h`; producers are in `mem.c`. Allocation rejection paths increment `failed_allocations`; `arena_reset` increments reset count but preserves high-water/failures; valid and invalid rewinds increment separate counters. `arena_init` resets all these values. `arena_sub` calls `arena_init` on the child, so the child's counters start fresh; later child allocation activity is not reflected in its backing parent's cursor statistics. Region/child/overlaid values are views of the same bytes in some layouts and must not be summed. `arena_release` leaves high-water intact, so it measures peak since the last `arena_init`, not per map unless the arena is reinitialized.

The counters are useful generic instrumentation, but they do not make every named subsystem instrumented: CE tag cache, uncached render DMA chains, fixed actor datum capacity, audio requests, and GS texture residency have independent producers that need their own sampling paths. The game-state/object-pool diagnostics are nested by ownership; dynamic simulation is a separate arena. Report owner identity and nesting explicitly, and do not sum overlapping capacities or peaks.

Earlier report records it passed: `m2-step8-game-state-object-pool-telemetry-2026-10-22.md`.
- `python3 tools/test_hcu_ps2_malloc_diagnostic.py` passes the current dynamic-simulation allocator fixture: preboot realloc preservation, 16-byte alignment, active-byte high-water, three failed allocations, coalesced free-block reuse, realloc byte preservation, and telemetry reset after free/rebind. This focused host fixture is not an EE timing or workload measurement. The earlier report `m2-step8-malloc-arena-telemetry-2026-10-22.md` predates free-list/realloc changes and no longer describes current free semantics.
- `tests/staging.c` covers staging state transitions and capacity rejection behavior, but does not assert a retained failure counter (none exists).
- Existing render tests exercise chain overflow/cache decisions; their current APIs do not test lifetime high-water/reset counters because those counters are absent.

This audit ran no tests or builds. It inspected the above tests/reports and source producers only; no runtime owner values are claimed.
