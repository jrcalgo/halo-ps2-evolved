# M2 CTAG v1 streaming audit: bounded validation and fixed-cache materialization

**Scope:** independent, report-only audit of the current CTAG v1 format and the parent HP2 reader, focused on whether a streamed CTAG can be validated and committed into CE's fixed tag-cache address without staging the full decoded HP2 section in `streaming`. This report does not change parser/runtime code, memory defaults, or map admission. Findings are based on the source tree and frozen Longest/UI artifacts present on 2026-10-21.

## Finding

The format is streamable with a small, measured Longest relocation workspace, but the existing APIs do not yet implement the required transaction. The current production path materializes the complete CTAG wire section in `streaming`, retains it for the map lifetime, then invokes the CE cache adapter which copies/rebases the embedded image. The HP2 visitor can deliver decoded chunks to a sink with 98,304 bytes of decoder workspace, but its contract explicitly permits a sink prefix before final section-CRC success. It therefore cannot be pointed at CE-visible state and treated as a commit without an unpublished-destination protocol.

For a first Longest experiment, the practical bounded design is to use the **fixed tag-cache span as unpublished staging only after CE has unloaded the prior map**, while keeping the relocation table and HP2 codec workspace in a separate bounded scratch lease. Stream the CTAG payload into disjoint destinations: header into a small fixed record, image bytes into the final tag-cache address in their still-relative form, and relocation records into scratch. The visitor must return success (including the HP2 raw-section CRC) before any pointer rebasing or cache-success signal. Then run the complete CTAG structural checks against those separated pieces, validate every target using the staged image, rebase in place, and only then allow CE's normal header/schema path to publish tag globals. On any failure, invalidate the destination and keep the cache/mount unpublished; a retry must start at image offset zero.

This uses the tag cache as a private transaction buffer, not as active CE state. It is safe only after the CE lifecycle boundary which clears old tag/scenario/BSP/game-global pointers; it is not safe during the ordinary preflight-before-unload callback. A literally no-write preflight that performs every current `ps2_ctag_open()` check is **not available** under current memory constraints: relocation entries arrive after the image, while checking each relocation target requires the corresponding image word. The preflight must either defer full semantic validation until after unload, use a separately proven image-sized scratch span, or use an independently pinned package digest as an additional integrity gate. It must not claim complete CTAG validation based only on the CTAG header/CRC.

## Existing source contracts and invariants

### Wire format and parser checks

`tools/ctag.py` defines a 52-byte little-endian header (`<4s12I`), version 1, zero flags, image size, relocation count, relocation-table offset, zero tag-header offset, scenario datum, image CRC, and reserved words. The image has a 36-byte nine-word CE header and 32-byte tag instances. `encode()` validates before writing; `decode()` verifies exact payload length, CRC, and the same image/relocation invariants before exposing a `CtagImage` ([`tools/ctag.py:18-23,73-112`](../../tools/ctag.py#L18), [`tools/ctag.py:143-174`](../../tools/ctag.py#L143)).

The PS2 C parser must preserve these exact checks, not just the envelope checks:

1. Header: payload at least 52 bytes; magic `CTAG`; version 1; flags/tag-header-offset/reserved words zero; image at least 36 bytes and no larger than caller maximum; relocation count no larger than caller maximum; payload length equals exactly `52 + image_size + 4*relocation_count`; relocation table begins immediately after image; CRC-32 over image matches.
2. Image header: signature `sgat` (`0x74616773`), image scenario datum equals envelope datum, nonzero tag count, scenario low-16-bit datum index below tag count, aligned/in-range 32-byte tag-instance table, and nonnull vertex/index pointers when their counts are nonzero.
3. Relocation contract: nonempty table whose first field is offset 0; required fields 20 and 28 plus `table_offset + i*32 + 16/+20` for every instance; all fields 4-byte aligned, within image, strictly increasing/unique; every nonzero target below image size.
4. Materialization contract: base address nonzero; image fits the 32-bit EE address space; destination capacity is sufficient; the legacy API rejects overlap with both image and relocation bytes; every relocation is revalidated before its first write; null targets remain null; nonzero targets are rebased without 32-bit overflow.

These checks and error classes are implemented in [`ps2_ctag.c:64-145`](../../submodules/halo-ce-universal/port/ps2/src/ps2_ctag.c#L64), and copy/rebase semantics are in [`ps2_ctag.c:148-214`](../../submodules/halo-ce-universal/port/ps2/src/ps2_ctag.c#L148). Python currently distinguishes more human-readable failure strings, while C returns `TRUNCATED`, `FORMAT`, `BOUNDS`, `CHECKSUM`, `SPACE`, `ADDRESS`, and `OVERLAP` ([`ps2_ctag.h:12-35`](../../submodules/halo-ce-universal/port/ps2/include/ps2_ctag.h#L12)). A new streamed parser should preserve the C status distinctions where possible and have a mapping table to Python's exceptions; it must not silently relax any field above.

### Current runtime path

`hcu_map_service_preflight()` currently whole-loads HMAP, CTAG, CRNG, and CBIX into `map_arena`, checks the HMAP/source identity, catalog BSP rows, CRNG tag extent, `ps2_ctag_open()`, and full retail-map SHA-256, then rolls the arena back ([`hcu_map_service.c:230-323`](../../src/stream/hcu_map_service.c#L230)). The map service deliberately admits only `ui`; every other catalog map is rejected as `capacity-not-qualified` ([`hcu_map_service.c:249-255`](../../src/stream/hcu_map_service.c#L249)).

After CE releases a map, `map_loader()` calls `ctag_mount_hp2_verified_source_discover()`; `ctag_mount_hp2_internal()` whole-loads and retains CTAG and CRNG, while the optional path also retains CBIX ([`hcu_map_service.c:95-149`](../../src/stream/hcu_map_service.c#L95), [`ctag_mount.c:112-173,238-274`](../../src/stream/ctag_mount.c#L112)). The PS2 backend passes the complete decoded CTAG payload to `ps2_cache_mount_ctag_with_file_source()` ([`ctag_ps2_backend.c:7-21`](../../src/stream/ctag_ps2_backend.c#L7)). That adapter calls `ps2_ctag_open()`, then stores pointers to the retained payload and view ([`ps2_cache.c:131-159`](../../submodules/halo-ce-universal/port/ps2/src/ps2_cache.c#L131)). CE's exact tag-data read later calls `ps2_ctag_materialize()` into `physical_memory_get_tag_cache_base_address()` ([`ps2_cache.c:399-416`](../../submodules/halo-ce-universal/port/ps2/src/ps2_cache.c#L399)).

The ordinary loader reserves complete raw output before decoding and rolls it back on failure ([`section.c:141-235`](../../submodules/halo-ps2/engine/src/world/section.c#L141)). The visitor instead leases 64 KiB history + 16 KiB input + 16 KiB output = 98,304 bytes, streams output to a sink, and only reports `HP2_OK` after the section CRC passes ([`section.c:63-139`](../../submodules/halo-ps2/engine/src/world/section.c#L63), [`hp2.c:264-390`](../../submodules/halo-ps2/engine/src/stream/hp2.c#L264)). Its sink may already contain a valid prefix on I/O/decode/CRC failure; the API docs call this out ([`section.h:8-24`](../../submodules/halo-ps2/engine/src/world/section.h#L8)).

### Frozen first target: Longest

The Longest artifact report freezes a 42,141,696-byte source map and a 2,041,856-byte HP2 package (package SHA-256 `6f9c19feb4df9e7ec49e797ce3eb6f7cfbdef3c89c6363b12aab2f05359f5a5b`). Its CTAG section is 4,339,096 bytes: 52-byte envelope + 4,263,624-byte CE image + 18,855 32-bit relocation entries (75,420 bytes). The map has 1,696 tags, CRNG is 9,380 bytes, CBIX is 44 bytes, and its single active BSP is 374,784 raw / 377,388 encoded bytes ([`m2-longest-artifact-freeze.md:1-51`](m2-longest-artifact-freeze.md#L1)).

The candidate diagnostic split is tag cache 4,477,120 bytes and BSP 1,814,336 bytes, exactly the current 6,291,456-byte `current_bsp` total. The fixed tag cache has only 213,496 bytes above Longest's image. Its relocation list plus the visitor's 98,304-byte decoder workspace is 173,724 bytes before alignment and parser metadata, fitting the 393,216-byte `frame_scratch` nominally with 219,492 bytes left. This is a useful bounded Longest-specific design point, **not** proof that future maps fit, that this scratch is otherwise unused at every phase, or permission to change the default split. The current binder obtains the tag span from the start of `current_bsp` and binds the remainder as BSP ([`hcu_memory_bind.c:41-56`](../../src/stream/hcu_memory_bind.c#L41)); the Longest sizing report explicitly labels the split diagnostic and not an accepted target layout ([`m2-capacity-next-slice-2026-10-21.md:31-60`](m2-capacity-next-slice-2026-10-21.md#L31)).

## Safe bounded algorithm (recommendation, not implemented)

### Lifecycle boundary

Keep the current preflight non-destructive while the prior scenario is live. It can stream-check HP2 table/layout, CTAG raw-section bound, outer CRC, envelope/header, and image CRC with bounded state, and can retain the already validated source identity. Full relocation-target validation must be repeated in the post-unload mount path unless a separate safe full-image span or package-authentication scheme is introduced. The current CE unload ordering is suitable: `scenario_unload()` clears scenario/BSP/game-global/tag state before `ps2_cache_release_map_owner()` releases the parent's map owner ([`scenario.c:370-412`](../../submodules/halo-ce-universal/source/scenario/scenario.c#L370)). Keep its lifecycle test as a prerequisite; never write the final tag span during preflight.

### Post-unload staging and commit

1. Reserve a small fixed CTAG header record and a relocation-array lease from `section_scratch`, with checked arithmetic and a configured relocation limit. For Longest, the measured relocation array is 75,420 bytes. Keep the HP2 visitor's 98,304-byte internal lease disjoint from those retained bytes; because the visitor releases to its entry mark, allocate relocation storage before calling it and assert its peak and final mark.
2. Invoke the existing bounded HP2 visitor for `CTAG`. The sink validates monotonic output offsets and exact section length. Copy bytes `[0,52)` into the fixed header; copy `[52,52+image_size)` into the CE final tag-cache span as **unrelocated private staging**; decode relocation words into the bounded scratch array. Reject any gap, duplicate, overrun, callback order mismatch, short section, or size inconsistent with the header. The destination is not published during this step.
3. Require visitor `HP2_OK`; this is the point at which the HP2 raw-section CRC is known good. Then call a new `ps2_ctag_open_parts(header, image, relocations, sizes, limits)` (or equivalent) that duplicates the complete checks from `ps2_ctag_open()` without requiring header/image/relocation bytes to be contiguous. It must check the inner image CRC, all table fields and required relocation rows, all sorted/aligned/in-range fields, every relocation target against the staged image, scenario datum, limits, base address, and pointer arithmetic. No absolute fixup is written until the entire table and all targets pass.
4. Rebase the unrelocated image **in place** only after validation succeeds. This is a distinct operation from `ps2_ctag_materialize()`: the legacy function deliberately rejects source/destination overlap and expects a separate contiguous payload. Add an explicit validated-in-place API or a tight HCU/PS2 helper with the same base-address/overflow and null-pointer rules. Revalidate or bind the view to the exact private image/relocation storage so it cannot be mutated between validate and apply.
5. Only after all bytes/fixups validate and apply should the backend mark CTAG mount state valid and CE be allowed to report the exact tag read complete. Preserve the existing CE `cache_file_header_verify()` and schema/tag validation path; do not publish CE globals from the mount callback itself. If this API's call order requires materialization before `cache_file_read()`, make the read callback a one-shot success acknowledgement only after `mounted_materialized` is set.
6. On any error, keep map cache read incomplete; clear the cache mount/view, destination signature (or otherwise mark it invalid), release relocation/decoder scratch and map owner to saved marks, close each source handle once, leave CE pointers null, and make a corrected-source retry start from offset 0. Since a failed visitor may have written a prefix, callback success must never be inferred from prefix size.

This avoids a duplicate 4.26 MiB image, a full 4.34 MiB decoded section in `streaming`, and an unbounded heap allocation. It uses the final tag destination as temporary unrelocated bytes only after the old map has been unpublished. The Longest scratch arithmetic is promising; measure actual aligned high-water and all other service state before claiming the slice fits.

## Required fault and differential tests

Build host tests around production `world_visit_section_with_scratch()` and the actual HCU/PS2 cache code, not a reimplementation-only fixture. Keep the old full-buffer APIs as the oracle.

1. **Parity:** for frozen UI and Longest, visitor output image and relocation list must exactly match the `tools/ctag.py` decode and existing `ps2_ctag_open/materialize()` result byte-for-byte. Compare every rebased pointer, null target, scenario index, image CRC, and final CE header. Assert image address equals fixed test cache base and never moves afterward.
2. **Envelope/structure negatives:** bad magic/version/flags/reserved/tag-header offset; truncated/extra bytes; image-size and relocation-limit overflows; wrong section/header scenario; bad CE signature/table/counts; scenario datum out of table; required relocation omitted (including first/last tag instance); duplicate/descending/unaligned/out-of-image relocation field; out-of-image target; non-null count with null render pointer; inner image CRC; base-address zero/wrap; insufficient final destination; and address overflow. Assert no pointer rebasing or cache publication on each failure.
3. **Late streaming failures:** injected file short-read after the image or during the final relocation chunk; HP2 decoder error after an output prefix; outer HP2 CRC mismatch after all sink bytes; CTAG inner CRC mismatch; malformed final relocation; relocation-workspace exhaustion; injected write/sink failure at each split boundary (header/image/relocation). Poison destination first and assert it is invalid/unpublished after failure; verify arena marks, descriptor count, source lifetime, and mount state return to baseline.
4. **Lifecycle/retry:** execute CE scenario unload, then fail after unrelocated staging, after complete CTAG validation, and after fixup validation but before publication. Assert all old CE globals were already cleared and all new CE globals remain unpublished. Restore the exact package/source bytes and retry in the same process; verify deterministic image hash and pointer graph.
5. **Source consistency:** stream the same opened HP2 file descriptor for all passes/callbacks. If implementation reopens by path, pin/verify HP2 package identity across passes (HMAP currently authenticates the retail `.map`, not the HP2 package itself; `hcu_map_catalog` records map length, tag extent, and map SHA but no HP2 package SHA: [`hcu_map_catalog.h:12-25`](../../src/stream/hcu_map_catalog.h#L12), [`hcu_map_catalog.c:7-10`](../../src/stream/hcu_map_catalog.c#L7)). Reject a changed package between validation/materialization rather than trusting the source-map digest.
6. **Capacity:** record exact bytes of header/relocations/visitor workspace/CRNG/CBIX/CBSP scratch, alignment waste, current/high values, peak across preflight→unload→tag stage→schema validation→BSP switch→failure/retry. Do not infer safety from the 219,492-byte nominal Longest scratch remainder.

## Unknowns and stop conditions

- `world_visit_section_reader_with_scratch()` shares static HP2 header storage and is synchronous/non-reentrant. A direct cache callback must not re-enter it through CE resource/BSP callbacks; otherwise make header state caller-owned or prove single-thread/non-reentrancy at the EE boundary ([`section.c:63-85`](../../submodules/halo-ps2/engine/src/world/section.c#L63)).
- The section visitor reads the HP2 package by path and closes its own descriptor; current service `load_section()` uses the separate full-output API. A persistent reader API or an explicitly reopened-and-identity-checked path is needed. Keep HP2 `.hp2` reads distinct from source retail `.map` reads in `ctag_map_source`/CRNG (`ctag_resource_index_read()` only authorizes source map extents: [`ctag_resource_index.c:100-143`](../../src/stream/ctag_resource_index.c#L100)).
- CTAG materialization and cache read occur through separate callbacks today. The exact hook/order must be traced in CE `cache_files.c` before choosing mount-time eager staging versus cache-read-time staging; preserve its completion flag and no-publication-on-failure semantics ([`cache_files.c:1258-1310`](../../submodules/halo-ce-universal/source/cache/cache_files.c#L1258)).
- Current `ps2_ctag_open()` accepts relocation count up to `tag_cache_size/4`, which is not the same as scratch capacity. The Longest 18,855-entry array fits one 393,216-byte frame scratch lease combined with 98,304-byte HP2 workspace, but other map counts and overlapping runtime frame-scratch users have to be audited before generalized catalog admission.
- Because `ps2_ctag_materialize()` rejects overlap, do not call it with the fixed tag cache as both source and destination. Introduce an explicit staged/in-place API only with complete validation-before-rebase and rollback tests.
- Do not alter `HALO_HCU_TAG_CACHE_BYTES`, memory-region sizes, reserve, or the runtime non-UI capacity gate based on this report. Longest is a candidate vertical slice only; the current all-map reports, resident gameplay owners, BSP/render/animation/sound peaks, and guest proof remain governing.

Halo-64 is relevant only as a methodological comparison: keep HCU data/state ownership separate from PS2 drawing/platform glue and require exact failure/report evidence. Its N64 memory budgets, cut features, ABI, and throttled simulation are not applicable to this R5900 path ([`submodules/halo-64/port/n64/NOTES.md:33-46`](../../submodules/halo-64/port/n64/NOTES.md#L33)).

## Follow-up implementation note (2026-10-21)

The follow-up lifecycle trace confirms the ordering boundary more precisely: CE `scenario_tags_load()` fills the destination tag span with `0xCD` immediately before the exact `cache_file_read()` call. A streamed loader must therefore execute inside that callback; any eager mount-time staging would be overwritten. The independent lifecycle agent also confirmed `scenario_tags_unload()` deregisters consumers and nulls `cache_file_globals.tag_header`, and `scenario_unload()` clears scenario/BSP globals before the parent map-owner release. The parent tag span is reusable only after this sequence.

The PS2 parser now exposes `ps2_ctag_open_parts()` for validating a 52-byte header, staged image, and separate relocation table with the same checks as the contiguous parser. The contiguous `ps2_ctag_open()` delegates to the split-span validator after enforcing exact payload length. This makes a future streaming sink's parser boundary testable without materializing a second contiguous CTAG payload. A separate `ps2_ctag_rebase_in_place()` primitive now accepts only `destination == view->image`, rejects relocation-table overlap, and validates every field, target, base, and address range before changing the staged image. Its host fixture compares output byte-for-byte to the legacy materializer and verifies a malformed final target leaves the entire staged image unchanged. Independent review then caught a legacy `ps2_ctag_materialize()` forged-view edge: `image_size - 4` underflowed for a caller-assembled view smaller than four bytes. The materializer now returns `PS2_CTAG_ERR_BOUNDS` before reading or writing, with a destination-unchanged regression. A retail-derived Longest case packages the local decompressed map with the current schema ELF, then runs the C split parser and in-place rebase against its 4,263,624-byte image and 18,855 relocation rows, comparing the complete output against the Python materializer.

The next host composition fixture, [`hp2_ctag_stream_main.c`](../../tests/hp2_ctag_stream_main.c), feeds the production `world_visit_section_with_scratch()` decoded chunks directly into separate CTAG header/image/relocation spans, then calls the split validator and in-place rebase. The real Longest-derived package passed byte-for-byte oracle comparison with a measured visitor+relocation scratch high-water of **173,760 bytes**. Three failure variants are covered: a sink abort after the full CTAG image and four relocation words have been staged returns `HP2_ERR_IO`; corrupting only the HP2 CTAG section CRC emits the complete decoded CTAG then returns `HP2_ERR_CRC`; and rebuilding HP2 around an image with a stale inner checksum yields visitor success but `PS2_CTAG_ERR_CHECKSUM`. For all three, the harness compares the **entire staged image** against the corresponding original relative image, proving that no CTAG pointer fixups were applied before the failure was accepted. This is limited to this host harness's control flow; it does not prove a production cache callback keeps CE publication blocked. The fixture does not yet contain CE globals or a cache publication flag. Combined verification: `PYTHONPATH=. python3 -m pytest -q tests/test_ctag.py tests/test_cbsp.py tests/test_retail_ui_ctag_mount.py tests/test_ctag_mount.py tests/test_hcu_ce_map_lifecycle.py tests/test_ctag_schema_walk.py` — **45 passed, 2 skipped, 8 subtests passed**; production-profile HCU closure compiled **369 units with zero failures**, while the M0 rooted-external gate remains open at **322**. The composition is host-only and not wired to cache callbacks, retained package identity, source-I/O fault rollback/retry, CE publication, or target runtime. The two skipped tests require external package/native ILP32 configuration; the approved lifecycle run was separately performed in its report. Preserve all remaining stop conditions above.

The next integration gate is the actual callback path identified by [`scenario_tags_load()`](../../submodules/halo-ce-universal/source/cache/cache_files.c#L1262-L1277): CE poisons the destination immediately before requesting the full tag image, then publishes globals only after a successful return and tag verification. Add a narrowly registered stream callback to the exact PS2 `cache_file_read()` request, and test completion-flag failure, CE-global nonpublication, source-I/O failure, destination unusability/re-poison, arena rollback, and same-process retry there. Keep this separate from host sink-only failure coverage.
