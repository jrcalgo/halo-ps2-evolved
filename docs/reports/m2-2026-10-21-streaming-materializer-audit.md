# M2 CTAG/CBSP final-destination streaming materializer audit

**Disposition: implementation review and recommended sequence; report only.** This review is tied to the current shared worktree on 2026-10-21. It does not change production code, tests, M2 admission, arena sizes, or milestone status. Current code supports bounded HP2 section decoding as a generic primitive, but the integrated CE consumer still stages whole decoded CTAG/CBIX/CRNG data and whole CBSP payloads. A final-destination stream consumer is still a proposal, and no retail gameplay map capacity is qualified by this report.

## Executive findings

1. **The generic bounded HP2 decoder exists; CTAG and CBSP do not use it.** `world_visit_section_reader_with_scratch()` opens the HP2 directory, leases 98,304 bytes (64 KiB history plus 16 KiB input and output windows), streams output to a sink, and only sets `raw_size` after HP2 CRC succeeds ([`section.c:79-138`](../../submodules/halo-ps2/engine/src/world/section.c#L79-L138)). The lower-level decoder checks exact output length and raw CRC after flushing ([`hp2.c:251-354`](../../submodules/halo-ps2/engine/src/stream/hp2.c#L251-L354)). It is synchronous, uses static section-header storage, and a sink can observe a prefix before a later read/CRC failure. The map service instead calls `world_load_section_with_scratch()` ([`hcu_map_service.c:56-79`](../../src/stream/hcu_map_service.c#L56-L79)), which allocates the full `raw_size` in an owner and a bounded decode workspace in scratch ([`section.c:141-235`](../../submodules/halo-ps2/engine/src/world/section.c#L141-L235)).
2. **The current whole-buffer parser/materializers are valuable reference oracles but unsafe as transaction commit functions.** `ps2_ctag_open()` validates its envelope, image CRC, CE header/table, required fixup fields, and sorted relocation table ([`ps2_ctag.c:64-145`](../../submodules/halo-ce-universal/port/ps2/src/ps2_ctag.c#L64-L145)). `ps2_ctag_materialize()` copies first and can then fail on a late absolute-address overflow, leaving a partially modified destination; it also does not enforce the documented source/destination non-overlap constraint ([`ps2_ctag.c:148-169`](../../submodules/halo-ce-universal/port/ps2/src/ps2_ctag.c#L148-L169)). Stream implementation should preserve `open()` invariants and improve the destination-write boundary, not blindly reuse its partial-write behavior.
3. **The decisive atomicity boundary is CE unpublish, not HP2 callback completion.** CE invokes the cache read synchronously for the full tag image and accepts only `read_complete == TRUE`, then validates the tag header and schema before publishing global tag pointers and `tags_loaded` ([`cache_files.c:1258-1309`](../../submodules/halo-ce-universal/source/cache/cache_files.c#L1258-L1309)). The PS2 callback begins with a non-success failure sentinel and makes the exact whole-tag read successful only after materialization ([`ps2_cache.c:375-416`](../../submodules/halo-ce-universal/port/ps2/src/ps2_cache.c#L375-L416)). Therefore a partial final-span write is tolerable only while the candidate is explicitly unpublished, with completion remaining non-TRUE and all retry paths rewriting from byte zero. Pre-unload failure must preserve map A; after the single fixed tag span has been made writable, failure must end in a clean no-map state, not pretend map A was restored. This distinction is already described in the CTAG design report ([`m2-streamed-ctag-destination-design.md:75-90`](m2-streamed-ctag-destination-design.md#L75-L90)).
4. **CBSP is a distinct stream/materializer, not a consequence of fixing CTAG.** Current parent BSP load allocates the entire decoded CBSP section in `bsp_scratch`, then retains it until the CE cache callback materializes it ([`ctag_mount.c:67-104`](../../src/stream/ctag_mount.c#L67-L104)). Blood Gulch B000 raw CBSP is 1,303,092 bytes, versus 393,216 bytes of `frame_scratch` (reported in [`m2-loader-architecture-audit.md:24-26`](m2-loader-architecture-audit.md#L24-L26)). CBSP has its own inner image CRC, source extent identity, relocation table, two address domains, and source-overlap/target-string rules ([`ps2_cbsp.c:62-128`](../../submodules/halo-ce-universal/port/ps2/src/ps2_cbsp.c#L62-L128), [`ps2_cbsp.c:131-187`](../../submodules/halo-ce-universal/port/ps2/src/ps2_cbsp.c#L131-L187)). It requires a separate bounded state machine and acceptance matrix.
5. **Streaming changes transient storage, not resident tag-image requirements or proof of fit.** CE consumers require the complete relocated tag image at one immutable address. Current `hcu_memory_bind_parent_v2()` binds tag cache to the front of `current_bsp` and gives CE the remaining BSP tail ([`hcu_memory_bind.c:41-71`](../../src/stream/hcu_memory_bind.c#L41-L71)); binding freezes at `physical_memory_allocate()` ([`ps2_memory.c:91-138`](../../submodules/halo-ce-universal/port/ps2/src/ps2_memory.c#L91-L138)). Budget-v2 keeps `current_bsp` at 6,291,456 B, `streaming` at 1,572,864 B, and `frame_scratch` at 393,216 B, with 5,767,168 B reserved ([`memory-budget.json:2-20`](../../config/memory-budget.json#L2-L20)). The proposed 4,477,120 B tag / 1,814,336 B BSP split is arithmetic only; it cannot be adopted as a general capacity result. Non-UI maps remain denied by the current explicit `capacity-not-qualified` check ([`hcu_map_service.c:247-253`](../../src/stream/hcu_map_service.c#L247-L253)).

## Required invariants for the implementation

### HP2 stream and outer CRC

1. Parse the pack header/table once per stable source lease (or reparse and compare it for each pass). Preserve `hp2_open_header()` checks: magic/version, declared file size, bounded section count/table, legal section tags/codec/alignment, sector-aligned offsets, non-overlapping in-file stored extents, and duplicate-tag rejection ([`hp2.c:18-70`](../../submodules/halo-ps2/engine/src/stream/hp2.c#L18-L70)). Do not trust the first preflight if the later open can refer to different bytes.
2. Every pass must consume exactly `stored_size`, produce exactly `raw_size`, and independently finish the HP2 raw CRC over the full decoded section. `hp2_load_stream()` may call the sink multiple times before its final raw CRC check, so each pass must use private/unpublished state and the adapter must expose no success until the final `HP2_OK` return ([`hp2.c:283-354`](../../submodules/halo-ps2/engine/src/stream/hp2.c#L283-L354)).
3. Do not confuse HP2 CRC with inner format CRC. For CTAG, HP2 raw CRC covers all decoded CTAG bytes (52-byte header + image + relocation offsets); CTAG inner CRC covers only `image_size` bytes. For CBSP, HP2 raw CRC covers the entire decoded CBSP envelope/image/relocation rows; CBSP inner CRC covers only its CBSP image ([`ps2_ctag.c:74-99`](../../submodules/halo-ce-universal/port/ps2/src/ps2_ctag.c#L74-L99), [`ps2_cbsp.c:72-103`](../../submodules/halo-ce-universal/port/ps2/src/ps2_cbsp.c#L72-L103)). No CRC is expected to match after absolute pointer fixups mutate the image.
4. Keep the generic visitor output contract explicit: the callback's `offset` sequence starts at zero, is contiguous/monotonic, never exceeds declared raw size, and ends at exactly raw size. An error after any prefix resets `raw_size` to zero, but does not undo bytes already written by a callback. The present API's static `hdr` means serialize map loads or move state into a caller-owned descriptor before reentrancy/concurrency.

### CTAG wire checks and relocation safety

Preserve all current `ps2_ctag_open()` checks rather than merely comparing the image CRC:

- Exact 52-byte header, `CTAG` magic/version 1, zero reserved words/bytes, `image_size >= 36`, relocation count within proven bound, exact `relocation_offset == 52 + image_size`, and exact payload end after `count * 4` bytes ([`ps2_ctag.c:72-95`](../../submodules/halo-ce-universal/port/ps2/src/ps2_ctag.c#L72-L95)). Use checked integer arithmetic before deriving image/table endpoints.
- Inner image CRC before relocation; CE tag signature; scenario index agreement; nonzero tag count and scenario low-16 index in range; aligned/bounded tag table and complete 32-byte instances; vertex/index table consistency ([`ps2_ctag.c:96-114`](../../submodules/halo-ce-universal/port/ps2/src/ps2_ctag.c#L96-L114)).
- Required relocation entries for the two tag-header arrays and each tag instance's name/data fields; sorted, strictly increasing, aligned fields with `field <= image_size - 4`; each relative target either zero or `< image_size` ([`ps2_ctag.c:115-139`](../../submodules/halo-ce-universal/port/ps2/src/ps2_ctag.c#L115-L139)). Avoid retaining all relocation offsets: at most the fixed image header words and one 4-byte table record are needed to parse; repeated HP2 passes can revisit table rows.
- Before any final-span write, prove destination pointer is the exact bound tag-cache base, span covers `image_size`, base is valid/aligned, `base + image_size <= 2^32`, and the destination does not overlap decode workspace, CTAG source buffer, or any active CE-published span. `ps2_ctag_materialize()` checks capacity and base overflow but checks relocation overflow after its copy and has no overlap check ([`ps2_ctag.c:148-169`](../../submodules/halo-ce-universal/port/ps2/src/ps2_ctag.c#L148-L169)).

### Proposed CTAG pass protocol (unpublished final destination)

The CTAG relocation list follows the image, while each relocation refers backward to a word in the image. Thus a bounded one-pass stream cannot both validate a relocation's target against earlier image bytes and avoid either a relocation list/image copy or a reread. Recommended sequence:

1. **Old-map-live preflight:** open the package and source under a stable identity; stream HMAP/CTAG/CRNG/CBIX validation without writing either final tag cache or active BSP. Verify source size/hash, package and section identity, CTAG header/size/count arithmetic, all checkable image/header/table invariants, HP2 raw CRC, and CTAG image CRC. To verify each relocation target's value without holding the whole image, either make a second bounded decode pass that compares table entries against previously parsed image bytes through bounded random access/replay, or explicitly defer this check to post-unload finalization. Never claim pointer-target validation from header/table structure alone.
2. **After CE unpublish and owner release:** reopen the HP2 package and revalidate the header/section, package identity, and the exact source hash/identity that authorize the request. Preflight metadata is advisory, not a lease on mutable file contents. There is no old-map rollback once the single fixed tag span is overwritten.
3. **Image write pass:** initialize transaction state `MATERIALIZING`, invalidate any previous candidate-ready token, then decode the complete CTAG section through a sink. Consume/validate the 52-byte envelope; copy only the image interval to the final tag-cache address; increment CTAG inner CRC only for image bytes; parse enough fixed image header bytes in a bounded local prefix; validate relocation-list framing as it streams. The entire destination remains unpublished and CE completion remains `_cache_file_read_failed`, even after all image bytes have been written.
4. **Late relocation validation:** after the image is staged, perform a separate complete HP2 pass (or equivalent parser pass with independently verified outer CRC) over relocation rows. Validate order/field bounds/required fields, read each target word from the staged image, check relative target `< image_size`, null policy, base arithmetic, and no address wrap. The final base+size precheck can prove every in-image target addition cannot overflow, but still verify target/domain and alignment per row.
5. **Fixup and commit boundary:** apply `base + target` only after validation succeeds; completion becomes exactly `TRUE` only after HP2 CRC and CTAG CRC/framing/relocation checks and all fixups finish. Any read/decode/sink/CRC/fixup error leaves the span marked invalid, completion non-TRUE (not zero/pending), CE globals and loaded state unpublished, and HP2 descriptor/scratch/source transaction released appropriately. The next attempt must rewrite the complete image from offset zero before CE can use it. The safest variant uses one extra relocation-only validation pass before a final apply pass; a lower-pass variant may partially patch the still-unpublished span but must guarantee abort and full rewrite.
6. **CE validation/commit:** leave CE's current ordering intact: tag-header verification and `tag_validate_tags()` must both pass before `cache_file_globals.tag_header`, `global_tag_instances`, `global_tag_count`, or `tags_loaded` are published ([`cache_files.c:1286-1309`](../../submodules/halo-ce-universal/source/cache/cache_files.c#L1286-L1309)). Add a distinct acknowledgment for these states; `cache_files_precache_map_loaded()` currently means a payload is mounted, not schema-validated or scenario-committed ([`ps2_cache.c:304-310`](../../submodules/halo-ce-universal/port/ps2/src/ps2_cache.c#L304-L310)).

### Proposed CBSP pass protocol

1. Resolve the CE request by exact `reference->file_offset` and `file_size` against the retained CBIX; reject extents overlapping CTAG or CRNG-authorized resource extents before reading ([`ctag_mount.c:67-85`](../../src/stream/ctag_mount.c#L67-L85)). Keep the raw map resource reader and HP2 package reader distinct: the original `.map` provides CE's virtual-file CRNG ranges; the `.hp2` package contains decoded CBSP sections.
2. Open the selected HP2 section, check package table and exact raw output length, then stream-validate the 36-byte CBSP header, `psbs` signature, source file offset/size, image/table exact extents, zero reserved/padding, image CRC, and each sorted relocation row ([`ps2_cbsp.c:72-128`](../../submodules/halo-ce-universal/port/ps2/src/ps2_cbsp.c#L72-L128)). Also require envelope source extent to equal the CE/CBIX requested extent, as current `ps2_cache_mount_cbsp_for_extent()` does ([`ps2_cache.c:230-267`](../../submodules/halo-ce-universal/port/ps2/src/ps2_cache.c#L230-L267)).
3. Write only image bytes into the one fixed, unpublished `structure_bsp_cache` span. Compute both HP2 raw CRC over the full CBSP section and CBSP CRC over its image bytes. The tag image must already be materialized and validated because relocation domain 1 addresses strings/data in that image.
4. Revisit relocation rows with bounded memory. Preserve exact rules: 12-byte rows; domain 0 BSP-relative, domain 1 tag-image-relative; sorted unique 4-byte-aligned field in range; padding zero; row target equals the relative word encoded in the unrelocated image; domain-0 nonzero target `< image_size`; domain-1 target `< tag_size` and NUL-terminated within the existing 256-byte search rule ([`ps2_cbsp.c:104-118`](../../submodules/halo-ce-universal/port/ps2/src/ps2_cbsp.c#L104-L118), [`ps2_cbsp.c:149-165`](../../submodules/halo-ce-universal/port/ps2/src/ps2_cbsp.c#L149-L165)). Validate address ranges/alignment/nonoverlap and base arithmetic before any BSP pointer is published ([`ps2_cbsp.c:131-148`](../../submodules/halo-ce-universal/port/ps2/src/ps2_cbsp.c#L131-L148)).
5. Apply fixups while BSP remains unpublished. On all-success, perform the existing PS2 handling for Xbox-only vertex/index buffer arrays, return `TRUE` for the exact cache request, then let CE verify the BSP header and `tag_validate_structure_bsp()` before setting BSP globals and the structure-BSP tag instance base ([`ps2_cache.c:417-443`](../../submodules/halo-ce-universal/port/ps2/src/ps2_cache.c#L417-L443), [`cache_files.c:1442-1508`](../../submodules/halo-ce-universal/source/cache/cache_files.c#L1442-L1508)). On failure, do not publish BSP pointers; preserve the valid tag map if this is a failed in-map BSP switch and follow retail CE's fallback attempt to reload the old BSP. A candidate initial BSP failure instead aborts/unloads the map.
6. Do not store an entire active CBSP wire payload in `frame_scratch`; after synchronous materialization the source descriptor can close and scratch returns to baseline. Retain only the final BSP image in the stable BSP destination until CE unloads/switches it. The one-active-BSP rule already appears in `ps2_cache.c:389-404` and parent lease management in `ctag_mount.c:54-60`.

## Output atomicity and failure-state correction

“Rollback” must be phase-qualified. The single fixed tag-cache span cannot contain arbitrary old and candidate images simultaneously (unless a separately measured second image buffer is added, which would alter the budget). Therefore:

| Failure point | Correct invariant |
|---|---|
| Candidate preflight while A is live | A's tag bytes, CE globals, active BSP, source/mount lease, arena owner, and render generation stay unchanged. No candidate final-span writes. |
| Before candidate writes after A has been unpublished | Service returns to a deterministic `EMPTY`/menu state; all candidate globals and callbacks are null, mounts/descriptors/temporary marks released, final tag span marked invalid. There is no assertion that A's bytes/globals were restored. |
| CTAG write/CRC/relocation error | No `TRUE` completion and no CE tag header/global publication. Candidate span is dirty-invalid; next attempt rewrites from byte zero. |
| CE tag header/schema refusal | Clear all CE references and validator/candidate state before owner release; same-process retry reopens/revalidates package and rematerializes the full tag image. |
| BSP switch candidate failure while map A is still live | Keep CTAG/map lifetime intact. Follow CE's implemented old-BSP reload attempt; if that fallback also fails, CE safe-nulls BSP state/menu path. BSP destination is private until verification. |
| Initial scenario BSP failure after CTAG succeeded | Abort map A/candidate: unpublish scenario/tag/BSP state in the correct lifecycle order, then release source/index/package and arena ownership. Retry begins as a full map load. |

This clarifies the overly broad “return exactly to prior baseline” wording in Step 9 at [`plans/7.hcu-remake-m2-m4.md:547`](../../plans/7.hcu-remake-m2-m4.md#L547). Snapshot comparison should compare phase-appropriate expected state, not demand restoration of overwritten bytes or historic arena high-water after an abort. CE's BSP-switch fallback behavior is visible at [`scenario.c:1081-1134`](../../submodules/halo-ce-universal/source/scenario/scenario.c#L1081-L1134); it is not a generic whole-map rollback mechanism.

## PS2 constraints and allocation ledger consequences

- Resident final CTAG image stays at the bound `tag_cache` address for the entire map. Do not hold a second decoded image. CE validator claims span tag+BSP capacity; the binder allocates those claims in `resident_gameplay`, separately from both cache spans ([`hcu_memory_bind.c:65-71`](../../src/stream/hcu_memory_bind.c#L65-L71)). Report the actual bytes and physical base for claims on the integrated ELF.
- One bounded HP2 decoder workspace currently totals 98,304 bytes in `frame_scratch`; source SHA hashing can request up to 262,144 bytes there ([`section.c:90-127`](../../submodules/halo-ps2/engine/src/world/section.c#L90-L127), [`hcu_map_service.c:26-53`](../../src/stream/hcu_map_service.c#L26-L53)). These uses must be proven sequential or their coexistence charged. Do not allocate a second hash window, parser chunk, relocation list, or CBSP temporary without accounting for alignment and peak overlap.
- Store only bounded parsed HMAP/CRNG/CBIX records, source/package descriptor state, and transaction metadata in `streaming`; derive maximum record counts from all supported assets and test them. Today's CTAG/CRNG/CBIX raw buffers nearly fill the 1.5 MiB arena on UI and exceed it on typical retail maps ([`m2-loader-architecture-audit.md:20-26`](m2-loader-architecture-audit.md#L20-L26)).
- Preserve the 5.5 MiB reserve and report every byte once across `elf_static`, `resident_gameplay`, `current_bsp`, `texture_cache`, `dynamic_simulation`, `streaming`, `frame_scratch`, DMA, and external GS/IOP/SPU2 stores. Decoding directly to final spans removes duplicate wire-section residency; it does not shrink CE's live tag image or BSP image.
- The exact configured current BPS-plus-tag region is 6 MiB. The proposed split from the design report (4,477,120 B tag + 1,814,336 B BSP) is based on one candidate's arithmetic and leaves only a particular max BSP tail; every supported map's actual simultaneous image plus BSP and claims/other owners must pass a measured gate. Blood Gulch lower-bound sum 5,543,948 B excludes several required working-set costs and cannot alone qualify it ([`m2-loader-architecture-audit.md:38-49`](m2-loader-architecture-audit.md#L38-L49)).
- `hcu_memory_bind_parent_v2()` must choose the final spans before `physical_memory_allocate()`; the provider rejects late binds after allocation ([`hcu_memory_bind.c:19-71`](../../src/stream/hcu_memory_bind.c#L19-L71), [`ps2_memory.c:91-110`](../../submodules/halo-ce-universal/port/ps2/src/ps2_memory.c#L91-L110)). Any per-map sizing decision is therefore a boot-time product decision, not a runtime realloc.

## Host fixtures and acceptance sequence

Implement in this order; each step retains legacy whole-buffer code as the oracle until parity is proven.

1. **HP2 visitor contract:** test stored and LZ4 content, max 65,535-distance back-reference and history wrap, callback offsets/contiguity, exact output, truncation at each read boundary, short-read/error, sink rejection, raw CRC mismatch after full output, malformed table/overlap/duplicate tags, zero-length case, and scratch/arena rollback. Run existing `test_world_section_capacity.py`, `test_world_section_visitor.py`, and engine C tests with ASan/UBSan. Confirm static-header non-reentrancy is either enforced or removed.
2. **CTAG parser state unit tests:** feed arbitrary chunk boundaries splitting each header word, image word, and relocation row; verify CTAG envelope parser reports exact field/error. Test each `ps2_ctag_open()` invariant and CRC separately from HP2 raw CRC. Assert invalid input has zero writes to a guard-filled destination; assert late HP2 CRC failure after complete image output leaves destination unpublished and marked invalid.
3. **CTAG materializer parity:** compare legacy `ps2_ctag_open/materialize()` versus streamed final bytes at the same simulated 32-bit base for UI and multiple retail packages. Compare image CRC on pre-relocated bytes, scenario index, all tag instances/pointers, relocation count/outcomes, and final image bytes. Inject relocation target OOB, missing/duplicate/unsorted fixup, address overflow, one-byte-short capacity, destination overlap, and late read/CRC errors; retry corrected package in the same process and prove the final bytes equal clean baseline.
4. **CBSP parser/materializer parity:** test B000 and structurally different BSPs; split stream at arbitrary CBSP header/image/row boundaries. Compare final bytes and domain-0/domain-1 addresses against `ps2_cbsp_open/materialize()` and Python `tools/cbsp.py`. Inject wrong CE/CBIX source extent, bad image CRC/raw CRC, wrong field target, domain >1, row padding, duplicate/unsorted field, invalid domain-1 string or unterminated 256-byte range, BSP/tag overlap, capacity overflow, partial stream, and retry.
5. **Unified transaction fixture:** compose parent map service, actual HCU PS2 cache adapter, actual CE header/schema validator, and scenario/BSP selection. Snapshot CE globals, cache callbacks, destination hashes/validity tokens, source and HP2 descriptors, all arena marks/high-water, and render snapshot generation. Assert old-map preservation only for pre-unload failures; assert empty safe state + retry for post-unload failures; assert BSP-only failure follows CE old-BSP fallback while tag-map remains live. Check no heap growth and no leaked descriptor across repeat loads.
6. **Target sizing/guest evidence:** before removing UI-only guard, pick candidate from whole-map source-hash audit; freeze boot spans; run integrated R5900 and exact PCSX2 interpreter/recompiler images; report physical addresses/canaries, all arena high-water, scratch peak, I/O timing, number of HP2 passes, final CTAG/BSP hashes, CE validator results, source/package/ELF hashes and clean retry. Add PCSX2/physical console evidence only to the scope it proves; host fixtures do not qualify mount device paths, EE timing, or 32 MiB fit.

## Implementation ownership and suggested source boundaries

1. **halo-ps2 HP2:** add transaction-local section descriptor/open/visit/reopen primitives under `engine/src/world/section.[ch]` or a narrow stream reader layer. Keep ownership of file readers, bounded history/input/output, source offsets, and outer CRC here. Preserve `world_load_section_with_scratch()` for small legacy consumers.
2. **HCU port CTAG/CBSP:** implement allocation-free begin/chunk/finalize/abort format states adjacent to [`ps2_ctag.c`](../../submodules/halo-ce-universal/port/ps2/src/ps2_ctag.c) and [`ps2_cbsp.c`](../../submodules/halo-ce-universal/port/ps2/src/ps2_cbsp.c). They own inner formats, relocation domain semantics, destination validation, and the unpublished validity token. Keep current whole-buffer APIs as reference paths.
3. **Parent map service/mount:** own map transaction phase, compact catalog/index lifetime, `.map` read source, HP2 package source/descriptor lifetime, scratch marks, and cleanup ordering in [`hcu_map_service.c`](../../src/stream/hcu_map_service.c), [`ctag_mount.c`](../../src/stream/ctag_mount.c), and [`ctag_map_source.c`](../../src/stream/ctag_map_source.c). Do not conflate original map reads with converted HP2 pack reads.
4. **CE cache/lifecycle:** retain retail cache function signatures and blocking completion semantics. Add abort/unmount calls on tag-header/schema and scenario failures, after clearing all CE references. The CE layer owns map-visible state; parent cannot release a tag image while `global_tag_instances`, scenario fields, or render snapshot still point into it.
