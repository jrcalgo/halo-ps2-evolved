# CE scenario-load tag/BSP failure rollback

## Result

Added a Step 9 lifecycle slice for two initial `scenario_load()` failures. First, a malformed CTAG relocation makes `scenario_tags_load()` fail before tag publication; second, a linker wrapper targets the UI package's `B000` HP2 visitor after mount/preflight and CTAG load have succeeded, forwards decoded callback bytes to CE's actual BSP sink, then returns failure from that same callback. The fixture verifies the first case releases the parent owner before remount/retry, and verifies a 16-byte destination witness for the second case so even a one-chunk UI BSP proves a late candidate-destination failure rather than a preflight or pre-copy failure.

The BSP failure exposed a CE lifecycle hole: `scenario_load()` returned `FALSE` when the first `scenario_switch_structure_bsp(0)` failed but retained `global_scenario`, the loaded tag table, and the parent map owner. The CTAG test then exposed a second gap: when `scenario_tags_load()` returned `NONE` before publishing a scenario, the `scenario_load()` failure branch only reported missing tags and left the preflighted parent owner active. Under `HALO_PS2`, that branch now also calls `scenario_unload()`. This closes texture/sound/tag consumers and releases the owner even when no scenario or tag header was published. The fixture checks null scenario/BSP/tag state, closed source, released owner/scratch, and a fresh source remount followed by successful tag retry; it also retains the initial-BSP late-write failure/retry.

- CE teardown ordering: [`scenario.c`](../../submodules/halo-ce-universal/source/scenario/scenario.c), `scenario_unload()` clears scenario/BSP globals and unloads tags before calling `ps2_cache_release_map_owner()`.

The HCU change is therefore a narrowly marked PS2 ownership departure, not a claim that Halo-64 has the rollback behavior.
- Real parent visitor boundary: [`hcu_map_service.c`](../../src/stream/hcu_map_service.c#L98-L120) connects `world_visit_section_with_scratch()` to the retained HP2 source and the CE cache sink.

- Regression checks: [`test_hcu_ce_initial_bsp_rollback_source.py`](../../tests/test_hcu_ce_initial_bsp_rollback_source.py) checks the cleanup branch, post-write fault placement, and production visitor wrapper wiring.
