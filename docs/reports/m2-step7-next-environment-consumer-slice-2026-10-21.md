# M2 Step 7 — next consumer slice: CE underwater/weather query

**Recommendation:** next add one source-oracle-backed call to CE `scenario_location_underwater()` for a real materialized BSP cluster with `fog_reference == NONE`. This is a small, deterministic location/environment consumer test over the existing `a30`/`a50` transaction. It requires neither Step 8 capacity changes nor a synthetic BSP. The current Step 7 sound test has closed the named no-collision sound branches, while the visibility/sound-visible branch still touches dynamic-object collision; this weather case advances a separate, explicitly outstanding CE BSP consumer without broadening that path.

The environment query below is the most bounded missing consumer that can add distinct CE behavior without those expansions. It does not replace the collision oracle or transaction-failure gate.

## CE source contract and existing build boundary

CE declares `scenario_location_underwater(const struct location *, const real_point3d *, short *optional_weather_palette_index)` in [`scenario.h:131-133`](../../submodules/halo-ce-universal/source/scenario/scenario.h#L131) and implements it in [`scenario.c:694-741`](../../submodules/halo-ce-universal/source/scenario/scenario.c#L694). It first calls `scenario_get_fog_region_index()` ([`scenario.c:632-691`](../../submodules/halo-ce-universal/source/scenario/scenario.c#L632)). When the selected cluster has `fog_reference == NONE`, that resolver returns `NONE`; the underwater path therefore does not dereference fog-region definitions. It then reads the cluster's `weather_palette_index`, bounds-checks it against the active BSP's `weather_palette.count`, writes the optional output, and returns false ([`scenario.c:707-740`](../../submodules/halo-ce-universal/source/scenario/scenario.c#L707)). This makes an unfogged cluster a clean path through both the location-sensitive API and cluster-weather metadata without introducing external fog-tag fixtures.

The exact CE fields are in [`structure_bsp_definitions.h:89-110`](../../submodules/halo-ce-universal/source/structures/structure_bsp_definitions.h#L89): `structure_cluster` is `0x68` bytes, `fog_reference` is at `+0x02`, and `weather_palette_index` at `+0x08`, with compile-time assertions. The active BSP already contains the cluster block and weather palette fields after the CE schema validator and CBSP materializer complete. The Python retail PVS oracle already resolves each original BSP extent from its map scenario/tag index and binds the source map/package identity ([`test_hcu_scenario_bsp_switch.py:25-91`](../../tests/test_hcu_scenario_bsp_switch.py#L25)). The current ILP32 runner compiles the real `source/scenario/scenario.c` together with the materialized transaction and CE collision sources ([`test_hcu_scenario_bsp_switch.py:228-274`](../../tests/test_hcu_scenario_bsp_switch.py#L228)); a map check shows `scenario_location_underwater` is not yet retained in the current final executable, so the symbol/map must be re-inspected after rooting this call.

## Narrow test design

1. **Select a real source record before invoking CE.** Extend the existing raw-map Python source oracle to locate the first cluster in each BSP where the raw `fog_reference == NONE`. Record cluster index, raw weather palette index, BSP `weather_palette.count`, source map SHA, package SHA, CBIX row/path, and CBSP identity. If a BSP has no such cluster, mark it absent and select the next hash-verified BSP; do not synthesize an unfogged cluster.
2. **Derive the independent expected output.** For each selected source record, expected underwater result is `false`; expected weather output is the source `weather_palette_index` only if `0 <= index < weather_palette.count`, otherwise CE `NONE`. Keep the raw `structure_cluster` field offsets tied to CE's C declarations with the existing style of `sizeof`/`offsetof` assertions. Do not use the relocated CE structure to establish the expected value.
3. **Run after successful publication.** In the existing package transaction seam, initialize a real CE `struct location` with the selected valid cluster index and a real non-null point, then call CE `scenario_location_underwater()` on the active published BSP. For `fog_reference == NONE`, the point is required by CE's API assertion but is not consumed by fog-plane math. A non-null optional weather output checks the documented fallback to cluster weather.
4. **Assert no mutation or identity drift.** Snapshot the active BSP bytes (the wrapper test already follows this pattern), CE BSP/scenario publication indices and pointers, and collision-user depth before/after. Assert all remain unchanged. Assert return false, expected weather output, and exactly one C output row for each Python-selected query; reject duplicates, missing rows, or a different source/BSP identity.
5. **Keep link closure bounded.** Root only `scenario_location_underwater()` through the transaction fixture and inspect its exact link map for retained `scenario_get_fog_region_index`, `scenario_fog_region_get_fog_index`, fog-tag lookup, and math helpers. The `fog_reference == NONE` runtime path avoids fog-tag dereferences, but the compiled function can still retain its alternative fog path. Do not add broad fake fog definitions merely to satisfy linker reachability; if the closure grows beyond a small audited set, isolate any necessary no-fog callback only if it preserves the exact function and source-level contract, otherwise report the measured blocker.
6. **Re-run the exact package test.** Test both `a30` and `a50` where each has a qualifying source cluster; preserve the existing source/package SHA checks and CE switch/unload/rollback flow. Record final ELF/map and C/Python/source identities together. This is a host semantic check only: the fixture's buffers are deliberately larger than `current_bsp`, and Step 8 remains the gate for lawful target residency.

The current runner's per-cluster PVS work already visits every cluster and maintains source-derived pair identities, so the extra oracle is small and sits at the same publication lifecycle. The new test should not invoke rasterizer or sound output and should not reinterpret weather as drawing-only state: CE exposes this API to determine the game’s underwater/weather state.

## Remaining collision and atomicity work after this slice

The independent collision golden remains a separate high-priority Step 7 item. Current wrapper expectations rely on CE `collision_surface_polygon()` and `collision_bsp_test_vector()` and compare the public wrapper to that CE result ([`m2-step7-full-ce-collision-wrapper-qualification-2026-10-21.md:9-18,58-60`](m2-step7-full-ce-collision-wrapper-qualification-2026-10-21.md#L9)). A later bounded slice should select a fixed source-hash-bound raw BSP query and expected surface/material/designator/plane/leaf tuple from raw source data or a reviewed source-derived golden, then exercise both one hit and one miss through the actual wrapper. A geometry oracle must not get its expected result from the CE function being tested. No PCSX2 target test should be substituted while the BSP exceeds its production owner.

Failure atomicity should remain separated from this positive query: Step 6 already proves a CRC-valid but invalid CTAG relocation fails in the real CE/PS2 package transaction, restores B000, and supports same-process retry. Step 7 still needs explicit query/schema failure checks tying unchanged BSP bytes and CE globals to the failure seam. Reuse existing exact-state transaction snapshots when implementing that later slice rather than duplicating a second package loader or weakening the prepublication invariant.

Halo-64 is relevant only as a platform-boundary comparison: its port notes preserve CE CPU camera/frame/first-person/HUD state even when original rendering is absent ([`port/n64/NOTES.md:33-55`](../../submodules/halo-64/port/n64/NOTES.md#L33)). That supports testing CE's environment/location query in the game-owned layer, but does not provide fog/weather expected values, PS2 capacity assumptions, or authorization to copy N64 cuts. REA is not applicable: the test concerns current CE source over exact hash-bound retail package data rather than unexplained shipped-binary behavior.

**Acceptance boundary:** a passing test closes only the host CE `scenario_location_underwater()` unfogged-cluster/weather-palette branch for identified materialized retail BSPs. It does not qualify fog-plane selection, underwater fog definitions, sound environment/palette selection, wind/weather simulation, independent collision geometry, dynamic-object collision, EE capacity, PCSX2 gameplay, renderer output, or SPU2 playback.
