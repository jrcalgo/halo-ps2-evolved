# M2 candidate-map capacity audit

**Disposition: no stock campaign or multiplayer map is qualified to fit the current implementation.** The smallest useful stock multiplayer candidate is **Longest** (`levels\\test\\longest\\longest`): its retained CTAG image plus the materialized BSP image is **4,638,408 bytes**. Its CBSP envelope is a separate **377,388-byte streaming input**, not a persistent addition to `current_bsp`. These are only lower-bound map-residency figures; they exclude parent-renderer packs, temporary overlap, and other map working sets. More importantly, the active entry still binds a 2 MiB tag cache and preflight stages the entire CTAG payload in the 1.5 MiB streaming arena, so Longest cannot pass the current runtime path. Do not enable it or mark M2 capacity complete on this report.

## Scope, inputs, and method

The governing product scope is all thirteen stock CE multiplayer maps and all ten campaign missions, not a hand-picked reduced set ([`plans/5.hcu-remake.md`](../../plans/5.hcu-remake.md#L233)). I compared the pinned 24-map retail-cache audits and all-map CBSP catalog-package audit, then cross-checked the candidate’s exact scenario/BSP identity in the generated runtime catalog. The audit uses the exact retained CTAG image, not the compressed on-disk HP2 package size; BSP residency uses the CBSP section envelope and the corresponding raw source extent. A compressed package on DVD/USB is not the same as an in-RAM materialized tag/BSP image.

Evidence sources:

- [`retail-map-minimum-working-set-current.json`](retail-map-minimum-working-set-current.json): all 24 compact CTAG image sizes, BSP raw extents, and explicitly optimistic projection fields. The report itself excludes claims scratch, load-overlap/alignment, renderer packs, textures, audio, and streaming from its lower-bound totals ([report interpretation](retail-map-minimum-working-set-current.json#L1)).
- [`retail-ctag-compaction-a4-current.json`](retail-ctag-compaction-a4-current.json): per-map CTAG image and payload bytes, tag count, source hash, and CTAG hash.
- [`retail-cbsp-catalog-package-audit-current.json`](retail-cbsp-catalog-package-audit-current.json): all-map package hashes and aggregate CBSP/package sizes. It explicitly makes no runtime memory-fit claim.
- [`retail-bsp-cbsp-audit-current.json`](retail-bsp-cbsp-audit-current.json): individual materialized CBSP section envelopes and hashes.
- [`hcu_map_catalog.c`](../../src/stream/hcu_map_catalog.c): exact map leaf, scenario path, source extent, and `B000` BSP catalog. For Longest the exact row is `{2048, 374784, "B000", "levels\\test\\longest\\longest"}` and the map record pins its source length/hash.
- [`m2-step7-retail-cbsp-validation.md`](m2-step7-retail-cbsp-validation.md): precedent and limitations for the actual Blood Gulch CBSP; no second retail BSP has yet passed the PS2 C materializer plus CE verifier/query path.

The auditable stock-source pin for Longest is decompressed map SHA-256 `e045b0843f4a167a516f050161a651610fafc94ccc8c5f2c5d5725d108d5d1b9`; its compact CTAG hash is `0e3765ef7373951063a0fcbc1cb5f3922c060b64b093429a44afc4c4f38093ff`. The package audit records Longest HP2 size `2,039,808` bytes and hash `988672a19e7753c71c6c2ed9f0d1a9552ad6303418c8b87f14a3cd29ee5c6b3e`; this compressed file size must not be mistaken for its **4,263,624-byte** CTAG image or its BSP’s resident extent.

Longest has the smallest CTAG-plus-materialized-BSP residency subtotal among the stock multiplayer candidates audited here. Prisoner has the smallest CTAG image of this group, but its larger BSP makes the resident subtotal 487,416 bytes larger than Longest. For Longest, the separately staged CBSP envelope is 2,604 bytes larger than the BSP image it materializes to. The compact CTAG/materialized-BSP pairs for all thirteen multiplayer maps range from Longest’s **4,638,408** to Sidewinder’s **6,362,672** bytes; Sidewinder alone already exceeds the 6,291,456-byte `current_bsp` budget before alignment, renderer data, or load overlap. Longest is therefore the strongest *first target for measuring a corrected loader*, not a supported-map exception.

For campaign, `c20` is the smallest campaign CTAG image in the supplied audit at **6,267,540 bytes**. That is **23,916 bytes below** the entire 6,291,456-byte `current_bsp` region before allocating any BSP; the current single-span cache owner therefore leaves no viable space for even the smallest active BSP. Moving tag data into `resident_gameplay` would require an implemented split/multi-span tag-cache contract; the current binder binds one tag-cache span at the start of `current_bsp`, so this comparison is not permission to reassign that owner. The largest raw active BSP is `c20_3` at **9,039,872 bytes**, exceeding the full current-BSP arena by **2,748,416 bytes**. The report’s projected compressed-vertex candidate is arithmetic only and does not demonstrate an equivalent preserved CE BSP or a physical PS2 destination ([`retail-bsp-cbsp-audit-current.json`](retail-bsp-cbsp-audit-current.json); [`plans/5.hcu-remake.md`](../../plans/5.hcu-remake.md#L352)).

## Current-arena accounting and blockers

Budget-v2 assigns `resident_gameplay=6,815,744`, `current_bsp=6,291,456`, `streaming=1,572,864`, `texture_cache=4,194,304`, `dynamic_simulation=2,621,440`, `audio=524,288`, `frame_scratch=393,216`, and keeps a **5,767,168-byte** reserve untouched ([`config/memory-budget.json`](../../config/memory-budget.json#L7)). This is not a license to borrow from the reserve or to count the same storage twice.

1. **Tag-cache capacity:** the production `hcu_main.c` defaults `HALO_HCU_TAG_CACHE_BYTES` to **2,097,152** bytes ([`hcu_main.c`](../../src/stream/hcu_main.c#L16)). `hcu_memory_bind_parent_v2` reserves that tag cache at the start of `current_bsp` and gives the rest of that region to the active CE BSP ([`hcu_memory_bind.c`](../../src/stream/hcu_memory_bind.c#L41)). Every non-UI multiplayer CTAG image in the audited table is at least **4,241,088** bytes; Longest is **2,166,472 bytes above** the current tag-cache binding. The tag cache cannot currently hold it. The 2 MiB is a configured bootstrap limit, not measured spare capacity.
2. **Streaming/preflight capacity:** map preflight loads HMAP, the complete CTAG payload, CRNG, and CBIX into the same `streaming` arena before validating, then rewinds that arena ([`hcu_map_service.c`](../../src/stream/hcu_map_service.c#L200)). Longest’s CTAG section payload alone is **4,339,096 bytes**, which is **2,766,232 bytes larger** than the full 1,572,864-byte arena. It cannot pass current preflight even if its destination tag cache were enlarged. UI’s recorded 1,550,572-byte high-water is evidence for the UI package only and does not extrapolate to campaign or multiplayer.
3. **Validator claims:** the binder computes claims scratch from the sum of configured tag-cache and separate BSP address spans, then allocates it from `resident_gameplay` ([`hcu_memory_bind.c`](../../src/stream/hcu_memory_bind.c#L65), [`tag_validate.c`](../../submodules/halo-ce-universal/port/linux/game/tag_validate.c#L272)). Current guest accounting has 4,214,784 bytes already consumed by CE game state plus claims, leaving **2,600,960 bytes** of resident region. Claims must be recomputed if those spans change; they are not scratch that may be ignored or overlaid on tag data.
4. **CBSP/materialization and load overlap:** Longest’s source BSP is a 374,784-byte image and its validated CBSP envelope is 377,388 bytes. The post-materialization CTAG+BSP residency subtotal (4,638,408) fits numerically in `current_bsp`, with 1,653,048 bytes remaining. The CBSP envelope is streamed separately and materializes to the source-sized BSP; it is not a second persistent 377,388-byte charge in `current_bsp`. Neither arithmetic result proves safe allocation: the current entry still reserves only a 2 MiB tag cache, parent render/GS pack co-ownership has not been included for Longest, and the map transition/rollback path must account for the prior published map and all transient copies. The existing real CBSP report demonstrates the Blood Gulch bytes only; it explicitly says there is no physical placement, CE query parity, or whole-map qualification yet ([`m2-step7-retail-cbsp-validation.md`](m2-step7-retail-cbsp-validation.md#L1)).
5. **Renderer, texture, audio, and conversion staging:** the available all-map report excludes PS2 render packs, texture/audio working sets, validator scratch, alignment, and overlap. Exact Longest `BSP0`/`COLL` converted pack high-water and simultaneous texture/audio requirements are not present in the cited Longest package audit. This prevents the requested end-to-end all-arena assertion even after the tag/preflight capacity changes. The Blood Gulch parent pack figures cannot be substituted for Longest.
6. **Behavioral and map-load proof:** gameplay maps are deliberately rejected until M2 peak qualification completes ([`hcu_map_service.c`](../../src/stream/hcu_map_service.c#L177)). The current M2 guest run is UI-only and has interpreter/recompiler differences after the UI map-loaded marker; it does not verify Longest or another retail map. The product plan says no gameplay marker or M2 completion until a selected map’s actual measured bytes fit and the runtime map path passes ([`plans/7.hcu-remake-m2-m4.md`](../../plans/7.hcu-remake-m2-m4.md#L484)).

## Recommendation and exit criteria

Use **Longest** as the first test map after fixing the storage topology, because it has the smallest audited multiplayer retained-tag-plus-CBSP footprint, a single BSP, and a modest 377,388-byte CBSP envelope. This is a candidate selection for a future qualification run only. Do not call it a feasible supported map today: with current constants and code, CTAG exceeds both the 2 MiB destination binding and the entire streaming arena.

Before enabling even this candidate, require one versioned, source-backed allocation table with simultaneous peak accounting for: (a) CE game state and claims; (b) complete Longest CTAG image and all referenced resident tag extents; (c) Longest materialized CBSP plus parent BSP/render and collision packs; (d) HMAP/CTAG/CRNG/CBIX decode and verification staging; (e) texture/lightmap and audio staging; (f) old-map/new-map overlap and rollback; and (g) alignment, guards, and untouched reserve. Then implement the necessary bounded section-streaming/rebinding design without changing the budget silently, validate the real Longest CBSP through the PS2 C materializer and CE BSP verifier/query path, add failure/rollback/retry evidence, and run the exact current ELF in both PCSX2 modes. The `2 MiB` cache and `1.5 MiB` streaming blockers make M2 capacity an implementation gap, not something this arithmetic table can close.
