# M2 C2 guest evidence (lane guest, round 4), 2026-10-23

Status: **not passed.** The runner and its parser tests exist and run, but the full two-ELF guest run did not complete in this session, so no guest counter set is claimed here. C2.3, C2.6, C2.7 and C2.8 remain open for guest evidence.

## What was built

- `tools/c2_guest_run.py`: stages the gameplay ELF and the `--m2-ui-lifecycle-test` ELF into `build/m2-c2-r4-guest/elf/` (copies of the existing probe outputs; nothing was relinked), checks their sha256 prefixes, reads LOAD segments with `mips64r5900el-ps2-elf-readelf -lW`, runs each ELF in PCSX2 headless under Xvfb with a bounded timeout, saves every `HALO_PS2_LOCAL` line to `build/m2-c2-r4-guest/runs/<run>/halo_ps2_local.txt`, checks the required markers, and writes `build/m2-c2-r4-guest/manifest.json`.
- `tests/test_c2_guest_parse.py`: 6 host tests of the parsers (LOAD parsing, reserve comparison, timestamp stripping, marker detection, per-owner counters). `python3 -I tests/test_c2_guest_parse.py`: 6 run, OK.

## Launch facts (verified)

- PCSX2 starts headless as `pcsx2 -batch -nogui -datapath <dir> -logfile <file> -elf <elf>` under `Xvfb :99` (no display `:0` exists here; the earlier `xcb` harness failed with `could not connect to display :0.0`).
- PCSX2's `host:/` root is the **directory of the ELF**. The probe's `maps/` (in `build/hcu-parent-link-probe/maps`) must sit beside the ELF. Without it the guest logs `[err] asset root host:/ failed read-only maps/ui.map probe at stat`. The runner symlinks it into each run directory.
- The gameplay ELF (`5a59813c492a7efe…`) logs `HALO_PS2_LOCAL machine entry`, then `[err] ELF/boot backing exceeds EE fixed budget`, and stops. In the first probe it was the only HALO line. This is a guest failure, not a passing result.
- The lifecycle ELF (`15fcbf8d6b89e6e0…`) gets through memory layout, storage bind, asset probe, map preflight and `map-mount result=0 active=1` within about 40 s of emulated time in the probe (not in a harness-recorded run).

## Why the run is incomplete

- A full `c2_guest_run.py` run (two ELFs, 200 s each) was launched in the background. Its process restarted repeatedly during this session and had not produced `manifest.json` when this report was written. A foreground re-run was requested, and the permission system denied it. That denial was for stopping the running emulator and harness processes to restart them, which could interfere with other lanes' workloads. Nothing further was killed.
- Next step for whoever continues: once `build/m2-c2-r4-guest/manifest.json` exists, check each run's `markers` and `summary`, then replace this report's table with the harness output.
