# M2 multiplayer production-sized capacity host run — 2026-10-21

## Result

The retained native ILP32 host fixture passed for Longest and Blood Gulch, executing each map through the real CE scenario load/unload lifecycle twice. Both maps passed the source-derived collision tuple and full per-cluster PVS comparisons on every load. While each map was active, preflight rejected `a30` and the fixture verified that the active-map snapshot remained unchanged. The refreshed fixture models production’s bounded streaming partition: one 1,572,864-byte streaming region split into a disjoint 1,048,576-byte map-owner child and a 524,288-byte section-scratch child. Both maps fit those host-side limits. This is still host-only semantic/capacity evidence: it does not prove EE addresses, placement, or runtime high-water on PCSX2/hardware.

The fixture is useful evidence that these two concrete CE/BSP cases pass lifecycle and query checks under the harness allocations, and that this admission failure preserves the running map. It does not qualify the proposed split for PS2 placement, prove other maps fit, or pass the still-closed gameplay-map admission policy.

For each map load it asserts a structure collision hit and exact equality for surface index, material index/type, plane designator, start and hit leaf indices, and hit fraction within `0.0002`. It then queries every cluster, requires its self-visibility bit, and compares the complete PVS bit-vector to the source-derived golden ([collision and PVS assertions](../../tests/hcu_mp_capacity_main.c#L25)). This run specifically fixed a path-name mismatch exposed by canonical multiplayer scenario paths. CE’s retail cache header has a fixed 32-byte name field containing the pathless map leaf; the scenario request can be `levels\\test\\<map>\\<map>`. The HCU cache adapter now normalizes mount and match requests to the final path component before using that fixed-width cache name ([`ps2_cache.c`](../../submodules/halo-ce-universal/port/ps2/src/ps2_cache.c#L67), [`map_leaf` and `map_matches`](../../submodules/halo-ce-universal/port/ps2/src/ps2_cache.c#L103)). ## Evidence boundary and comparison

This is not a console execution. The executable is a native host ILP32 build with compatibility shims and generated golden headers; it does not execute on the EE, measure EE memory placement or high-water, exercise PCSX2, or establish visible gameplay/rendering. The source-loaded collision/PVS comparisons are useful semantic evidence for these maps. The array sizes and observed owner values describe the host harness, and its oversized scratch arena bypasses the production scratch limit; none of these results is an EE memory map proof.

Halo-64’s port can be cited only as an architectural comparison for explicit ownership, target adapters, and measured capacity discipline. Its N64 pool sizes and product-specific cuts do not corroborate these PS2 byte counts or replace EE evidence ([Halo-64 comparison report](halo64-hcu-adaptation-findings-2026-10-21.md)).
