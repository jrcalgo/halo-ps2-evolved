# M2 Step 7 — Full CE collision-wrapper feasibility

**Disposition: practical as an additive host ILP32 package probe; not a Step 8 or guest-capacity substitute.** The current transaction fixture already publishes a real package-backed BSP, links the actual CE scenario switch plus `collision_bsp.c` and `bsp2d.c`, and generates deterministic structure hits by crossing polygons in the relocated collision BSP. Extending it to call the public CE `collision_test_vector()` is a well-bounded next host test, provided the first version uses structure-only flags and a fail-closed adapter for the initial breakable-surface state. It would exercise important CE wrapper behavior not covered by the existing low-level primitive: CE global BSP resolution, structure-material mapping, leaf-to-cluster mapping, plane orientation, and `collision_result` construction.

This report is source/fixture analysis only. No implementation was changed and no new test was run.

## CE wrapper behavior and the smallest targetable slice

The public entry point is [`collision_test_vector(flags, point, vector, ignore_object_index, collision)`](../../submodules/halo-ce-universal/source/physics/collisions.h#L141), implemented at [`collisions.c:478-735`](../../submodules/halo-ce-universal/source/physics/collisions.c#L478). For a query with `_collision_test_structure_bit` set, and without media/object flags, the retained behavior is:

1. Initialize CE result type, start/end locations, and `t` to the no-hit defaults (`collisions.c:495-500`).
2. Resolve the active published structure BSP and collision BSP through CE's `global_structure_bsp_get()` and `global_collision_bsp_get()` (`collisions.c:502-535`). The transaction fixture's `scenario_switch_structure_bsp()` already publishes these same globals; the getters are real CE functions in [`scenario.c:444-458`](../../submodules/halo-ce-universal/source/scenario/scenario.c#L444).
3. Call real `collision_bsp_test_vector()` with the CE-derived facing/ignore flags, maximum breakable count, breakable-state bytes, and `REAL_MAX` (`collisions.c:519-537`).
4. On a surface hit, populate CE result type, `t`, oriented plane, material runtime type, surface and material indices, flags, and breakable index (`collisions.c:539-560`). The material type is read from the relocated `structure->collision_materials` by the actual private helper `collision_structure_material_type()` (`collisions.c:290-320`).
5. Map the first and last collision leaves to CE structure leaves/clusters using `collision_cluster_index_from_leaf()` (`collisions.c:563-577`, helper at `263-288`). This validates the cross-object relationship that the existing probe currently checks itself after receiving low-level leaf IDs.
6. Produce `collision->point` from the input segment and result `t`; the optional location-repair branch is not entered unless `_collision_test_try_to_keep_location_valid_bit` is requested (`collisions.c:692-720`).

The best initial flags are `_collision_test_structure_bit | _collision_test_front_facing_surfaces_bit` (plus a separate back-facing case if the selected fixture data supports it). Do **not** set `_collision_test_media_bit` or `_collision_test_objects_bit` in the first slice. This keeps the asserted target as the actual structure collision wrapper rather than accidentally broadening into fog/material-media, object pools, marker iteration, dynamic collision models, or vehicle physics. The code is still CE's production wrapper and the collision BSP is still the relocated package payload.

## Bounded link closure and adapter requirements

### Existing real components to retain

Keep the existing CE `scenario.c`, `collision_bsp.c`, and `bsp2d.c` objects; add CE `collisions.c`. Keep the package/mount/CBSP path and the current pointer-publication assertions unchanged. These provide the active `global_structure_bsp`, `global_collision_bsp`, and `global_bsp3d` set by the real scenario transaction (`scenario.c:1185-1197`), rather than test-local shadow objects.

The PS2 manifest includes CE source directories by default and does not exclude `source/physics/collisions.c`; its explicit `exclude_sources`/`exclude_dirs` are elsewhere in [`port/ps2/port.json`](../../submodules/halo-ce-universal/port/ps2/port.json). Thus this is already production gameplay code, not an N64-only algorithm to import.

### Required narrow fixture adapters

- **Breakable flags:** CE requests `MAXIMUM_BREAKABLE_SURFACES_PER_MAP` (256) and a pointer from `breakable_surface_flags_get()` (`collisions.c:528-535`; constant in `breakable_surfaces.h:25`). The true accessor in `breakable_surfaces.c:169-182` requires initialized game-state globals. For a fresh BSP switch with no gameplay ticks or damage, a narrowly documented test adapter returning 32 bytes of `0xFF` models CE's fresh-map “all still extant/not broken” state: `breakable_surface_extant()` treats a set bit as extant (`breakable_surfaces.c:185-198`), and the collision BSP skips a breakable surface only when its bit is clear (`collision_bsp.c:1404-1412`). The adapter must be immutable and fail if any test tries to damage/mutate it. Do not use this adapter to claim persistence or breakable-surface runtime behavior.
- **Collision logging/timing:** the current harness already defines no-op `collision_log_usage/start_time/end_time()` at `hcu_scenario_bsp_switch_main.c:879-887`; the vector query calls these around structure traversal (`collisions.c:526-580`). Keep them as instrumentation-only stubs, and assert the start/end calls balance if convenient.
- **Tag block access and `error()`**: existing scenario/package host shims already support the real CE tag blocks. Confirm from the new link map that any additional `tag_block_get_element_with_size`, `match_assert`, `error`, or C-series utility imports are backed by the same current shims or add explicit bounded ones. No shim may fabricate a collision hit, material, leaf, or BSP pointer.
- **Dynamic-object symbols:** even if runtime flags exclude objects, `collision_test_vector()` contains a conditional object path (`collisions.c:642-690`) and calls the static `object_test_vector()` (`collisions.c:1671-1770`), which in turn refers to object datum lookup, object sphere tests, model/vehicle collision, matrix transforms, and related services. Function-section GC will not remove code that remains referenced by the retained wrapper. The exact compile/link map must therefore be inspected after adding `collisions.c`. If the object branch makes the closure large, add only fail-closed test adapters for its unresolved object/dynamic entry points and assert the object flag remains clear and none are called. Do not add broad fake object gameplay. If clean-linking demands a sprawling set of stubs or replaces CE functions, defer the wrapper test and report that measured blocker rather than weakening the production path.
- **Media/fog symbols:** similarly, the wrapper has a conditional media/fog branch (`collisions.c:582-640`) that calls its private `collision_cluster_fog_plane()` helper (`collisions.c:322-396`). Keep media disabled and make any boundary adapters return “no media” only if actually reached; ideally instrument and fail if the media branch runs. Fog palette selection should remain out of scope for this structure-only slice.
- **Scenario location:** with a structure hit and no `try_to_keep_location_valid` flag, CE uses the leaf/cluster result from the BSP traversal and computes the point directly; it does not need the repair walk. The current real scenario object already provides global getters. Avoid a test-only reimplementation of `collision_test_vector()` or a shim for `scenario_location_from_point()` unless a dedicated miss case is intentionally run with no environment flags; the initial test can simply keep the structure flag set for both hit and miss.

The minimum link-closure qualification artifact should list every selected input object, `--gc-sections` kept section, undefined symbol resolved by an adapter, and runtime assertion that proves the adapter was not called. Compare the map against the current fixture map to quantify the actual wrapper cost. Report ELF/map hashes and keep the wrapper fixture's test-only stubs distinct from the production HCU closure ledger.

## Minimum useful cases and an oracle that is not circular

Use the existing geometry-based input search as a **candidate generator only**. It currently calls CE `collision_surface_polygon()` to get a polygon, computes its centroid and plane normal, and makes a segment from `center + 2n` to `center - 2n` (`hcu_scenario_bsp_switch_main.c:786-835`). That is suitable for finding a robust material-bearing sample, but the expected result should not simply be copied from CE's low-level result and re-labeled as the wrapper's golden.

For each package BSP that passes schema/transaction publication (both `a30` and `a50`, with successful return to B000), add the following first cases:

1. **Structure hit:** seed the `struct collision_result` with a poison byte pattern, invoke the public wrapper with structure-only/front-facing flags, and assert true plus `_collision_result_structure`; `t` is finite and in `[0,1]`; `point` is within an epsilon of `start + t * vector`; `surface_index` and `material_index` are in their source blocks; `material_type` equals the runtime physics material field for the source surface's material; `plane` is finite/in-bounds semantically and oriented consistently with the selected designator; and start/end leaf and cluster indices match the source-mapped CE result. Retain before/after snapshots of all relocated collision and material/PVS/sound bytes.
2. **Structure miss:** construct a segment outside a selected surface polygon but within a valid collision-BSP world path, or use a source-audited miss segment. Assert false, `type == NONE`, `t == 1`, `point == point0 + vector`, and no bogus material/surface/object outputs. Preserve the exact expected leaf/cluster defaults or values according to the actual `collision_bsp_test_vector()` leaf path; do not guess them—capture them from the independent source oracle.
3. **Facing-side case:** where the selected retail geometry permits it, query the same plane with front-only and back-only flags. Assert the expected hit/miss and oriented plane from the designator. This exercises CE's flag mapping (`collisions.c:514-524`) without turning the test into a complete surface-policy matrix.
4. **Query-state purity:** prove the wrapper does not mutate the published CBSP bytes, structure material table, cluster leaves, or transaction owner. The existing fixture already snapshots some PVS/sound bytes; expand to the exact regions the wrapper reads and to the global BSP pointers/index.

Use two layers for expected values:

- **Independent geometry oracle:** derive chosen candidate surface, vertex/plane/designator, expected source material and expected source leaf mapping from the decompressed retail map using the audited HCU schema/CBSP metadata before CE materialization. Bind each record to map SHA, HP2 SHA, CBIX section tag, raw CBSP SHA, and exact relocation output identity. The runner already validates package/source hashes and catalog entries before C runs (`test_hcu_scenario_bsp_switch.py:172-205`).
- **CE composition invariant:** optionally run the already-existing `collision_bsp_test_vector()` on exactly the same query alongside `collision_test_vector()`, then verify that wrapper `t`, surface/material IDs, facing-adjusted plane, and first/last leaf mapping are the documented CE transformation of that low-level record. This is valuable integration evidence but is **not** independent expected behavior because both values are produced by CE code over the same image. Keep the independent oracle as the acceptance source for literal expected tuples.

If the package-specific source parser cannot reliably produce independent exact intersection expectations without duplicating CE collision logic, the first acceptance can be deliberately narrower: static expected tuple rows captured once from the retail source package and reviewed against raw extents, with the derivation script and hashes checked in. Do not claim Halo CE binary parity from a tuple that was generated by the function being tested. REA is not currently needed: the question is a source-coded CE wrapper's behavior over source-backed package data, not an unexplained retail executable discrepancy.

## Feasibility versus Step 8

**Host-side wrapper qualification is practical before Step 8.** It uses the existing host ILP32 transaction with oversized test buffers and runs synchronously at BSP publication, so the new test can validate CE wrapper semantics without asserting any campaign map fits EE RAM. The collision wrapper is already present in the selected CE source closure and the production R5900 compile has separately demonstrated broad source compilation; a host test compile must still validate the exact retained closure and adapters.

**EE/PCSX2 execution is not practical to qualify until Step 8 resolves package capacity and ownership.** The audited a30/a50 arrays deliberately exceed the real `current_bsp` region; the Step 7 plan itself records the capacity blocker and prohibits promoting the package-host pass into target evidence. Do not copy the wrapper's collision data into a second pool, consume reserve, or run an over-capacity campaign map merely to get a guest collision marker. When Step 8 provides a measured topology, a target query can be a follow-up using the exact same known segment and expected tuple, with physical spans/canaries recorded.

## Comparison and recommendation

Halo-64 is only relevant at the boundary level: its [`port/n64/NOTES.md:33-55`](../../submodules/halo-64/port/n64/NOTES.md#L33) says CE CPU-side camera/frame/first-person/HUD state remains necessary even without its Xbox renderer. Its game code also calls CE `collision_test_vector()` directly (e.g. [`n64_golden.c:213`](../../submodules/halo-64/port/n64/game/n64_golden.c#L213)); that confirms the collision wrapper is simulation/gameplay, not drawing. It is not authority to copy N64 platform cuts or budgets.

**Recommendation:** add the structure-only full-wrapper hit + miss now as a separate host integration subcheck. Reuse the existing package transaction and query candidates, but add a reviewed source-backed expected tuple, an all-intact breakable-state adapter, an exact kept-section/link map audit, and fail-closed dynamic-object/media adapters. Keep object arbitration, fog/media, breakable mutations, target capacity, and guest execution explicitly open. This closes a real Step 7 integration gap without waiting for Step 8, while leaving Step 8 as a strict prerequisite for target/PCSX2 gameplay-map acceptance.
