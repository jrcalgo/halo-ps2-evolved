# C3 memory budget v6 (2026-10-29)

Budget v6 moves 2,097,152 bytes (2 MiB) from the uncommitted reserve to `texture_cache`. The user approved it for the frozen render-stall lineage on 2026-10-27 and, for the main lineage, on 2026-10-29 (a "smaller pool" for vehicles on screen, in place of the ~4.2 MB first proposed). The 32 MiB EE map remains 33,554,432 bytes.

## Owner chain

Same chain as [`m3-c3-budget-v5-2026-10-25.md`](m3-c3-budget-v5-2026-10-25.md), with +2,097,152 instead of +524,288:

1. `texture_cache` region row, 4,718,592 -> 6,815,744 (`mem.c`).
2. `MEM_LAYOUT_V2_BYTES`, 24,641,536 -> 26,738,688 (`mem.h`).
3. Every partition row's `render_texture_bytes` (28 rows, including the `bots_sidewinder` candidate and its fixture) += 2,097,152. The C3 row `bloodgulch_mounted_gunner_4p4bot`: 3,862,352 -> 5,959,504.
4. The C3 object model-cache arena is 4,169,088 bytes (was 2,071,936).

Physical layout: boot backing end (`HCU_RESERVE_START`) `0x01ae0000` -> `0x01ce0000`; untouched reserve `[0x01ce0000, 0x01f80000)`. The 1.5 MiB FX source pool (`hcu_main.c`, top of the reserve) is carved from this reserve and now leaves about 1.18 MB of it unclaimed before other fixed users; it was not previously formalised in a budget version.

## Measured status

The frozen lineage ran Blood Gulch with this layout (pool 4,169,088 B). Under it a spawned Warthog or eight armed bipeds still drove object-residency `pool_refusals`, so v6 alone does not qualify vehicles on screen. It is the pool the frozen measurements were taken with, not a vehicle sign-off. Nothing here is a console-qualification claim.
