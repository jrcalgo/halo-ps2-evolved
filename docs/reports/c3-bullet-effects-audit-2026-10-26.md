# C3 bullet effects and firing cost audit — 2026-10-26

## Finding

The current firing effect path is a useful bounded snapshot and GS submission path, but it is not yet a faithful CE effect renderer. In particular, all admitted kinds ultimately become a camera-facing colored quad (`hcu_render_fx_flat_colour`, `hcu_render_fx_build_quad` in `src/stream/hcu_render_objects.c`); texture resolution only supplies bitmap identities for particle systems, particles, contrails, and decals. CE `EFFECT` records have no direct bitmap identity in the iterator contract and therefore remain flat. This explains visual mismatch, but source inspection alone does not establish that it is the cause of the reported FPS drop.

## Source-backed path

1. `submodules/halo-ce-universal/port/ps2/src/ps2_render.c:767-900` copies five live streams—particle systems, live particles, contrails, effects, decals—into the snapshot, preserving datum index/generation, bitmap tag and element identity, owner, world position/forward, scale and age. The fixed table holds 64 records. Fair admission uses a quota pass and a fill pass; both call every stream iterator, so the five live arrays are traversed twice per published frame even when the table is already full. The iterator API says each iterator visits live datums in datum order (`port/ps2/include/halo_ps2_fx_iter.h`). This is the most specific source-level CPU-cost candidate during sustained firing: spawned particle/effect populations increase the work of these repeated walks. Instrument elapsed time and visits before changing the bounded fairness policy.
2. `hcu_render_effects_select` walks the snapshot list for each view, checks owner membership against that view's references, and selects at most 64 quads (half or quarter per viewport in split-screen). `fx_pass` constructs/clips each quad and budgets chain space before writing. Thus work is bounded on the EE, though per-view selection still scans the request list.
3. For each distinct bitmap bucket, `fx_pass` calls `fx_source` before `bsp_render_fx_texture`. `fx_source` performs profile lookup, chunk SHA-256 comparison, full chunk read into staging, `tex_open`, source-datum validation, and mip-0/CLUT extraction (`hcu_render_objects.c:1686-1708`). Only then does `bsp_render_fx_texture` call `tc_acquire` and discover a cache hit (`submodules/halo-ps2/engine/src/render/bsp_render.c:653-715`). Consequently cache hits still pay the profile read/hash and texture parse cost per bucket per rendered view/frame. This is a concrete avoidable CPU/IO candidate; cache presence currently avoids GS upload, not source loading. A safe minimal optimization is to expose a checked cache-hit fast path keyed by the already validated bitmap binding identity before reading the chunk, while preserving cache-key generation/digest validation on binding setup and invalidation.
4. Texture misses copy pixel and CLUT bytes into a fenced, fixed 32 KB-per-chain-parity upload ring. Cache admission, upload, and frame-chain use are fence-aware; do not remove or weaken those lifetime checks. Existing counters cover drawn/skipped/textured/flat/no-binding/budget/cache-full, but not iterator visits/time or source reads/time. `c3-fx` diagnostics print every 30 frames, reducing logging frequency but not measuring costs.

## Minimal faithful correction plan

- First record source-backed asset identity from retail tag data: effect tag index, event slot, particle-system tag, bitmap group tag index, bitmap element, bitmap dimensions/format, blend/flags, lifetime, and attachment/owner. Preserve tag identity in the snapshot; do not substitute renderer aliases or hard-coded bitmap IDs. Retail reference is `/home/ai/Documents/Halo/Halo - Combat Evolved.xiso.iso`; this audit did not make a new extraction or claim a specific muzzle/impact asset binding.
- Implement effect-event expansion using CE effect definitions and their particle blocks: spawn timing/age, event position/orientation, attachment transform and per-particle bitmap/material data. Render particles with their real bitmap and alpha/blend/depth behavior; retain decals as surface-aligned quads and contrails with their CE segment geometry. A single generic flat quad cannot express these semantics.
- Separate identity/resource resolution from per-frame bitmap byte reads. Decode and validate the exact bitmap once on a binding/cache miss; on a validated resident cache hit, bypass profile IO and `tex_open`. Preserve content hash, source-datum checks at binding construction, and the existing cache's fenced upload path.
- Keep the 64-record request cap and fair stream admission while measuring. If two full iterator passes are material, replace with a single bounded walk plus deferred per-stream cursors only after proving deterministic fairness and no CE mutation or dangling datum references across frames.

## Bounded private A/B probe

Use the existing private emulator run after it reaches Blood Gulch; do not send input to the user's desktop. Capture at least three 5-second windows each: idle, controlled automatic-fire at empty sky, and cooldown. Repeat in alternating baseline / candidate order. Keep camera, view count, resolution, map, weapon, and emulator core/clock fixed. Record private emulator frame-time percentiles and guest frame counter; never report those as hardware/PS2-native FPS.

Add temporary, bounded counters (no per-datum prints): total source iterator callbacks by stream and pass; snapshot publication elapsed ticks; selected requests by kind; per-bucket `fx_source` calls, bytes read, read/parse ticks; `bsp_render_fx_texture` hit/upload counts and ticks; `fx_pass` total ticks and submitted vertices/qwords. Emit one aggregate every 150 frames, then remove instrumentation or keep it behind the existing telemetry gate. Compare firing-minus-idle and cooldown-minus-idle deltas. If publication callbacks/time rise with shots, investigate the two-pass stream walks; if source bytes/time repeat with cache hits, validate the cached-source fast path; if neither rises, effects are correlated with firing but not shown to be the bottleneck. Preserve visual request counts and all existing skipped/deferred/cache counters in both arms.

## Evidence limits

This is source inspection, not runtime profiling. No FPS causation is claimed. It does not assert PS2-native performance, exact retail muzzle/impact bitmap bindings, particle shader/blend values, or successful end-to-end effect parity. Those require the exact retail tag/resource binding and a measured private A/B run. The render path's current `flat_colour` fallback and source-before-cache ordering are directly observable in checked-in code.
