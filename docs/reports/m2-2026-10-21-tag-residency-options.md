# M2 tag/BSP residency options — source-backed feasibility review

**Scope:** report-only investigation supporting Steps 8–9 of [plans/7.hcu-remake-m2-m4.md](../../plans/7.hcu-remake-m2-m4.md). This report does not alter code, memory limits, map coverage, tag schemas, collision ownership, or the 5.5 MiB reserve. It distinguishes a smaller encoded package from a smaller resident EE working set; only the latter solves the retail gameplay-map capacity problem.

## Executive finding

The current HCU/CE object model uses ordinary 32-bit pointers into a stable, relocated tag image and a stable, materialized active structure BSP. `tag_data_get_pointer` returns `data->address + offset` directly with no provider, page-fault, read, or pin operation ([tag_groups.c:91-114](../../submodules/halo-ce-universal/source/tag_files/tag_groups.c#L91)); `tag_block_get_element_fast` similarly returns `block->address + index * element_size` ([tag_groups.h:128-145](../../submodules/halo-ce-universal/source/tag_files/tag_groups.h#L128)). CE publishes the tag table only after reading the complete image, validating its header, and schema-walking it ([cache_files.c:1258-1310](../../submodules/halo-ce-universal/source/cache/cache_files.c#L1258)). BSP collision, visibility, scenario globals, and other systems then dereference pointers into that image/BSP during ticks: `scenario.c` installs `global_collision_bsp` from the active BSP tag block ([scenario.c:1172-1183](../../submodules/halo-ce-universal/source/scenario/scenario.c#L1172)), and visibility immediately traverses BSP3D ([structure_visibility.c:363-370](../../submodules/halo-ce-universal/source/structures/structure_visibility.c#L363)).

Consequences:

1. **Streaming decode is useful for staging but cannot shrink the intact CE image.** The HP2 visitor can stream decoded bytes to a sink with bounded codec work memory ([section.c:63-139](../../submodules/halo-ps2/engine/src/world/section.c#L63)); `world_load_section_with_scratch` still reserves the complete raw output ([section.c:141-190](../../submodules/halo-ps2/engine/src/world/section.c#L141)). CTAG must still be resident and stable under the current CE pointer contract.
2. **Current tag-data externalization is not a drop-in.** `animation_get_frame_data` returns a pointer into `tag_data.address`, and compressed readers also call `tag_data_get_pointer` directly ([model_animation_definitions.c:500-515](../../submodules/halo-ce-universal/source/models/model_animation_definitions.c#L500), [model_animations.c:2145-2185](../../submodules/halo-ce-universal/source/models/model_animations.c#L2145)). The animation feasibility report measures 12,590 records / 60.8 MB across maps and up to 4.97 MB in one campaign map, but lacks stable external IDs, lease lifetimes, concurrent-pin bounds, and I/O/tick evidence ([m2-animation-data-contract-feasibility.md:38-99](m2-animation-data-contract-feasibility.md#L38)). This is a possible HCU redesign, not an accepted M2 optimization.
3. **BSP data can only be reduced after proving it is renderer-owned or safely replaceable.** The PS2 cache hook already zeroes obsolete Xbox vertex/index buffer handles because HP2/VU packs feed the parent renderer ([ps2_cache.c:429-439](../../submodules/halo-ce-universal/port/ps2/src/ps2_cache.c#L429)). CE also consumes BSP lists for collision, collision materials, surfaces/materials, visibility, portals/PVS, pathfinding, sounds, weather/fog, and effects. A parent render pack does not replace those CE owners. Current CBSP handling reconstructs the full raw CE-format BSP in the separate BSP span ([ps2_cache.c:417-427](../../submodules/halo-ce-universal/port/ps2/src/ps2_cache.c#L417)).
4. **IOP RAM, GS local memory, SPU2 RAM, and removable/optical storage are not substitutes for arbitrary CE-readable tag pointers.** The ledger assigns GS eDRAM, IOP RAM and SPU2 RAM separate owners ([hcu-ps2-memory-map.json:101-105](../../config/hcu-ps2-memory-map.json#L101)); `current_bsp` is EE RAM ([memory-budget.json:8-20](../../config/memory-budget.json#L8)). A file-backed provider can be built, but requires access/lifetime redesign and cold/warm I/O measurement. Encoding bytes on disc or in an HP2 pack does not remove RAM required by a raw-pointer target.

The evidence rejects a small capacity tweak or “transparent” file-backed substitution as a credible completion path. Plausible no-loss directions are (a) finish single-destination section streaming to remove staging duplication, while proving a complete physically valid owner layout; (b) investigate a typed provider for selected large payload classes; and (c) audit a CE collision/render data split against every BSP consumer. None is currently proven to fit all campaign maps under the fixed PS2 budget.

## 1. Existing access contract and owners

### CE tag image

`struct tag_data` stores size, source offset, direct `address`, and schema definition; `struct tag_block` stores count and direct `address` ([tag_groups.h:64-126](../../submodules/halo-ce-universal/source/tag_files/tag_groups.h#L64)). Valid `tag_data_get_pointer` calls return pointer arithmetic, not an abstraction ([tag_groups.c:91-114](../../submodules/halo-ce-universal/source/tag_files/tag_groups.c#L91)); the fast block accessor does the same ([tag_groups.h:128-145](../../submodules/halo-ce-universal/source/tag_files/tag_groups.h#L128)). Any external storage design must preserve a stable CPU address for the whole use or replace all direct consumers.

CE reads `header.tag_data_size` into the tag-cache base, waits for completion, verifies tag/header pointers, schema-validates, and only then publishes `tag_header`, `global_tag_instances`, and `global_tag_count` ([cache_files.c:1258-1310](../../submodules/halo-ce-universal/source/cache/cache_files.c#L1258)). This atomic publication boundary is important: partial image contents are not a usable map. The PS2 CTAG path likewise materializes/rebases the whole image into the fixed tag-cache destination (`ps2_cache.c:405-415`; `ps2_ctag.c:148-180`).

### BSP image

CE validates scenario BSP extents against the BSP capacity and binds their load base to `physical_memory_get_structure_bsp_cache_base_address()` ([cache_files.c:486-532](../../submodules/halo-ce-universal/source/cache/cache_files.c#L486)). The load path waits and verifies the BSP header and internal pointers (`cache_files.c:1423-1455`). Scenario switching unloads the old BSP, loads/verifies a new one, can reload the old one on failure, then installs global BSP and collision pointers ([scenario.c:1120-1183](../../submodules/halo-ce-universal/source/scenario/scenario.c#L1120)). Single-active-BSP semantics help peak capacity but do not make active BSP demand-paged.

`structure_bsp` includes collision materials/BSP, nodes, leaves, surfaces, lightmaps, clusters, cluster/PVS data, portals, breakable surfaces, fog/weather, pathfinding, sound, markers, detail objects, decals and leaf maps ([structure_bsp_definitions.h:178-220](../../submodules/halo-ce-universal/source/structures/structure_bsp_definitions.h#L178)). `structure_bsp_port_verify` requires collision data and bounds cluster/surface/PVS/sound arrays ([structure_bsp_definitions.c:26-43](../../submodules/halo-ce-universal/source/structures/structure_bsp_definitions.c#L26)). BSP3D is used by visibility ([structure_visibility.c:363-370](../../submodules/halo-ce-universal/source/structures/structure_visibility.c#L363)) and physics callers including sphere/vector/pill queries (`source/physics/collisions.c:404-410, 507-530, 746-753`). Thus the complete CE BSP cannot be labelled render-only.

The PS2 BSP materializer validates relocation domains and cross-image strings, then creates CE-format data at the final BSP base ([ps2_cbsp.c:148-202](../../submodules/halo-ce-universal/port/ps2/src/ps2_cbsp.c#L148)). The PS2 cache adapter only removes Xbox vertex/index buffer counts/pointers ([ps2_cache.c:429-439](../../submodules/halo-ce-universal/port/ps2/src/ps2_cache.c#L429)). Separately, the PS2 renderer submits HP2/VU data through DMA ([bsp_render.c:747-769](../../submodules/halo-ps2/engine/src/render/bsp_render.c#L747)); it does not own CE gameplay collision.

### Streaming already present

`world_visit_section_reader_with_scratch` reads the HP2 header via a retained file handle, allocates bounded history/input/output buffers, streams decoded bytes to a sink, and releases scratch ([section.c:79-139](../../submodules/halo-ps2/engine/src/world/section.c#L79)). The streaming decoder validates output size and final section CRC ([hp2.c:251-354](../../submodules/halo-ps2/engine/src/stream/hp2.c#L251)). But `world_load_section_with_scratch` allocates the full raw section in the owner before decoding ([section.c:141-190](../../submodules/halo-ps2/engine/src/world/section.c#L141)). So streaming removes encoded staging duplication, not resident raw image size.

The current map service uses that full-output loader for CTAG/CRNG/CBIX/CBSP ([hcu_map_service.c:56-79](../../src/stream/hcu_map_service.c#L56)); `ctag_mount` retains CTAG/CRNG and loads encoded CBSP into scratch before materialization ([ctag_mount.c:67-104](../../src/stream/ctag_mount.c#L67)). This is a real staging/high-water opportunity, separate from the larger final tag+BSP capacity deficit.

## 2. Candidate alternatives: verdicts and required proof

| Candidate | Potential saving | Verdict | Required work / principal risk |
|---|---|---|---|
| Stream HP2 decode to final CTAG/BSP | Full decoded-section staging and duplicate package copies | **Feasible staging optimization; no reduction in final residency.** Existing visitor/decoder supports bounded sinks/CRC, but CE still requests a whole stable image. | Use an inactive destination/transaction so failure cannot corrupt the active map. Validate outer HP2 + inner CTAG/CBSP checks before publish. For CBSP either two-pass input (validate then materialize) or bounded relocation metadata; preserve cross-image string validation and CE BSP-switch rollback semantics. Compare exact output against current whole-buffer materializer. |
| Keep one contiguous CTAG image | Avoids redesign | **Required by current CE source contract.** Tag header, tag instances, block/data addresses and globals point into it until unload. | A segmented image is not an implementation shortcut. Replace pointer graph/API and every caller together before claiming externalized residency. |
| Transparent CTAG demand paging from DVD/USB/SMB/HDD | Avoid seldom-used pages in EE RAM | **Not transparent under current code.** Raw pointer loads do not invoke a provider; no PS2 CPU virtual-memory fault/file-page service is evidenced in this path. FileXio reads into caller-provided EE memory. | Either do a broad typed-handle redesign or a separate low-level R5900 TLB/exception architecture. Prove page alignment/address map, fault and interrupt safety, locked references, eviction/reentrancy, cache coherency, I/O blocking semantics and tick budget. Disc bytes are not CPU-addressable tag pointers. |
| Compact schema-recognized fields/padding | Eliminate gaps or unsupported data | **Potential representation change, unproven.** CE expects ABI structures and direct pointers. Current compact CTAG still occupies 4.24–11.78 MB across maps. Schema lower bounds omit opaque roots/names and do not constitute an accepted image. | Emit complete relocation/ownership manifest for all blocks, data, strings, refs, aliases and unknown fields. Preserve tag IDs and CE schema/HS/runtime behavior; compare all 24 retail maps. |
| Externalize selected tag-data, e.g. animation | Potentially several MB of image | **Possible only with HCU access/lifetime redesign; not drop-in.** Frame accessors return direct pointers; compressed paths bypass a single accessor; multi-pointer callers exist. | Typed stable IDs, acquire/pin/release scopes, a bounded cache, non-eviction during use, reentrancy, validator and error semantics, whole-consumer parity, and PS2 I/O/tick measurements. Keep `frame_info`, `default_data`, tag structs and all unaudited data resident. |
| Put tag payloads in GS eDRAM | Reclaim EE RAM | **Not a general CPU tag backing store.** GS is a separate 4 MiB local memory used for framebuffer/texture residency; CE needs CPU pointer loads. | Only render-consumed formats belong there under explicit DMA/GS transfer contracts; cannot impersonate a C pointer. Do not steal renderer texture capacity. |
| Put tags in IOP RAM | Reclaim EE RAM | **Not a direct-pointer backing store.** IOP is a separate CPU/address domain; storage RPC copies into EE buffers. | Metadata/service buffers may live there only with explicit IOP ownership; CE data still has to transfer to EE before dereference. Preserve OPL’s IOP stack. |
| Put samples in SPU2 RAM | Reclaim EE RAM | **Only sound playback payloads, not general tags.** SPU2 has its own 2 MiB playback owner; sound selection/tag logic remains CE EE state. | Audit conversion, voice lifetime, and EE staging separately; never count same sample in EE and SPU2 or treat SPU2 as general tag memory. |
| Externalize Xbox render buffers/use PS2 packs | Avoid unsupported Xbox rendering data | **Already partly implemented and valid.** Xbox vertex/index buffer handles are zeroed; parent HP2/VU renderer has its own geometry. This does not imply CE surface/cluster/collision lists are removable. | Consumer-classify every BSP field. Preserve CE gameplay/collision/material/visibility data and one CE collision authority. |
| Keep one BSP and stream encoded CBSP to its final base | Avoid encoded-envelope scratch and old/new BSP overlap | **Plausible and necessary for staging; does not reduce active raw BSP size.** CE loads one active BSP; parent unmount releases encoded CBSP. | Validate before overwriting active bytes if rollback requires the old BSP; test scenario switch/failure/retry, global-pointer invalidation, CRC and relocation semantics. |
| Split CE collision core from parent renderer representation | Reduce active BSP if truly duplicated render bytes are removable | **Most relevant BSP residency investigation, but not yet proven.** CE needs collision plus many gameplay-facing non-collision fields; parent render packs are separate. | Per-field and callsite inventory. Versioned sidecar preserving CE collision, PVS, portal, surface/material, pathfinding, audio/script/effect semantics; CE remains sole collision authority. Measure actual duplicate resident bytes and behavior parity. |
| Repartition named EE owners | Use slack in other regions | **Possible only after a complete physical ledger, not arithmetic.** Current BSP region is 6 MiB; texture, dynamic simulation, streaming, DMA, checkpoint/audio and kernel owners are already committed. Reserve is forbidden. | Version budget + allocator/link map + physical proof; charge all overlapping map-transition, CE state, renderer and I/O staging peaks. Do not call unused nominal capacity “free” without high-water evidence. |

## 3. PS2 storage and memory limits

`file_reader_read_at` validates bounds, seeks FileXio, and reads in bounded 256 KiB chunks into the caller’s buffer ([file.c:143-169](../../submodules/halo-ps2/engine/src/stream/file.c#L143)). It is a storage bridge, not a memory map. The current adapter can perform explicit resource reads outside the mounted tag-data/BSP extents through CRNG (`ps2_cache.c:449-455`); CRNG itself indexes sorted ranges disjoint from the whole tag-data interval ([ctag_resources.py:45-65](../../tools/ctag_resources.py#L45)). That path can support conventional texture/sound/resource read callsites, not arbitrary direct tag struct dereferences.

The EE budget fixes regions and reserves 5,767,168 bytes uncommitted ([memory-budget.json:8-20](../../config/memory-budget.json#L8)). GS/IOP/SPU2 are separately assigned hardware stores ([hcu-ps2-memory-map.json:101-105](../../config/hcu-ps2-memory-map.json#L101)). Do not count those as CPU-addressable EE pointers; do not claim texture cache as spare while PS2 renderer uses it; charge old/new maps, mounted sections and source buffers if simultaneously live; do not spend reserve; and do not duplicate collision ownership between CE and parent renderer.

## 4. Recommended evidence-led direction

### A. Remove avoidable staging duplication first

1. Keep stable whole CE pointers for the next experiment.
2. Stream CTAG/CRNG/CBIX/CBSP decode directly into final owner spans or bounded consumers. Retain only compact metadata that truly needs to survive mount; avoid retaining a full decoded CTAG package when its relocated image is separately resident.
3. For CBSP, maintain source and inner CRC, relocation order/domain, string-target validation, and atomic publication. Do not write an unvalidated candidate over active BSP bytes if CE rollback expects the old image. Measure all simultaneously live buffers.
4. Tests must distinguish encoded input, decoder workspace, retained index metadata, final CTAG, final active BSP, and transition/failure peaks.

This can remove accidental package/staging copies, but does not make a map fit when its intact final tag image + active raw BSP + indispensable owners exceed EE RAM.

### B. Investigate a lossless BSP representation split

Classify every structure-BSP field and every consumer as CE collision/physics-critical, CE gameplay non-collision (visibility/scripts/audio/damage/effects), PS2 parent renderer-only, unused Xbox buffer handle, or unknown/opaque. Only proven renderer-only/obsolete fields can move/elide; unknown remains. Compare actual raw duplicate bytes against parent HP2/VU pack data. Preserve all `structure_bsp_port_verify` constraints and keep CE the sole gameplay collision authority. Acceptance fixtures must cover rays/pills/spheres, material/surface IDs, damage, camera leaf/PVS, script triggers, sounds/footsteps, effects, BSP switching, and parent render.

### C. Treat typed external animation access as a redesign experiment, not a result

Add stable `(map source hash, tag datum, block element, field)` IDs and record every direct/indirect use before selecting a cache. Define a whole-animation decode lease with bounded pin lifetimes, since callers may hold multiple frame pointers. Test forced eviction, reentrancy, four-frame interpolation, multiple actors/players/first-person views, unload and failed read/retry. Measure cold/warm USB, SMB, HDD, ISO and optical I/O plus 30 Hz deadline misses on target. Keep the in-image provider as reference. A maximum-record-sized cache is not capacity proof.

## 5. Acceptance evidence still required

1. Regenerate the retail conversion/schema/BSP/animation/working-set reports against one retained schema ELF, maps, manifest and source hashes. `m2-next-capacity-design-review.md` notes a prior embedded-vs-current-path schema ELF mismatch; do not combine such runs.
2. Produce a complete field/callsite ownership map, including macros, generated schema, aliases and pointer lifetimes; source search is discovery rather than final proof.
3. Measure allocations simultaneously at boot, preflight, mount, tag publication, BSP load, active tick, BSP transition, map transition, failure/rollback/retry and unload. Account CE state/claims, resource tables, renderer packs, tags/BSP, caches, DMA, staging and stack once each.
4. Differential-test any alternate tag/BSP representation against CE validators and behavior fixtures for campaign and multiplayer maps. Never substitute renderer output or collision state for the other subsystem.
5. For data-provider redesigns, force exhaustion/eviction and all read/corruption/short-read/reload cases; prove no stale pointer or partially published map.
6. Obtain exact EE physical-placement/high-water and target I/O/per-tick latency evidence. PCSX2 wall time alone is not hardware qualification.
7. Load every supported map and BSP transition. UI-only or one small multiplayer smoke test is not full map acceptance.

## 6. Proposed test sequence

1. Freeze one package, retail source-map hashes, converter manifest, schema ELF, parent/HCU/halo-ps2 identities and memory profile.
2. Host-differential-test streaming CTAG/CBSP into final buffers against existing whole-buffer output; compare every relocation target. Inject short reads, bad outer/inner CRC, malformed relocation/domain/address, overlap, and failure at every decoder flush boundary.
3. Record map-owner and scratch high-water at preflight, post-mount, post-tag-publish, BSP load, active state, BSP switch, switch failure/rollback, map unload and retry. Verify tags remain unpublished until complete validation and staging is not retained accidentally.
4. Run every candidate BSP through `structure_bsp_port_verify`, collision/visibility/script/audio/material fixtures, and CE global-pointer checks. Test old-BSP restoration and no-BSP failure state.
5. Complete BSP field/callsite inventory; prototype alternate placement only for proven renderer-only bytes. Keep CE collision canonical and compare behavior before/after.
6. Separately prototype typed animation leases under host tests, instrument maximum simultaneous live records, then test all 24 maps and target cold/warm I/O before sizing a bounded cache.
7. Reconcile all bytes to physically disjoint eligible EE owners, preserve named hardware owners and untouched reserve. Reject designs whose final intact data cannot fit; do not convert compressed package size or lower-bound projections into an M2 pass.
8. Update Steps 8–9 with exact architecture, measured limits, rejected options, and remaining gaps. Streaming tests prove staging behavior only, not campaign fit or a rendered/playable map.

## Conclusion

Source evidence supports bounded package/decompression streaming and explicit external resource reads; neither changes the minimum EE-resident footprint of CE’s direct-pointer tag/BSP graphs. The strongest BSP investigation is to separate what the parent renderer already owns from what CE needs for collision/gameplay, then measure any duplicated resident bytes that can move without changing CE-visible behavior. Typed payload leases can be explored as an explicit HCU API redesign; they are not transparent paging and remain unproven until every consumer, lifetime, capacity and PS2 I/O stall is measured. Until a complete 32 MiB physical ledger and all supported maps fit, M2 capacity acceptance remains open.
