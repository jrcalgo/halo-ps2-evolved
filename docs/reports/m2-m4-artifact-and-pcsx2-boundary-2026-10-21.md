# M2–M4 artifact/runtime boundary review (2026-10-21)

## Findings

The PCSX2 “Please insert a PlayStation or PlayStation 2 format disc” screen is expected if the data-only ISO is selected as the boot disc. `tools/test_hcu_boot.py` launches the standalone ELF with PCSX2 `-elf` and supplies `build/hcu-m1-disc-data.iso` as a data argument; the recorded test explicitly has `boot_from_disc: false`. The data ISO SHA-256 is `79f2855a5953483637ca060e778589a9f8c54e5fc4cda4a69347f22484457d79`. It is not a PS2 bootable game disc.

An earlier guest run does establish a later boundary than the memory-ready smoke: the retained recompiler run `build/hcu-ps2-closure/emulator-m1-recompiler-33230a6978924fcca86118febd8b2329/result.json` binds its tested ELF SHA-256 `8d3c9aa1dba93b2ad77ef0b37b32ed39d4ad7ad3a33b634ab8521b19bb3ec222`, parent revision `70e2ed0cf2145a45d23aa07414a3a88c05155d4c`, HCU revision `6933490b2d16bb1c637295b6a0f3880ba23a7d56`, and halo-ps2 revision `71183bb0a9adc586cd267b2780c82bbc12cfd95b`. The guest log reaches `game-initialize-done` and `m2-ui-map-loaded`; it is a two-cycle UI map lifecycle test, not the current source image, a retail campaign map, or proof of scene rendering. The retained screenshot `build/hcu-ps2-closure/emulator-m1-recompiler-c3fe4c2843b146b786ee98eac2d55a10/pcsx2-render-clear-final.png` shows only the blue clear color and no rendered scene. So, for the current integration state, a full Halo scene is not expected in the PCSX2 window yet.

## REA scope and limitation

REA’s connected 6.5.0 server was queried before analysis. Opening the current combined ELF (`build/hcu-parent-link-probe/hcu-gameplay-machine.elf`, SHA-256 `289d47b1978f77e74c0894a876ecdbb05f4a6150fd56620e0115c3b8618373d4`) with Ghidra was rejected: the artifact is ELF32 little-endian MIPS/R5900, while the available REA Ghidra/Hopper profiles do not admit this MIPS variant. The session listed Ghidra 12.1.4 as available for supported targets; it did not claim a failed analysis of this ELF. The separate GNU objdump route did work. For the current ordinary ELF, complete symbol Evidence `ev_9f145a960d0c36fc4b7957067b96b32adba86704ba0eab304235a2c48aea578e` contains `render_frame` but no `video_init`, `video_present`, or `bsp_render_init`/`build`/`kick`. For the opt-in diagnostic ELF (`build/hcu-parent-link-probe/hcu-gameplay-machine-m3-render-clear.elf`, SHA-256 `01b65ade39b5e8ecbe48fc12ae58604e982632680f6911b5eeb0c239341f7b90`), complete symbol Evidence `ev_69ab9ef55eafc97852fcb34253060d314db751ec200037ade3ed7783a0a8c46b` adds `video_init` and `video_present`, while still lacking those BSP renderer entry points. The current ordinary ELF's complete section Evidence `ev_ef99ff778bacf515c3505358b65f1591c461cd392f8a219c925628dc6e85730b` reports `.text=0x18c1c0`, `.bss=0x20441c`; diagnostic section Evidence `ev_70b1ce599d16b124675068bb292d04087a17d1b466a35cd86b870389f999d0a1` reports `.text=0x18c778`, `.bss=0x20441c`. This confirms symbol-level distinction for the exact current ELF; it does not decompile MIPS or imply that the diagnostic is in the default production profile. REA `inspect_binary_layout` was unavailable because the connected Linux pwntools provider is not configured. REA does not accept ISO9660 as an ELF/native target, so no REA ISO inventory is claimed here. These are tool/architecture limitations, not implementation failures.

Independent, non-REA ELF inspection observed an ELF32 little-endian executable with entry `0x001010b0`, one LOAD segment beginning at `0x00100000`, `p_filesz=0x1fd804`, `p_memsz=0x401c9c`, and MIPS flags including `5900`/`mips3`. These structural facts do not establish runtime behavior. The current HCU-parent ELF hash above is not the tested guest ELF hash in the lifecycle result, so do not combine their measurements.

## Plan effect

- M2 remains open: the UI lifecycle boundary is useful integration evidence, but the current map admission gate remains UI-only and gameplay BSP loading/rendering is not qualified.
- M3 remains open: the PCSX2 capture is consistent with clear-only output; it does not satisfy a scene-render acceptance check.
- M4 remains open: the artifact inspection does not qualify combat behavior, performance, or weapon parity.
- Keep run identities separate. Re-run PCSX2 against the exact freshly linked ELF after any production-source change and bind the result to that ELF, assets, emulator, and settings hashes.
