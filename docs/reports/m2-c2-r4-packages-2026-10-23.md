The `ui` case passes through the same test. Return code 15 is `read_tags` failing after the deliberate
byte-corruption check, in the restored-file retry (`tests/hcu_profile_mount_main.c`, the `read_tags(&mount, 1)` call after
`restore_byte`).

## What was verified (gdb on the built fixture, pristine package copy)

- The lane's earlier diagnosis (raw read `rc=-1`, source span wrong) is not the current failure path. The owner read at
  `read_tags` takes the owner branch of `cache_file_read` with `offset == 0x26cc600`, `size == 6913928 == mounted image_size`,
  and passes the bounds check and `ps2_cache_bsp_readers_drained()` (returns 1).
- The CE visitor (`visit_ctag`) runs and calls `stream_chunk_pinned`. On the post-restore read that pinned stream returns 0,
  so `stream_ctag_for_read` returns 0 and the read returns NONE.
- The CE chunk length equals `52 + image_size + 4 * relocation_count` for both `ui` and sidewinder (7,045,744 B), so the
  sink's size check is not the failure.
- After the fixture finishes, the package copy is byte-identical to the pristine package (`cmp`), so the restore wrote the
  original byte.
- `ps2_cache_bsp_read_lease_acquire` has no caller on the mount path, so no BSP lease leaks from the fixture.
- `residency.count` is 0 at the point of the post-restore retry, which falsifies the hypothesis that a stale corrupt
  residency segment persists. The cause of the pinned-walk digest mismatch after restore is still unknown.
