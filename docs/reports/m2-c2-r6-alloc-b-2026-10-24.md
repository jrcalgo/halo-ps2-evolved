## Changes

1. `submodules/halo-ce-universal/source/hs/hs_compile.c`, `hs_compile_add_source`: a non-scenario compile (a console or cheat command) whose text fits `hs_compile_expression_scratch` (0x400 bytes, the buffer the expression path already uses) is compiled in that buffer. No heap block is made. Longer commands take a heap block marked `malloced`, which `hs_compile_dispose` frees. Before this change a non-scenario heap block was never freed (`hs_compile_dispose` freed `compiled_source` only in the scenario branch, and `malloced` was never set TRUE), so each console command that reached the heap leaked. Scenario compiles keep the heap as before.
2. `tools/audit_hcu_postload_allocations.py`: verdicts are keyed by (path, enclosing function, API), not by line, so a moved line does not unmatch a verdict. `merge_verdicts` reads `docs/reports/m2-c2-r6-alloc-a-verdicts.json` when present (absent is tolerated, malformed is refused). A row names a file and a function, optionally an API, and replaces the built-in rows of that file and function. The tool prints totals by verdict and the open count. Open means any verdict other than `load-only` and `unreachable-selected-build`, so a verdict string this tool does not know (for example `bounded-in-pool`) is counted as open.
3. `docs/reports/m2-c2-5-postload-allocation-source-inventory-2026-10-23.json`: regenerated with the tool.
4. `tests/test_hcu_c2_alloc_b.py`: 9 tests (verdict merge, precedence, unknown verdict counting, refusal of malformed input, the console scratch path in the source text, the malloced/dispose pairing, the inventory's lane-B rows).

No file in `game_state_xbox.c`, `files.c` or `hs.c` was changed. Their sites stay open (see below).
