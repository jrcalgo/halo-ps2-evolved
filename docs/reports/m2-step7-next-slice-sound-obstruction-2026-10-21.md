## Source-backed scope

CE’s public signature is `compute_sound_obstruction(short, struct sound_source *, real)` ([`game_sound.h:96-99`](../../submodules/halo-ce-universal/source/sound/game_sound.h#L96)); its implementation is [`game_sound.c:950-1049`](../../submodules/halo-ce-universal/source/sound/game_sound.c#L950). `struct sound_source` is private to that translation unit ([`game_sound.c:159-168`](../../submodules/halo-ce-universal/source/sound/game_sound.c#L159)) and has a CE compile-time size assertion of `0x40` bytes at lines 199-204. Therefore the test must not recreate that structure in the test main. A tiny test-only bridge TU can include the unchanged `game_sound.c`, construct an actual CE source, invoke the actual function, and return outputs; do not copy the algorithm or expose a production ABI solely for the test.

The function’s no-collision path is especially testable. It initializes `obstruction=0.6`, `occlusion=1.0`, then only reads the live BSP when both camera and source cluster indices are not `NONE` ([`game_sound.c:978-987`](../../submodules/halo-ce-universal/source/sound/game_sound.c#L978)). It gets encoded sound distance, maps low seven bits to `cluster_distance = value * 256/127`, and enters the PVS branch only if distance is strictly below 256 ([`game_sound.c:989-1003`](../../submodules/halo-ce-universal/source/sound/game_sound.c#L989)). A clear PVS bit leaves obstruction at 0.6 and computes occlusion as `PIN((1 - distance/(cluster_distance+distance))*1.4, 0, 1)` ([`game_sound.c:1029-1033`](../../submodules/halo-ce-universal/source/sound/game_sound.c#L1029)). By contrast, a set PVS bit invokes collision with structure, media, objects, scenery, and machines flags ([`game_sound.c:1004-1022`](../../submodules/halo-ce-universal/source/sound/game_sound.c#L1004)).

The existing fixture’s object-path adapters deliberately abort and its current collision-wrapper tests keep object/media flags clear ([`hcu_scenario_bsp_switch_main.c:173-207`](../../tests/hcu_scenario_bsp_switch_main.c#L173); [`m2-step7-full-ce-collision-wrapper-qualification-2026-10-21.md:17-22`](m2-step7-full-ce-collision-wrapper-qualification-2026-10-21.md#L17)). CE’s wrapper has an actual collideable-object traversal when those flags are active and BSP leaves are returned ([`collisions.c:642-690`](../../submodules/halo-ce-universal/source/physics/collisions.c#L642)). Thus a real visible-PVS `compute_sound_obstruction()` query is not currently a bounded real-collision test; do not remove those flags or relax fail-closed adapters to force one through.

## What this closes—and what stays open

If it passes, this slice adds actual CE `compute_sound_obstruction()` execution over relocated package data for defaults, unreachable attenuation data, and a reachable hidden-PVS pair. It closes the current direct-consumer gap for those branches, with independent source evidence for the sound byte and PVS. It does **not** execute the visible-PVS collision branch, verify geometric wall obstruction, test dynamic objects/media, validate sound palette/tag choice, produce audible output, qualify codec/voice/mixer behavior, or establish SPU2 parity. No sound output or device parity is implied. Step 7 still needs other consumers and failure-atomicity evidence; Step 8 remains the target-capacity dependency.

For visible-PVS policy alone, a future explicit interposition spy may assert CE forwards the exact endpoint and flag mask, but must be reported as a policy branch test, not a real collision/occlusion result. An end-to-end visible path requires a separately bounded, source-backed dynamic-object world; weakening flags or the current aborting stubs would invalidate the evidence. REA is not applicable to this source/data-path test. Halo-64 offers only the general comparison that CE CPU-side query/state remains distinct from replaced platform output; it does not justify N64 feature cuts or PS2 memory assumptions.
