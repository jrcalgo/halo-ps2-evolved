# Current CBSP direct-stream implementation audit (2026-10-21)

**Disposition:** the direct-to-fixed-BSP-destination path is implemented through the normal HCU map-service callback and is exercised end-to-end through that callback with the retail UI B000 HP2 section. Host evidence now includes a late *outer HP2 section CRC* failure after destination writes and a same-process retry that restores the full destination hash. Completion remains false on the failed read and is set true only after visitor completion, CBSP validation/rebase, and PS2 header normalization. This materially advances Step 9 beyond the earlier parser-only/synthetic-callback description.

It does **not** yet qualify Longest or a campaign map. The real CE `scenario_structure_bsp_load()` / `scenario_switch_structure_bsp()` fixture is a separate integration path and currently registers the legacy whole-payload `load_bsp_extent` callback; it does not register `ctag_mount_set_bsp_section_visitor()`. The new direct-stream service test calls the production HCU map service and production HCU `cache_file_read()` callback, but not the CE scenario transaction or CE global-publication code. Moreover, `hcu_map_service_preflight()` still rejects every map except `ui`, and current CTAG mount/preflight still materializes the full CTAG wire section into the 1.5 MiB streaming arena. The 4,477,120-byte tag / 1,814,336-byte BSP Longest split is an arithmetic/diagnostic candidate, not an enabled or loaded profile.

## Production callback path and publication boundary

1. `hcu_map_service_preflight()` currently admits only the `ui` entry ([`hcu_map_service.c:288-299`](../../src/stream/hcu_map_service.c#L288)). For an admitted entry, the loader mounts CTAG/CRNG/CBIX, then registers `visit_section()` as the BSP section visitor; successful registration disables the legacy whole-section BSP loader ([`hcu_map_service.c:145-157`](../../src/stream/hcu_map_service.c#L145), [`ctag_mount.c:332-352`](../../src/stream/ctag_mount.c#L332)). The exact source extent must be present in CBIX and must not overlap the CTAG tag extent or CRNG-authorized resources ([`ctag_mount.c:108-145`](../../src/stream/ctag_mount.c#L108)).
2. HCU `cache_file_read()` identifies the BSP request by `tag_index == NONE` and exact physical BSP destination, initializes the completion output to `_cache_file_read_failed`, and—when the visitor is installed—takes the visitor-only branch. It returns with the failure sentinel on any visitor/validation/rebase failure and changes it to `TRUE` only after `stream_cbsp_for_read()` returns success ([`ps2_cache.c:566-589`](../../submodules/halo-ce-universal/port/ps2/src/ps2_cache.c#L566)). This branch cannot fall through to legacy materialization after failure.
3. `visit_section()` calls `world_visit_section_with_scratch()` ([`hcu_map_service.c:98-120`](../../src/stream/hcu_map_service.c#L98)). That reader opens the HP2 path, parses its header/table, leases a 98,304-byte decode workspace, streams decompressed chunks to the sink, and returns `HP2_OK` only after decoded byte count and the outer section CRC pass ([`section.c:67-85,89-149`](../../submodules/halo-ps2/engine/src/world/section.c#L67), [`hp2.c:251-354`](../../submodules/halo-ps2/engine/src/stream/hp2.c#L251)). The visitor uses a newly opened path reader; it is not the retained `service->source.reader` used for resource reads/source hashing. The open/close pair is bounded and tested for the UI service, but the implementation does not pin the source descriptor/content identity across preflight and later BSP visitor open. A mutable/replaced package at the same path between those operations remains a source-identity/TOCTOU question.
4. `cbsp_stream_sink()` buffers the 36-byte CBSP header in stack state, then places image bytes at offset zero of the fixed BSP destination and relocation rows immediately after the image. Before copying image/row bytes it checks the declared image and row byte totals against destination capacity, with checked wide arithmetic ([`ps2_cache.c:390-497`](../../submodules/halo-ce-universal/port/ps2/src/ps2_cache.c#L390)). Longest B000's frozen sizes are 374,784-byte image and 214 rows = 2,568 row bytes; the staged destination footprint is therefore 377,352 bytes. Under the candidate 1,814,336-byte BSP span, this leaves 1,436,984 bytes. The 36-byte wire header is not stored in the destination.
5. Only after the HP2 visitor reports success does `ps2_cbsp_open_parts()` validate the split header/image/table, image CRC, exact source extent, row ordering/domains and unrelocated pointer values; `ps2_cbsp_rebase_in_place()` validates all cross-image strings and effective EE addresses before its first fixup write. The cache adapter then zeroes Xbox-only vertex/index-buffer count/pointer pairs and returns success ([`ps2_cache.c:500-563`](../../submodules/halo-ce-universal/port/ps2/src/ps2_cache.c#L500), [`ps2_cbsp.c:76-151,240-315`](../../submodules/halo-ce-universal/port/ps2/src/ps2_cbsp.c#L76)).
6. CE's actual BSP loader then checks the read completion flag and header/source-range invariants, runs `tag_validate_structure_bsp()`, and only after those gates sets `cache_file_globals.structure_bsp_header` and the tag-instance `base_address` ([`cache_files.c:1430-1513`](../../submodules/halo-ce-universal/source/cache/cache_files.c#L1430)). `scenario_switch_structure_bsp()` publishes the scenario/global BSP pointers and indices only after that load and `structure_bsp_port_verify()` succeed; on a failed candidate it clears globals, attempts to reload the old reference, and otherwise returns to menu ([`scenario.c:1088-1198`](../../submodules/halo-ce-universal/source/scenario/scenario.c#L1088)).

Thus the *production callback* has a clear unpublished staging rule and a sound sequential completion order. However, the host test that exercises the new direct callback does not execute steps 6 or 7. The separate real-CE switch integration test compiles `scenario.c` and CE's cache loader and covers CE publication/rollback, but it currently mounts with `ctag_mount_hp2_file_verified_discover_with_bsp_catalog()` and legacy `load_bsp_extent`; the test never calls `ctag_mount_set_bsp_section_visitor()` (see [`test_hcu_scenario_bsp_switch.py`](../../tests/test_hcu_scenario_bsp_switch.py) and [`hcu_scenario_bsp_switch_main.c:630-705`](../../tests/hcu_scenario_bsp_switch_main.c#L630)). The latest work therefore composes the production map service → HP2 visitor → HCU cache callback for UI, not the full CE scenario transaction with that new visitor.

## Failure flags, partial writes, and retry proof

The fixed BSP cache is a **candidate buffer**, not rollback-safe storage. The HP2 decoder flushes each completed output window to the sink before it checks the final outer CRC ([`hp2.c:207-229,347-354`](../../submodules/halo-ps2/engine/src/stream/hp2.c#L207)). Therefore a late I/O, sink, or outer-CRC failure can leave bytes changed in the final physical span. The adapter correctly keeps `_cache_file_read_failed`; an unchanged destination is not a valid assertion for such a late fault. The required safety property is that CE does not accept/publish the candidate and that a complete same-request retry rewrites all candidate bytes before success.

Current test evidence is stronger than the stale Step 9 prose in `plans/7.hcu-remake-m2-m4.md` lines 621–622:

- Synthetic adapter test [`ps2_cache_cbsp_main.c:223-259`](../../tests/ps2_cache_cbsp_main.c#L223) exercises fragmented callbacks, a late prefix failure (destination changes, completion remains failed), retry, full-transfer malformed relocation data, and retry. It validates cache-adapter semantics but uses a synthetic stream provider and manually models the caller contract.
- Production retail UI service test [`ctag_mount_main.c:687-723,724-750`](../../tests/ctag_mount_main.c#L687) first succeeds through actual HCU `cache_file_read()` + HCU map service/HP2 visitor. It injects EOF before sink output and confirms the destination hash is unchanged, no BSP lease/scratch is retained, completion is false, and retry passes. Then it flips a B000 payload byte while leaving HP2 section CRC unchanged; the visitor writes a prefix/full decoded candidate before the final outer CRC rejection. It confirms completion stays false, destination hash differs from the poisoned starting span, map/source/owner remain active, visitor scratch and BSP lease return to baseline, and an immediate retry restores the exact successful full-span hash. `tests/test_retail_ui_ctag_mount.py` drives this composed fixture.
- Command run during this audit:

The retry is valid because each successful visitor starts at decompressed offset zero, must consume exactly the declared raw envelope, and writes the entire declared CBSP image plus every declared row before validation/rebase; bytes from failed candidates are not reused as parse input. The tests hash the full host destination for the UI retry. The target-facing ABI still needs canaries around the real fixed BSP span and a guest transaction failure/retry trace before this is accepted as PS2 evidence.

## Scratch alignment and fixed-span arithmetic

The production map service uses a child `render_section_scratch` carved after two render-snapshot banks ([`hcu_main.c:331-354`](../../src/stream/hcu_main.c#L331)). The main plan's current memory budget gives 393,216 bytes for `frame_scratch`; the two banks occupy 268,992, leaving a 124,224-byte child arena (derivation and snapshot layout are recorded in [`m2-longest-streamed-live-set-reconciliation-2026-10-21.md:59-78`](m2-longest-streamed-live-set-reconciliation-2026-10-21.md#L59)). The HP2 visitor requests `64 KiB history + 16 KiB input + 16 KiB output = 98,304 bytes` with 64-byte alignment. If the child arena starts aligned and is idle at the synchronous cache callback, the visitor uses exactly 98,304 bytes, leaving 25,920 bytes; if its current cursor is not 64-byte aligned, at most 63 alignment bytes are additionally needed, leaving at least 25,857 bytes. The nominal arithmetic fits, but a production simultaneous-use assertion/high-water trace at the direct BSP callback has not been tied to the Longest span. The unrelated host CTAG composition fixture's 173,760-byte peak includes a 75,420-byte relocation allocation in the *same scratch arena*; that shape is not used by this CBSP callback because its 2,568-byte Longest relocation table is staged in the fixed BSP span.

The candidate Longest span arithmetic is:

| Span / content | Bytes | Evidence and status |
|---|---:|---|
| Fixed `current_bsp` combined owner | 6,291,456 | Existing budget cap; no budget increase proposed. |
| Candidate tag-cache partition | 4,477,120 | Fits Longest 4,263,624-byte compact CTAG image with 213,496 bytes left; not current default. |
| Candidate BSP partition | 1,814,336 | Fits 374,784-byte Longest B000 image and 2,568-byte table tail; 1,436,984 bytes remain after both. |
| CBSP streamed destination footprint | 377,352 | Image + relocation rows; CBSP's 36-byte fixed header is held on stack. |
| HP2 visitor child scratch | 98,304 + up to 63 alignment bytes | Fits 124,224-byte scratch child in arithmetic; actual Longest direct-callback high-water unmeasured. |

These arithmetic results say the individual B000 algorithm can fit those *candidate final spans*. They do not close the map: map preflight and mount still whole-load the Longest 4,339,096-byte CTAG wire section, plus 9,380-byte CRNG and 44-byte CBIX, in a 1,572,864-byte `streaming` arena ([`hcu_map_service.c:329-357`](../../src/stream/hcu_map_service.c#L329), [`ctag_mount.c:152-235`](../../src/stream/ctag_mount.c#L152), budget/reconciliation [`m2-longest-streamed-live-set-reconciliation-2026-10-21.md:38-58`](m2-longest-streamed-live-set-reconciliation-2026-10-21.md#L38)). The current explicit UI-only preflight rejects Longest before load ([`hcu_map_service.c:288-299`](../../src/stream/hcu_map_service.c#L288)). The candidate tag-cache split is also not the production default or an enabled catalog profile. Therefore no current host command can truthfully be called “Longest at fixed spans” through the new map-service/visitor path.

## Exact missing qualification slice

To graduate the direct CBSP path from UI implementation evidence to Longest production evidence, the next test must use the frozen Longest package and candidate fixed spans **without enabling normal gameplay admission**. It should:

1. Resolve the blocking CTAG policy first: bind stable candidate spans before CE initialization; provide a bounded CTAG path that leaves the full image at the fixed tag address and keeps the 75,420-byte relocation table, 9,380-byte CRNG, and 44-byte CBIX in explicitly owned disjoint storage; preserve the existing CE pointer/stable-address and untouched-reserve contract. The old whole-payload `ps2_ctag_materialize()` cannot be assumed to support source/destination aliasing.
2. Mount the exact Longest package and register the new visitor. Assert current fixed base/capacity identities for both tag and BSP; record package/source hashes; keep the normal catalog UI-only guard unchanged.
3. Route Longest `scenario_structure_bsp_load()` through CE `cache_file_read()` with the visitor actually installed, then run CE header verification, `tag_validate_structure_bsp()`, `scenario_switch_structure_bsp()`, and `structure_bsp_port_verify()`. Compare the full final BSP image (after documented Xbox vertex/index-array normalization) with the Python/legacy C oracle and assert CE globals/tag datum publish only after all checks.
4. Inject faults before first sink write, after image-prefix output, after complete image but partial relocation rows, HP2 outer CRC, CBSP inner CRC, bad final relocation/domain/string, target I/O EOF, CE schema rejection, and BSP-port verification rejection. For each, verify the completion sentinel and CE publication state, scratch/descriptor rollback, candidate-buffer semantics, and an immediate retry that fully overwrites and matches the oracle. Also cover switch failure restoring old BSP and the candidate+old-reload-failure safe-null/menu path.
5. Capture exact R5900 build/object/ELF and package hashes, direct visitor's target child-scratch high-water/alignment padding, fixed-span canaries, full candidate profile physical addresses, full map co-live budget, and PCSX2 interpreter/recompiler logs. No gameplay map marker should be emitted until CE scenario+BSP publication has completed.

The existing full CE switch fixture is a valuable oracle for steps 3–4, but currently uses the whole-payload BSP loader. Extend it (or create a distinct parallel fixture) to register the direct visitor and exercise a Longest package rather than relabeling existing legacy-path passes. The UI guest lifecycle run with three visitor traversals in both PCSX2 modes is useful callback-lifetime evidence for small UI B000 only; it does not close the Longest size boundary, target failure/retry, map support, or rendering. See the current guest trace recorded in [`plans/7.hcu-remake-m2-m4.md:605`](../../plans/7.hcu-remake-m2-m4.md#L605).
