# M2 CTAG streamed-consumer audit

Scope: report-only source audit of the current HCU CTAG lifecycle and a bounded design for a future streamed CTAG consumer. This does not qualify any fixed map span/capacity and does not recommend enabling campaign maps. Keep the current non-UI map rejection in place until physical capacity, end-to-end correctness, and M2 acceptance evidence are separately established.

## Findings at a glance

1. The present path is not streamed end-to-end. Parent map preflight loads decoded `HMAP`, `CTAG`, `CRNG`, and `CBIX` sections as whole buffers into the streaming arena; mount loads and retains the whole decoded CTAG payload and CRNG index. The generic HP2 visitor can emit bounded chunks, but it closes its reader after the call and is not wired into CE's tag read.
2. CE currently requires the complete relocated CTAG image at one stable, contiguous tag-cache base. The existing backend copies the whole image there, then fixes relocations. A future streamed consumer can avoid retaining the *encoded envelope* by streaming directly into that final span, but cannot claim to remove CE's resident tag-image requirement without a broad CE consumer redesign.
3. The tag-validation claim bitmap is also a material capacity consumer: its required address domain is tag-cache plus separate BSP-cache on PS2, one bit per byte, rounded to machine words. It must be measured and assigned an owner; no present arena size should be treated as qualified by this report.
4. There are two failure/lifecycle traps: `ps2_ctag_materialize` can leave a partially copied/patched destination on an address error; and normal scenario unload currently calls `ps2_cache_release_map_owner()` only under `HALO_PS2_M2_UI_LIFECYCLE_TEST`, not in the ordinary `HALO_PS2` build. A diagnostic lifecycle run therefore does not prove production teardown.
5. A safe single-span transaction has to distinguish package-mounted, tag-image-materialized, CE-tags-validated, and map-committed state. Before old-map teardown, preflight can validate package/source identity and stream-integrity checks without mutating the live tag cache. After teardown, the streamed finalization may fail; the correct invariant is a clean unpublished/empty map state followed by a leak-free retry, not preservation of the prior map unless a second full staging image is explicitly budgeted and measured.

## Current data and ownership path

### 1. Preflight stages whole sections

`hcu_map_service_preflight()` rejects every non-UI map as `capacity-not-qualified` before staging. For the UI map, it opens the raw `.map` source and takes a mark on `map_arena`, then calls `load_section()` for HMAP, CTAG, CRNG, and CBIX. It validates HMAP identity, CBIX, source length, CRNG extents, `ps2_ctag_open()`, and the source SHA-256, then releases the temporary arena mark. The source reader remains available for the later mount. See [`hcu_map_service.c`](../../src/stream/hcu_map_service.c#L202-L295).

`load_section()` delegates to `world_load_section_with_scratch()`, which returns a whole decoded raw section owned by the arena; it does not currently call `world_visit_section_with_scratch()`. See [`hcu_map_service.c`](../../src/stream/hcu_map_service.c#L28-L78). The generic visitor exists in halo-ps2 and uses bounded workspace, but its contract permits a sink to receive a prefix before a later decode/CRC error; the caller must not publish that prefix until success. See [`section.h`](../../submodules/halo-ps2/engine/src/world/section.h#L8-L19) and [`section.c`](../../submodules/halo-ps2/engine/src/world/section.c#L63-L131). The section visitor closes the HP2 reader before returning, so using it for a lazy future CE callback needs an explicit retained-reader API or a synchronous decode during the parent loader callback.

### 2. Mount retains encoded CTAG for the map lifetime

`ctag_mount_hp2_internal()` loads complete CTAG and CRNG sections into the owner arena, verifies transaction ownership, initializes the resource index, then passes the encoded CTAG payload to the backend mount callback. It records the arena mark and registers the mount only after the callback succeeds. See [`ctag_mount.c`](../../src/stream/ctag_mount.c#L112-L174). On failure it rolls back the mark. On unload it releases any mounted BSP, asks the backend to unmount before closing the source reader, then releases the owner mark and clears the mount record. This is a sound ownership order for a synchronous mount: [`ctag_mount.c`](../../src/stream/ctag_mount.c#L277-L290).

The generic world visitor's bounded decode is therefore only a decode primitive today, not a streamed CE tag consumer. The current mount still retains CTAG payload bytes and the CRNG resource index in the map owner. The parent raw `.map` reader is separate and serves the synthetic Xbox cache file's CRNG-authorized ranges.

### 3. CTAG validation and materialization are whole-buffer operations

`ps2_ctag_open()` validates the 52-byte CTAG v1 header, image and relocation extents, envelope reserved bytes, image CRC, CE tag signature/scenario index, tag table and required relocation records, then validates every relocation field/target. The returned `ps2_ctag_view` stores pointers into the original payload; its owner must keep those bytes live. See [`ps2_ctag.c`](../../submodules/halo-ce-universal/port/ps2/src/ps2_ctag.c#L64-L145) and the API/lifetime comments in [`ps2_ctag.h`](../../submodules/halo-ce-universal/port/ps2/include/ps2_ctag.h#L28-L35).

`ps2_ctag_materialize()` requires the complete image in the view, copies it to the fixed destination, and then applies relocation entries. If a relocation address overflows, it returns after destination bytes have already been copied and possibly some earlier fields patched. The caller must treat the destination as dirty and unpublished on every non-OK return; a retry must rewrite the full image before any CE pointer can observe it. The API comment also requires the destination not overlap the payload, but the implementation does not check overlap. See [`ps2_ctag.c`](../../submodules/halo-ce-universal/port/ps2/src/ps2_ctag.c#L148-L169).

The cache mount validates the envelope against `physical_memory_get_tag_cache_size()` and retains the view/payload. `cache_file_read()` recognizes one exact whole-tag request—`tag_index == NONE`, requested extent equals the complete image, destination equals the fixed tag-cache base—and only then calls `ps2_ctag_materialize()`. It sets completion TRUE only on success; other requests start and remain `_cache_file_read_failed`. See [`ps2_cache.c`](../../submodules/halo-ce-universal/port/ps2/src/ps2_cache.c#L114-L143) and [`ps2_cache.c`](../../submodules/halo-ce-universal/port/ps2/src/ps2_cache.c#L358-L428). The whole-image destination requirement is a current interface invariant, not a capacity qualification.

### 4. CE validates and publishes in distinct phases, but failure cleanup is incomplete

CE first checks the Xbox-style cache header. In particular, `cache_file_header_verify()` rejects a `tag_data_size` larger than the tag-cache capacity and validates the file offset/length arithmetic. Then `scenario_tags_load()` fills the tag span with `0xCD`, requests the entire tag region in one blocking `cache_file_read()`, waits while the completion flag is false, and requires its value to equal TRUE. It next verifies the tag header/table/buffers, then calls `tag_validate_tags()`. Only after both validation stages does it set `cache_file_globals.tag_header`, global tag instance/count pointers, register vertex/index buffers, and set `tags_loaded = TRUE`. See [`cache_files.c`](../../submodules/halo-ce-universal/source/cache/cache_files.c#L895-L960) and [`cache_files.c`](../../submodules/halo-ce-universal/source/cache/cache_files.c#L1214-L1373).

The completion contract must be preserved exactly for a stream implementation: zero means pending, TRUE means complete, and any other value must terminate as failure rather than being mistaken for success. The present synchronous adapter uses `_cache_file_read_failed` as the failure sentinel and CE checks `read_complete != TRUE`, which is safe even though the sentinel is nonzero. A stream adapter must either remain synchronous/blocking or provide a genuine completion transition; it must not leave the loop forever at false.

On tag-image read, tag-header verification, or schema-validation failure, `scenario_tags_load()` closes the cache file and returns NONE, but these branches do not explicitly call the parent owner release/unmount callback. Because the parent cache-mount predicate reports a mounted payload, it can still report the package mounted even though CE did not publish valid tags. Add one centralized abort/unmount transition for failed load; do not overload the existing “precache map loaded” meaning as “validated map committed.”

`tag_validate_tags()` claims ranges over the tag region and traverses/fixes schema-described values. The validator's PS2 claim address domain is `tag_cache_size + structure_bsp_cache_size`; storage is one bit per byte (`CLAIM_BITS = 32` bits per word), rounded up and multiplied by word size. It has a bind-before-first-use API and readiness check. See [`tag_validate.c`](../../submodules/halo-ce-universal/port/linux/game/tag_validate.c#L72-L78), [`tag_validate.c`](../../submodules/halo-ce-universal/port/linux/game/tag_validate.c#L244-L299), and [`tag_validate.c`](../../submodules/halo-ce-universal/port/linux/game/tag_validate.c#L1328-L1367). Reserve and measure this buffer separately; do not assume the bootstrap bitmap or an existing named arena is sufficient.

### 5. Production unload does not currently run the diagnostic owner-release callback

`scenario_unload()` clears scenario, BSP, and game globals. Its comment correctly says CTAG bytes should be released only after those references are unpublished. However, the `ps2_cache_release_map_owner()` invocation is nested under both `HALO_PS2` and `HALO_PS2_M2_UI_LIFECYCLE_TEST`; ordinary `HALO_PS2` builds skip the call. See [`scenario.c`](../../submodules/halo-ce-universal/source/scenario/scenario.c#L370-L410). The lifecycle diagnostic therefore verifies order only in the test-defined build, not normal production map unload. The production profile needs an unconditional PS2 teardown hook (with any trace/assert output conditional), or a separate production caller with equivalent guaranteed ordering.

The parent map service's `map_unloader()` releases the active mount (or closes an unmounted source), resets preflight state, and normally clears staged identity; shutdown calls it explicitly. See [`hcu_map_service.c`](../../src/stream/hcu_map_service.c#L157-L172) and [`hcu_map_service.c`](../../src/stream/hcu_map_service.c#L280-L309). `ctag_mount_unload()` correctly delegates backend unmount before releasing arena bytes. Those are valid primitives, but the production CE lifecycle must actually invoke them on normal unload and on post-mount load failure.

## Proposed bounded streamed CTAG design

### Design constraint: keep CE's stable final image

The smallest compatible change is to stream the CTAG envelope into the existing fixed tag-cache span, not to make every CE tag consumer stream. CE's cache header verifier, tag-header verifier, global tag pointers, schema validator, tag accessors, and loaded-tag callbacks all expect the complete image to remain at a stable address. Changing that would be a much wider CE memory and pointer-lifetime redesign. Thus “streamed CTAG” should mean bounded HP2 decoding and relocation into the final CE tag span while avoiding a whole encoded CTAG section allocation.

Do not choose or enlarge the tag span, streaming arena, scratch, BSP span, or claim bitmap from this report. Measure the exact current package, worst supported maps, decoded/final tag bytes, HP2 decoder scratch, CRNG index, validator claims, BSP peak, and alignment/canary overhead in the final machine ELF first. Keep maps disabled unless the measured physical working set and acceptance gates pass.

### Transaction states and visibility

Use explicit states owned by one map-service transaction, rather than treating the current `mounted_payload != NULL` boolean as a complete load state:

| State | Meaning | Public CE/game visibility |
|---|---|---|
| `EMPTY` | no source, no mount, no candidate image | no map |
| `PREFLIGHTED` | source/package identity and non-mutating metadata checks passed; old map may still be live | old map only |
| `MOUNTED_PENDING_TAGS` | CE has requested map cache; callbacks/source available; final tag span is not validated | no new scenario/render publication |
| `IMAGE_MATERIALIZED` | complete final-span bytes and relocations produced; stream/CTAG checks passed | still private to CE loader |
| `CE_TAGS_VALIDATED` | CE tag header and schema checks passed; tag globals may now be published | candidate scenario, but not yet a committed playable map |
| `MAP_COMMITTED` | scenario, selected BSP, and required map setup succeeded | normal game/render snapshot |
| `ABORTING` | failure cleanup is clearing CE references before parent frees backing | no candidate visibility |

Expose separate queries/operations for package availability and validated/committed map readiness. A cache `precache_map_loaded()` success must not be represented as proof that CE tag validation or scenario/BSP loading succeeded.

### Preflight, without corrupting the current map

1. Keep current preflight non-mutating with respect to the old map's final tag-cache bytes and existing mount owner. Verify map/catalog identity, raw file length/hash, HMAP/CRNG/CBIX extents, HP2 directory metadata, CTAG envelope size fields, and all capacity checks possible without touching the live tag span.
2. Convert HMAP/CRNG/CBIX handling to bounded visitors or bounded metadata readers where their schema supports it. Do not leave whole decoded sections on `map_arena` merely to obtain their first/last fields; retain only the parsed bounded index/identity records whose maximum sizes are source-format constraints and measured.
3. For CTAG, add a first pass that decodes to a validation sink while accumulating HP2 CRC and CTAG image CRC and checking envelope/header/table/relocation-list structure. It must not write the live final tag span while the old map is active. The generic visitor can report partial output then a late CRC failure, so its sink state stays private and is discarded unless the callback returns success.
4. A full “all relocation target values checked before unload” promise is not automatic: CTAG places relocation records after the image, but each record names a word in the earlier image. Either design a bounded second-pass validator that rereads the HP2 section to inspect named words, or explicitly document that target-value checks occur only during post-unload finalization. Do not retain an unbounded relocation list or a second full image without a measured arena budget.
5. For same-map reload, preserve the existing rule that no owner/source is overwritten during CE's preflight-before-unload stage and redo source/section verification after old ownership has been released. The current service already has a deferred reload guard and performs post-release preflight in `map_loader()`; retain and test this contract.

### Post-unload materialization and commit

1. After CE has unpublished and released the old map owner, open/retain the package reader needed for a **synchronous** CTAG visit. Keep raw `.map` source I/O separate from HP2 section input. If a lazy HP2 callback is chosen instead, introduce an explicit descriptor lease with close-on-all-paths and a documented limit within the fixed file descriptor table; the current visitor's open/close-per-call API cannot back later CE reads.
2. Stream the envelope header and image into the fixed final tag-cache span. Do not allocate a second image. Validate image size against the physically verified destination; compute image CRC incrementally. As relocation entries arrive after the image, validate ordering/alignment/bounds/required pointer slots and validate each target against the already materialized image before applying its absolute fixup. Check base+size and every absolute pointer for 32-bit overflow.
3. Do not publish `mounted tag ready`, CE tag globals, loaded flags, render snapshots, or map-committed state until the entire visitor returns success **and** the post-stream CTAG validation succeeds. On any HP2/CTAG/sink/relocation error, regard the destination as dirty; set it invalid, clear candidate status, close the HP2 lease, release temporary indices/scratch and parent owner, and leave CE globals null/unpublished. A subsequent retry rewrites the entire destination from byte zero.
4. Let the existing CE path run its header verifier and `tag_validate_tags()` over that complete final span. Keep the current order in which CE global tag pointers and `tags_loaded` are set only after both validations. Add a parent/adapter “CE tags validated” acknowledgment at this boundary, and do not call the full map committed until scenario setup, BSP reference/materialization/schema validation, and game load success have completed.
5. On tag-validation or subsequent scenario/BSP failure, run one abort routine that clears CE global tag/header/instance pointers and `tags_loaded`, deregisters any buffers or callbacks already registered, closes sound/texture/menu/mod/HUD tag caches opened for the candidate, then invokes parent backend unmount and arena release. Normal successful unload must do the same CE-unpublish-before-owner-release order in the production build, not only a diagnostic configuration.
6. If candidate materialization fails after the old map was unloaded, remain in `EMPTY`, not a half-mounted state. Unless a separately measured rollback image is introduced, do not promise the old map can be restored. Retry should execute from a clean service state with no open descriptor, arena mark drift, stale global pointer, cache “loaded” flag, or render-snapshot generation update.

### Boundedness and concurrency

- Decoder history/input/output buffers remain caller-owned and explicitly bounded; sink writes are sequential and may be partial before failure. Include their high-water and alignment in memory proof.
- The current halo-ps2 visitor uses static/shared section-header state and is documented non-reentrant. Keep map loading serialized or refactor that state to transaction-local storage before allowing concurrent map reads.
- A sink must reject writes beyond `image_size + envelope_header + relocation_bytes` with overflow-safe arithmetic. Verify monotonically increasing offsets and exact final byte count; no sparse/duplicate writes.
- Keep fixed tag-cache and BSP-cache payload ownership distinct. Validator claim storage spans both logical ranges and cannot overlap either payload or active DMA/render memory.
- Keep source descriptors stable only for the phase that requires them. Close the HP2 descriptor immediately after synchronous finalization; retain the raw map reader only while mounted CRNG data may service sound/bitmap/tag-resource file reads. Test descriptor counts return to baseline on every abort/retry.
- No heap allocation after map load. All scratch, parsed indices, callback state, and transaction records must be boot-arena-backed or static with audited single-owner semantics.

### Reference-vs-stream parity checks

For each accepted UI fixture and later individually qualified map, run the old whole-buffer parser/materializer and the streaming consumer against the same immutable CTAG bytes and same final base address. Require identical final tag image bytes, scenario index, tag-table entries, relocation outcomes, tag-validator result, and failure class for malformed variants. Keep golden input hashes, HP2 package hashes, final image hash, source pins, and ELF hash together. This is a parity test, not a substitute for a current PCSX2 guest boot/load trace.

## Suggested implementation/test ownership

1. **Format layer:** add stream-state parser/finalizer near `ps2_ctag.c` with explicit begin/chunk/end/abort APIs and no hidden allocations. Keep `ps2_ctag_open/materialize` as the reference implementation until byte-for-byte parity is established.
2. **HP2 layer:** expose a transaction-local reader/visitor that can feed CTAG output while preserving exact raw section bytes, CRC status, and offsets; handle callback prefix-on-error and reentrancy explicitly. Existing visitor tests should remain generic; CTAG integration tests should be separate.
3. **Parent map service:** replace whole CTAG section staging in preflight/mount only after stream preflight and post-unload finalization states are explicit. Preserve the raw map source reader and CRNG policy. Add a single rollback path that unwinds HP2 lease, parent source, arena marks, backend mount, and candidate status.
4. **CE cache adapter:** retain exact whole-image cache read semantics outwardly, but implement it as a blocking streamed decode into the requested final tag-cache base. Completion must become exactly TRUE only after full stream and all CTAG relocation checks; any failure must set a terminating non-TRUE result and invoke transaction abort.
5. **CE lifecycle:** remove the test-only guard from the production owner-release operation while keeping trace-only output conditional. Make tag-load failures call centralized candidate abort. Ensure scenario/BSP failures after tag publication use scenario unload/abort even if `game_globals->map_loaded` was never set.
6. **Capacity/qualification:** before enabling any map, reconcile actual physical destination capacity, decoder scratch, CRNG/CBIX metadata, validator claims bitmap, BSP materialization peak, source/cache descriptors, and all arena high-water/canary data in the exact production ELF/PCSX2 run. Current capacity rejection is correct until this is complete.

## Acceptance gate for a streamed CTAG consumer

Do not mark this work complete merely because HP2 chunk callbacks work or the UI diagnostic still mounts a package. Require: (a) no full decoded CTAG envelope retained at steady state, (b) full final CE tag image produced in the fixed destination with relocations matching the reference materializer, (c) exact CE completion/validation/publish semantics retained, (d) every fault row above terminates safely and retries without leaks, (e) production normal unload invokes CE-unpublish-before-parent-release, (f) measured high-water/physical placement for all needed state, and (g) exact rebuilt integrated ELF passes guest load and unload/reload traces. Until those gates and map-specific capacity evidence pass, keep non-UI map loading disabled.
