Date: 2026-10-21
Disposition: report-only audit of the remaining multiplayer structure-BSP field and consumer evidence. Step 7 remains partial. This report does not change implementation, admission policy, or the product scope.

## Executive finding

The member inventory is now substantially better than the older grouped consumer table suggests: [`m2-step7-bsp-member-ledger-2026-10-21.md`](m2-step7-bsp-member-ledger-2026-10-21.md#L15) enumerates the top-level `structure_bsp` members and nested schema records, including aliasing, opaque blocks, pointer domains, and the explicitly reset `leaf_map.bsp`. It is an ownership/preservation ledger, not a test-coverage ledger. The remaining gap is proving the important CE consumers against the **13 in-scope multiplayer maps**. The governing scope is multiplayer, co-op, and bots; campaign-only maps are not acceptance targets ([plan](../../plans/7.hcu-remake-m2-m4.md#L3), catalog list at [plan line 246](../../plans/7.hcu-remake-m2-m4.md#L246)).

Several excellent consumer tests use campaign `a30`/`a50` BSPs and should be retained as CE behavior evidence, but they do not establish multiplayer-data acceptance. The in-scope production-sized host fixture currently loads Longest and Blood Gulch only; it exercises collision and cluster PVS on both and player-PVS aggregation only on Blood Gulch ([`test_hcu_mp_capacity.py:32-38,69-75`](../../tests/test_hcu_mp_capacity.py#L32), [`hcu_mp_capacity_main.c:20-65`](../../tests/hcu_mp_capacity_main.c#L20)). Its later sound-environment selector test covers a fog-free listener on those same two maps. No single BSP payload family beyond the Xbox vertex/index-buffer header handles is proven safe to strip ([member ledger lines 132-146](m2-step7-bsp-member-ledger-2026-10-21.md#L132)).

## Fastest useful acceptance slices

1. **Add one valid MP fog-plane semantic case on Beavercreek.** Extend the existing package-backed CE fixture path and generated fog-golden path rather than inventing a parallel query. The existing CE fixture already calls the production region, underwater/weather fallback, and water-depth APIs against materialized BSPs ([`hcu_scenario_bsp_switch_main.c:1294-1402`](../../tests/hcu_scenario_bsp_switch_main.c#L1294)); `test_hcu_mp_capacity.py` already generates empty fog goldens at lines 136-143. Add the Beavercreek package/source tuple and assert raw-derived region, plane, weather fallback, fog tag, two signed plane-side results, water-depth result, immutable BSP/publication state, and in-owner reads. First validate current package/source hashes and actual fit against the fixture limits. This would create the first direct fog/location/weather consumer evidence on an in-scope map without requiring a guessed result.
2. **Use the same slice for Chillout and Damnation after Beavercreek.** Both have one raw-derived valid chain with the same broad branch shape; first check their exact package provenance and whether they pass existing candidate array/claims limits. A compact case table over these three maps provides product data diversity, while negative/default cases remain necessary for maps with no candidate.
3. **Add a cheap all-13 structural census to the existing MP source inventory.** `test_hcu_mp_capacity.py` already walks all 13 source maps for sound-environment candidates and records BSP counts/source hashes ([lines 81-105](../../tests/test_hcu_mp_capacity.py#L81)). Extend that generated inventory to count and range-check collision materials, cluster PVS/sound bytes, fog/weather blocks and indices, sound palettes, portals/surface references, pathfinding, and detail/decal blocks. This is not a CE behavior test, but it quickly identifies map-specific/default branches and catches product-scope omissions before building more packages.
4. **Then add branch coverage, not redundant happy paths.** For sound, the next useful case is multi-listener priority/tie and a fog-over-cluster/water-boundary selector on an MP package; CE's comparison uses strict `>` priority in [`scenario.c:1359-1405`](../../submodules/halo-ce-universal/source/scenario/scenario.c#L1359), so order/tie expectations must be explicit. For BSP gameplay, add a raw-derived miss/reverse-face or swept-pill case to Blood Gulch/another MP map; one direct hit per Longest/Blood Gulch is narrow geometry coverage.
5. **Keep `scenario_fog_at_point()` separate and blocked.** The raw BSP census above enables CE fog-region queries but cannot recover the viewer-to-target attenuation formula. The plan explicitly disallows an inferred formula because both CE and Halo-64 are zero stubs; controlled retail CE output/disassembly is still required before a correct bot-perception implementation can be accepted.
6. **Treat visibility/material/lighting as the next larger CPU-consumer slice.** Derive a stable surface identity map between CE source `surfaces`/`surface_references` and the matching PS2 HP2 pack; then run real CE visibility/material preparation and assert source surface IDs, material intervals, triangle vertex indices, portal/PVS decisions, and any transformed payload reads. No current test gives this parity or authorizes compressed-vertex/lightmap removal.

After semantic host subchecks, Step 8 must still qualify all 13 multiplayer maps' simultaneous owners, especially Sidewinder. The current scope-filtered lower-bound report records Sidewinder CTAG + raw BSP at 6,362,672 bytes, 71,216 above the current combined tag+BSP span before other owners ([plan line 246](../../plans/7.hcu-remake-m2-m4.md#L246)); the projected compressed-vertex number is not approved without the field/consumer parity above. Target consumer queries remain downstream of a lawful complete capacity design and exact guest map-load trace.

## Halo-64 comparison and disposition

Halo-64 is useful as a method comparator for keeping CPU frame/camera/frustum/first-person/HUD state alive when the drawing backend changes, and it retains geometry sampling for unit illumination ([`port/n64/NOTES.md:33-62`](../../submodules/halo-64/port/n64/NOTES.md#L33)). This supports keeping CE BSP CPU consumers and lighting queries in the inventory even with the Xbox draw backend excluded. It does not establish PS2 semantics, map capacity, or permission to copy N64 feature cuts. The original CE source and raw multiplayer maps remain the behavior inputs; the fog-attenuation exception is blocked specifically because both inspected source trees contain the same stub.
