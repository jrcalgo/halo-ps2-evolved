The load map’s largest source-level contributors include the `ps2_platform.o` generated platform implementation (10,896 bytes of `.text`/`.rodata`/`.data`), `ps2_edge.o` (10,164 bytes), and `ps2_abi.o` (7,808 bytes). The final HCU `rooted.o` contribution is 6,885 bytes. Runtime ABI smoke code is not dead baggage: `ps2_abi_check()` exercises representative tag/datum/weapon/projectile layouts at `submodules/halo-ce-universal/port/ps2/src/ps2_abi.c:85-147`, and parent startup calls it at `src/stream/hcu_main.c:228-233`. If refactoring it for code size, preserve every checked field and target load/store coverage, then rerun both host and R5900 ABI checks and boot tests. Do not simply delete it.

The lifecycle runner itself is 972 bytes in the linked symbol table (`hcu_m2_ui_lifecycle_test_run`); the parent map service fault helpers are small. They are necessary evidence for this profile, so removing the diagnostic path would violate the requested acceptance. The data suggests a narrow optimization/refactor should be feasible, but the source/map audit has not yet established a safe 4–20 KiB saving.

Do not cut required HCU/gameplay, AI, effects, sound-selection, platform, or render-state owners to hit the number. The ELF includes a broad CE source closure; `plans/5.hcu-remake.md` and the M0 owner audit remain authoritative for what may be excluded. In particular, the provisional region ledger keeps all CRT, libc, SDK, and platform globals in `resident_gameplay` (`config/hcu-ps2-memory-map.json:1-35,60-70`); those costs cannot be hidden by assigning them to the kernel.

## Recommended search order (no gate relaxation)

1. **Perform source-level size analysis on only large retained owners.** Generate `nm -S --size-sort` reports for the exact lifecycle ELF; inspect `ps2_abi_check`, `ps2_platform`, `ps2_edge`, and retained libc entry points against the rooted call-site report. Refactor duplicated checks/log formatting only where exact behavioral checks remain. Do not replace validated CE layouts or alter ownership semantics.
2. **Test compiler size options in isolated build directories.** `-Os` versus `-Oz` has already failed to shrink this exact profile. Next compare narrowly scoped `-fno-ipa-cp-clone`, a conservative inline limit, and `-fomit-frame-pointer` only after querying the compiler’s effective current defaults. These are candidates, not known wins; measure PT_LOAD and cycle/frame cost. Avoid `-mips16` (EE instruction-mode/ABI risk), `-mabi=32`/O32 (changes call ABI and structure/calling assumptions), and unmeasured floating-point substitutions.
3. **Evaluate LTO only as a separate experiment.** It may reduce cross-object duplication but can change inlining, code size, and hot-path performance. Apply consistently to the HCU closure and parent objects, keep the same `-mabi=n32` and data-layout flags, check all unresolved symbols/relocations and exact layout assertions, then run the complete UI lifecycle test. Do not accept on ELF size alone; compare EE cycle profiles and verify behavior.
4. **Recompute the *exact* current image’s budgets before PCSX2.** Require no allocated PT_LOAD byte beyond `elf_static`, non-overlap with all arena intervals, and positive reserve headroom after all known guards and allocation metadata. Verify `unassigned_owners=[]`, no undefined imports, and that the lifecycle fault/retry symbols and logs remain present. If the minimum placement proof is still negative or guest allocator placement is unobserved, do not launch it as a Step 2 acceptance image.
5. **Only after the fit gate passes, run the same ELF hash in PCSX2 interpreter and recompiler.** Capture the lifecycle refusal-preserves-owner, injected post-unload failure leaves safe-empty, retry restores UI state, and repeated unload/reload assertions. The exact hash and pins must be recorded in both run reports; then update the M2 Step 2 row to complete. This report does not complete the step.
