# M2 animation trace context implementation

## Result and scope

The opt-in M2 animation observer now attaches a bounded, fixed-width identity snapshot to each recorded byte-touch event. The event itself remains 24 bytes on R5900; its former phase slot is now an explicitly named `context_token`. A token is one-based and indexes the context row at `token - 1`; zero means that the event has no installed caller context. Context rows contain map epoch, datum, simulation tick, render frame, graph, animation, frame, owner/local-player index, phase, and a validity mask. Missing values are not inferred from pointers and are valid only when their corresponding mask bit is set. See [`ps2_animation_trace.h`](../../submodules/halo-ce-universal/port/ps2/include/ps2_animation_trace.h) and the recorder implementation in [`ps2_animation_trace.c`](../../submodules/halo-ce-universal/port/ps2/src/ps2_animation_trace.c).

The context array is caller-owned, fixed-capacity, and allocated only for `HALO_PS2_M2_ANIMATION_TRACE` from `resident_gameplay`, alongside the pre-existing event buffer in [`hcu_main.c`](../../src/stream/hcu_main.c#L286-L317). At 4,096 records this adds 114,688 bytes (28 bytes per context row) to the existing 98,304-byte event array. It does not borrow dynamic simulation, frame scratch, streaming, audio, or reserve. The PS2 manifest already includes the recorder source; without the trace define the implementation remains inert.

## Context actually populated

- `object_compute_node_matrices()` installs object-datum and `object_pose` context for the function. Around its primary selected-animation read it additionally installs graph index, animation index, and computed frame index. The context is restored after the call and at the single function exit.
- `unit_preprocess_node_orientations()` installs the unit datum, graph index, and `unit_pose`. Action, overlay-action, soft-ping, emotion, mouth-aperture, acceleration, aiming-screen, and looking-screen applications now push their selected animation index. Discrete frame indices are recorded exactly; aiming/looking and continuous acceleration explicitly clear frame validity because their helpers may read/interpolate multiple frames.
- `first_person_weapon_build_node_matrices()` installs local-player owner index and `first_person_pose`; once a weapon is available it adds the weapon datum and first-person graph. State animation and current frame are set around the first orientation decode, and adjacent interpolation decode carries the same animation index and next frame. Firing, moving, and jitter animation applications also carry selected animation identity. The directional camera-motion overlay block is scoped once by overlay animation with frame validity unset, because its selected directional frame varies by motion input.
- Map epoch, monotonic trace tick, and CE render frame are now populated independently at their owners: successful parent map mount and unload boundaries call `ps2_animation_trace_map_epoch_advance()` in [`hcu_map_service.c`](../../src/stream/hcu_map_service.c#L135-L218); `game_tick()` advances after CE's active-game assertion ([`game.c`](../../submodules/halo-ce-universal/source/game/game.c#L334-L356)); and the PS2 frame clock copies `render.frame_index` immediately after increment ([`ps2_render.c`](../../submodules/halo-ce-universal/port/ps2/src/ps2_render.c#L91-L110)). These clocks are separate: render may advance on a different schedule than simulation tick, and map epoch does not imply that a gameplay map was successfully exercised by the observer.

The map-epoch hooks now have a real CE lifecycle fixture, not only source checks. [`hcu_ce_map_lifecycle_main.c`](../../tests/hcu_ce_map_lifecycle_main.c) links the production `hcu_map_service.c`, CE `scenario_load()`/`scenario_unload()`, and the trace recorder; it samples epoch from recorded sidecar rows through a test event. The instrumentation is guarded by `HALO_PS2_M2_ANIMATION_TRACE`; no gameplay state, random state, pose math, or rendering behavior is changed by the hooks. The low-level reader still reports conservative spans for compressed containers rather than exact decoder dereferences, and a context reports caller identity, not a data lease or live-memory pin.

Halo-64 remains a useful design comparison at the same seam: [`n64_anim.c`](../../submodules/halo-64/port/n64/src/n64_anim.c#L22-L40) moves graph payloads to ROM files and keeps 16 × 4 KiB chunks, while its comments explicitly tie that cache reservation to the N64's 8 MiB memory pressure. That is evidence that animation locality matters, not a PS2 cache size/policy: this PS2 trace keeps CE tag pointers and animation behavior untouched, charges its diagnostic sidecar to `resident_gameplay`, and earns no capacity credit until full gameplay live-set and parity evidence exists.

## Bounds and failure behavior

`ps2_animation_trace_bind()` and `ps2_animation_trace_bind_contexts()` reject null, zero, misaligned, overlarge, address-wrapping, duplicate, mismatched-capacity, and overlapping buffers. Both capacities must match and are capped at `SHRT_MAX`, because positive signed-short tokens address context rows. `ps2_animation_trace_valid()` is false until both stores are bound and remains false after any event/context-capacity failure; dropped counters saturate instead of wrapping. Recording performs no allocation or I/O. Reset clears active context/counters but does not unbind storage. The diagnostic closure roots both bind functions explicitly so the parent entry's calls survive the HCU rooted partial link (`tools/hcu_ps2_closure.py`).

## Versioned capture stream and offline decoder

`ps2_animation_trace_export()` now provides a synchronous sink-based export without allocating a second capture-sized buffer. It refuses a missing sink, unbound storage, dropped events, malformed event-site/admission/range/token values, or a token row that lacks an installed context. The caller must quiesce recording during export. A sink failure can leave a prefix at the sink; that prefix is deliberately unusable because the decoder requires the complete declared length.

The `H2ANIMT1` v1 stream is explicitly little-endian: a 28-byte header (magic, version, header/event/context sizes, count, dropped count, payload CRC-32), followed by one 24-byte event and one 28-byte context row per event. Event pointers are exported as 32-bit guest addresses, not host pointers. A zero-token event receives an all-zero context row so no uninitialized sidecar bytes leak. The decoder in [`decode_ps2_animation_trace.py`](../../tools/decode_ps2_animation_trace.py) imposes a 32,767-row / 1,703,912-byte maximum, validates exact length, CRC, supported layout, no drops, site/admission/range fields, token bounds, validity-mask bits, reserved bytes, and token-to-installed-context consistency. It requires a provenance JSON with parent/HCU/halo-ps2 commit IDs, source-manifest SHA-256, build profile, toolchain identifier, and ELF SHA-256; it hashes the supplied ELF and rejects any mismatch before decoding. It treats guest addresses as opaque identities and emits the validity mask separately from the values.

`tests/test_ps2_animation_trace.py` compiles the actual C recorder/export implementation, captures its bytes through a test sink, runs the offline CLI, and tests rejection of incomplete, truncated, CRC-corrupt, invalid-paired-token, unknown-mask, and wrong-ELF-pin cases. The provenance values and test ELF are synthetic, so this proves the serialization/decoder contract, not provenance of a real guest capture. The opt-in R5900 closure compiles the recorder translation unit (source SHA-256 `128100e859f2c2354b62b36ad80826b9042c2d15bec7b9638ba56666406fa3e4`, object SHA-256 `65bc68cdc60bc38080cfbad69685ceed6d79cd0054e38c046362b450c9a1dd2b`, `.text` 2,844 bytes), but the parent-linked machine ELF does not retain `ps2_animation_trace_export()` because no guest sink calls it. This is consequential: the export and row-encoder functions alone are 568 and 396 bytes in the R5900 object, while the current machine ELF has only 252 bytes of `elf_static` margin. A guest extraction path therefore depends on either recovering measured code space in the exact image or choosing a smaller/externally supported extraction mechanism; simply rooting this implementation breaks the current static-image bound. No real guest capture artifact exists yet.
