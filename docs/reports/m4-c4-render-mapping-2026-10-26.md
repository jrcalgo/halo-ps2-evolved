## Findings

- F1 (runtime identity gap): BSPS has no serialized CE surface id. bsp_batch_surface() returns UINT32_MAX unless a borrowed source ops table is bound (submodules/halo-ps2/engine/src/world/bsp.c:203-209; bsp.h:97-98). The CE surface id exists only in the converter's in-memory Material.surfaces (bspconv.py:71). The round trip is proven offline, not from the shipped section. Proposed fix: Serialize a per-triangle u32 surface table (4 B per expanded triangle, batches capped at 24 triangles) in BSPS, or bind a borrowed source ops with a surface table; charge its bytes in capacity.

## Blocked

- CE collision-hit surface resolution on PS2 (structure_render_surface_from_point_and_leaf): needs a runtime surface id (F1) and the collision leaf candidates; not present in the PS2 closure
- retail HP2 packs / shipped BSPS bytes per map: no HP2 packs under build/ or data/ (see m2-bsp-compressed-vertices-parity-audit.md); this audit re-converts from decompressed maps with the same converter
- CBSP byte recomputation per map: schema ELF for convert_retail_bsp.py is not built in this checkout; the preservation ledger's cbsp_round_trip_valid is cited, not recomputed

## Limits

- The CE-side point->cluster walk uses the same parsed collision BSP3D tree as the converter (bsp.read_structure); it is a host re-implementation of the CE tree walk, not the CE binary.
- Engine-side checks run the real engine/src/world/bsp.c on the emitted section bytes.
- No PCSX2, GS, VU or target output is claimed.
