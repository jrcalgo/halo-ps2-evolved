# M2 Step 9 host fault-matrix audit

**Scope:** report-only comparison of the current M2 Step 9 requirements (L0–L6) with the checked-in parent map-service/CTAG mount, HCU cache adapter, and host fixtures. No implementation or shared plan files were changed.

**Conclusion:** the host coverage is a useful end-to-end UI-positive control with several meaningful corruption/rollback checks, but it is not yet the deterministic L0–L6 transactional fault matrix required by Step 9. It lacks injected failures at each boundary, full snapshot comparison, broad malformed HP2/CTAG/CBSP cases, CE publication invariants, missing-presentation handling, and a same-process valid-retry check for most failures. A single current fixture does prove the special deferred same-map reload path can fail on a changed source after old-owner release and then succeed after restoring the source; it must not be generalized to all L0–L6 failure states.

## What current tests do prove

1. **Catalog/path basics:** `hcu_map_catalog_main.c` checks 24 entries, canonical aliases (`levels\\ui\\ui`, slash form, and `ui`), unknown/traversal names, and HMAP/CBIX match/mismatch cases. This is L0 identity/catalog logic, not service-level source-open/length failures.
2. **HMAP/source identity:** synthetic fixture passes a valid package and rejects same-length wrong source bytes. In the retail service fixture, a byte is toggled in `ui.map` after preflight and before deferred post-unload reload; the loader rejects the changed hash with empty released owner and all FileXio handles closed.
3. **HP2 section-integrity negative control:** synthetic fixture corrupts a CTAG stored byte and verifies cache-begin fails, map owner returns to its prior mark, source closes, and cache remains unpublished. `world_section_capacity` separately checks bounded allocation rollback for too-large retail CTAG and CBSP sections.
4. **CRNG integrity:** synthetic fixture builds a valid HP2 containing a CRNG payload with a damaged internal CRC; the service rejects it and restores owner/source/cache state. `test_ctag_resources.py` also exercises wrong identity, CRC and noncanonical range contracts in the resource-index implementation.
5. **CBIX semantic mismatch independent of HP2 section CRC:** the retail-service test changes a CBIX row while recomputing the HP2 section CRC. `load_section` rejects the catalog before mount/publication and rewinds its allocation. This validates one semantic catalog fault class.
6. **CTAG capacity denial:** a small tag-cache capacity causes preflight failure without active mount/cache publication and closes its source. This is a bounded-rejection control, not a CTAG malformed-claims matrix.
7. **Mount transaction ownership:** synthetic fixture rejects section pointers that predate the transaction or lie outside its owner; the prior 32-byte sentinel allocation remains intact and the arena mark is restored. A second competing mount is rejected while the current mount owns the global slot.
8. **BSP decode/read failure:** a package whose B001 CBSP checksum is damaged can mount the CTAG package but fails the B001 read. Scratch usage returns to zero; ordinary valid BSP reads/materialization are separately exercised. This is not yet a full post-L5 rollback/snapshot test.
9. **Range-authorized resource read behavior:** fixture exercises an allowed source read, a denied/out-of-range request that leaves the caller buffer unchanged and reports read failure, and normal final close with open-count == close-count.
10. **Owner teardown/retry (narrow specialized case):** the retail UI service test proves initial mount → same-map CE-like preflight → owner release to `used=0` → mutate source → deferred load reject with no active source/mount/handles → restore source → fresh preflight/load succeeds with the same arena base/capacity and used/high water. It also rejects an inconsistent cache-unmounted-but-parent-owner-live order while preserving the parent arena/source until shutdown. The exact guest clean-cycle test separately covers successful UI unload/reload; it does not add guest failure injection.

## Cross-cutting invariants currently missing from the matrix

The existing fixtures often assert `map_arena.used == baseline`, `!mount.active`, `!cache_files_precache_map_loaded()`, and open/close counts at selected failure points. These are valuable but weaker than Step 9's requested complete transaction snapshot. Define one test snapshot helper and capture before every injected stage and after failure:

- **Arenas:** fixed `base`, `cap`, `used`, and `high` for map/streaming, section scratch, BSP scratch, and destination arenas; verify alignment, canaries and all inter-arena disjointness. Distinguish `high` monotonic growth from cursor rollback: rollback can restore `used` while `high` correctly records a failed peak.
- **Ownership/service:** `mount.active`, payload and resource-index pointers/sizes, owner pointer/mark, BSP active/mark, `s_active_mount`, `source.active`, reader descriptor, `preflight_ready`, `reload_pending`, staged entry and staged map.
- **CE cache:** mounted name/payload, CTAG/CBSP view pointers, read callback/context, file-open state, BSP loader/release callback/context, `cache_files_precache_map_loaded`, synthesized cache header fields and completion flag. These are static internals today; expose test-only snapshot hooks or test through stable public queries rather than poking production globals unsafely.
- **CE published runtime:** scenario/tag-data/tag-reference globals, `main_menu_scenario_loaded` / map-loaded state, current structure-BSP pointer/index, collision/BSP generation, presentation/HUD/first-person pointers or handles, and render-snapshot publication generation. These do not exist in the current parent host shim; the CE guest lifecycle trace only reports a subset on successful cycles.
- **Files and source:** source identity/hash, FileXio descriptor count/open-close parity, no descriptor reuse/close of a live owner's source, no open handles after failure or unload. Test truncated-read and seek/stat failures from fake I/O rather than relying only on filesystem mutation.
- **Allocator behavior:** no `malloc`/`free` after startup/load cycle, no hidden fallback allocation; zero temporary staged bytes at commit and exact rollback after failure.
- **Retry semantics:** for failures before the old map is unpublished, old map remains usable; for post-unpublish single-cache failures, explicit safe empty/unloaded state is expected, then a fresh valid load in the same process succeeds. Do not require restoration of old CTAG after destination overwrite unless a second buffer design exists.

## Recommended test implementation order (no code changes made here)

1. Add a test-only deterministic failpoint enum with a single injector at explicit L0, L1, L2, L3, L4, L5, and L6 boundaries. Keep it absent from production builds and fail closed if an unknown value is supplied. A stage failpoint is distinct from malformed-input cases: both are needed so all cleanup edges can be reached even if constructing a given malformed package is difficult.
2. Add a shared C `map_service_snapshot`/assert helper in the host fixture that captures the cross-cutting fields available today; extend it later with a CE-side snapshot hook for actual published globals. At minimum, compare exact `used` and live-state fields for each fault and assert capacity/canaries/base invariance. Record allowed `high` growth separately.
3. For each L0–L6 failpoint, run `valid-load → inject failure at stage → snapshot comparison → assert handles closed/no publication → clear failpoint → valid-load retry`. Add a separate pre-unload test that proves the currently mounted map stays readable after each L0–L3 preflight rejection; test post-unload failure against the defined empty-state contract.
4. Add a corruption fixture builder that mutates one HP2/CTAG/CRNG/CBIX/CBSP property at a time and recomputes outer checksums when the test intends to isolate an inner semantic validator. Pin the specific error stage and expected no-publication invariants. Include short-read fake-I/O injection and arena-exhaustion boundaries.
5. Add L4/L5 publication tests against the actual HCU CE cache adapter (host compiled), including invalid schema/relocations and failed tag/BSP materialize calls. Add minimal CE globals only through explicit test seams; do not represent parent shims as proof of CE global rollback.
6. Resolve L6's presentation-tag contract, then inject missing/invalid required sections and prove the one-commit behavior. If no presentation data is required for M2 map residency, document L6 as “no additional tags in this profile” with evidence rather than leaving it implied.
7. Run the focused suite under ASan/UBSan, then the entire M2-targeted suite. Preserve per-case exact status/state matrices. Guest/PCSX2 tests remain an additional later check; they do not substitute for the deterministic host failpoint matrix.

### Verified additions and scope

- **L0 source-open failure:** `test_retail_ui_ctag_mount.py` builds roots missing `ui.map` and missing `ui.hp2`, then invokes `--retail-ui-service-open-failure`. It does **not** cover arbitrary path normalization at the service boundary, stat/seek errors, read interruption, or failure preservation while a prior committed map is live.
- **L0 source length mismatch:** a 4,096-byte `ui.map` with the valid UI HP2 is passed through the same service test. It proves rejection/rollback for a source whose actual length disagrees with HMAP. This is a useful truncated-map length case, but not a short-read after a successful stat/open (the reader is told the short file's true length); fake-I/O truncation during read remains distinct and untested.

- **L1 codec field:** it writes `0xffffffff` to the CTAG section codec field. The C parser rejects `codec > HP2_CODEC_LZ4` in `hp2_open_header()` (halo-ps2 `engine/src/stream/hp2.c`, `open_common()`), before section decode/allocation. This covers an invalid/unsupported codec metadata field as fail-closed behavior; it does not exercise the streaming LZ4 decoder's `HP2_ERR_CODEC` branch or assert a stage-specific status.
- **L1 extent/overlap:** it changes CTAG section offset to `0xfffff800` and separately aliases HMAP's offset to CTAG's offset. Both go through `open_common()` bounds/overlap validation and assert owner rollback/no active cache. These add genuine out-of-file and overlapping-section table negatives.
- **Failure snapshot:** `map_service_snapshot` captures only the two supplied arena identities/capacities/cursors/high-water, parent mount/source state, source descriptor, preflight/reload/staged state, one public `cache_files_precache_map_loaded("ui")` query, and fake open/close counters. The failed-preflight helper demands fixed identities/capacities and `used`, checks high-water is monotonic and capped, requires service state cleared, and checks aggregate open/close balance. This is a meaningful partial snapshot for a fresh failed preflight. It is not a full transaction snapshot and is not applied to the new synthetic L1 invalid-header cases, which use local assertions instead.

### Claims to keep narrow / potential overstatement

1. The updated Step 9 text accurately says the changes “close only the noted source/package/header/codec cases” and explicitly retains full L0 length/path and L1 structural-table gaps. “Truncated-source” should be understood as a true short file/length mismatch, not a simulated short read while the stat length stays intact.
2. The `bad-codec` mutation is rejected at HP2 header/table validation because the codec value is out of the declared enum; it is not a compressed-stream decode fault and does not prove valid-LZ4 malformed-block handling. The existing damaged-CTAG case provides a payload corruption negative, but asserts only aggregate rejection/rollback, not the exact decoder status (CRC versus decode versus I/O).
3. The table additions now do cover one basic header magic error, invalid codec enum, one beyond-file extent and one overlapping extent. They do **not** yet cover header version/reserved bytes, truncated header/table, excessive count, duplicate tags, malformed tag bytes, nonzero entry-reserved fields, unsupported alignment, stored/raw mismatch, missing-required-tag behavior through service, HP2 section CRC isolated from decode corruption, or I/O short read after stat/open. 4. The service-level missing-map/missing-HP2/truncated-map tests use an initially empty service. Their snapshots prove no premature publication for those failures, but do not show a live previously committed map remains usable on each L0/L1 preflight failure. The changed-source deferred-reload test proves a different post-unload failure contract and is the only specific service-level retry-after-failure sequence; the newly added missing-file tests terminate after shutdown and do not correct the root and retry in the same process.
5. The `map_service_snapshot` does not include tag-cache/BSP base and capacity, canary bytes, arena alignment/overlap, `s_active_mount`, `ctag_mount` payload/index pointers, mounted cache name/read callbacks/file-open state, cache header contents, CE scenario/tag/BSP globals, map-loaded transition flags beyond the public UI query, source hash, or render publication generation. It should be described as partial owner/service state, not the Step 9 full pre/post snapshot.
