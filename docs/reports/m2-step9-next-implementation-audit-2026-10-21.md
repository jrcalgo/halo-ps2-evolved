# M2 Step 9: highest-value next implementation slice

**Audit mode:** report-only, against the current working tree on 2026-10-21. No code or plan files were changed by this audit. The working tree is dirty, including `src/stream/hcu_map_service.c`, `src/stream/ctag_mount.c`, `submodules/halo-ce-universal`, and `submodules/halo-ps2`; the observations below describe those current files, not only their pinned commits.

## Recommendation

The highest-value next slice is a **single-file-reader fault-injection seam carried through the actual HCU map-service → CTAG mount → CE cache/BSP callbacks**, followed by a focused transaction matrix that injects short read/EOF and late integrity failures at each ownership boundary, captures the full before/after state, then retries the same load successfully. Keep the production reader unchanged except for a narrow injectable `read_at` boundary (or test-only reader backend); tests should link the real service/mount/cache/CE path, with only the device and fault schedule controlled.

Prioritize these fault points in that one slice:

1. HP2 transport short read/EOF after some output has reached the *private* CTAG or CBSP staging span, including the end-of-section CRC failure.
2. A late failure while the selected CBSP is staged/materialized, after an earlier BSP has been valid, verifying CE's safe-null/menu fallback and parent lease cleanup.
3. An error in the post-unload map reload sequence, followed by reopening a corrected/valid source and proving same-process retry.

For each, capture and compare map/BSP arena cursors and high-water, CE tag/BSP globals and indices, cache mount state, callback registrations, map-source descriptor/size, reader-open count, completion flag, and the exact output span's publish/valid state. A failure must make the candidate unreachable to CE, release every lease/handle exactly once, return all private arena marks to their prior values, and permit a clean retry. Do not require restoration of the old tag image after the fixed tag-cache span has been overwritten: after the CE unpublish boundary, a failed replacement must remain a deterministic no-map/menu state, matching the plan's explicit single-cache constraint.

This slice closes the largest *evidence gap* between existing successful-path/selected-failure tests and Step 9's L0–L6 transaction contract. It is safer and more immediately actionable than implementing streamed final-span CTAG materialization now: streaming is needed for capacity, but requires a separate two-pass validator/materializer and a proven boot-fixed tag/BSP split first. Do not combine the two changes or let a test-only fault adapter become a runtime heap/buffer allocation.

## Why this is the next slice

### Current production state and transaction edges

* `hcu_map_service_preflight()` restricts admission to UI, opens and hashes the source, loads HMAP/CTAG/CRNG/CBIX into the map arena, validates identities and extents, calls `ps2_ctag_open()`, then rewinds the temporary arena span ([`hcu_map_service.c`](../../src/stream/hcu_map_service.c#L230-L310)). It retains a source descriptor and staged metadata, while avoiding writes to a live map. `map_loader()` later verifies that old mount/source ownership has been released, repeats preflight for deferred reloads, and passes the retained source into `ctag_mount_hp2_verified_source_discover()` ([`hcu_map_service.c`](../../src/stream/hcu_map_service.c#L95-L145)). These are important separation points, but the fixture should prove them under injected failures rather than only happy-path reloads.
* `ctag_mount_hp2_internal()` starts an owner mark, stages the entire CTAG and CRNG payloads, opens the resource index, mounts the CE cache callback, and publishes `mount->active` only at the end ([`ctag_mount.c`](../../src/stream/ctag_mount.c#L112-L173)). `ctag_mount_hp2_*_with_bsp_catalog()` adds CBIX staging and callback registration; on catalog/registration failure it calls unload to unwind ([`ctag_mount.c`](../../src/stream/ctag_mount.c#L230-L274)). `load_bsp_extent()` has its own scratch mark, materializes one BSP at a time, and releases the failed attempt ([`ctag_mount.c`](../../src/stream/ctag_mount.c#L67-L105)). The corresponding mount teardown releases the BSP, unmounts CE callbacks before closing the source, and finally rewinds the owner ([`ctag_mount.c`](../../src/stream/ctag_mount.c#L277-L290)). These are exactly the boundaries where short-read, malformed-after-output, and one-shot retry faults should be injected.
* `cache_file_read()` initializes completion to failure and sets success only after the exact CTAG or CBSP request materializes into its fixed physical destination ([`ps2_cache.c`](../../submodules/halo-ce-universal/port/ps2/src/ps2_cache.c#L375-L427)). A fault test must preserve that contract: it must not leave a zero completion that causes a CE wait loop or set `TRUE` for a partial result.
* CE owns lifecycle publication. `scenario_switch_structure_bsp()` disconnects/unloads the old BSP, clears its index, attempts candidate load and `structure_bsp_port_verify`, restores the old BSP if possible, and otherwise enters the main menu ([`scenario.c`](../../submodules/halo-ce-universal/source/scenario/scenario.c#L1088-L1195)). `scenario_load()` loads scenario tags, sets scenario globals, and requires the first BSP switch to succeed ([`scenario.c`](../../submodules/halo-ce-universal/source/scenario/scenario.c#L1230-L1253)). Tests that call the cache/mount in isolation cannot establish all CE globals were unwound at these failure points.

### Existing failure tests are substantial but not full Step 9 closure

* `tests/test_hcu_scenario_bsp_switch.py` builds real CE `scenario.c`, the HCU PS2 cache/CTAG/CBSP adapters, the parent mount/resource-index, and halo-ps2 HP2/file/section readers for the retail integration case ([test build closure](../../tests/test_hcu_scenario_bsp_switch.py#L78-L200)). The C fixture already injects candidate BSP load failure, candidate port-verifier rejection, schema rejection, and simultaneous candidate+old-BSP failure, checks global tags/BSP state and BSP-byte snapshots, and exercises retry ([`hcu_scenario_bsp_switch_main.c`](../../tests/hcu_scenario_bsp_switch_main.c#L727-L855)). The CE BSP-switch-only test has additional branches but uses controlled CE/cache fakes, not the actual package ingress ([`hcu_scenario_bsp_switch_main.c`](../../tests/hcu_scenario_bsp_switch_main.c#L879-L927)).
* The retail package fixture already mutates the CBIX expected CRC, requires the real HP2 decoder to fail after streamed output, checks owner/scratch rewind and cache unavailability, and retries on the valid package. This is a valuable but narrow HP2-failure point: the report says transport short reads, resource-read EOF, candidate-CBSP decode/CRC failure, full CE scenario teardown, and target traces remain uncovered ([`m2-group-d-file-backed-transaction-followup-2026-10-21.md`](m2-group-d-file-backed-transaction-followup-2026-10-21.md), “Scope and remaining Group D work”).
* `tests/test_hcu_reader_fault_matrix.py` and `tests/hcu_reader_fault_matrix_main.c` thoroughly mutate standalone HMAP, CRNG, CBIX, and CBSP metadata (counts: 11/15/16/21 malformed cases). They do not run those faults through the full owner/source/cache/CE transaction ([test launcher](../../tests/test_hcu_reader_fault_matrix.py#L9-L31); matrix assertions begin in [`hcu_reader_fault_matrix_main.c`](../../tests/hcu_reader_fault_matrix_main.c#L160)).
* `tests/test_ctag.py`, `tests/test_ctag_mount.py`, and `tests/test_retail_ui_ctag_mount.py` include parser, mount, and UI ingress regressions. The CTAG materializer has a strong pre-write validation guarantee: it rejects invalid fields/targets/address ranges before its first destination copy ([`ps2_ctag.c`](../../submodules/halo-ce-universal/port/ps2/src/ps2_ctag.c#L148-L207)); CBSP validates cross-image strings before copying, and its bounds derive from checked disjoint final spans ([`ps2_cbsp.c`](../../submodules/halo-ce-universal/port/ps2/src/ps2_cbsp.c#L131-L187)). These tests do not yet inject an ingress read fault after the final physical destination begins to be written, nor test the CE publication invalidation/retry contract for that operation.

## Why not start with streamed CTAG as the next slice

The repository already has a generic bounded HP2 visitor that leases fixed history/input/output windows, passes decoded chunks to a sink, and releases scratch on return ([`section.c`](../../submodules/halo-ps2/engine/src/world/section.c#L63-L139)). However, its contract explicitly permits the sink to see a prefix before a late CRC error; the visitor reports `raw_size` only on success but cannot undo arbitrary sink writes. The current HCU path does not call it: `load_section()` calls `world_load_section_with_scratch()` ([`hcu_map_service.c`](../../src/stream/hcu_map_service.c#L56-L65)); that whole-output loader reserves the entire section and rewinds the output mark if HP2 decoding fails ([`section.c`](../../submodules/halo-ps2/engine/src/world/section.c#L187-L235)).

Switching CTAG directly to a streaming sink now would therefore risk partial writes to CE's fixed tag cache before its checks complete. CE tag blocks/data are direct pointers; the final image must remain at the exact bound tag-cache address, not be moved after validation. The current materializer's safe contract comes from checking every relocation before copying; a streaming replacement must preserve HP2 CRC, CTAG CRC/envelope, every relocation invariant, and CE schema validation, while keeping the candidate unpublished until all of them succeed. The architecture report's staged plan is appropriately ordered: complete host visitor parity, implement stream validator, settle boot-fixed destination binding, then direct materialization and late-fault/retry tests ([`m2-streamed-ctag-destination-design.md`](m2-streamed-ctag-destination-design.md), sections “Validate CTAG in a no-write first pass” and “Materialize at the existing CE read destination after teardown”).

The destination is presently capacity-limited too: the report records a 2 MiB bound tag-cache span versus the 4,477,116-byte Blood Gulch compact CTAG image. Streaming removes staging pressure but cannot make that final image fit; late binding is disallowed after the physical allocation ([`m2-streamed-ctag-destination-design.md`](m2-streamed-ctag-destination-design.md), “Finding in brief” and “Existing ownership and lifetime constraints”). Therefore a production streamed materializer is not yet a valid isolated next increment. Fault-injection through current full-buffer paths is both useful immediately and prerequisite evidence for a later streamed path.

## Concrete acceptance for the recommended slice

1. Add an injectable read backend to the existing `file_reader`/section ingress boundary, or a test-only adapter selected at compile time. Production remains FileXio/POSIX as configured, fixed-buffered, and allocation-free; no production global fault controls. Fault schedule is deterministic by file identity, offset, requested count, and one-shot/repeat mode.
2. Cover a short read/EOF after at least one successful HP2 output window in CTAG, CRNG/CBIX and CBSP reads. Include full-output CRC failure after output, and a read failure while a CRNG-authorized source resource request is active. Keep parser-mutation tests; this slice complements rather than replaces them.
3. Exercise actual CE scenario load/BSP switch and parent owner callbacks, not only helper return values. Inject faults before mount publication, after mount callback installation, during candidate BSP load/materialization, and after the old map has been unpublished on reload.
4. For each failure, compare the transaction snapshot: map and BSP arena marks, cache/mount active flags, registered callback ownership, source descriptor and close count, CE `global_scenario`, `global_structure_bsp`, `global_collision_bsp`, `global_bsp3d`, scenario/BSP indices, map-loaded flags, cache completion state, and candidate destination validity/publication. Assert no stale pointer references bytes released by arena rewind.
5. After each failure, disable the fault and retry in the same process. Require the expected map/BSP and pointer values, source hash, resource reads, and successful unload; require descriptor/arena baselines to return exactly after teardown. For post-unload replacement failures, require no-map/menu and a successful fresh retry, not restoration of bytes that were intentionally overwritten in the single fixed tag cache.
6. Run the current host ILP32 integration and malformed-input suites; preserve source/package hashes and exact executable/map. Then compile the target closure and, once a candidate map passes capacity design, add the same deterministic guest-visible marker/fail/retry sequence to PCSX2. Host success alone must not close target placement or M2.

## Non-goals and invariants

* Do not relax direct-pointer tag/BSP semantics, serialize runtime pointers, move materialized images after CE publication, or return transient scratch pointers from tag accessors.
* Do not resize the fixed arena from the test result, allocate heap staging proportional to section size, consume the reserved 5.5 MiB, or count IOP/GS/SPU2 memory as EE addressable memory.
* Do not add non-UI map admission in this slice. The current UI-only check in `hcu_map_service_preflight()` is an intentional capacity gate ([`hcu_map_service.c`](../../src/stream/hcu_map_service.c#L247-L253)).
* Do not call a candidate payload “rolled back” merely because the owner cursor was rewound; separately prove no CE/cache pointer publishes the bytes. After the single fixed cache is overwritten, expected recovery is safe-null/no-map followed by retry, not old-map resurrection.
* Halo-64 may be used for comparative discipline around bounded-memory failure and preserving required state; its N64 storage sizes, streaming layout, and gameplay cuts are not evidence for this PS2 transaction. The overarching remake plan explicitly keeps HCU as gameplay/tag authority and halo-ps2 as the EE/platform owner.

## Bottom line

Step 9 has much of the parser safety and BSP rollback skeleton already. The next implementation should make late ingress failures observable through the complete transaction and prove cleanup plus same-process retry, especially at HP2 transport/CRC and post-unload CE publication boundaries. Only after that should the separate streamed CTAG design proceed, gated by its no-write validation pass and fixed final-destination capacity. This advances L0–L6 without weakening direct pointers or claiming a rollback that the single physical tag cache cannot provide.
