# M2 Step 9 current loader-gap audit

**Scope.** Independent read-only audit of the current worktree against Step 9 (L0–L6 transaction/rollback) in [`plans/7.hcu-remake-m2-m4.md`](../../plans/7.hcu-remake-m2-m4.md#L519-L529). This report identifies production callsites and present test evidence, then ranks test-only next steps that can be isolated from runtime/source integration. No source or plan files were edited.

## Bottom line

Step 9 remains partial. Host tests now cover meaningful parent/adapter failure paths and retry, but they do not execute CE's `scenario_tags_load()` / `scenario_load()` publication transaction, nor do they validate all stage boundaries. The highest-value safe next test additions are (1) make the existing composed host fixture inject faults *after* the adapter is mounted and at each later section/stream boundary, (2) add a narrow real-CE tag-load harness or test seam for completion/header/schema publication and abort, and (3) carry one end-to-end guest fail/retry marker through the normal production lifecycle. These can be test-only or harness-only work; avoid changing `hcu_map_service.c`, `ctag_mount.c`, `ps2_cache.c`, or CE load code concurrently with the active integrator.

## Recommended next test-only work, ordered by value and conflict risk

1. **Isolated L1/L2 composed fault driver (lowest implementation overlap).** Add a new test-only fixture file rather than editing the busy `tests/ctag_mount_main.c`. Reuse the existing FileXio shim and production C objects, but add named failpoints for a specific HP2 section read, section sink byte limit, decoder completion/CRC, map-source range read, and arena allocation call index. For each L0–L2 point capture baseline cursors, bases/caps, map/source/mount/staging state, public cache query, open/close balance and canaries; prove failure is closed and then a good UI preflight/mount/read works in that same process. The existing service snapshot in `ctag_mount_main.c:77-136` is a useful model, but is not a CE-global snapshot.
2. **L3/L5 post-mount unwind.** Add independent injected callbacks around the already-compiled production functions: allow the real backend mount to succeed, then fail CBIX decode/catalog validation or BSP callback registration; later fail the selected CBSP visitor after a prefix has been produced. Assert cache callbacks are unmounted before backing bytes/arena marks are released, source handle ownership is correct, BSP span isn't considered valid, and a retry succeeds. This catches a different boundary than existing backend-reject-before-publication tests.
3. **L4 CE publication harness.** Prefer a separately named fixture linking the real CE cache/tag-validator code with existing PS2 shims. Exercise four outcomes: completion exactly TRUE; completion false/pending; non-TRUE nonzero failure sentinel; corrupted tag header/schema failure after successful materialization. After every failure assert `tags_loaded==FALSE`, `global_tag_instances==NULL`, count zero, no registered buffers, `cache_file_close` done, candidate adapter/parent owner released, and same-process retry succeeds. Avoid a test that copies the CE implementation or only greps source; source-order assertions are not behavioral proof.
4. **L6 guest fault→retry trace, after CE seam and current-image stability.** Extend the opt-in UI lifecycle runner with one controlled post-unload source fault followed by restoring the exact asset and retrying; compare ordered guest markers and exact arena/source/descriptor state. Add targeted header/schema/BSP failure only if the fault can be triggered without hand-editing volatile memory. Run interpreter and recompiler against the exact ELF, package, source pins and settings; preserve logs/result hashes. This remains UI lifecycle evidence, not render acceptance.
5. **Preserve exact-image evidence, then qualify the next build.** The `72fe0034…b2319ff2` image already has verified PCSX2 interpreter/recompiler UI-stage evidence as described above; do not rerun it just to re-establish that same UI marker. Any source change or rebuild creates a new candidate that needs its own run manifests and hash binding. The linked probe's `acceptance=false` remains correct because it is a diagnostic link report, not a gameplay-map/runtime-tick/physical-fit acceptance result.

## Decision

Do not close Step 9 or enable gameplay maps on the current evidence. The immediate safe deliverable is a new isolated host fault driver that raises coverage at L1/L2 and post-mount unwind, followed by a real-CE L4 publication/abort fixture. Only after those pass should a normal-profile PCSX2 fault→retry trace be attempted on a newly hashed exact image. Capacity measurements and the L2/L5 streaming redesign remain prerequisites, not test parameters to guess.
