# M2 capacity re-audit: next gameplay-map slice

**Disposition:** implement a Longest-only, lossless CTAG/CBSP streamed-materialization vertical slice against an explicitly boot-fixed tag/BSP split, then measure its complete live set before enabling that one map. This is the highest-likelihood route to an actual gameplay scenario under the existing 32 MiB budget. It is not evidence that campaign maps fit, and it must not widen product scope or close M2 until the plan's full acceptance criteria pass.

**Mode:** independent, report-only audit. No shared plan or runtime code was changed. The parent, HCU, and halo-ps2 submodule pins are `70e2ed0cf2145a45d23aa07414a3a88c05155d4c`, `6933490b2d16bb1c637295b6a0f3880ba23a7d56`, and `71183bb0a9adc586cd267b2780c82bbc12cfd95b`; all three worktrees are dirty. Pin hashes alone do not identify the exact current source. Re-freeze file hashes and the built image before implementation/guest claims.

## Recommendation

Use **Longest** as the first gameplay-map vertical slice. It is a real multiplayer scenario with a frozen, reproducible, all-BSP HP2 package and one scenario BSP. Its complete compact tag image (4,263,624 B, 16-byte-aligned reservation 4,263,632 B) plus its complete raw B000 (374,784 B, aligned 374,784 B) fit inside the existing 6,291,456-byte `current_bsp` region without changing any budget row. The already-reviewed provisional Longest/Blood Gulch split—4,477,120 B tag cache and 1,814,336 B BSP cache—also holds both Longest final images and leaves 213,496 B and 1,439,552 B respectively within those two subspans. Because their combined capacity remains 6,291,456 B, CE's capacity-derived validation claims remain 786,432 B; this must be recomputed by the real target code and demonstrated after binding, not hard-coded from this arithmetic.

The work that actually removes the current blockers is not another parser-only test or a broad budget repartition. It is the following cohesive implementation slice:

1. Bind that exact split before CE allocation, with disjoint canaries and claims verified; keep every v2 region and the 5,767,168-byte reserve unchanged.
2. Replace full-section CTAG staging with the existing bounded HP2 visitor plus an HCU-owned, no-write CTAG validation pass and an unpublished second-pass materializer into CE's existing final tag-cache address. Preserve HP2 and CTAG CRC/envelope checks, all relocations, schema validation, and CE's exact publish/failure completion contract.
3. Apply the equivalent bounded path to Longest's selected B000, materializing into the separate fixed BSP destination. Preserve CBSP envelope/internal and CTAG-name relocations, CE verification, one-active-BSP behavior, and failure-safe CE globals.
4. Keep HMAP/CRNG/CBIX/resource-source metadata bounded and retained only for the map lifetime; measure it rather than assuming the existing UI high-water applies.
5. Run the exact source/package/image through actual `scenario_load`, BSP verification, collision/visibility/resource smoke, unload, and same-process retry. Only then allow a Longest gameplay-load marker. A black viewport remains no rendering evidence.

This recommendation is a *test-map path*, not permission to mark a retail map supported in the product. The governing M2 acceptance continues to require the campaign-capacity set and whole-machine ownership proof; see [`plans/5.hcu-remake.md`](../../plans/5.hcu-remake.md) and the M2 gates in [`plans/7.hcu-remake-m2-m4.md`](../../plans/7.hcu-remake-m2-m4.md#L181-L189).

## Current implementation gap, traced to owners

* Boot currently requests a 2 MiB tag-cache span. The binder reserves it at the start of `current_bsp`, then binds the remainder as the BSP span ([`hcu_main.c:16-18`](../../src/stream/hcu_main.c#L16), [`hcu_memory_bind.c:41-56`](../../src/stream/hcu_memory_bind.c#L41)). The 2 MiB tag span cannot hold Longest's 4.26 MiB final image.
* Preflight calls `world_load_section_with_scratch()` for HMAP, all 4.34 MiB of CTAG wire data, CRNG, and CBIX ([`hcu_map_service.c:56-79,283-310`](../../src/stream/hcu_map_service.c#L56)). The full-output reader reserves `raw_size` before decoding and retains the result until the caller releases its transaction ([`section.c:141-235`](../../submodules/halo-ps2/engine/src/world/section.c#L141)). The real UI high-water around 1.55 MiB does not establish Longest's capacity.
* The existing bounded visitor has a 64 KiB history plus 16 KiB input and 16 KiB output lease (98,304 B total) and can validate/decode HP2 to a sink, but it closes its own reader, shares static header storage, is synchronous, and may deliver a prefix before a late CRC failure ([`section.c:63-138`](../../submodules/halo-ps2/engine/src/world/section.c#L63)). It is infrastructure, not safe CTAG cache materialization.
* Current mount retains the complete CTAG payload, CRNG bytes, and CBIX bytes for the map lifetime ([`ctag_mount.c:112-173,238-274`](../../src/stream/ctag_mount.c#L112)). Selected CBSP load currently stages the entire encoded section in `frame_scratch` ([`ctag_mount.c:67-104`](../../src/stream/ctag_mount.c#L67)); the `frame_scratch` budget is 393,216 B, while the Longest envelope is 377,388 B before adding the visitor's 98,304 B decode work. It therefore cannot be staged alongside that workspace in the same arena even though the decoded raw BSP itself is small.
* CE's final cache reader uses the stable provider-owned tag/BSP destinations and marks completion successful only after materialization; the tag path currently expects an in-memory `ps2_ctag_view`, and the BSP path expects an in-memory CBSP payload (`ps2_cache.c:375-456`). Preserve CE's callback/completion semantics and the normal schema/verifier path; do not bypass them for the test map.
* After a committed CE tag/BSP image exists, it must remain at the same address. CE blocks and data use direct addresses; this is why the prospective loader streams *into the final fixed spans* rather than staging then moving the images. The tag span must not be written while the old map's published pointers remain live. Preflight can check source/metadata; after CE unpublishes old globals and releases map ownership, the second validation must be repeated or bound to an immutable source lease before destructive materialization. On post-unload failure the correct result is explicit no-map/menu state and a successful retry, not restoration of overwritten bytes. The two-cycle UI unload/reload PCSX2 evidence does not yet cover this streamed/failure path.

## Concrete implementation order and acceptance tests

### A. Freeze and qualify the Longest boot layout

1. Rehash the decompressed map, package, schema ELF, catalog entry, tag/BSP destination code, dirty HCU and halo-ps2 files, toolchain, prefix, production ELF recipe, and v2 budget. The committed-v2 regions remain unchanged; specifically `current_bsp=6,291,456`, `resident_gameplay=6,815,744`, `streaming=1,572,864`, `frame_scratch=393,216`, and reserve `5,767,168` B ([`memory-budget.json:8-20`](../../config/memory-budget.json#L8)).
2. In a diagnostic build configuration, request tag=4,477,120 B/BSP=1,814,336 B (both 16-byte aligned) before the one boot allocation. Keep the sum exactly 6,291,456 B; do not change the budget or bind late. Mark/canary the boundary, derive the CE claims-buffer size from `tag_validate_claims_buffer_size()`, assert it is 786,432 B for this sum, and prove actual returned base/capacity and non-overlap with ELF/BSS, backing allocation, all other named regions, stack/kernel reservations, and reserve.
3. Ensure existing user/worktree modifications are preserved. Do not make the diagnostic split the unconditional default until its target placement and current-map lifecycle pass.

**Pass condition:** an exact R5900/PCSX2 memory-ready marker reports the chosen bases/caps, claims high-water, all arena canaries intact, no overlap, and unchanged reserve. This is layout evidence only.

### B. Build a streamed, transaction-safe CTAG final-destination adapter

1. Preserve `world_load_section_with_scratch()` for UI and small callers. Extend the bounded reader path so the HCU service can retain a package reader across preflight, post-unload validation, mount, BSP/resource callbacks, and close; enforce its single-thread/non-reentrant contract or remove the static shared header state. Keep map `.map` resource reads and `.hp2` section reads as distinct sources.
2. Implement an HCU-owned streaming CTAG parser that consumes HP2 output without retaining the complete wire payload. Its first pass is **no-write** and validates the full HP2 table/extent/codec/raw CRC plus every CTAG envelope, image CRC, source/tag-data identity, counts, sorted/aligned/in-bounds relocation offset, and relocation-target rule currently checked by `ps2_ctag_open()`. Treat this as a second parser with complete error-code parity; do not drop checks because the whole image is absent.
3. After CE unpublishes its old tag globals and releases the prior owner, re-open/revalidate against the exact pinned package source (or a cryptographically verified immutable retained reader). Stream the CTAG image interval to the already-bound final tag base, leave CE completion failed until the whole image, relocation table, CRCs, relocations, cache header, and ordinary CE schema walk succeed, then publish. If a late fault occurs, keep the destination unpublished, clear CE/cache flags/pointers, close the source exactly once, restore private owner cursors, and let a corrected package retry from offset zero.
4. Where the relocation table arrives after the image, do not apply fixups until every relocation has been verified against the new image. A bounded relocation iterator / repeated file pass is acceptable; a full 4-byte relocation array or duplicate CTAG image is not assumed free. Count reads, EE cycles, and source I/O latency.

**Host tests:** byte-for-byte parity with current `ps2_ctag_open/materialize` and Python reference on UI and Longest; all parser/error cases; no destination writes in pass 1; injected short read, late HP2 CRC, CTAG image CRC, invalid final relocation, and source-hash change; no publication and no stale tag pointers on failure; same-process corrected-source retry. Run sanitizer and ILP32 target-layout builds. Keep the old full-buffer implementation as oracle until parity passes.

### C. Build the corresponding one-active-BSP streamed path

1. Give CBSP an explicit no-write/open pass that verifies envelope and decoded/raw CRC, source extent, image header, internal relocation target domains, and CTAG-name string references. Retain only bounded descriptor/relocation metadata; the Longest maximum census is 138 internal and 76 name relocations, but general parser bounds should come from the format/table validator rather than this one map's counts.
2. In the CE cache-read callback, perform verification before overwriting the fixed BSP span; then decode the validated raw image directly to the stable BSP base. Apply only prevalidated relocations and run `structure_bsp_port_verify()` before CE publishes the BSP/collision globals. One active BSP only. Keep its loading scratch separate from the final BSP destination and account both simultaneously.
3. Exercise Longest B000 through real `scenario_switch_structure_bsp()` and `scenario_load()` calls. Assert address identity, CE scenario/global BSP/collision pointers, BSP index, successful collision BSP query, scenario objects/spawn or equivalent gameplay-state initialization, and safe-null cleanup if loading or verification fails.

**Host tests:** compare final CBSP bytes and pointer fixups with current whole-buffer `ps2_cbsp_materialize()`; inject faults before output, after partial unpublished output, in both relocation classes, on the last input window and on CRC; assert no CE publication, reset marks/handles, and retry. Add a real CE scenario/load closure test rather than only a mount callback test.

### D. Bound retained metadata and whole-map live set

1. Parse/retain HMAP, CRNG, and CBIX as bounded metadata, not pointers into temporary visitor output. Freeze counts/record bytes for Longest and use checked maximums for parser allocations. Leave the source `.map` open only for documented resources; retain the `.hp2` source only as long as streamed map/BSP or retry operations need it.
2. Instrument per-region current/high-water and all leases across preflight, CE unpublish, tag write/schema, BSP switch, first gameplay tick, unload, post-unload failure, and reload. Charge CE game state, claims, map final bytes, renderer BSPS/texture/lightmap representation, animation/sound, dynamic actors/scripts/effects, HP2 scratch, descriptors, canaries and alignment once. Distinguish EE RAM from GS eDRAM/IOP/SPU2; none backs CE raw pointers.
3. Require `resident_gameplay` and `dynamic_simulation` actual use to fit their capacities with independent margins; do not label unused nominal capacities spare without their required runtime owners and peak phases. Prove the total of all occupied spans remains within 27,787,264 committed bytes and below the 33,554,432-byte EE ceiling; reserve remains exactly 5,767,168 bytes. A CTAG+BSP fit inside `current_bsp` is necessary but not sufficient for map acceptance.

### E. Guest qualification of the first gameplay map

1. Rebuild one exact production combined ELF and Longest package from the frozen source set. Add a success marker only after tag schema, real CE scenario load, selected BSP publication and verifier all pass; follow it with gameplay-state invariants. Hash ELF, package, source map, settings, logs and source inputs.
2. Run identical artifacts in PCSX2 interpreter and recompiler. Require matching normalized CE identities/state and memory/high-water trace; then repeatedly unload/reload and execute one post-unload fault/retry scenario. Capture the viewport to distinguish map load from renderer output. A black image can still be a scenario-load pass but never a visible-scene pass.
3. Keep runtime catalog admission closed for Longest and every other non-UI map until this exact test and M2's governing map/live-set gates pass. Do not claim this first multiplayer map establishes campaign fit.

## Hard stop conditions / dependencies

* If actual target claims, global map owners, render resources, or transition peaks do not fit, stop before admitting Longest. Do not increase named arena sizes, overlay the tag and BSP spans, count GS/IOP/SPU2 as EE, reduce maps/features, or spend reserve. Return to Step 8 with a source-backed ownership/API redesign (typed leases or complete per-field replacement proof) and measured alternatives.
* If any streamed parser differs from current CE/PS2 validators, keep catalog admission closed and compare all checked fields; no marker may be emitted on partial publication.
* Host ILP32, package creation, and schema audits are not guest evidence. PCSX2 is necessary for this vertical slice but does not replace physical EE/OPL performance qualification.
* Continue Halo CE as the behavior oracle and HCU as sole object/tag/collision/gameplay-state owner. halo-ps2 contributes bounded readers/arenas and parent GS/VU/DMA presentation; do not duplicate gameplay simulation there.
* Halo-64 is useful only for *method*: its port keeps platform glue separate and records explicit limits/failures. Do not reuse its 8 MiB pools, N64 layouts, reduced actors/scripts/effects, or map policy. Compare the lifecycle/render-adapter separation in `submodules/halo-64/port/n64/NOTES.md` only where it illuminates state needed by a non-N64 renderer.

## Why the Step 9 fault matrix is not this next slice

The report [`m2-step9-next-implementation-audit-2026-10-21.md`](m2-step9-next-implementation-audit-2026-10-21.md) correctly identifies a remaining transaction evidence gap: ingress short-read/CRC faults must traverse actual CE globals, parent ownership and a corrected retry. That test should be incorporated into sections B/C above, because streamed direct-destination code needs precisely those guarantees. Implementing only the generic Step 9 fault seam first would strengthen M2 correctness but would not change the current fatal capacity mismatch: the map service still whole-stages CTAG/CBSP and the fixed tag span remains 2 MiB. The Longest slice couples the needed fault/retry evidence to the first implementation that can actually cross those gates.

The current whole-resident campaign lower bounds remain impossible in the present representation: d20 complete CTAG + largest BSP is 18,564,640 B before additional map/game owners, and even hypothetically removing all d20 animation data leaves 2,751,784 B for every omitted EE owner/cache. This makes the Longest vertical slice a diagnostic milestone step, not proof that all ten campaign maps fit. See [`m2-capacity-viable-design-review-2026-10-21.md`](m2-capacity-viable-design-review-2026-10-21.md) and [`m2-2026-10-21-budget-repartition-review.md`](m2-2026-10-21-budget-repartition-review.md).
