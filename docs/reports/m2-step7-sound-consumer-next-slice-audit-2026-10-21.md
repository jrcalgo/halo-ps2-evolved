## Best next slice: CE sound-environment palette selection

### Why this is the next sound consumer

The completed sound-obstruction slice proves the geometry-independent branch of acoustic attenuation using `sound_cluster_data` plus PVS, not the BSP cluster's sound-environment/background palette selection. `scenario_get_sound_environment()` is the direct CE owner for that missing selection. At each active player camera with a valid cluster, it may first consider a fog-derived environment and then a cluster's `sound_environment_palette_index`; a winning environment is chosen by definition priority, and the corresponding cluster background-sound palette entry supplies the background sound index ([`scenario.c:1335-1406`](../../submodules/halo-ce-universal/source/scenario/scenario.c#L1335)). CE then updates/interpolates `scenario_globals->sound_environment`, reports the crossed-water-boundary state, background sound and selected definition ([`scenario.c:1407-1450`](../../submodules/halo-ce-universal/source/scenario/scenario.c#L1407)). This is game-owned selection state; outsourcing playback does not make the indices safe to zero.

### Feasibility and exact source oracle

Use the same package transaction's published `global_structure_bsp`, rather than a separately fabricated BSP. The existing package catalog and transaction already provide hash-bound a30/a50 maps, BSP references, relocated CTAG/CBSP, CE scenario globals, and CE source-oracle parsers. Package audit manifest identity is recorded in the current reports as SHA-256 `e4a9721846db228b88e6a563c34c0dccc7c6dc7694cf5a393d66c67ca004503b`; source map hashes are a30 `287959f34a7379a1dbec5fec15b4d94d17fe97ccd861f5c0c8fc80148b7ed293` and a50 `d7a3e80a86f2b0f23d855ce353aed3c0eb252145697797d87f25623dc470f38d` ([sound qualification report](m2-step7-ce-sound-obstruction-qualification-2026-10-21.md)). These are proven package/test inputs, not a claim all palette cases exist in every BSP.

Before writing C expectations, extend/read the **original raw map** oracle to enumerate, per BSP:

1. `structure_bsp.clusters` and `sound_environment_palette` / `background_sound_palette` serialized extents and counts.
2. For each candidate cluster: `fog_reference`, `sound_environment_palette_index`, and `background_sound_palette_index` using CE declaration offsets/strides, not guesses. `structure_cluster` is 0x68 bytes with fog at +0x02, background-sound palette at +0x04 and sound-environment palette at +0x06; these are asserted in [`structure_bsp_definitions.h:89-110`](../../submodules/halo-ce-universal/source/structures/structure_bsp_definitions.h#L89). The palette entries and tag-reference offsets/strides are defined immediately below this structure in the same header and must receive matching `sizeof`/`offsetof` assertions before parsing.
3. The selected palette entry's referenced CE tag index/name, referenced `sound_environment_definition.priority`, and background-sound tag index/name. Bind each record to raw map hash, package-manifest hash, BSP path/index, CBSP identity, and exact source/tag datum bytes.
4. A multi-cluster or multi-player case where priority arbitration is observable, if source data supplies one. If not, at minimum a valid palette-backed single listener case plus explicit `NONE` and invalid-index fallback cases. Do not invent a synthetic BSP record to force the behavior.

The CTAG package contains the referenced tag table and cache payload, so real CE `sound_environment_definition_get()` / `looping_sound_definition_get()` is preferable to stubbing. A test-only source bridge may expose private/internal helpers, but it must invoke unchanged CE code. First conduct a rooted-link probe using function/data sections and `--gc-sections`; list every retained symbol and any machine-boundary adapter. If `scenario_get_sound_environment()` retains broad sound manager, fog, debug-render, or tag-cache dependencies, do not add success-shaped fake definitions. Either narrow to a source-valid `scenario_location_deafening()` query with an actual background palette/tag and real `looping_sound_definition_get()`, or report the exact blocker and keep the broader sound-environment query open.

### Runtime assertions and oracle independence

For each raw-selected candidate, initialize real CE local-player/camera state at the chosen cluster, and set fog reference to a real source-derived no-fog cluster for the first palette slice. Then call actual `scenario_get_sound_environment()` after publication. Assertions should include:

- The selected CE sound-environment index and background-sound index match the raw-derived chain after resolving the referenced CE tag definitions; selected definition priority matches independently parsed source tag bytes.
- With two active players/cameras, the selected environment is the highest-priority source-backed candidate regardless of iteration order; a tie should preserve CE's strict `>` behavior if a source-valid equal-priority case exists.
- Invalid/`NONE` palette indices do not dereference beyond the active relocated BSP and preserve the source-verified default/no-environment result. Do not rely on the port's comments alone; assert the exact output and unchanged state.
- `crossed_water_boundary`, `scenario_globals->sound_environment_initialized`, and the environment output pointer/value match CE's first-selection and subsequent interpolation behavior. Exercise the first call and a second same-source call separately; derive floating expected values from raw tag definitions and CE interpolation constants.
- The source/palette/BSP bytes, published BSP pointer/index, CE scenario/BSP owner state, and collision-user depth are unchanged by selection. Query must not emit or require an SPU2 request in this M2 slice.
- Emit one machine-readable observation per tested BSP/case; Python rejects missing/duplicate cases and compares to raw map + raw tag-data oracle. Do not take expected palette indices, priorities, or selected tags from CE's relocated structs after the call.

The minimum high-value output is not a full sound mixer. It proves that relocated BSP palette fields and tag references still select the right game environment/background index under CE logic. If the required input-player mapping or CE global state cannot be initialized from the existing transaction without fabricating gameplay behavior, constrain the fixture to the existing real CE global initialization path or defer rather than emulate the selection loop.

## Scope and comparative-source disposition

This proposed palette test is host ILP32 semantic evidence over retail package data only. `a50`'s BSP size already exceeds the production 6 MiB `current_bsp` region, and Step 8 has not established a lawful target capacity topology; do not run or label it as target/PCSX2 gameplay-map acceptance. No BSP family may be stripped from this evidence. The broader Step 7 plan still requires production `structure_bsp_port_verify`, byte-preservation, failure-atomicity, and capacity-qualified target query evidence ([`plans/7.hcu-remake-m2-m4.md:591-597`](../../plans/7.hcu-remake-m2-m4.md#L591)).

Halo-64 is an architecture comparator only: its port notes preserve game-owned CPU frame/camera/first-person state across the platform renderer boundary ([`port/n64/NOTES.md:33-55`](../../submodules/halo-64/port/n64/NOTES.md#L33)). It does not define HCU sound palettes, CE sound semantics, PS2 memory limits, or permit N64 feature cuts. REA is not indicated: CE C source and decompressed Xbox map/tag package data are directly inspectable. Use REA only if a specific retail-only binary behavior remains opaque after CE source, raw data, and runtime evidence are exhausted.

**Handoff:** sound obstruction no-collision branches, raw encoded sound accessors, per-cluster PVS/raw pair checks, player PVS aggregation, and unfogged location/weather fallback are covered. Sound-environment/background-sound palette selection/tag resolution, fogged location/plane/region behavior, wind/weather updates, visible-PVS geometric acoustic obstruction, actual sound request/playback, and target-capacity execution remain open.
