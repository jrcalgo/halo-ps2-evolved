## What is genuinely exercised

The test extends [`assert_relocated_collision_query()`](../../tests/hcu_scenario_bsp_switch_main.c#L855) in the existing package fixture. The candidate generator continues to use CE `collision_surface_polygon()` on the currently published retail collision BSP, computes a polygon centroid and encoded plane normal, then forms a segment across that plane ([`hcu_scenario_bsp_switch_main.c:898-933`](../../tests/hcu_scenario_bsp_switch_main.c#L898)). The existing CE low-level `collision_bsp_test_vector()` first finds a hit with a material-bearing surface and valid leaves. For the exact same endpoints, the new portion calls the public `collision_test_vector()` with only `_collision_test_structure_bit | _collision_test_front_facing_surfaces_bit` ([`hcu_scenario_bsp_switch_main.c:965-972`](../../tests/hcu_scenario_bsp_switch_main.c#L965)).

The wrapper assertions then establish:

- CE returns a hit and `_collision_result_structure`; the wrapper `t` lies in `[0,1]`.
- Wrapper surface index, material index, and plane designator match the low-level CE result; wrapper `material_type` matches the `runtime_physics_material_type` found through the relocated structure collision-material array (`hcu_scenario_bsp_switch_main.c:973-979`).
- Wrapper start/end leaf IDs match the low-level result’s first/last traversed leaves, and wrapper start/end cluster IDs match those leaves’ CE structure-leaf records (`hcu_scenario_bsp_switch_main.c:980-987`).
- Wrapper hit point matches `point0 + t * vector` within `1e-4` per component (`hcu_scenario_bsp_switch_main.c:988-991`).
- The forbidden object-adapter call counter remains zero; the test increments the wrapper query counter, and final transaction assertions require one wrapper query for each counted retail collision query (`hcu_scenario_bsp_switch_main.c:992-994, 1377-1385`).

This is real HCU CE wrapper code executing against a relocated retail package BSP. It is not a test-local duplicate of `collision_test_vector()`. The selected structure-only flags ensure media and dynamic objects are not the expected subject; the source comment accurately limits this to structure-result composition (`hcu_scenario_bsp_switch_main.c:965-967`).

## Assertions and claims to tighten

1. **No independent collision golden yet.** The candidate surface and segment are derived from CE `collision_surface_polygon()` and plane data; the “expected” surface, material, and leaf tuple is then obtained by CE `collision_bsp_test_vector()` on the same image and same endpoints. Comparing wrapper output with that result is a valuable CE composition invariant, but not an independent expected result. A wrong shared BSP traversal can make both agree. The Python runner now has an independent raw-map PVS pair oracle (`retail_source_pvs_pair_oracle`, lines 25-91), but there is no analogous raw-source collision tuple oracle.
2. **Plane contents/orientation are not actually asserted.** The test checks `plane_designator`, but does not compare `ce_result.plane.n`/`d` to either the low-level plane (including CE's sign rule at `collisions.c:541-547`) or a source-derived expected plane. The README/report should avoid saying plane orientation is verified until that comparison exists.
3. **No exact `t` equality/composition assertion.** Both low-level and wrapper `t` are only checked in `[0,1]`; the test does not assert `ce_result.t == result.t` within tolerance. The point formula then validates the wrapper’s own `t`, not that it maps the low-level hit parameter unchanged.
4. **Only successful front-facing structure hits.** There is no miss through the wrapper and no back-facing or two-sided/ignore-policy vector. Thus result default initialization and miss behavior (`type`, `t`, point, locations) are not qualified by this fixture.
5. **No wrapper-query byte snapshot.** The helper snapshots PVS and sound-cluster payloads, but the new collision wrapper query does not snapshot/compare collision-BSP bytes, structure leaves, or collision-material bytes around the call. The wider transaction rollback checks are not a query-local immutability assertion.
6. **Dynamic-object branch is excluded, not tested.** The source wrapper has a conditional object collision branch (`collisions.c:642-690`) and `object_test_vector()` itself remains linked. Fail-closed stubs plus clear object flags prove the current test avoids that branch; do not phrase this as object arbitration coverage. Likewise, media/fog flags are off, so the linked `collision_cluster_fog_plane()` code is not a tested sound/media path.
7. **Breakable state is synthetic initial state.** `0xFF` models all surfaces extant, so the test says nothing about broken surfaces, changing flags, state persistence, or the real game-state-backed getter. Keep the explicit source comment and caveat.
8. **Result count naming is broader than evidence if interpreted loosely.** `collision_query_count` increments only after a material-bearing low-level hit and its wrapper hit; final `collision-query-bsp=` is a count of successful structure-hit probes, not arbitrary collision queries or a full wrapper test matrix. If retained, label it “structure-hit wrapper probes” or document the exact meaning.

The strongest immediate assertion improvements are low-risk and do not broaden scope: assert `fabsf(ce_result.t - result.t) < epsilon`; compare all four plane components with the low-level result after applying the exact designator high-bit orientation rule; assert the wrapper surface/material/flags/breakable index fields against low-level outputs; snapshot collision-BSP, structure-leaf, and material spans around the wrapper call; and record explicit scope counters for `structure-hit=...`, `object=0`, `media=0`. These will improve the composition contract but still will not be independent golden parity.

For an independent oracle, have the Python side derive a small fixed query record from the audited original Xbox map and schema, bind it to source-map + HP2 + CBSP hashes, and pass expected candidate surface/material/designator and expected geometric hit location/plane/t to C. Avoid using CE `collision_surface_polygon()` or `collision_bsp_test_vector()` to generate values later claimed as independent expected values. A reviewed checked-in golden record is also acceptable if it records the raw offsets, source derivation and exact artifact hashes. If full independent geometry derivation would duplicate CE’s BSP algorithm, distinguish a package integrity oracle from a geometry oracle instead of overstating independence.
