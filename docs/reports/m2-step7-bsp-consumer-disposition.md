# M2 Step 7 — Structure-BSP runtime consumer disposition

**Purpose.** Source-backed audit of the CE structure-BSP fields accepted by the PS2 tag/schema path. This report distinguishes (a) fields with demonstrable Halo CE gameplay/runtime consumers, (b) render-facing fields whose consumers are compiled into the HCU layer but whose machine-side renderer is intentionally not CE's renderer, and (c) what the current PS2 map path has actually exercised. It is evidence for Step 7, not a claim that a retail BSP is playable or that the M2 gate is closed.

**Source pin inspected:** `halo-ce-universal` `6933490b2d16bb1c637295b6a0f3880ba23a7d56`. Parent checkout at inspection: `70e2ed0cf2145a45d23aa07414a3a88c05155d4c`. Line references below refer to those checked-out sources. The PS2 manifest compiles `source/physics/collisions.c`, `source/structures/structure_bsp_definitions.c`, `source/structures/structure_visibility.c`, `source/scenario/scenario.c`, `source/scenario/wind.c`, and `source/sound/game_sound.c`; it excludes CE `source/structures/structure_render.c` and all `source/render/` and `source/rasterizer/` drawing trees (`submodules/halo-ce-universal/port/ps2/port.json:31-77`). The compiled closure is not by itself proof that a function has run on PS2.

## Executive disposition

1. **Collision BSP is required gameplay data, not safely discardable render metadata.** CE's vector/pill/sphere collision paths query the active collision BSP, then return collision surface, material, breakable-surface, plane and leaf/cluster data. These results feed movement, projectiles, damage/effects and location state. The material mapping is in `structure_bsp.collision_materials`; the collision traversal is rooted at `structure_bsp.collision_bsp`. Do not accept or strip either family as render-only.
2. **Cluster PVS, leaf-to-cluster mapping and cluster sound data are live semantic data.** CE uses PVS for player visibility, cluster visibility, and sound occlusion. The encoded pairwise sound-distance table is consulted by `game_sound.c`, not only by a sound renderer. Cluster fog/weather/sound palette indices also affect scenario behavior and environmental sound selection.
3. **Environment `surfaces` and nested lightmap/material ranges are consumed by visibility/render preparation.** Their CE routines enumerate surface indices, resolve a surface to a lightmap/material, and read the three `vertex_indices`. They are not collision surfaces (which are a separate array under `collision_bsp`). PS2 geometry is supplied through HP2/VU packs and CE drawing is excluded; these arrays remain part of the full accepted CTAG/schema and can be dropped from the eventual resident CE view only after a deliberate, tested adapter transformation proves no enabled CE consumer dereferences them. Current M2 evidence does not establish that transformation.
4. **Current PS2/parent map work is loader/transaction evidence, not runtime consumer evidence.** Parent preflight verifies HP2 section identity and CBIX catalog extents (`src/stream/hcu_map_service.c:285-323`). CE's PS2 cache adapter reads/materializes CTAG and one catalog-selected CBSP into bounded arenas, and clears Xbox-only vertex/index-buffer handles (`submodules/halo-ce-universal/port/ps2/src/ps2_cache.c:375-457`). The package-backed host transaction invokes CE cache/switch/schema paths, but has not run the gameplay collision queries or demonstrated the queries against the PS2-loaded BSP in PCSX2. Keep Step 7 partial until those are tested.

## Data layout and ownership boundaries

The CE `structure_bsp` has separate blocks for `collision_materials`, `collision_bsp`, `nodes`, `leaves`, `surface_references`, render `surfaces`, nested `lightmaps`, `clusters`/`cluster_data` (PVS), portals, breakables, fog/weather, pathfinding, sound palettes/`sound_cluster_data`, and `leaf_map` (`submodules/halo-ce-universal/source/structures/structure_bsp_definitions.h:178-220`). Do not conflate the top-level environment `structure_surface` (three `word vertex_indices`, six bytes; lines 42-48) with `collision_surface` (plane designator, first edge, flags, breakable index and material index; `submodules/halo-ce-universal/source/physics/collision_bsp_definitions.h:35-42`).

The nested `structure_material` binds a shader/permutation and flags to a surface interval (`first_surface_index`, `surface_count`), a breakable-surface index, and vertex/lightmap data (`structure_bsp_definitions.h:50-66`). Each collision material's `runtime_physics_material_type` is the CE gameplay material mapping (`structure_bsp_definitions.h:222-227`). `structure_cluster` has `fog_reference`, background-sound, sound-environment and weather palette indices and a predicted-resource block at fixed source offsets (`structure_bsp_definitions.h:89-110`). The BSP's raw cluster PVS and packed sound pair data are distinct `tag_data` fields (`structure_bsp_definitions.h:197-214`).

## Which paths are actually active today?

### Active parent/PS2 code established by source and current M2 artifacts

- Parent map preflight loads HMAP/CTAG/CRNG/CBIX and checks map identity, the BSP catalog against the selected entry, source length/hash and CTAG bounds (`src/stream/hcu_map_service.c:285-323`). This proves the listed BSP extents and schema-image bounds, not runtime collision/sound behavior.
- Parent binds distinct tag and structure-BSP cache arenas (`src/stream/hcu_memory_bind.c:43-57`). The HCU cache adapter materializes CTAG into CE tag memory and a selected CBSP into the BSP cache (`port/ps2/src/ps2_cache.c:405-427`), with CBSP relocation/size/address/overlap checks in `port/ps2/src/ps2_cbsp.c:131-187`.
- The successful CBSP read clears Xbox renderer handles before returning to CE's real cache loader (`ps2_cache.c:429-440`). A failed or nonmatching BSP read returns a failed completion rather than fabricating bytes (`ps2_cache.c:444-457`).
- The package transaction fixture described in the current Step 7 work invokes CE scenario-switch/cache/schema validation on the host ILP32 process for B000→B001→B000 and failure paths. This supports lifecycle and structure safety only; it is neither a PS2 target nor evidence that any function in the table above queried the materialized BSP.

### Compiled/reachable CE call sites are not yet demonstrated as guest runtime calls

The PS2 port manifest retains the CE collision, scenario, sound, and visibility source families but excludes CE drawing/rasterizer backends. M0 closure data is useful to establish compiled/GC-rooted functions; it is not a runtime trace. The current guest acceptance boundary described by the parent plan has not yet loaded a retail gameplay map and rendered/played it. Therefore mark collision traversal, PVS use, acoustic-distance lookup, environmental sound selection, wind and surface-list derivation as **source-backed required consumers; PS2 map-query execution unverified**. Avoid both extremes: do not say these fields are “already proven active on PS2,” and do not mark them “unused” merely because the CE draw backend is excluded.

## Required consumer-level fixtures before Step 7 can close

1. **Material/surface collision fixture:** using a retail CBSP loaded through the actual PS2 cache/switch boundary (first on host with the production CE functions, then guest), query a deterministic known segment or swept volume. Assert hit/no-hit, `surface_index`, `material_index`, `material_type`, plane orientation, start/end leaf and cluster. Select two collision materials with distinct `runtime_physics_material_type` values; include a breakable and a two-sided/invisible surface case where source tags provide them.
2. **Relocation-consumer fixture:** after materialization, invoke the CE collision query with pointers into the actual relocated CBSP and CTAG. Assert returned indices resolve within the original block counts and records, not only that every relocation points within the image. Include a repeated map switch so stale prior-BSP pointers are detected.
3. **PVS fixture:** for a BSP with at least two clusters, compare `structure_bsp_get_cluster_pvs()` bits against the retail `cluster_data`; exercise local-player OR aggregation and camera fallback in `players.c`. Assert same-cluster visibility, a PVS-visible other cluster, a PVS-hidden cluster, and safe rejection of count/data extents exceeding CE's limits.
4. **Leaf/location fixture:** choose points on either side of a known leaf/cluster boundary; verify `scenario_leaf_index_from_point`/collision leaf output, `leaf.cluster_index`, and the resulting location. Include `NONE`/invalid cases and bounds checks.
5. **Sound-cluster fixture:** assert same-cluster zero, both index orders return the same packed pair byte, distance/unreachable-bit interpretation, and PVS gating through the actual `game_sound.c` obstruction path. Separately verify cluster sound-environment/background-sound palette indices resolve to the expected tags. Playback can be replaced by an SPU2 request assertion; selection/spatialization cannot be stubbed.
6. **Fog/weather fixture:** query locations in and outside a known fog region; assert fog plane and region mapping, underwater result, weather palette selection and wind. Exercise invalid palette references without dereferencing outside the owning BSP.
7. **Surface/lightmap preparation fixture:** run CE surface-reference/visibility preprocessing on the actual CTAG+CBSP and assert all material intervals and triangle vertex indices remain in range. Then compare its produced surface list/triangle mapping with HP2 pack metadata. This is the evidence needed before stripping or zeroing candidate render-only data.
8. **Capacity and map diversity:** repeat the consumer fixture on a structurally different BSP/map with materially different clusters/surfaces and with the real `current_bsp` allocation cap. Host-overprovisioned arenas are useful for parser correctness only and do not satisfy this requirement.
9. **Execution trace:** provide exact guest ELF/source pin and a deterministic marker/counter proving each query family executed after successful map load in PCSX2 (interpreter and recompiler); follow with target hardware when available. A viewport or black frame does not prove BSP consumers ran.

## Safe-to-discard conclusions

The only source-backed safe discard/normalization established here is the Xbox renderer vertex/index-buffer header handles, subject to the stated PS2 pack ownership and validation postcondition. **No whole structure-BSP block family is proven safe to remove from the accepted CTAG today.** `structure_bsp_port_verify` itself requires a collision BSP, clusters, bounded surface count, sufficient PVS and sound data (`source/structures/structure_bsp_definitions.c:26-43`); the render adapter can separately prove a field family bypassed only after examining all live caller paths. `structure_material` vertex payloads, lightmaps/materials, portals, decals, detail objects, pathfinding, markers and leaf-map internals need individual reachability plus target allocation/behavior evidence before any conversion strips them.

## Recommended disposition for M2 Step 7

Record that schema/transaction integrity is improving and that the PS2 cache boundary has a narrowly justified Xbox-buffer normalization. Keep the Step 7 exit gate open. The next implementation should add consumer queries for collision/material and PVS/sound cluster semantics against a real retail package, then connect them to the target map-load path and measure CE+CBSP working-set in the actual 6 MiB `current_bsp` arena. Do not claim “render ready” until the parent snapshot/GS/VU path consumes validated HP2 geometry; do not claim “gameplay BSP ready” until collision, location, and the required cluster/environment queries pass.
