# M2 d20 animation/live-set next-experiment audit

**Disposition:** Report-only source audit. The d20 whole-map owner/live-set experiment is the correct next *capacity decision* after the lower-bound rejection, but the experiment must be split into (1) a semantics-preserving diagnostic trace against the resident CE oracle and (2) only if that establishes a measurable candidate, a separately instrumented typed-lease prototype. Do not start by adding paging, removing bytes from CTAG, resizing a region, or admitting d20. There is no existing measured animation live set, no campaign owner high-water, and no evidence that `animation.data` alone is sufficient.

The authoritative scope is unchanged: ten campaign missions, campaign AI/scripts/effects, all stock multiplayer maps, and a 30 Hz simulation on the 32 MiB PS2. `plans/5.hcu-remake.md` keeps HCU as owner of gameplay state and `halo-ps2`/the parent as machine/render/pack owners, while explicitly rejecting N64 pool and feature cuts ([scope and owner split](../../plans/5.hcu-remake.md#L233-L270)). This audit sharpens M2 Step 8 in `plans/7.hcu-remake-m2-m4.md`, which currently says bind order is stable but campaign fit is not established and catalog admission must remain closed ([Step 8](../../plans/7.hcu-remake-m2-m4.md#L578-L585)).

## Source-backed consumer/lifetime audit

An animation record has three distinct tag-data descriptors: `frame_info`, `default_data`, and `data` (`model_animation_definitions.h:66-97`; [code](../../submodules/halo-ce-universal/source/models/model_animation_definitions.h#L66)). `animation_get_frame_data()` returns a raw pointer into `animation.data`; it selects `compressed_data_offset` for compressed mode or `frame_index * frame_size` otherwise (`model_animation_definitions.c:500-515`; [code](../../submodules/halo-ce-universal/source/models/model_animation_definitions.c#L500)). This is a discovery point, not a complete lease boundary.

The source inventory finds no persistent frame pointer stored by the listed in-tree animation consumers; they decode to orientation values synchronously. That is encouraging but not proof that a lease can be short-lived: public `animation_get_frame_data()` can have uninspected external callers, nested helper calls occur during decodes, two-frame overlays overlap, and the aiming-screen path holds four frame pointers. Run a whole-source and rooted-closure caller audit for every accessor/helper before any eviction/lifetime claim. The independent access inventory already documents these bypasses and caveats ([full inventory](m2-animation-live-set-access-inventory-2026-10-21.md#L18-L48)).

Animation bytes are not presentation-only. The required trace scenario matrix must attribute these callers independently:

* Object create/update computes node matrices and base/overlay pose (`objects/objects.c:2457-2636`; object lifecycle call sites at `3410,3629,3786,3810,3860,3904,5042`).
* Unit poses blend idle/moving/airborne/seated animations; this includes campaign actors and player biped pose (`units/units.c:11071-11327`). Biped root motion affects gameplay movement, while melee x-offset derivation affects combat (`bipeds.c:3663-3701`, `units.c:1396`). Seat exit velocity and root-matrix paths also sample animation data (`units.c:10403`, `1296-1300`).
* First-person weapon state advances at tick cadence in `first_person_weapons_update()` (`first_person_weapons.c:869-895`) and node matrices are sampled when visible during render update (`:649-667`, builder `:1172-1478`). These need distinct tick-vs-render counters; a render-schedule variation must not mutate the simulation hash.
* Devices apply position/power overlays (`devices/devices.c:352-423`); vehicle preprocessing applies steering, speed, wheel and suspension animations (`units/vehicles.c:1410-1489`); ordinary object overlays and sky animation also consume frame data (`objects/objects.c:2548-2610`, `render/render_sky.c:145-170`).
* Scripted camera animation mode samples a root matrix (`camera/camera_scripting.c:457-485`). Campaign cinematics and script-driven viewpoint paths must be represented; a UI or multiplayer map is not coverage.

No direct effect-system or HaloScript source consumer of these three animation payload descriptors was identified in the current animation access inventory. That is not evidence that effects/scripts need no animation data: their object/unit spawning, animation selection, cinematic/camera decisions and tag references can trigger the listed consumers. Instrument the effect/HS activity as a *scenario trigger and ownership phase* around these call paths, and report zero only after the authored d20 encounter scripts/effects have executed. Do not label the bytes as “animation-only rendering.”

## Fixed-owner lower bound: interpretation and consequence

Budget v2 commits `27,787,264` bytes and preserves `5,767,168` bytes as reserve. Its named regions include 1,572,864 system/kernel, 2,097,152 ELF static, 6,815,744 resident gameplay, 6,291,456 current BSP, 4,194,304 texture, 2,621,440 dynamic simulation, 1,179,648 DMA, 1,572,864 streaming, 524,288 checkpoint, 524,288 audio and 393,216 frame scratch ([budget](../../config/memory-budget.json#L4)). The plan forbids silently spending reserve or treating GS/IOP/SPU2 as EE backing ([plan](../../plans/5.hcu-remake.md#L259)).

Current binding makes the attribution concrete: CE game state is allocated from `resident_gameplay`; tag cache takes the beginning of `current_bsp`; the one BSP cache gets the remaining tail; the validator claims bitmap is allocated separately back in resident gameplay; texture/audio/dynamic arenas are independently bound ([`hcu_memory_bind_parent_v2`](../../src/stream/hcu_memory_bind.c#L19)). Claims size is computed from the sum of tag+BSP capacities, rounded to one bit per 32 bytes (`tag_validate.c:244-283`; [code](../../submodules/halo-ce-universal/port/linux/game/tag_validate.c#L244)). Therefore claims are not free and do not disappear when animation data is externalized; if capacity spans change, claims must be recomputed and charged to the actual resident owner.

The matching d20 arithmetic in the capacity-topology report is intentionally a lower bound, not a measurement: aligned complete tag+BSP = 18,564,640 B; corresponding claims = 2,320,580 B; plus system/kernel 1,572,864, ELF LOAD 2,086,532, ELF BSS 2,114,588 and CE game state 3,428,352 gives 30,087,556 B, already 2,300,292 B above the complete committed ceiling before textures/lightmaps, actors/AI/scripts/effects, DMA, stream/audio/scratch, renderer packs, allocator metadata and load-transition overlap ([arithmetic and exclusions](m2-campaign-capacity-topology-review-2026-10-21.md#L58-L80)). Hypothetically removing every d20 `animation.data` byte at zero cache, descriptor, staging, or I/O cost still leaves 2,751,784 B for every omitted owner. That is less than the named 2,621,440 B dynamic arena plus even 130,344 B for all the other uncounted owners; this comparison is a warning only, not a claim that every named arena is simultaneously full or non-reclaimable.

So the decisive question is broader than “how many animation bytes are read?” It is whether an explicit, behavior-preserving contract can reduce simultaneous EE ownership enough to fit *all* required owners and reserve with measured margin. Animation is a useful first typed candidate because byte extents are enumerated, not because the lower-bound report shows it is sufficient. Do not present the candidate savings as available RAM until a whole-owner ledger validates its lifecycle and replacement costs.

## Concrete experiment sequence

### Phase A — diagnostic instrumentation on the resident oracle (safe to implement next)

This phase changes no data placement, access behavior, or acceptance. Build it as an opt-in diagnostic profile with fixed preallocated tables/counters. The production profile remains untouched.

1. **Freeze the tuple.** Generate a machine-readable manifest containing the exact inputs listed above and fail the run if any input hash changes. Include `all-no-bootstrap-memory` compile closure, rooted object, generated schema ELF, final production ELF and source manifest. Use one d20 map/package and regenerate d20 tag/BSP/animation range inventories from it.
2. **Enumerate and close the read surface.** Use source-aware enumeration plus compiler/link references to list every read/dereference of `animation.data`, `.default_data`, and `.frame_info`; specifically include accessor calls, compressed helper bypasses, default-data macro, frame-info bulk path, schema validator, and any PS2-specific path. Store symbol/file/function and line/condition in the run manifest. Fail instrumentation coverage if a known function lacks a hook. Review `animation_get_frame_data()` rooted callers for pointer escape outside the audited translation units.
3. **Add no-op observation hooks.** Put a compact phase enum and an animation identity context (map SHA/id, tag index/datum, graph datum, animation index, field, frame, compression mode, caller phase) into the opt-in profile. Hook: `animation_get_frame_data()`; all three compressed helpers; the default-data cursor; indexed and bulk frame-info paths; schema animation validation entry and every payload range it validates. Counters must be fixed-size or allocated before map publication from an explicitly charged arena. Never allocate per read, print per node/frame, or retain a raw pointer in diagnostic state.
4. **Measure logical ranges, not accessor calls.** Record validated byte intervals for each field, unique-byte union per animation/field/phase, read count, invalid-range/correction outcome, simultaneous caller intervals/pins, nested acquire depth, and data bytes consumed. Tag accessor assertion probes separately from actual decode. For compressed readers, instrument exact subranges established after checked offsets. Record table overflow/dropped-event count and fail the run if nonzero; silently dropping records invalidates the result.
5. **Measure per-tick and phase costs.** Use the EE timer for entry count and worst/percentile cycles per phase/call, plus cumulative `animation.data` work in 30 Hz ticks. Separate map validation/load, object create, simulation/object update, actor/unit pose, movement/root-motion, melee, device/vehicle, first-person tick, first-person render, sky, cinematic/camera, effects/HS-triggered work and unload. PCSX2 measurements are functional/regression evidence; only EE hardware can establish EE cycle and I/O deadline cost.
6. **Run deterministic d20 scenario set.** Start with d20 hangar load and its real scenario lifecycle, then authored encounter/replay states that cover actor idle/movement/alert/damage/death, player weapon firing/reload and first-person pose, melee, seat enter/exit and vehicle occupancy, animated devices, BSP switch, camera/cinematic path, script/effect activity, and at least 1-4 local players where product mode permits. Include all campaign BSP references one at a time. Preserve an equivalent resident baseline/replay for comparison.
7. **Prove instrumentation is observational.** Run the same frozen input/replay with instrumentation disabled/enabled and compare gameplay state hashes at tick boundaries, actor/object counts, positions/velocities, damage and script/effect state; for first-person, vary render schedules (0/1/multiple draws per tick) while holding simulation input constant. The only allowed differences are diagnostic counters/output. Compare exact validator corrected bytes/errors and pose outputs, not just “map loaded.”
8. **Report the result honestly.** Separate (a) whole-map resident payload sizes, (b) bytes ever touched, (c) observed per-window working set, (d) maximum simultaneously live/pinned bytes, (e) proposed lease residency, and (f) actual all-owner phase high water. Do not conflate these. State whether the observed d20 run covers all script/actor/camera/vehicle paths and which scenarios remain unexecuted.

Phase A is implementable now without changing runtime semantics. It answers whether a whole-record lease has plausible locality and what callers must be preserved. It does **not** demonstrate any memory savings because every original tag-data byte remains resident.

### Phase B — only if Phase A supports a lease hypothesis

Do not begin this phase unless Phase A has complete hook coverage and parity, and owner accounting shows a plausible nonnegative budget with charged cache/descriptor/read-ahead costs.

1. Add a typed source descriptor keyed by stable map/tag/graph/animation identity plus field and logical size/digest. Preserve exact logical bytes and schema correction semantics. Do not use raw media offsets without binding them to the package/hash manifest.
2. Define acquire/release as explicit, scoped operations; the acquire returns one contiguous EE view valid until release. The cache must pin records until all nested consumers release. Map unload must assert zero pins and invalidate every descriptor before the source/package closes. No asynchronous pointer may outlive the source or the acquired lease.
3. Make schema validation read the logical animation data through the same provider before publication. Validate compressed header, defaults, offsets, all keyframe arrays and ordering; compare accepted/rejected/corrected results and modified tag bytes to the resident CE oracle. On short read, invalid digest, I/O failure, table exhaustion or capacity exhaustion, fail the map deterministically; never continue with partial/stale payload.
4. Route every direct runtime access found in Phase A. The four-pointer interpolation case must hold four valid simultaneous views; continuous overlays must hold both frame views; the three compressed subreaders and schema validator must use the same byte source. Keep `frame_info` and `default_data` in resident CTAG in this first experiment.
5. Test deliberately undersized cache, overlapping requests, nested/reentrant pose decode, malformed source offset, short read, CRC/hash mismatch, media removal, cache pressure, map unload with outstanding lease, retry after failed acquire, and load/unload/reload. Verify deterministic refusal and that no old pointer/lease is observed after rollback.
6. Compare every captured pose output, root-motion displacement/yaw, melee x-offset, vehicle/device pose, camera root matrix, validator correction, and gameplay replay hash against the resident build. Stress 1–4 local players and actor high-water; include render schedule invariance. A passing unit test over synthetic bytes is necessary but not sufficient for d20 parity.
7. Rebuild the per-map/per-phase ledger with every new EE object: animation payload remaining in CTAG, live lease/cache buffers, descriptors/index tables, page/codec staging, alignment, diagnostics (excluded only in non-instrumented production after proving their removal), file buffers, claims bitmap, transition overlap and old/new sources. Attribute each address interval once to the physical store and named v2 owner; prove with canaries/high-water.
8. Measure disk/OPL request latency and worst tick stall on target hardware. PCSX2 interpreter/recompiler can validate control-flow and failure behavior but cannot qualify R5900 throughput, physical DVD seek/OPL performance, or EE memory high-water.

## Acceptance, stop conditions, and dependencies

The experiment succeeds as a **diagnostic** only if all known access paths are covered, event overflow is zero, source/ELF hashes match, instrumentation-on/off gameplay and validation parity holds, and its owner ledger identifies maximum live bytes by phase. This leaves M2 Step 8 and gameplay-map admission open.

The lease experiment can inform a capacity design only if the same assertions also pass for the typed implementation: zero pointer escapes after release; four-frame/interpolation and nested use are safe; all validator and gameplay comparisons match; cache/provider/I/O costs are measured; all required d20 BSPs/encounters and failure/unload/retry paths execute; and the complete physical EE owner ledger fits budget v2 with guard/canary margin while the 5,767,168-byte reserve remains untouched. Then proceed to a separate capacity proposal and production PCSX2/EE acceptance. Do not count an animation-only subtraction as a fit when it leaves every other owner unaccounted.

Stop the animation-only line if its optimistic maximum savings plus measured non-animation owner topology cannot fit, or if leases stall 30 Hz ticks, external pointers escape, schema correction differs, or behavior parity fails. A stop is not permission to cut AI, scripts, actors, effects, maps, or animation semantics. It means compare another individually audited representation or lifetime-reuse candidate with the same exact-owner and parity standard, then record an evidence-based infeasibility/design decision if no lossless combination fits.

Dependencies in order: exact source/artifact freeze → exhaustive accessor/validator coverage → diagnostic resident-oracle run → d20 scenario and complete owner high-water → feasibility decision → optional lease API/prototype → parity/fault/lifetime tests → target I/O/cycle and physical-memory proof → generalized capacity contract → map-service admission and M2 guest gate. Keep catalog admission UI-only until the latter gates pass. The parent’s current cache path materializes complete CTAG and a complete active BSP into stable addresses and CE publishes global tag/BSP pointers only after whole-image validation (`cache_files.c:1262-1333`; [tag publication](../../submodules/halo-ce-universal/source/cache/cache_files.c#L1262), [BSP switch](../../submodules/halo-ce-universal/source/scenario/scenario.c#L1116)). HP2 bounded decode alone does not alter that pointer contract.
