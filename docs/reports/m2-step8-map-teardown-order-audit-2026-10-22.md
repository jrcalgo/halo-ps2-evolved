# Step 8 CE map-teardown order audit

Date: 2026-10-22  
Scope: report-only source audit of the reproduced Step 8 teardown issue; no implementation edits and no PCSX2 launch in this audit.

## Finding

The PS2 production transition order is unsafe for a singleton CTAG-backed map owner. **CE `game_dispose_from_old_map()` must run before `game_unload()` when an old scenario is loaded.** On this port, `game_unload()` calls `scenario_unload()`, and the PS2 `scenario_unload()` path first clears the CE scenario/BSP globals and then calls `ps2_cache_release_map_owner()`. The parent callback unloads the CTAG mount/source and makes the old tag/BSP storage available for reuse. Calling CE disposal only afterward reverses the lifetime contract: old-map callbacks execute after the storage and global pointers they are meant to retire have been unpublished/released.

This conclusion is established by source order and the port’s own test-fixture contract, not by a new emulator reproduction performed for this report. The currently running workload run/result must be treated as separate runtime evidence; this audit did not launch or alter it.

## Source-backed lifetime chain

1. CE’s `game_unload()` only calls `scenario_unload()` when `game_globals->map_loaded` is true ([`game.c:754-785`](../../submodules/halo-ce-universal/source/game/game.c#L754)).
2. CE’s `game_dispose_from_old_map()` performs map-derived cleanup—including structures, render objects, objects, players, effects, sound, and scenario cleanup—and calls `scenario_dispose_from_old_map()` near the end ([`game.c:946-984`](../../submodules/halo-ce-universal/source/game/game.c#L946)).
3. `scenario_unload()` calls `scenario_tags_unload()`, clears `global_scenario`, `global_structure_bsp`, `global_collision_bsp`, `global_bsp3d`, and `global_game_globals`, then releases the PS2 parent map owner ([`scenario.c:387-425`](../../submodules/halo-ce-universal/source/scenario/scenario.c#L387)). `scenario_tags_unload()` closes tag consumers and clears the cache header/tag table publication before returning ([`cache_files.c:617-658`](../../submodules/halo-ce-universal/source/cache/cache_files.c#L617)).
4. The parent unloader releases the active CTAG mount (and thus its source/owned sections) in `map_unloader()` ([`hcu_map_service.c:333-353`](../../src/stream/hcu_map_service.c#L333)). The source confirms that this is a storage-owner release, not merely an advisory flag.
5. The workload fixture explicitly uses `game_dispose_from_old_map(); game_unload();` and comments that CE must tear down map-derived state while tags are still owned ([`ps2_m2_ui_lifecycle_test.c:278-297`](../../submodules/halo-ce-universal/source/main/ps2_m2_ui_lifecycle_test.c#L278)). The same fixture’s guarded failure cleanup avoids `game_unload()` unless the CE map and tag table are published ([`ps2_m2_ui_lifecycle_test.c:280-287`](../../submodules/halo-ce-universal/source/main/ps2_m2_ui_lifecycle_test.c#L280)).
6. Retail CE control flow independently corroborates disposal-before-unload: non-PS2 map transition code calls `game_dispose_from_old_map()` before `game_unload()` ([`main.c:1612-1621`](../../submodules/halo-ce-universal/source/main/main.c#L1612), [`main.c:1984-1988`](../../submodules/halo-ce-universal/source/main/main.c#L1984), and [`network_game_manager.c:801-805`](../../submodules/halo-ce-universal/source/networking/network_game_manager.c#L801)). The PS2-specific early-unload branches are the divergence.

The strongest concrete consequence is a dangling/invalid old-map lifetime at subsequent disposers. For example, `game_dispose_from_old_map()` calls `objects_dispose_from_old_map()` before `scenario_dispose_from_old_map()` ([`game.c:965-980`](../../submodules/halo-ce-universal/source/game/game.c#L965)); object teardown walks and frees map-era object datums and invalidates cluster partitions ([`objects.c:1172-1205`](../../submodules/halo-ce-universal/source/objects/objects.c#L1172)). The sequence is designed as an ordered CE teardown, not as a harmless second idempotent clear after scenario unload. Not every individual callback has been proven to dereference a tag byte on every map, so the exact failure mechanism for a particular run is an inference; the ownership/lifetime violation itself is directly proven.

The PS2 branches needing production source-marked ordering edits are therefore three `main.c` paths (map-name transition, return-to-UI, local startup) plus the test-only Step 8 start helper. Two diagnostic-only paths need order correction to avoid tests normalizing the bug. The network manager and in-map BSP reset are controls, not fixes.

## Minimal regression set

### Host/source regression (fast, deterministic)

Add a narrow source contract test scoped to the actual `HALO_PS2` branches and test-only fixture code. It should parse/normalize the bodies of `main_change_map_name()`, `main_load_ui_scenario()`, `main_setup_connection()`, `hcu_step8_test_start_local_map()`, the capacity diagnostic setup, and the injected UI lifecycle setup; for any branch that retires a loaded scenario it must assert `game_dispose_from_old_map()` precedes `game_unload()` and that successor `game_precache_new_map()` follows both. Separately assert `main_reset_map_private()` remains BSP-switch/reset-only and the network manager retains the already-correct dispose-before-unload order. Avoid a global textual ordering test that accidentally conflates CE’s non-PS2 staging order or unrelated function bodies.

Add/extend a host lifecycle test with observable owner events: old-map CE dispose callbacks must see (a) `game_map_loaded()`, (b) the same scenario/tag-table identity, and (c) active parent CTAG mount; only then may scenario unload clear publications and invoke the parent owner release. Assert the precise event sequence `dispose-begin → dispose-complete → CE scenario-unpublish → owner-release → successor-load`. Inject failure at preflight and verify no dispose/unload event occurred; inject successor-load failure after owner release and verify the documented safe-empty/retry state. A fixture that only observes null globals after unload is insufficient to catch use-after-release ordering.

### PCSX2 lifecycle regression (after source fix)

Use one exact image and record ELF/source pins. In interpreter and recompiler, start from the loaded UI scenario, run UI→two-player Sidewinder workload, tick, dispose→unload back to a verified empty owner, then load UI and repeat a second map transition. Assert ordered markers for CE-dispose start/end while tag count and owner are live, CE unpublication, parent owner release, successful successor map load, gameplay workload completion, and clean teardown. Also test preflight refusal while the old UI/game map remains intact, followed by successful retry. No free-camera/render pixel claim is required for this teardown regression. The existing runner already checks workload success and empty-state markers ([`test_hcu_step8_mp_workload.py:27-58`](../../tools/test_hcu_step8_mp_workload.py#L27)); extend evidence to include order/identity, rather than accepting only the terminal marker.

## Halo-64 comparison boundary

Halo-64 is not lifecycle authority here. Its generated N64 stubs include no-op map-disposal callbacks ([`n64_stubs_generated.c`](../../submodules/halo-64/port/n64/game/n64_stubs_generated.c)); those are artifacts of the separate N64 port’s feature/platform boundary, not proof that CE map state can be disposed after tag storage is freed. The useful comparison is architectural only: keep platform ownership explicit and have the PS2 machine layer own storage release. For actual CE callback semantics and order, use HCU’s CE source and its PS2 parent-owner bridge described above.

## Confidence and limits

- **Observed/source facts:** `game_unload()` delegates to `scenario_unload()`; PS2 scenario unload clears CE publications and releases parent-owned CTAG storage; the three PS2 production transitions currently unload before dispose; the workload cleanup and non-PS2 CE path dispose before unload.
- **Strong conclusion:** dispose-before-unload is required whenever old map state is published, because tag-backed state remains in scope for CE cleanup until the ordered teardown completes.
- **Inference, not yet a reproduced runtime diagnosis:** a specific failing teardown may manifest as a stale dereference, corrupt cleanup, or later map/load error. This report did not run PCSX2 and does not assert which callback faults first.
- **Scope:** source audit covers direct `game_unload()`/`game_dispose_from_old_map()` pairs found under HCU `source/`; it does not prove all dynamic callback side effects or unrelated shutdown behavior.
